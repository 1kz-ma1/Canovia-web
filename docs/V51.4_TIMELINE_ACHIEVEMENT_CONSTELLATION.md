# V51.4 Timeline / Achievement Constellation

## 目的

Primary TimelineをWorkLog一覧から、Canoviaで起きた重要な出来事を時系列で振り返るSurfaceへ拡張する。

Timelineが答える問いは変えない。

> 何が起きた？何を積み上げた？

V51.4では、既存データからread-only projectionを生成し、次を同じSurfaceへ統合する。

- Work activity
- Collaboration activity
- Plan completion
- Achievement Constellation

## Surface Responsibility

```text
Home          = WHAT SHOULD I DO NOW?
Constellation = WHERE AM I? / WHOLE STRUCTURE
Execution     = HOW DO I EXECUTE?
Timeline      = WHAT HAPPENED? / WHAT DID I BUILD?
```

Timelineは次のActionを決めるSurfaceではない。
Plan構造の探索はConstellation、実行はExecutionへhandoffする。

## 1. Unified Timeline Projection

TimelinePageDataServiceはevent projectionを返す。

event kinds:

- work
- collaboration
- plan_completed

各eventは共通contractを持つ。

```text
kind
occurred_at
plan
title
summary
actor
target
url
```

表示順はoccurred_at降順。同日時では安定したtie-breakを利用する。

## 2. Work Event

既存WorkLogをTimeline eventへ投影する。

表示:

- Plan
- Task
- actual minutes
- memo

既存WorkLogのsource of truthは変更しない。

## 3. Collaboration Event

既存PlanActivityLogを利用する。

- collaborative Planのみ
- Timelineでは自分の操作も履歴として表示可能
- actor名
- action
- metadata由来のsummary
- target type / target id

Homeの重要変化signalとは役割が異なるため、Timelineでは履歴として保持する。

新しいnotification DBは追加しない。

## 4. Plan Completion Event

Planが完成状態の場合、Timelineへ一度だけpresentation eventを投影する。

Completion判定はAchievementと共通化する。

条件:

- weighted progress >= 100
- またはdone Taskが1件以上あり、全Taskがdone/cancelled

completed_atは既存Achievement互換で次の最新日時から導出する。

- Task updated_at
- WorkLog created_at
- Adjustment applied_at / created_at
- fallback deadline

永続event rowは追加しない。

## 5. Achievement Projection

Achievement判定と集計をAchievementProjectionServiceへ集約する。

projection:

- completed_at
- progress
- actual_minutes
- completed_tasks
- adjustment_count
- stable constellation position

既存Achievements index/showも同じcompletion source of truthを使う。

## 6. Achievement Constellation

Timeline上部にcompleted Planだけのcompact constellationを表示する。

- 1 Plan = 1 achievement star
- stable orderはcompleted_at降順 + Plan ID
- deterministic position
- Plan accentを維持
- starからAchievements detailへ遷移
- score / ranking / competitive comparisonは表示しない

これは達成履歴を見るSurfaceであり、Primary Constellation Roadmapを置き換えない。

## 7. Existing Achievement Pages

維持:

- /achievements
- /achievements/{plan}
- praise
- PlanTimelineService
- completion summary

V51.4ではroute削除・統合を行わない。

## 8. Timeline Empty State

eventが0件の場合のみempty state。

completed Planだけが存在する場合、Plan completion eventとAchievement Constellationが表示されるためemptyではない。

## 9. Data / Persistence

DB migrationなし。

追加永続状態なし。

すべて既存canonical dataからrequest時に再生成する。

## 10. DOM Contract

Timeline root:

- data-timeline-surface
- data-timeline-schema="2"

Achievement Constellation:

- data-achievement-constellation
- data-achievement-star
- data-achievement-plan-id

Timeline event:

- data-timeline-event
- data-timeline-event-kind
- data-timeline-plan-id

## 11. Tests

最低限:

- WorkLog -> work event
- collaborative PlanActivityLog -> collaboration event
- completed Plan -> plan_completed event
- incomplete Planはcompletion eventなし
- Achievement判定がAchievements indexとTimelineで共通
- Achievement Constellationにcompleted Planのみ表示
- deterministic constellation position
- Timeline event ordering
- Timeline empty state compatibility
