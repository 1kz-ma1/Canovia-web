# V53.5 Study Intelligence

## Goal

V53.5 turns Human-confirmed Study Scope plus real learning Evidence into an exam-relative Study State.

The primary pipeline is:

```text
Confirmed Study Scope
+ Practice Evidence
+ Recall Evidence
+ deadline context
        ↓
scope-level observation
        ↓
Coverage
Mastery
Retention
Speed status
Remaining Effort
Deadline Pressure
        ↓
Exam Readiness
```

Task progress is not an input to Study Intelligence truth.

## Inputs

V53.5 consumes only confirmed scope facts:

- `StudyScopeItem` whose parent `StudyScopeCapture.status = confirmed`
- normalized `study_practice_assessed` TaskEvidence
- normalized `study_recall_reviewed` TaskEvidence
- confirmed Capture exam date when unambiguous
- Plan deadline only as a fallback when no confirmed exam date exists

AI Draft data from V53.4 is not consumed as confirmed scope.

## Scope-to-Evidence matching

`StudyScopeEvidenceMatcher` links existing Practice / Recall Evidence to confirmed scope conservatively.

Strong matching signals:

- explicit unit phrase in Task or Evidence labels
- distinctive range token in Task or Evidence labels

Subject-only matching is allowed only when that subject has exactly one confirmed scope item and the scope has no more specific unit.

This rule prevents a generic Task such as:

```text
数学を勉強する
```

from marking both:

- 二次関数
- 図形

as observed.

A scope/Evidence link must reach the deterministic confidence threshold before it contributes to Coverage, Mastery, Retention, or Remaining Effort.

## Coverage

Coverage answers:

> How much of the confirmed exam scope has Canovia observed through safely linked learning Evidence?

```text
Coverage
= observed confirmed scope items
/ total confirmed scope items
```

Coverage does not use:

- Task progress
- elapsed calendar time
- estimated Task completion
- AI Draft scope

## Mastery

Per-scope Mastery uses linked Practice scores.

V1:

```text
performance
= latest score × 0.65
+ average score × 0.35
```

A bounded penalty is applied only for weakness labels that match that scope.

Plan-level Mastery is the average of measured scope Mastery values.

Unobserved scope does not receive an invented Mastery value.

## Retention

Per-scope Retention uses linked Recall Evidence.

Current rating mapping:

- again = 20
- hard = 50
- good = 80
- easy = 95
- mastered = 100

Multiple observations use:

```text
retention
= latest × 0.65
+ average × 0.35
```

Plan-level Retention averages measured scope Retention.

No Recall Evidence means Retention remains unknown for that scope.

## Speed

V53.5 deliberately does not score Speed.

Current `StudyPracticeSession.started_at → completed_at` can include:

- learner response time
- draft persistence time
- assessment generation
- provider latency
- result review / apply delay

Treating that duration as answer speed would create false precision.

Therefore:

```text
speed_score_percent = null
speed_status = unmeasured
```

Speed is surfaced as a missing dimension and does not affect the V1 Readiness score.

Readiness confidence is capped while Speed remains unmeasured.

A future phase may add authoritative per-question or active-solving timing.

## Remaining Effort Units

V53.5 does not manufacture a precise minutes-remaining estimate.

One confirmed scope item begins as one normalized Study Unit.

Per-scope remaining unit decreases as Evidence becomes stronger:

- unobserved = 1.00
- observed but mastery unknown = 0.90
- mastery < 50 = 1.00
- mastery < 70 = 0.75
- mastery < 80 = 0.50
- mastery >= 80, retention unknown = 0.35
- mastery >= 80, retention < 70 = 0.25
- mastery >= 80, retention >= 70 = 0.10

A matched active weakness keeps the item at least 0.75.

The output includes:

- remaining effort units
- remaining effort percent
- units per day when a deadline is known
- prioritized remaining scope

These units are relative workload, not clock minutes.

Future models can calibrate Study Units to time after enough authoritative duration/outcome data exists.

## Deadline semantics

Exam date priority:

1. exactly one unique confirmed Study Scope exam date
2. Plan deadline fallback
3. unknown

If multiple confirmed Captures contain different exam dates:

```text
exam_date = null
exam_date_conflict = true
```

Canovia does not silently choose one date.

Deadline Pressure is based on remaining units per available day:

- low: <= 0.75 units/day
- medium: > 0.75 units/day
- high: > 1.50 units/day
- overdue: deadline passed while remaining work exists
- unknown: no usable deadline

## Exam Readiness V1

`StudyExamReadinessEvaluator` is separate from the earlier V53.2 `StudyReadinessEvaluator`.

V53.2 remains a generic evidence-readiness baseline.

V53.5 Exam Readiness is specifically relative to confirmed exam scope.

Score:

```text
Exam Readiness
= Coverage × 0.35
+ Mastery × 0.45
+ Retention × 0.20
```

Missing Mastery or Retention contributes zero rather than being guessed.

Targets:

- Coverage >= 85
- Mastery >= 80
- Retention >= 70

Ready also requires:

- total score >= 80
- remaining effort <= 25%
- deadline pressure not high/overdue

Blocked may be used when:

- deadline already passed with remaining work
- Readiness score < 40
- deadline pressure is high

Otherwise the state is Developing.

## Readiness gaps

V53.5 can emit:

- `confirmed_scope_missing`
- `coverage_below_target`
- `mastery_unmeasured`
- `mastery_below_target`
- `retention_unverified`
- `retention_below_target`
- `speed_unmeasured`
- `exam_date_conflict`
- `exam_date_unknown`
- `exam_deadline_passed`
- `remaining_load_pressure_high`
- `remaining_load_pressure_medium`

These are structured inputs for V53.6 Adaptive Action.

## Evidence boundary

V53.5 extends normalized Study Evidence with controlled fields only.

Practice Evidence can expose:

- score_percent
- strengths
- weaknesses
- weakness_topics

Recall Evidence can expose:

- recall review/item IDs
- rating
- repetitions
- lapse count
- interval days
- mastered

Raw questions, answers, provider payloads, source documents, and arbitrary free text are not imported into Intelligence State.

## State snapshots

`StudyPlanIntelligenceService` assembles Plan-level Study Intelligence.

Snapshot persistence occurs after facts change:

- Study Scope Human Confirmation
- Practice assessment Evidence creation
- Recall review Evidence creation

Those paths use fail-safe projection through `tryPersistSnapshot()`.

The primary product action is not rolled back if Intelligence projection fails.

Study Scope GET display evaluates current State ephemerally and does not create a snapshot on every page view.

Persisted snapshot metadata includes:

- builder = `StudyIntelligenceStateBuilder`
- builder_version = `53.5`

## Duplicate scope

Confirmed scope from multiple captures is deduplicated by a semantic key built from:

- subject
- unit
- range text
- page start
- page end

This avoids double-counting the same test range when a user imports overlapping materials.

## Ordinary school tests

V53.5 completes the V53.4 category generalization.

Study Activity, AI Practice, Recall, and Recall candidate import now use:

`PlanCategoryProfileService::forPlan(...)->key === study`

instead of exact `category === 資格学習`.

AP-specific calibration remains available when the Plan/Task context identifies AP Subject A.

The generic practice profile is now `generic_study` with the label `学習・試験`.

## Diagnostic UI

The Study Scope page contains a temporary/minimal Study Intelligence diagnostic surface showing:

- Exam Readiness score / level / confidence
- Coverage
- Mastery
- Retention
- Speed = unmeasured
- remaining effort percent
- remaining Study Units
- deadline pressure
- high-remaining scope items

This is not the final Intelligence UX.

V53.6 owns Next Action generation and V53.9 owns the final default presentation.

## What V53.5 does not do

V53.5 does not:

- generate a large static Task list from scope
- use Task progress as Study State truth
- invent answer speed
- convert Study Units into fake minute precision
- mutate Task progress from Readiness
- automatically choose a Next Action
- automatically replan Tasks
- use OpenAI for the deterministic Study Intelligence calculations

## Next: V53.6 Adaptive Action

V53.6 should transform Study Intelligence gaps and prioritized remaining scope into a small current Action set.

The intended flow becomes:

```text
State
→ Exam Readiness
→ biggest current Gap
→ Decision
→ Next Action
→ execute
→ Evidence
→ State refresh
```

Task remains an optional/durable projection of Action, not the source of truth.


## V53.6 evolution note

V53.5 stopped at Study State / Exam Readiness.

V53.6 now projects those outputs through:

```text
Study State
→ Exam Readiness
→ Adaptive Decision
→ Current Action
```

The authority boundary remains unchanged:

- Task progress is not Study State truth
- AI Draft scope is not Study State truth
- Action existence does not automatically create a Task
- Task creation is explicit/user-triggered when no suitable existing Task exists
- Scope confirmation / Practice / Recall Evidence refresh Current Action after facts change

See `docs/V53.6_ADAPTIVE_ACTION.md` for the current Action and Task-projection semantics.
