# V40.2 Question Bank Provider

## Goal

V40.2 is the first release where the provider abstraction from V40.1 actually switches execution paths.

The AI Practice entry point remains unchanged.

```
Task
  ↓
AI演習
  ↓
Practice Strategy
  ↓
Coverage
  ├ sufficient → Canovia Question Bank
  └ insufficient → external AI
```

The user does not choose a provider manually.

---

## Coverage policy

`QuestionBankCoverageService` evaluates published Question Packs.

A Pack is eligible only when:

1. the qualification identity matches the Plan/Task
2. it contains at least the requested number of active questions
3. when focus topics exist, enough questions cover those topics

### Qualification identity

Identity comes from:

- `pack.exam_code`
- `pack.metadata.match_terms[]`

`subject` is only an additional score after qualification identity has matched.

This prevents a generic subject such as `科目A` from making a Basic Information (FE) Pack eligible for an Applied Information (AP) Plan.

### Current question count

Practice Strategy currently asks for 10 questions.

A Pack with fewer than 10 active questions does not replace the external-AI fallback.

### Focus coverage

When Strategy has focus topics, at least 3 questions must match the current focus.

Question matching uses:

- learning_metadata.concepts
- learning_metadata.weakness_targets
- learning_metadata.tags
- learning_metadata.keywords

This is intentionally conservative. A large generic Pack should not take over a weakness-reinforcement session if it cannot cover the weakness.

---

## Question selection

`QuestionBankStudyPracticeQuestionProvider` selects questions in this order:

1. focus topic match
2. questions not used in the most recent five Question Bank sessions
3. difficulty preference
4. explicit sort_order
5. question id

For `retention_and_transfer`, harder questions are preferred.

Other strategies prefer lower difficulty first after focus/repetition criteria.

Selected question ids and provenance are persisted in `StudyPracticeSession.selected_questions`.

## User flow

### Question Bank available

```
AI演習
→ Canovia shows Practice Strategy
→ Canovia Question Bank is selected
→ 「演習を始める」
→ questions appear immediately
```

No generation Prompt and no question JSON paste are shown.

### Coverage insufficient

The existing external AI flow remains:

```
AI演習
→ generation Prompt
→ external AI
→ paste JSON
→ answer in Canovia
```

The external provider is pinned for that session. A Pack being published while the user is already doing the handoff cannot silently switch the same exercise to Question Bank.

## Deterministic grading

`QuestionBankGrader` currently supports:

### exact_choice

```json
{
  "type": "exact_choice",
  "field_id": "answer",
  "answer": "A"
}
```

### exact_multiple

```json
{
  "type": "exact_multiple",
  "field_id": "answer",
  "answers": ["A", "C"]
}
```

Order does not matter.

### numeric_tolerance

```json
{
  "type": "numeric_tolerance",
  "field_id": "answer",
  "answer": 42,
  "tolerance": 0.5
}
```

If every question can be graded deterministically, Canovia produces the assessment immediately after submission.

No external assessment JSON is required.

### Task progress

Deterministic grading does not infer Plan/Task completion.

`recommended_task_progress_percent` remains the current Task progress.

The result may still update the Task's next action and learning history after user confirmation.

## Reasoning / written assessment

A Question Bank problem may contain optional reasoning fields.

Example:

```json
[
  {
    "id": "answer",
    "type": "single_choice",
    "required": true,
    "choices": [...]
  },
  {
    "id": "reasoning",
    "type": "textarea",
    "required": false
  }
]
```

If the learner leaves the optional reasoning blank, Canovia can grade the exact answer directly.

If the learner actually writes reasoning, Canovia routes assessment to the external AI so the reasoning receives feedback.

For Question Bank questions, the assessment provider enriches the evaluation Prompt *after the learner has answered* with:

- grading_rule
- explanation
- learning_metadata

The Question Bank's grading context is authoritative. The AI is explicitly told not to invent a different answer.

This gives:

```
trusted answer key + AI reasoning feedback
```

rather than asking AI to solve its own generated problem again.

## Question Pack Admin

Admin entry:

`/admin/question-packs`

The Admin dashboard and navigation expose the Question Bank manager.

### Import

Question Pack JSON is pasted into the Admin UI.

Import always produces an editable `draft`.

For Draft/Review re-imports, the supplied JSON is treated as the authoritative snapshot:

- matching external_key → update
- new external_key → create
- previously existing but omitted question → mark inactive

### Publish quality gate

A Pack can be published only when:

- it has at least one active question
- every active question has a grading_rule
- written questions use ai_rubric when deterministic grading is not possible
- every active question has at least one learning classification term
- the Pack has exam_code or metadata.match_terms for qualification routing

Drafts may remain incomplete while content is being prepared.

### Published Pack immutability

A published Pack cannot be imported over.

Allowed lifecycle:

```
draft ↔ review
draft/review → published
published → retired
retired → retired
```

A corrected published Pack must use a new slug/version.

This prevents live problem content and answer keys from changing silently.

## Import schema

Top level:

```json
{
  "schema_version": "1.0",
  "pack": {},
  "questions": []
}
```

### pack

```json
{
  "slug": "ap-a-v1",
  "title": "応用情報技術者試験 科目A",
  "exam_code": "AP",
  "subject": "科目A",
  "version": "1",
  "downloadable": true,
  "metadata": {
    "match_terms": [
      "AP",
      "応用情報",
      "応用情報技術者試験"
    ],
    "locale": "ja-JP"
  }
}
```

### question

Important fields:

- external_key
- source_type
- source_reference
- prompt
- response_schema
- grading_rule
- learning_metadata
- explanation
- difficulty
- sort_order
- is_active

### source_type

Allowed:

- official
- licensed
- canovia_original
- derived
- ai_generated

`official`, `licensed`, and `derived` require `source_reference`.

The Admin operator must still verify copyright/licensing conditions before publishing. Canovia only enforces provenance metadata, not legal permission.

## learning_metadata

Recommended structure:

```json
{
  "concepts": ["ネットワーク", "TCP"],
  "weakness_targets": ["MTU", "TCP分割"],
  "tags": ["科目A", "計算"],
  "keywords": ["フラグメンテーション"]
}
```

This metadata drives future selection quality.

Problem text alone is not used as the primary weakness-matching mechanism.

## Admin quality boundary

V40.2 intentionally does not scrape or automatically publish official questions.

The operational flow is:

```
source acquisition / rights check
→ build Question Pack JSON
→ Admin Draft import
→ validate source / answer / tags
→ Review
→ Publish
```

This keeps content acquisition and application execution separate.

---

## Pack selection priority

Published Pack metadata may include:

```json
{
  "selection_priority": 100
}
```

This priority is evaluated only after qualification matching and Pack availability.

A higher priority Pack cannot override a Pack that lacks enough questions or enough focus-topic matches for the current strategy.

This allows authentic official past-question Packs to be preferred for General Practice while retaining a broader derived/original Pack for gaps.

Absent or invalid priority defaults to 0.
