# V58.12 Study Activity Outcome Observation

Status: implemented / validated  
Branch: `feature/v58-12-study-activity-outcome-observation`

## 1. Goal

Use accumulated Study execution data to observe what happened after each
Activity without claiming that the Activity caused the result.

```text
Practice assessment
→ one observed Activity type
→ next Practice assessment
→ before / after score observation
```

V58.12 is a descriptive observation layer.

It does not automatically alter Study Method Recommendation.

## 2. Actor and Task boundary

All projection is scoped to:

- the same Plan;
- the same Task;
- the current actor.

Actor isolation:

- authenticated actor → `user_id`
- anonymous actor → `actor_token`

Evidence from another actor is never included in the comparison.

## 3. Objective comparison boundary

The comparison anchor is:

`study_practice_assessed`

with a valid integer:

`score_percent = 0..100`

Practice assessments with missing or invalid scores are ignored as comparison
boundaries.

## 4. Tracked intervening Activities

Between two adjacent valid Practice assessments, V58.12 observes:

- `study_recall_reviewed` → Recall
- `study_resource_study_completed` → Resource Study
- `study_language_activity_completed`
  - Listening
  - Dictation
  - Shadowing

If no tracked non-Practice Activity exists between the two valid Practice
assessments, the interval is classified as:

`question_practice`

This means "Practice → later Practice with no other tracked Study Activity",
not proof that no unrecorded study occurred.

## 5. Same-type grouping

Multiple events of one Activity type between the same two Practice assessments
still produce one before/after score observation.

Examples:

```text
Practice 50
→ Recall review
→ Recall review
→ Recall review
→ Practice 70

Recall observation:
50 → 70
delta +20
usage_count 3
observation_count 1
```

The same applies to multiple Resource Study / Listening / Dictation /
Shadowing completion Evidence rows.

## 6. Mixed intervals

If more than one tracked Activity type occurs between adjacent Practice
assessments, the interval is excluded from per-Activity attribution.

Example:

```text
Practice
→ Recall
→ Listening
→ Practice
```

This increments:

`ambiguous_interval_count`

but does not create either a Recall or Listening outcome observation.

Unknown future language Activity keys are also treated as ambiguous rather than
silently falling back to Question Practice.

## 7. Temporal proximity guard

If adjacent valid Practice assessments are more than 14 days apart, the
interval is excluded.

This increments:

`stale_interval_count`

The 14-day boundary does not make shorter intervals causal. It only avoids
presenting very distant assessments as a useful local before/after comparison.

## 8. Supported Activity rows

The projection returns:

- Question Practice
- Recall
- Resource Study
- Listening
- Dictation
- Shadowing

V58.14 adds explicit Resource Study completion Evidence.

Resource Study now uses the normal measurement states:

- `waiting` when no comparable explicit Evidence exists;
- `observed` when a valid before/after pair exists.

Canovia still does not infer Resource Study usage merely from opening a Resource
URL.

## 9. Per-Activity metrics

Each Activity row includes:

- usage_count
- observation_count
- average_before_score
- average_after_score
- average_score_delta
- latest_before_score
- latest_after_score
- latest_score_delta
- latest_observed_at
- measurement_status

All score deltas are deterministic integer point differences.

## 10. Task-level metrics

The projection includes:

- practice_assessment_count
- valid_observation_pair_count
- ambiguous_interval_count
- stale_interval_count
- max_interval_days

No table or persisted aggregate is introduced.

## 11. UI

Study Activity shows a collapsed:

`実利用でのActivity観測`

section.

It explains that the values are descriptive before/after observations, not
causal proof.

Summary cards show:

- Practice assessment count
- comparable intervals
- mixed-Activity exclusions
- intervals excluded for >14 days

Per-Activity rows show:

- execution count
- comparison count
- average before → after
- average score delta
- latest before → after

If fewer than two valid Practice assessments exist, the UI shows:

`観測待ち`

instead of creating a synthetic result.

## 12. Interpretation boundary

A positive delta after an Activity does not prove the Activity caused the
improvement.

Possible confounders include:

- question difficulty;
- topic mix;
- outside study;
- prior knowledge;
- elapsed time;
- sleep / attention;
- unrecorded Resource Study;
- other unrecorded study.

Therefore UI language uses:

- 観測
- 前後差
- 後続Practice

and does not claim optimized or proven effectiveness.

## 13. Recommendation boundary

V58.12 does not modify:

- `StudyActivityPolicyService`
- `StudyMethodRecommendationService` scoring
- primary Activity selection
- Practice Strategy
- Practice Reliability
- Task progress
- mastery rules

Dedicated validation confirms that adding observation Evidence does not change
the same fixed Study Method Recommendation input/output.

A future recommendation-feedback policy requires a separate reliability /
causal-design contract.

## 14. Provider and storage boundary

Projection is:

- DB-only
- deterministic
- read-only
- provider-free

Opening Study Activity because of V58.12 sends no AI/provider request.

No migration is required.

## 16. Result

Canovia can now distinguish:

```text
"this Activity fits the Task semantically"
```

from:

```text
"after this recorded Activity, later Practice changed this much"
```

The second statement is now visible from real usage data without being promoted
into an unsupported causal claim or automatic recommendation rule.

## V58.14 Resource Study observation update

V58.14 adds `study_resource_study_completed` as the explicit Resource Study
Activity Evidence.

The V58.12 projection now maps that type to `resource_study`. Repeated
Resource Study Evidence inside one Practice interval counts as multiple usage
events but one score observation. Mixed Resource Study + another tracked
Activity remains ambiguous and excluded.

The previous permanent `unmeasured` Resource Study state is retired.

See `docs/V58.14_RESOURCE_STUDY_EVIDENCE.md`.
