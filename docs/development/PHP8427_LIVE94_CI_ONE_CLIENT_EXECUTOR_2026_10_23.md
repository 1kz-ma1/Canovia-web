# PHP 8.4.27 Track H — source-bound one-client executor (synthetic CI only)

**Date:** 2026-10-23. **Review scope:** Old Live94 of `15abdc9de6f24b5250fb255c579d1aa55facaf1a`, with the frozen seven SELECTs, **MySQL 8.0 and 8.4 disposable containers only**. **No Aiven connector or operator live mode exists in this artifact.**

## Why a new executable is required

The old deployed operator script `scripts/ops/p0_mysql_operator_select_only_collect.sh` uses three independent MySQL sessions. A grants check in one session cannot by itself authenticate the identity or scope of a later query session. CI #843–#847 exercised real disposable MySQL with synthetic SQL wrappers, TLS CA/SAN, roles and processlist; this step implements and tests a single source-bound **client launcher** with bounded output, sanitized MySQL environment, no reconnect, and a strict parser in the same process. It is **not** an authorization to run the legacy collector on real Aiven, and not a production-ready reader.

## Exact execution invariant

`scripts/ci/php8427_live94_ci_single_session_executor.py`:

1. Before any MySQL invocation, requires the exact fixed `GITHUB_ACTIONS=true`, testing environment, source/port/DB/user/password markers, and ephemeral MySQL container ID matching the existing disposable tests. Rejects Aiven-specific variables and live/owner approval flags. The CLI accepts **only** `--checkout` and `--ca`; no configurable target, user, port, SQL, approvals, environment, output path or login path. A manually supplied `GITHUB_ACTIONS=true` is not an attestation; the hardcoded disposable account/loopback and CI service setup are also required.
2. Checks complete old Live Git SHA `15abdc9...`, exactly 94 migration Git objects/tree and all seven original operator code/SQL file blobs through `build_manifest()`. Builds exactly the six original schema-inventory `SELECT` statements and one full-ledger `SELECT`, in that frozen order, with identity/grants/roles/mandatory-roles markers before and after, **without modifying** old audit SQL.
3. Checks CA file exists under `RUNNER_TEMP`, non-symlink/regular file, restricted write permissions, bounded size and PEM structure. The CA used here is generated by the **existing disposable** TLS test script for `localhost` SAN, not an Aiven CA.
4. Starts **one** official MySQL CLI process **inside the pinned disposable MySQL service container**, via `docker exec -i`; never a shell. This avoids accidentally using the GitHub runner's different MySQL/MariaDB client, which may not support `--no-login-paths`. The actual MySQL CLI process uses fixed `--no-defaults --no-login-paths --protocol=TCP --host=localhost --port=3306 --user=live94_ci --database=canovia_live94_synth_ci --ssl-mode=VERIFY_IDENTITY --ssl-ca=<CI CA> --skip-reconnect --local-infile=0 --skip-system-command --skip-named-commands --batch --raw --skip-column-names`. The MySQL CLI itself receives no `--password` argument, query text or certificate private key in argv; the wrapper argv does contain the **published synthetic-only password** as a Docker env parameter. This MUST NOT be reused for any live account.
5. Scrubs all host-side inherited MySQL/DB/operator environment; passes only minimal `PATH`, isolated temporary `HOME`, and `LC_ALL=C` into the Docker wrapper. The **fictional**, hardcoded `MYSQL_PWD` is passed by `docker exec --env` to the container's single MySQL process and is consequently visible in the **CI-only Docker wrapper argument vector**. This is acceptable only for the publicly fixed, throwaway credential: **never adapt this transport for a real database/password**. No real provider secret is read or accepted. This is not a model for real operator credential transport.
6. Runs a fixed SQL packet once through standard input, with bounded wall-clock (70s), private temporary 0600 output, kernel file-size limit (262145 bytes), suppressed raw stderr and fail-closed process kill on deadline; no retry. Captured raw TSV and test CA stay private on the disposable runner and are deleted on normal cleanup; do not expose raw grants, identifiers or any actual data in logs.
7. Uses the existing redacted observer parser to assert *same* connection ID, server UUID, MySQL user, schema, active/mandatory-role absence and tightly restricted grants at both ends, correct source-pinned inventory and fictional **94/94** ledger, and deliberately incomplete physical schema. As with all synthetic tests, its final state is **`HOLD`**, not release authorization.

MySQL official references: [`--no-login-paths` suppresses `.mylogin.cnf` even with `--no-defaults`](https://dev.mysql.com/doc/refman/8.4/en/option-file-options.html); [`--skip-reconnect`, `--local-infile=0` and `--ssl-mode=VERIFY_IDENTITY`](https://dev.mysql.com/doc/refman/8.4/en/mysql-command-options.html).
