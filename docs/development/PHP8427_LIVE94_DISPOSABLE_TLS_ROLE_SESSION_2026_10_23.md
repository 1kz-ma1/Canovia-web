## New disposable CI tests

Run `scripts/ci/php8427_live94_disposable_tls_role_session.sh` **only after** the existing matrix CI has created `canovia_live94_synth_ci` and fixed fictional account `live94_ci`. Guard the shell by GitHub Actions marker, app environment testing, loopback and exact synthetic DB/user/password markers, fixed root CI-only password, and the exact ephemeral MySQL service container ID. Abort before any MySQL invocation when not in this environment. `bash -n` and negative tests confirm a local non-CI invocation is refused.

1. **Role privilege escalation:** revoke the preceding CI-only direct grant on `users`, check denied access, create a disposable `live94_ci_unsafe_role` carrying `SELECT users`, grant and activate it as the default role, independently prove the fictional personal-data read is now possible, and re-run the reviewed same-client-session audit. The result parser must reject the active role (or role GRANT). Restore no default role and drop the throwaway role. This directly tests a limitation of bare `SHOW GRANTS FOR CURRENT_USER()`. It still does not prove that mandatory roles and every effective privilege can be recognized in actual Aiven. Never install/enable roles on a real service.
2. **Actual synthetic TLS CA:** copy `ca.pem` only from this disposable container into a private temporary directory on the GitHub runner. Connect with `--ssl-mode=VERIFY_CA` and require a nonempty TLS cipher. Reject a different freshly generated CA and reject `--ssl-mode=VERIFY_IDENTITY` when the auto-generated test-server certificate does **not** contain matching hostname/IP identity. Require SSL for the disposable reader and ensure `--ssl-mode=DISABLED` is rejected. Importantly, **a positive, custom-SAN, hostname-verified TLS connection remains NOT TESTED**. A known bad hostname rejection cannot be treated as positive production identity assurance. See [MySQL encrypted connection options](https://dev.mysql.com/doc/refman/8.4/en/connection-options.html).
3. **Observed connection removal:** a separate ephemeral root connection checks `information_schema.PROCESSLIST` for the exact prior reader `CONNECTION_ID()` after normal client exit, expecting absence. A second fictional query `SLEEP(10)` triggers a bounded local `timeout -k 2s 3s`, followed by a capped independent observer polling for eventual absence of that thread, without granting any extra privilege to the scoped reader or issuing `KILL`. A local timeout, client QUIT or even a later observed removal on *this CI MySQL server* **does not prove reliable remote Aiven session termination** after a network/host crash. Failure to observe termination in the bound is a CI failure and remains HOLD. See [MySQL process-list visibility](https://dev.mysql.com/doc/refman/8.4/en/processlist-access.html).
