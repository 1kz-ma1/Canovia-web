# Security Audit v1 — 旧Canovia暗号化バックアップ保全・復元検証記録（2026-11-16）

**判定：ARCHIVE_DB_RESTORE_PASS（オーナー実行結果に基づく）／DATA_FRESHNESS_UNVERIFIED／FULL_APP_RECOVERY_UNVERIFIED／RELEASE_HOLD_UNCHANGED**

この文書は、旧Canovia/Aiven MySQLの**既存暗号化バックアップ**に対してオーナーがMacで実施し、会話で提示した検証結果を記録する追補である。GitHubのCI・エージェント・Aiven APIが実データや秘密鍵を直接検証したという意味ではない。運用上の正本と公開判定を置き換えない。

- 関連既存正本：[Platform release baseline §4・§6](PLATFORM_RELEASE_BASELINE_AND_PREFLIGHT_2026_10_14.md)。同文書には2026-10-14時点のオーナー申告として91テーブル・94 migrations・48,916行の復元実績が記録されている。
- 既存の暗号文コピー検査：[scripts/ops/platform_backup_ciphertext_check.py](../../scripts/ops/platform_backup_ciphertext_check.py)。本検証の手動シェル操作とは**別**。このスクリプトの実行結果や、バックアップ取得時の期待SHA-256との照合を推認しない。
- 本追補はSecurity Audit v1の**旧データ保全に関する限定証跡**であり、他のセキュリティ指摘の解消・本番公開・Aiven削除・有料化を許可しない。

## 1. 検証対象と時点

| 項目 | 値・出典の扱い |
| --- | --- |
| バックアップ形式 | `mysqldump → gzip → age`（既存ドキュメント・オーナー申告） |
| SQLダンプ終了日時 | `2026-10-14 12:34:37`（SQL内の終了コメントをローカルで読み取り。**タイムゾーン未記録**） |
| 暗号化ファイルサイズ | Mac側・iCloud由来として選択したコピーとも `2,802,646 bytes` |
| 対象DB | 旧CanoviaのMySQL論理ダンプ。現行Aivenの実行中状態は照会していない |
| 実施・報告日 | 2026-11-15〜16（オーナーが結果コードを会話で提示） |

`DUMP_COMPLETED_AT`はSQLダンプ完了を示すもので、**テーブル行の最終更新日時ではない**。2026-10-14以降、旧Web版の更新は「なかったと思う」とのオーナー認識があるが、サーバーログ・DB差分などによる独立確認は未実施。

## 2. オーナーが提示した実行結果

| 段階 | 出力・観測 | 判定範囲 |
| --- | --- | --- |
| 暗号化ファイル照合 | `PASS_CIPHERTEXT_MATCH`、両コピー各 `2,802,646 bytes` | SHA-256で両コピーが同一。**取得時に別記録した期待ハッシュとの一致やiCloud.com取得経路の独立証明はなし** |
| 復号・gzip | `PASS_AGE_DECRYPT_GZIP` | Mac上の元のage秘密鍵で復号でき、gzip整合性検査を通過 |
| SQL構造 | `SQL_HEADER_FOUND=True`、`CREATE_TABLE_COUNT=91`、`INSERT_STATEMENT_COUNT=55`、`MIGRATIONS_TABLE_FOUND=True`、`SQL_FOOTER_FOUND=True` | MySQLダンプの基本構造を検出。**55はINSERT文数であり行数ではない** |
| 検証用MySQLの起動 | `ISOLATED_MYSQL_READY`、`NETWORK=NONE`、`HOST_PORTS=NONE`、`DATABASE_STORAGE=TMPFS` | Dockerの専用 `mysql:8.4` コンテナをネットワーク無効・ホストポート公開なし・DB領域tmpfsで準備 |

**観測の限界：** 出力はいずれもオーナーが実行して提示したテキストで、GitHubに機密ログ・SQL本文・秘密鍵・利用者データを収集していない。復号されたSQLを**明示的に平文ファイルとして保存しない**パイプ方式だったが、Docker Desktopのスワップ、システムログ等まで含めた完全な非残留性や安全消去は証明していない。上記の検証はアプリケーション機能・参照整合性・個々のレコード内容の正当性を網羅するものではない。

## 3. 鍵の保管・確認範囲（秘密情報を記録しない）

- 元のage秘密鍵はMacで利用可能であり、今回の復号成功によって**動作を実証**した。
- オーナー申告では同じ秘密鍵テキストを**パスワードマネージャーにも保存**している。ただし、その保存内容を取り出した予備鍵による**独立復号試験は未実施**。パスワードマネージャー自体への障害時アクセスも未検証。
- 別途Finderで選択した2ファイルの比較では `FAIL_KEY_MISMATCH` が出たが、**パスワードマネージャー内のテキストを照合した結果ではない**。予備鍵を失効・不正と断定しない。
- 鍵内容、鍵の全文パス、保管サービスの認証情報、SQL本文、利用者情報、暗号化ファイル本体はGitHubに保存しない。復号可能な鍵と暗号化バックアップを同一の無保護共有領域へ平文で共置しない。

## 4. 保全判断と残余リスク

**確定してよい範囲：** 保有する2026-10-14版の.ageから、指定したMacの秘密鍵でSQLを復号し、隔離されたMySQL 8.4で**91テーブル・94 migrations・48,916行**を復元できた（オーナー提示結果）。バックアップの「DB復元可能性」は実証済みとして扱う。

**未確定・未受入の範囲：**

1. **鮮度：** 2026-10-14以降に旧Canoviaのアカウント/Plan等の更新がなかったことは本人認識であり、現Aivenとの比較では未証明。したがって最終保存対象の鮮度には留保がある。
2. **保管独立性：** Mac/iCloudの暗号文同一性は確認したが、ダンプ作成時に記録した期待SHA-256との一致、外部保管経路、ファイル権限およびパスワードマネージャー側の予備鍵による復号は独立に確証していない。
3. **アプリ全体の復旧：** DB外の添付ファイル・オブジェクトストレージ・アカウント連携・外部ID・運用環境、必要な場合のLaravel `APP_KEY` 等の機密設定、復旧先アプリバージョンとschema互換性は**別途確認が必要**。DBのIMPORT成功はログイン・暗号化カラム・旧Web版機能の復旧成功ではない。
4. **本番復旧/リリース：** 本検証はローカル隔離コンテナ限定。現行Aiven/Render本番へ問い合わせ、変更、復元、権限付与、デプロイは行っていない。Security Audit v1のP0/P1等の別指摘、製品リリースHOLDは**継続**。

**費用・終了判断：** アーカイブしたDBの復元可能性だけを理由にAiven有料プランを選ぶ必要性は低い。一方、最終鮮度・復旧に必要な周辺資産・保管鍵を確認するまで、**Aivenのサービス削除、プラン変更、課金、現行バックアップの破棄はいずれも未承認**とする。Aiven Freeの提供終了日と実際のサービス状態は実行時に公式情報で再確認すること。
