# V45.6 Map Signal Density

## Goal

V45.5後のスマホ実機確認で見えた2点を補正する。

1. Fullscreen Mapの外側にApp shell由来の余白が残る
2. Personalized Satelliteが「航路短縮」ではなく「よく使うもの一覧」化し、L0の固定意味構造を濁らせる

V45.6では新機能を増やさず、Mapのsignal-to-noise ratioを上げる。

## Edge-to-edge Map shell

原因:

`layouts/app.blade.php`のmainは通常Surface向けに:

- px-4
- py-5
- density別padding

を持つ。

Fullscreen Map側でもpadding:0を指定していたが、
Tailwind utility / densityの!important指定が勝つ経路があり、
Map routeでもbody backgroundが左右・上下に見えていた。

V45.6ではMap routeだけ:

- body margin/padding = 0
- app-main inset = 0
- app-main width = 100vw
- app-main height = 100dvh
- app-main max-width = none
- app-main padding = 0 !important
- map page / workspace / shell horizontal padding = 0

を強制する。

Safe AreaはCanvas外余白ではなく、
Top Bar / Dock / Context Surface側でenv(safe-area-inset-*)を受ける。

## Personalized Satellite principle

L0 Satelliteは「候補があるから出す」ものではない。

新原則:

> Satelliteは、固定Intentから複数階層を辿る必要がある独立Contextへの航路短縮であり、
> Taskの従属物や固定Intentと同義のものを複製しない。

## Candidate eligibility

### Personal Plan

未完了Taskを持つPersonal Planはcandidateにできる。

ただしpromotionには強い利用signalが必要。

### Shared Plan

Shared PlanはL0 Satellite candidateから除外する。

理由:

L0には固定の`共同`Intentが存在し、
Shared Planを同時にSatellite化すると同じ意味領域への入口が重複するため。

Shared Plan自体はL1/L2 collaboration hierarchyに残る。

### Task-bound Tool

AI Practice等、Task IDとセットで意味を持つToolは
L0 Satellite candidateから除外する。

```text
Plan
  -> Task
      -> AI Practice
```

を

```text
L0 -> AI Practice
```

へ独立昇格しない。

Task-bound ToolはExecution Map / Task Context内で表現する。

将来、Taskから独立して再訪するToolが明確になった場合のみ
別candidate種として再検討する。

## Promotion density

V44.4初期:

- threshold 0.28
- max 4

V45.6:

- threshold 0.55
- max 2
- same anchor Intent: max 1

同じ`intent:plan`配下に複数Planが強くても、
L0へ出すのは最上位1件だけ。

これにより現在のcandidate setでは
実質1件程度のPlan Shortcutになることが多い。

## Signals

4軸とweightは維持する。

- importance 0.35
- usage_frequency 0.25
- recency 0.20
- continuity 0.20

重要度だけではpromotionしない。

例:

```text
importance = 1.0
usage = 0
recency = 0.25
continuity = 0.45

score = 0.49
```

threshold 0.55未満なので表示しない。

## UI copy

Satellite visual metaphorは内部Visual Grammarとして維持するが、
Node eyebrowでは`PLAN SATELLITE`ではなく`PLAN`と表示する。

ユーザーに内部実装名を読ませず、
形・位置・Plan名で意味を伝える。

## Architecture boundary

変更しない:

- fixed L0 5 nodes
- Space Station center
- Navigation Graph
- L1/L2/L3 canonical hierarchy
- Projection persistence policy
- Telemetry whitelist
- Pan/Zoom
- Focus / Context Surface
- Visual Grammar
- Classic Home

Satelliteは引き続きAttention projectionであり、
canonical entityではない。

## Persistence / privacy

新規DB tableなし。

保存しない:

- satellite rank
- promotion score history
- absolute position
- hidden candidate list
- user content

既存BehaviorEvent / WorkSession等からrequest時に決定する。

## Tests

- max 2
- same anchorから1件のみ
- Shared PlanはSatellite化しない
- repeated AI PracticeはTool Satellite化しない
- AI Practice利用が強い場合でもPlan Shortcutとして表現可能
- fixed L0 semantic graphは5 nodeのまま

Space Station
