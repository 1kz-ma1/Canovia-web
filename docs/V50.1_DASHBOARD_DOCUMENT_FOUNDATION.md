# V50.1 Dashboard Document Foundation

> **V50.3 implementation:** Plan Dashboard now uses this generic Dashboard Document runtime directly at `/plans/{plan}/dashboard`; it is no longer Map-owned. Spatial Roadmap remains an embedded structure Region. See `docs/V50.3_STANDALONE_PLAN_DASHBOARD.md`.

> **V50.2 implementation:** Plan Dashboard is the first production surface to adopt the 12-column Information Board composition. It remains Map-owned during this phase. See `docs/V50.2_PLAN_DASHBOARD_INFORMATION_BOARD.md`.

## 目的

複数の情報を一度に俯瞰して判断するDashboardを、縦スクロール前提のFeedではなく「一枚の情報ボード」として表現できる共通Surfaceを作る。

V49.9でMap最下層に実装したDocument CameraをMap専用技術から切り離し、Canovia全体で再利用できるDashboard Documentへ昇格する。

V50.1では既存Dashboardの配置変更そのものは行わず、共通runtime / component / layout contractを先に整える。

## Surface responsibility

Canoviaの主要Surface責務は次の3つに分ける。

```text
Classic
= 入力・編集・一覧・日常操作

Dashboard Document
= 複数情報の俯瞰・比較・判断

Map
= 構造・関係・依存・並行性の探索
```

Dashboard DocumentはMapではない。

必要な場合だけDocument内部の一RegionとしてSpatial Roadmap / Contextual Mapを埋め込める。

## Dashboard Document interaction

初期状態は全体fit。

```text
Fixed Chrome
├ Title / Navigation
├ −
├ 全体
├ ＋
└ Zoom %

Document Scroll
└ Document Stage
   └ Document Canvas
      └ Information Regions
```

Document Canvasだけをscaleし、Chromeは常にscreen-space sizeを維持する。

操作:

- 初期fit
- explicit zoom
- touch pinch
- trackpad pinch
- pan
- double click zoom
- resize時再計算

fit scaleを下限、160%を上限とする。

## Shared runtime

`resources/js/dashboard-document.mjs`

が以下を提供する。

- documentFitScale
- documentZoomScale
- documentPinchScale
- documentRegionFocusScale
- documentAnchorScroll
- mountDashboardDocuments

V49.9 Map runtimeはCamera mathをこのmoduleからimport / re-exportする。

これによりCamera mathのsource of truthをMapからDashboard Documentへ移す。

## Ownership boundary

既存Plan Dashboard / leaf Detailは段階移行のため:

```html
data-dashboard-document
data-dashboard-document-owner="map"
```

を持つ。

Generic Dashboard runtimeは `owner="map"` をmountしない。

当面:

- Map-owned Plan / Detail -> living-map runtime
- Map外Dashboard Document -> dashboard-document runtime

とし、二重gesture handlerを防ぐ。

将来Map固有のBack / Semantic Zoom依存を除去できたSurfaceからgeneric runtimeへ移行できる。

## Information board

Dashboard Document Canvasは12-column gridを標準とする。

Regionは:

- span: 1〜12
- rows: 1〜4
- emphasis:
  - normal
  - primary
  - quiet
  - alert

を持つ。

例:

```text
┌──────────────────────────────────────────┐
│ Plan Summary      KPI        Progress     │
│                                          │
│ Today / Next      Blocker / Alert         │
│                                          │
│          Spatial Roadmap                 │
│                                          │
│ Activity           AI Insight             │
└──────────────────────────────────────────┘
```

Mobileでも情報構造を縦一列へ強制reflowせず、同じ一枚をfitして必要箇所へzoomできる。

## When not to use Dashboard Document

以下は従来のClassic / Scrollを優先する。

- 長文を順番に読む
- 大量のForm入力
- Table編集
- Settings
- Chat
- 大量Task list
- 高頻度の単一Action

Dashboard Documentは「何でもCanvas化する」ためのSurfaceではない。

## Map embedding

Dashboard Document内にMapを埋め込む場合、Mapは1つのRegionとして扱う。

例:

```text
Dashboard Document
├ Progress Region
├ KPI Region
├ Next Action Region
├ Alert Region
├ Spatial Roadmap Region
└ AI Insight Region
```

MapはDashboard全体のNavigation責務を持たない。

## CSS

Generic styles:

- resources/css/dashboard-document.css

app.cssからMap CSSより先に読み込む。

Map-owned Documentsは既存Map CSS / runtimeを維持する。

Generic controlsはMap classへ依存しない。Map compatibilityが必要な旧partialだけ明示的にlegacy aliasesを付与する。

## Persistence

追加DBなし。

保存しない:

- scale
- scroll position
- pinch state
- fit state

V50.1ではDashboard Document preferenceも追加しない。

## Non-goals

- 既存Dashboardの全面移行
- Plan Dashboardの情報再配置
- Home DashboardのCanvas化
- Automatic Dashboard/Scroll選択
- Dashboard layout editor
- Region drag-and-drop
- Region位置永続化
- Map runtime完全廃止
