# V44.5 Collaboration / External Tools

> **V49.0 update:** この文書のHuman Review / explicit collaboration state / external truth境界は引き続き有効。一方、Map hierarchyはPurpose-first L1/L2から `L1 Shared Projects -> L2 Project Workspace Palette` へ変更された。Purpose情報はProject内の運用stateとして残し、入口hierarchyには使用しない。詳細は `docs/V49.0_CONTINUOUS_SEMANTIC_ZOOM_COLLABORATION_WORKSPACE.md` を参照。

## Goal

L0「共同」をShared Plan一覧やGitHub一覧として見せず、
ユーザーが共同作業で次に判断する目的へ再投影する。

初期Purpose:

- 自分が進める
- レビュー待ち
- 相手待ち
- 外部Toolで確認

```text
Shared Plan / Artifact / Task
        ↓
Canoviaで確認できる事実
        ↓
Collaboration Purpose
        ↓
次のExecution / 外部確認先
```

外部サービスの状態は推測しない。

## Core principle

V44.5でも:

> Navigation Graphは存在と関係を表し、Attentionは見せ方を表す。

を維持する。

さらに共同Contextでは:

> Providerではなく、人間の次の判断で整理する。

を追加する。

GitHub / Google Drive / OneDriveは目的ではなく確認先である。

## L0

固定L0「共同」Nodeはそのまま維持する。

```text
L0 共同
  ↓
L1 Purpose
  ↓
L2 Collaboration Item
  ↓
L3 Execution / External Tool
```

L0 Node自体を増やさない。

## L1 Purpose

共同Intentでは通常のPlan.category Domain Projectionを使わない。

固定Purpose:

### 自分が進める

以下を表示する。

- current userがassigned_user_idのArtifact
- owner / editorとして編集可能なShared Planで、担当Artifactがない場合の次Active Task

Viewerには「編集可能Task fallback」を出さない。

### レビュー待ち

`PlanArtifact.metadata.collaboration_state = review`

と人が明示したArtifactだけを表示する。

GitHub Pull Request URLだからという理由だけでレビュー待ちにはしない。

### 相手待ち

`PlanArtifact.metadata.collaboration_state = waiting`

と人が明示したArtifactだけを表示する。

assigned_user_idが他人だからという理由だけで自動的に相手待ちにはしない。

### 外部Toolで確認

providerが:

- github
- google_drive
- onedrive
- external

のArtifact、または明示stateがexternal_followupのArtifactを表示する。

これは「外部に確認先がある」という事実だけを示す。

## Collaboration state

既存PlanArtifact.metadataを利用し、migrationは追加しない。

allowed state:

- active
- review
- waiting
- external_followup

Artifact UIで人が明示変更する。

新規Artifactのdefaultは未設定。

自動でstate変更しない。

旧クライアントがcollaboration_state fieldを送らずArtifactを更新しても、
既存stateを維持する。

明示的に空値を送った場合のみstateを解除する。

## External Tool boundary

V44.5ではlive GitHub API / connector statusをcanonical stateにしない。

GitHub URL pathから安全に識別できる表示上の種類:

- /pull/{number} -> GitHub Pull Request
- /issues/{number} -> GitHub Issue
- その他 -> GitHub

までを扱う。

識別してよいのはlink kindだけ。

推測しないもの:

- open / closed
- merged
- review requested
- approved
- CI status
- assignee state
- branch freshness

これらは将来Connectorからauthoritative dataを取得した後に接続する。

## CollaborationContextService

責務:

- 閲覧可能なShared Plan取得
- member / role確認
- Task / Artifact / assigned user / explicit state集約
- Purpose別item projection
- external link kind判定

責務外:

- visual position
- node size
- external live status
- canonical mutation

## CollaborationNavigationGraphService

L1:

center:
- Collaboration Hub

children:
- My Next Action
- Review Waiting
- Waiting on Others
- External Follow-up

L2:

center:
- selected Purpose

children:
- concrete Task / Artifact Context

semantic graph段階ではposition / importance / edge strengthを持たない。

既存HierarchyMapAttentionStateServiceでvisual projectionする。

## CollaborationMapProjectionService

共同IntentのL1 / L2 composer。

`MapProjectionService`は:

- intent=collaboration + L1/L2 -> CollaborationMapProjectionService
- その他L1/L2 -> existing HierarchyMapProjectionService

とする。

他IntentのDomain / Plan hierarchyを変更しない。

## L2 actions

### 自分が進める / レビュー待ち / 相手待ち

primary:
- selected Shared PlanのL3 Execution

secondary:
- Plan / external Artifact等

### 外部Tool

primary:
- external URL

external actionは:

- target=_blank
- rel=noopener noreferrer
- action_role=external_tool

とする。

External Toolを開くだけではCanovia内部Mutationではないため、
Living Reevaluation pendingを作らない。

## L3 continuity

L2からL3へ移動するとき:

- intent=collaboration
- collab_context
- domain
- plan

を保持する。

L3 breadcrumb:

```text
Canovia
  > 共同
    > Review Waiting等
      > Plan
```

L3 Space Station Capture / Suggest / Confirm後も
collab_contextをwhitelistされたstructural fieldとして引き継ぎ、
同じPurpose Contextへ戻れる。

任意return URLは受け取らない。

## Spatial Memory

既存V44.3を維持する。

L1 / L2:
- Space Stationは右下Dock

L3:
- 同じ右下Dock

共同Purposeへ入ってもDock位置は変えない。

## UI grammar

共同Map:

- violet / cyan系 constellation
- Hierarchy circle grammarを継続
- Depth wording:
  - L0 Intent
  - L1 Purpose
  - L2 Context
  - L3 Execution

Provider logoをMap hierarchyそのものにはしない。

外部ToolはContext nodeのterminal actionとして扱う。

## Telemetry

追加structural values:

node_type:

- collaboration_hub
- collaboration_context
- collaboration_item

action_role:

- external_tool

position_roleは既存:

- hierarchy-parent
- hierarchy-child

を再利用する。

保存しない:

- Artifact title
- external URL
- collaboration state
- GitHub path
- member name
- Plan title
- external status

Map Telemetry whitelist外metadataは破棄する。

## Permissions

PlanOwnershipServiceをそのまま利用する。

- owner: view / edit
- editor: view / edit
- viewer: view only

ViewerにもShared Contextは見せられるが、
編集可能Taskを「自分が進めるfallback」として自動表示しない。

明示的にassignedされたArtifactはViewerでも自分担当Contextとして表示できる。

## Non-goals

V44.5では行わない:

- GitHub API live sync
- PR status inference
- automatic review completion
- automatic waiting state
- automatic assignee mutation
- Slack / Calendar live connector ingestion
- external webhook
- Graph DB
- background polling
- automatic canonical mutation
