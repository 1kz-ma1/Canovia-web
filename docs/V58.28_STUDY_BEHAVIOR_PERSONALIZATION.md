# V58.28 Study Behavior Personalization Adapter

## Goal

V58.27 Living Profile Foundationへ、Studyのdurable behaviorを最初のDomain Adapterとして接続する。

目的は学習者を能力レベルで再分類することではない。

> 実際の学習行動が「演習中心」へ移ったことを、CanoviaがObserved Factとして理解する。

## Source of truth

Current Study behavior source:

- `StudyPracticeAttempt`
- existing Study Practice assessment flow
- existing Study Workspace / Strategy / Evidence contracts

Relevant Active Specs:

- `docs/CANOVIA_PERSONALIZATION_SPEC.md`
- `docs/V58.27_LIVING_PROFILE_FOUNDATION.md`
- `docs/V56.13_STUDY_STATE_FIRST_WORKSPACE.md`
- `docs/V56.0_STUDY_EXAM_CONVERGENCE_POLICY.md`
- `docs/V58.3_STUDY_WORKSPACE_SURFACES.md`

This specification does not replace Study Intelligence.

## Observation threshold

V58.28 uses a conservative deterministic threshold:

```text
same authenticated user
+ same Study Plan
+ assessed StudyPracticeAttempt count >= 3
→ observed study stage = practice_focused
```

One isolated exercise is not enough.

This threshold is an implementation heuristic for the first adapter, not a universal learning-science rule.

## Context update

Observed:

```text
observed_context.study_behavior = {
  stage: practice_focused,
  plan_id,
  assessed_attempt_count,
  recent_average_score_percent,
  observed_at
}
```

Derived candidate:

```text
inferred_context.update_candidates.study_practice_focused
```

Candidate:

- domain: study
- kind: learning_stage_observation
- risk: low
- confidence: high
- status: auto_applied
- confirmation_required: false

Derived readiness:

```text
feature_readiness.study.practice_focused.enabled = true
```

## What does NOT change

V58.28 does not rewrite:

- `self_reported_context.domain_context.study.stage`
- Guidance Level
- Study Plan
- Study Task progress
- Study Practice strategy
- score interpretation
- weakness model
- Entitlement

The observation is behavioral context only.

## Growth Experience

Living Profile page may show:

> 演習中心の学習段階に入っています

The explanation must state:

- this is based on repeated assessed practice
- this is not ability reclassification
- initial diagnosis remains preserved
- Plan / Guidance are not automatically rewritten

## Trigger

The adapter runs only after a newly persisted assessed Study Practice attempt.

Duplicate assessment requests must not generate duplicate profile updates.

After the threshold is reached:

- each later attempt refreshes observed count / recent average
- the same Context Update Candidate is not recreated
- the same auto-apply event is not recreated

## Telemetry

Existing Living Profile events are reused:

- `context_refresh_triggered`
- `context_update_candidate_created`
- `context_update_auto_applied`

Metadata uses enumeration / IDs only.

No question text, answer text, or free-form learning content is written to Behavior Event metadata.

## Release boundary

Minimum:

```text
L1 Early Access Core
```

No new public route.

Manual Release Review:

- `study_behavior_personalization`

Manual check:

- 1–2 assessed attempts do not change Living Profile
- 3rd assessed attempt produces practice-focused observed context
- Living Profile Growth Experience appears
- self-reported Study stage remains unchanged
- Guidance remains unchanged
- later attempts refresh metrics without duplicate candidate/event
- mobile / desktop

## Non-goals

Not implemented by V58.28:

- mastery inference
- retention inference
- forgetting-curve estimation
- experience-level inference
- Study Plan automatic replanning
- Study Guidance automatic promotion
- exam readiness reclassification
- cross-provider Study activity ingestion
- AI inference
- arbitrary phase thresholds

These remain future Living Profile adapters.
