# V58.28 Study Behavior Personalization Adapter

## Goal

V58.27 Living Profile Foundationへ、Studyのdurable behaviorを最初のDomain Adapterとして接続する。

目的は学習者を能力レベルで再分類することではない。

> 実際の学習行動が「演習中心」へ移ったことを、CanoviaがObserved Factとして理解する。

## Source of truth

Current Study behavior source:

- `StudyPracticeAttempt`
- existing Study Practice assessment flow
- existing Study Workspace / Strategy / Evidence contracts

Relevant Active Specs:

- `docs/CANOVIA_PERSONALIZATION_SPEC.md`
- `docs/V58.27_LIVING_PROFILE_FOUNDATION.md`
- `docs/V56.13_STUDY_STATE_FIRST_WORKSPACE.md`
- `docs/V56.0_STUDY_EXAM_CONVERGENCE_POLICY.md`
- `docs/V58.3_STUDY_WORKSPACE_SURFACES.md`

This specification does not replace Study Intelligence.

## Observation threshold

V58.28 uses a conservative deterministic threshold:

```text
same authenticated user
+ same Study Plan
+ assessed StudyPracticeAttempt count >= 3
→ observed study stage = practice_focused
```

One isolated exercise is not enough.

This threshold is an implementation heuristic for the first adapter, not a universal learning-science rule.

## Context update

Observed:

```text
observed_context.study_behavior = {
  stage: practice_focused,
  plan_id,
  assessed_attempt_count,
  recent_average_score_percent,
  observed_at
}
```

Derived candidate:

```text
inferred_context.update_candidates.study_practice_focused
```

Candidate:

- domain: study
- kind: learning_stage_observation
- risk: low
- confidence: high
- status: auto_applied
- confirmation_required: false

Derived readiness:

```text
feature_readiness.study.practice_focused.enabled = true
```

## What does NOT change

V58.28 does not rewrite:

- `self_reported_context.domain_context.study.stage`
- Guidance Level
- Study Plan
- Study Task progress
- Study Practice strategy
- score interpretation
- weakness model
- Entitlement

The observation is behavioral context only.

## Growth Experience

Living Profile page may show:

> 演習中心の学習段階に入っています

The explanation must state:

- this is based on repeated assessed practice
- this is not ability reclassification
- initial diagnosis remains preserved
- Plan / Guidance are not automatically rewritten

## Trigger

The adapter runs only after a newly persisted assessed Study Practice attempt.

Duplicate assessment requests must not generate duplicate profile updates.

After the threshold is reached:

- each later attempt refreshes observed count / recent average
- the same Context Update Candidate is not recreated
- the same auto-apply event is not recreated

## Telemetry

Existing Living Profile events are reused:

- `context_refresh_triggered`
- `context_update_candidate_created`
- `context_update_auto_applied`

Metadata uses enumeration / IDs only.

No question text, answer text, or free-form learning content is written to Behavior Event metadata.

## Release boundary

Minimum:

```text
L1 Early Access Core
```

No new public route.

Manual Release Review:

- `study_behavior_personalization`

Manual check:

- 1–2 assessed attempts do not change Living Profile
- 3rd assessed attempt produces practice-focused observed context
- Living Profile Growth Experience appears
- self-reported Study stage remains unchanged
- Guidance remains unchanged
- later attempts refresh metrics without duplicate candidate/event
- mobile / desktop

## Non-goals

Not implemented by V58.28:

- mastery inference
- retention inference
- forgetting-curve estimation
- experience-level inference
- Study Plan automatic replanning
- Study Guidance automatic promotion
- exam readiness reclassification
- cross-provider Study activity ingestion
- AI inference
- arbitrary phase thresholds

These remain future Living Profile adapters.


## Adaptive Context v0.5 Phase 0 / G3 (2026-10-12): source-derived freshness read fence

This is the **first bounded G3 implementation slice**, not a global Fact/Context graph invalidator.

**Source:** actor's `study_practice_attempts` for one accessible Plan. **Materializations:** `UserPersonalizationContext.observed_context.study_behavior`, the `study_practice_focused` and `study_review_cycle` inferred candidates, and `feature_readiness.study.practice_focused` / `study.review_cycle`. These fields may be presented by Living Profile and Study-facing personalization readers.

The Study behavior adapter now persists a `source_signature` alongside its observed behavior, deterministically derived from owner identity, Plan ID, attempt count and last 12 attempt IDs, scores, creation and modification timestamps. The central `PersonalizationContextService::current()` checks this signature **before returning the derived values**. If a source is corrected/deleted, Plan access changes, a historical row lacks the signature, or the lineage query fails, the returned context **omits only those unverified derived Study fields**. It continues to include the user's self-reported context and unrelated domain data. This is a read-only safety fence; historical database records are neither rewritten nor purged on a GET.

This distinguishes **record retention** from **authorization to reuse a derived claim**. Normal new assessments may regenerate the source signature on their established explicit update path. A failed/queued refresh does not authorize disclosure of old assessments or auto-applied recommendations. Source signatures are not a replacement for a transactional snapshot at every external disclosure boundary.

**Boundaries:** this gate applies only to the named Study Living Profile materializations; it does not yet revoke V53 Intelligence history/Action projections, all Study caches, Career/development profile derivations, copied AI exports, already-delivered external data, or independently authorized MCP read responses. The existing MCP tool currently only projects bounded Plan/Task metadata and independently rechecks its grant on each read; it does not consume this Study profile. A full G3 source-to-derivation dependency inventory, source-specific invalidation across those other outputs, purpose changes and async job commit gates remain separate work.

**Acceptance:** tests exercise read-after-correction, read-after-deletion, owner transfer/revocation and unsigned legacy materialization, including preservation of initial self-reported answers, plus V58.28 / V58.33 regression. CI does not establish an actual production deployment or all multi-worker TOCTOU safety.
