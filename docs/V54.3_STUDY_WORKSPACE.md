# V54.3 Study Workspace

## Goal

> V56.13 supersedes V54.3's fixed capture-first empty-state rule. The dedicated Study Workspace remains, but existing Study Plans now use State First composition. See `docs/V56.13_STUDY_STATE_FIRST_WORKSPACE.md`.

V54.3 turns Study Mode from a mode indicator plus redirects into a dedicated Study Home.

The surface must make Canovia's Study specialization obvious in one screen:

```text
Exam Readiness
→ Biggest Gap
→ Current Action
→ Coverage / Mastery / Retention / Remaining Load
→ Scope / Practice / Recall / History
```

V54.3 is presentation and navigation work over the existing V53 Study Intelligence loop.

It does not introduce a second readiness model and does not add AI traffic.

## Entry

Study Workspace canonical route:

```http
GET /workspace/study
```

named:

```text
workspace.study.index
```

V54.3 changes Study Mode entry behavior:

- GET `/workspace/study` renders Study Home
- persistent Study selection redirects to Study Home
- Overview and Development entry behavior remains unchanged in V54.3

The static Study route is registered before the generic `/workspace/{workspaceMode}` route.

## Workspace / Plan relationship

Workspace Mode is not Plan category filtering UI, but Study Intelligence remains Plan-scoped.

Study Home therefore:

1. loads every accessible Plan whose `PlanCategoryProfile` is `study`
2. orders them by the existing Canovia priority semantics:
   - Plan priority
   - nearest deadline
   - stable Plan ID
3. selects the first Plan by default
4. allows an explicit `?plan_id=...` choice when that Plan is accessible and Study-profiled

An explicit invalid/inaccessible/non-Study `plan_id` returns 404 rather than silently switching to another Plan.

This keeps deep links deterministic and avoids leaking or misrepresenting Plan context.

## Empty states

### No Study Plan

If the actor has no accessible Study Plan, Study Home remains a valid Workspace surface.

It shows:

- Study Workspace identity
- explanation of the Study loop
- CTA to create a Plan

It does not bounce back to generic Home.

### Study Plan exists but no confirmed Scope

V54.3 originally treated this as a universal capture-first empty state.

V56.13 changes that rule:

```text
Plan
→ Learning Type
→ existing Practice / Recall / Task Evidence
→ current position known?
→ ask only for context that changes the next action
```

Study Scope remains first-class for learning types such as school tests where range information directly changes the study allocation. It is not a universal gate for certification, score-exam, skill-learning, or memorization Plans.

The page still does not present a fake numeric Exam Readiness before the existing Scope-based readiness model has meaningful Scope.

No Task is created by merely viewing the Workspace.

## Populated Study Home

Once confirmed Study Scope exists, the main hierarchy is:

### 1. Exam Readiness

Show:

- readiness score
- readiness state
- confidence
- exam date / days until exam when authoritative
- deadline pressure

The score and state come from existing `StudyPlanIntelligenceService` / `StudyExamReadinessEvaluator`.

### 2. Biggest Gap

Use the existing V53.6 Decision as adapted by `StudyIntelligencePresentationAdapter`.

No second gap-ranking algorithm is introduced.

### 3. Current Action

Use the existing V53.6 Adaptive Action.

Execution remains explicit:

- viewing Study Home never creates a Task
- POST to the existing Study Action execution route may reuse/project a Task according to V53.6 rules

### 4. Study metrics

Show the existing normalized metrics:

- Coverage
- Mastery
- Retention
- Remaining Load

Remaining load is a relative Study Unit model, not fake minute precision.

### 5. Priority remaining scope

Show a bounded list from:

```text
state.facts.priority_remaining_scope
```

including:

- subject / unit
- remaining Study Unit
- Mastery
- Retention

### 6. Study navigation

Study Home exposes stable Study-specific navigation:

- Current Action
- Readiness
- Study Scope
- Practice
- Recall
- History

Practice / Recall require a Task-scoped context. V54.3 chooses:

1. the current Intelligence target Task when available
2. otherwise the first active Task
3. otherwise the first Task

If no Task exists, Practice / Recall remain visibly unavailable rather than auto-creating a Task.

## History

V54.3 reuses `IntelligencePresentationHistoryService`.

Study Home shows bounded recent:

- Decisions
- Actions
- State snapshots / Evidence counts

No new history table is introduced.

## Authorization

Study Home uses the existing `PlanOwnershipService`.

Supported access remains:

- owned Plan
- collaborative editor/viewer
- guest-owned Plan

The selected Plan must remain inside the actor's accessible Study Plan collection.

Action execution respects existing edit authorization.

## Workspace Mode semantics

`workspace.study.*` is a strong Study route hint.

The fixed Workspace Mode Bar therefore remains Study even when another manual preference is stored.

Opening Study Home does not erase a different stored preference.

This preserves the V54.2 deep-link contract.

## Performance

Study Home evaluates Intelligence for only the selected Study Plan.

It does not evaluate every Study Plan.

Other accessible Study Plans are loaded only for selection metadata.

No new AI/provider request is made.

## Compatibility

V54.3 preserves:

- Study Scope Capture
- Study Practice
- Study Recall
- Study Activity
- V53 Study State / Readiness / Decision / Action
- explicit Task projection
- Workspace Mode persistence semantics
- generic Home
- Development Mode behavior

## Non-goals

V54.3 does not:

- implement Development Workspace Home
- redesign Overview
- introduce new Study scoring
- auto-create Tasks on GET
- infer Study Scope without confirmation
- invent answer speed
- convert remaining Study Units into minutes
- add AI traffic
- change Plan category
- change billing

## V58.2 Study Top responsibility update

V58.2 splits the old Study Home responsibility into:

```text
Study Top
→ accessible Study Plan list
→ progress / deadline / Task counts
→ Study Scope / Resources / Scores preparation links
→ Plan selection

Study Plan Workspace
→ one selected Plan
→ current Study state / action / readiness / methods
```

The Study Plan Workspace now exposes a compact `← 学習トップへ` link and no
longer renders a multi-Plan selector.

Existing `?plan_id=` deep links remain valid and still require the selected
Plan to be accessible and Study-profiled.

Study Top uses the existing `PlanProgressService` and persisted Study facts.
It does not evaluate the Study Intelligence pipeline for every Plan and does
not add AI/provider traffic.

Canonical V58.2 contract:
`docs/V58.2_STUDY_DEVELOPER_MODE_TOPS.md`.
