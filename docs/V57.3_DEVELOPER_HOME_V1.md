# V57.3 Developer Home V1

## Goal

V57.3 changes Development Workspace from a Release dashboard that requires
GitHub Evidence first into a Developer Home that starts from the next useful
action and then shows the current development reality.

Canonical hierarchy:

```text
Next Action
→ Recent GitHub Reality
→ Active Development
→ Release Readiness / Quality Gates
→ History
```

The workspace remains backed by the existing Development Intelligence,
V57.1 Observation and V57.2 Task Association layers. V57.3 does not create a
second decision engine.

## State First boundary

Development Mode onboarding becomes Plan creation only.

Before V57.3:

```text
create Plan
→ connect GitHub Evidence
→ normal Development Workspace
```

V57.3:

```text
create Plan
→ Development Home
→ current state determines whether GitHub, execution, review, deploy,
  verification or specification is the next action
```

GitHub is therefore an optional State Sensor / Execution Provider, not a
universal prerequisite for entering the workspace.

The existing Development Adaptive Action remains canonical for the top
Next Action. When Development Evidence is missing, that action may still be
"connect / inspect GitHub". The difference is that the entire workspace is not
blocked behind setup onboarding.

## Recent GitHub Reality

The Developer Home reads the most recent V57.1
`DevelopmentActivityObservation` records for the selected Plan.

It may show:

- Pull Request
- Issue
- Branch
- Commit
- Deployment

Ignored observations are excluded.

Resolution is displayed explicitly:

- linked → associated Task through the resolved Artifact
- suggested → deterministic V57.2 Task candidate
- unlinked → needs human association
- other observation-only activity → observed, no forced association

The V57.2 association controls remain available only for supported unresolved
PR / Issue / Branch / Commit observations.

## Active Development

The Home shows up to six unfinished Tasks.

Ordering:

1. current Development Intelligence focus Task
2. doing
3. todo
4. paused / other unfinished states
5. Task priority
6. Task sort order

Each Task may show:

- status
- progress
- remaining minutes
- linked GitHub Artifact count
- CTA to the existing execution orchestration route

Task progress remains Plan/Task state. GitHub observations do not advance it.

## Readiness

Release Readiness remains authoritative but moves below day-to-day execution.

The primary surface is compact:

- Readiness state
- passed Gate count
- Evidence count
- biggest Release gap

The seven existing Quality Gates remain available as detail rather than
occupying the first screen.

No Release scoring logic changes in V57.3.

## History

Decision / Action / State history remains available but secondary and
collapsible. It is not part of the primary daily workflow.

## Mutation / provider boundary

Workspace GET may refresh deterministic local V57.2 suggestion metadata.

It does not:

- create Task associations
- create Task Evidence
- change Task progress
- change Task status
- change remaining time
- call GitHub
- call AI

Human confirmation remains required before Observation → Task association.

## Compatibility

V57.3 preserves:

- V53.7 Development Evidence
- V53.8 Release Readiness
- V57.0 GitHub stabilization
- V57.1 Development Activity Observation
- V57.2 Task Association
- existing GitHub Workflow
- existing execution orchestration
- explicit quality-gate confirmation

V54.7 Development onboarding semantics are superseded only for Development:
Plan creation is now the sole onboarding step. Study and Career onboarding are
unchanged.

## Next

V57.4 should deepen the Developer Home from presentation into execution
assistance, especially:

- repository-aware Current Action detail
- PR / Issue / CI state summaries
- task-scoped development context
- implementation / review / validation handoff quality
