# V51.9.6 Real-device UI Refinement

> **V55.5 update:** この文書の `SAME WORKSPACE` / Execution内の「Workspace」表現は現在は退役している。V54以降のglobal Workspace Modeと区別するため、`/navigate` 内の分類は **Execution Mode / 実行タイプ** と呼ぶ。V51.9.6で導入した候補railの意味・同一実行タイプfilterは変更しない。詳細は `docs/V55.5_EXECUTION_MODE_TERMINOLOGY.md` を正とする。

## 背景

iPhone実機確認で、Performance改善後の残課題としてExecution候補RailとConstellation Task領域にUI/意味のズレを確認した。

対象:

1. Executionの横候補にPrimaryと同じPlanの別Taskが混ざる
2. Study Workspaceの候補に、Primaryと同じ学習Activityでは実行できないTaskが混ざる
3. 旧「条件変更」導線とIntent/Time設定フローが横スライド候補と役割重複している
4. Mobile ConstellationでTask Groupの縦表示領域が不足する

## 1. Execution候補はOther Plan only

Candidate Railは「同じPlanの別候補」ではなく、別Planとの横比較として扱う。

- Primary Planは候補生成対象から除外
- 別Planごとに最大1 Task
- 固定カード数を埋めるためのsame-Plan fallbackを廃止
- View側でもPrimary Plan IDをdefensiveに除外

表示文言も:

- SAME WORKSPACE
- 他Planの同じ実行タイプ

へ合わせる。

## 2. Candidate Handoff Compatibility

「同じExecution Mode」だけでは候補互換性として粗すぎる。

特に資格学習Planでは:

- Question Practice / AI演習
- Recall
- Resource Study
- 受験申込・予約などの管理Task

が同一Plan内に共存する。

### Study Task applicability

`StudyActivityPolicyService::supportsTask()` を追加し、Task自身のtitle / description / next_action_noteに学習実行SignalがあるかでStudy Workspace適用可否を判定する。

Plan title/categoryは判定材料に含めない。資格学習Planに属するだけで管理TaskをAI演習候補にしないため。

Study Workspace非適用TaskはExecution上ではTimer actionへfallbackする。

### compatibility_key

`ExecutionModeService::actionFor()` は `compatibility_key` を返す。

- Question Practice: `study:question_practice`
- Recall: `study:recall`
- Resource Study: `study:resource_study`
- Development: `development`
- Career: `career`
- Timer / admin Task: `timer`

Candidate RailはPrimary Taskと同じcompatibility_keyを持つTaskだけを対象にRecommendationを実行する。

これによりAI問題演習Taskの横候補へRecall / 教材学習 / 申込Taskを混ぜない。

## 3. Condition Flow retirement

実機では横スライド候補だけで「別の選択肢を見る」を十分吸収できるため、Primary Execution Surfaceから旧条件変更UIを退役する。

削除:

- 「条件変更」link
- 「今日はどう進めたい？」Intent選択UI
- 「どれくらい時間がありますか？」Time選択UI
- recommendation無し状態の「条件を変える」link
- stale condition state用header reset control

既存sessionに `intent` / `time` stepが残っている場合は、NavigationControllerで `recommendation` stateへ正規化する。

旧POST route / methodは互換性のため現時点では残すがPrimary UIからは到達しない。

## 4. Mobile Constellation Task Area

Selected Constellationのmobile focus paletteをTask確認優先へ調整する。

変更前:

- height: `clamp(30rem, 61dvh, 35rem)`
- graph / task rows: `56% / 44%`

変更後:

- height: `clamp(34rem, 70dvh, 41rem)`
- graph / task rows: `45% / 55%`

Task panel:

- `min-height: 0`
- `overscroll-behavior: contain`
- paddingをわずかに圧縮
- Star rail下marginを圧縮

Graph自体のstar selection / swipe contractは変更しない。

## 5. Regression contract

Testsで以下を固定する。

- Study question/review/admin Taskが異なるcompatibilityを持つ
- Study admin TaskはTimer fallback
- Primary Planの2つ目TaskがRailに入らない
- Other Planでもcompatibilityが違うTaskはRailに入らない
- compatibleなOther Plan TaskはRailに残る
- legacy `configure=1` でもCondition UIを表示しない
- stale intent/time sessionをrecommendationへ正規化
- mobile constellation 45/55 Task優先splitを維持

## DB migration

なし。
