# V53.4 Study Scope Capture

## Goal

V53.4 makes the first Study acquisition flow concrete:

```text
test-range image / screenshot / PDF
→ Canovia structured extraction
→ human review / correction
→ confirmed Study Scope
```

The target is not only professional certifications.

Ordinary school tests, university exams, mock exams and similar range sheets must work without requiring the user to manually decompose every subject first.

## Product boundary

Study Scope Capture is a **Plan-level input**, not a Task-level execution tool.

The source file describes what may need to be learned.

It is not Evidence that learning was completed.

Therefore V53.4 does not:

- create Tasks
- change Task progress
- create Intelligence State snapshots
- create Decisions
- estimate remaining study effort
- calculate exam readiness

Those responsibilities belong to later V53 phases.

## Free capability

V53.4 adds:

`FeatureKey::StudyScopeCapture = study_scope_capture`

The capability is part of the Free core.

Reason:

> A Free user must be able to experience the actual Canovia Study loop. Reading the test range is part of the product input boundary, not merely a Premium acceleration feature.

This is intentionally separate from:

`FeatureKey::AutomaticAiExecution`

which remains a Premium capability for higher-cost autonomous/reasoning flows.

## Source storage

V53.4 reuses the existing private `InboxItem` file boundary instead of introducing a second file-storage system.

A Study Capture source is stored as:

```text
InboxItem
  source_type = image | pdf
  plan_id = target Study Plan
  metadata.capture_surface = study_scope
  metadata.study_scope_capture = true
      ↓
StudyScopeCapture
```

Supported upload types:

- JPEG
- PNG
- WebP
- PDF

Maximum upload size:

- 10 MB

The existing iOS WKWebView shell can use the standard file/photo picker because this remains a normal Web file input.

## Structured extraction

`StudyScopeCaptureAnalysisService` reuses the existing `NativeAiGateway`.

Purpose:

`study_scope_capture_extraction`

Schema:

- exam_title
- exam_date_text
- exam_date
- overall_confidence
- items[]
- ambiguities[]

Each extracted item may contain:

- subject
- unit
- range_text
- page_start
- page_end
- source_excerpt
- confidence

The provider receives the original image/PDF through the existing Native AI multimodal input boundary.

The response is Structured Output.

## No invented scope

The extractor is instructed to use only facts explicitly supported by the source.

Rules include:

- do not invent unseen subjects
- do not invent units
- do not infer pages that are not written
- do not force uncertain text into a confident field
- use `ambiguities` when the source is unclear
- keep subject/unit nullable in the draft when the source does not identify them

The review UI requires a subject before an item can become confirmed truth.

## Date semantics

The extraction contract separates:

- `exam_date_text`: source text such as "10月15日"
- `exam_date`: normalized `YYYY-MM-DD` only when the source supports that normalization confidently

If the year is missing or ambiguous:

```text
exam_date_text = source text
exam_date = null
```

The user can then set the final date during review.

Canovia does not silently manufacture the year.

## Human confirmation boundary

AI extraction is a Draft.

The flow is:

```text
source
→ AI draft
→ review form
→ user edits
→ confirm
→ StudyScopeItem
```

Before confirmation:

- `StudyScopeItem` is not created
- Task is not created
- Task progress is not changed
- Intelligence State is not changed

At confirmation:

- prior confirmed items for the same Capture are replaced transactionally
- user-edited subject/unit/range/pages become the confirmed facts
- the linked Inbox source becomes processed
- the Capture becomes confirmed

The confirmed item confidence is `1.0` because the authority at that point is explicit Human Confirmation, not the AI extraction score.

The original extraction confidence remains on the Capture for evaluation.

## Review UX

Study Plans receive a Plan-level **試験範囲** entry.

The page supports:

- source upload
- original source preview / link
- extraction confidence
- unresolved ambiguities
- exam title edit
- exam date edit
- subject edit
- unit edit
- range text edit
- page range edit
- adding/removing scope rows
- AI retry before confirmation
- manual confirmation without AI

Confirmed scope can be edited and reconfirmed.

Unconfirmed captures can be discarded together with their private source file.

Confirmed captures cannot be casually discarded from this surface because later Study Intelligence may depend on them.

## Ordinary school test acceptance case

V53.4 deliberately authorizes Study Capture using:

`PlanCategoryProfileService::forPlan(...)->key === study`

instead of checking only:

`category === 資格学習`

Examples that can be Study Plans include:

- 定期テスト学習
- 学校の試験勉強
- 大学試験学習
- 資格学習

This prevents the specialized Study product from collapsing into certification-only behavior.

## Provider failure behavior

The source file is committed before AI analysis.

If Native AI fails:

```text
source file remains
StudyScopeCapture.status = failed
failure_code recorded
↓
user may retry
or
user may manually enter scope and confirm
```

A temporary model/provider failure must not destroy the user's capture.

If Native AI is not configured, the source remains in `captured` state and manual confirmation is still available.

## Privacy / data minimization

V53.4 does not persist a full OCR transcript.

Persistent structured extraction is limited to:

- test metadata
- scope items
- short source excerpts
- ambiguity notes
- confidence

The original private source file remains in existing Canovia storage through `InboxItem`.

Native AI continues to use the existing gateway behavior including `store=false` for OpenAI Responses requests.
