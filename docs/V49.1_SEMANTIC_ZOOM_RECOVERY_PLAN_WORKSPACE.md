## 目的

V49.0実機確認で見つかった致命的なSemantic Zoomの戻り不具合と、Plan Intentの階層違和感を修正する。

今回の主眼:

1. 拡大後に確実に縮小・親階層へ戻れる
2. Plan Intentではカテゴリを独立階層として挟まない
3. Plan詳細は共同Project Workspaceと同じくClassicカードをPaletteとして再利用する

## 1. Semantic Zoom Recovery

### 問題

V49.0ではsemantic zoom-out destinationを主にscene内の:

`a[data-map-semantic-zoom][data-map-zoom-direction=out]`

から探索していた。

この方式はNode presentation / entry mode / overlay構造への依存があり、物理縮小ができても親Projectionを見失う余地があった。

また既定threshold:

- in 1.62
- out 0.72

はgesture量が大きく、特にzoom-outが「縮小はするが戻らない」と感じやすかった。

### 修正

各Map pageへserver-authoritative:

`data-map-parent-url`

を出す。

source:

`graph.hierarchy.parent_url`

zoom-out destination precedence:

1. hierarchy parent URL
2. scene上のsemantic link
3. destinationなしなら同level

DOM上の「戻る」linkはvisual / transition anchorとして使えるが、Navigation truthにはしない。

L0のように親が存在しないlevelでzoom-out thresholdを跨いだ場合は、縮小状態を放置せずcameraをscale 1へ戻す。これによりNode群が中心へ潰れて重なる状態を防ぐ。

### Threshold

既定:

- zoom in: 1.42
- zoom out: 0.82

へ変更。

目的はsemantic level変更を「大きく拡大縮小し切る操作」ではなく、Mapアプリに近いgestureとして扱うこと。

### Workspace上のdesktop pinch

Plan / Collaboration Workspace Paletteはsceneの上にcardが存在するため、wheel listenerをscene限定からMap Shellへ広げる。

- Ctrl+wheel / precision pinch:
  - Palette上でもMap zoom
- ordinary wheel:
  - Palette上ではcard scroll
  - Map Scene上ではcamera pan

card閲覧とsemantic zoomを両立する。

さらにgestureが利用できない環境でも1階層で詰まらないよう、Workspace headerへ明示的なsemantic back actionを置く。

- Plan Workspace: `← Plan一覧`
- Collaboration Workspace: `← 共同計画`

これらも通常遷移ではなく `data-map-semantic-zoom direction=out` を使い、Spatial Continuityを維持する。

## 2. Plan-first hierarchy

旧:

```text
L0 計画
 -> L1 Category / Domain
     -> L2 Plan
         -> L3 Execution
```

V49.1 Plan Intent:

```text
L0 計画
 -> L1 Plan
     -> L2 Plan Workspace
```

Plan.categoryは削除しない。

- badge
- subtitle
- metadata
- 将来Plan数が多い場合のgrouping signal

として残す。

ただし少数〜通常数のPlanで毎回カテゴリを1階層として通過させない。

Execution Intentは従来通り:

```text
L0 実行
 -> L1 Domain
     -> L2 Plan
         -> L3 Execution Context
```

を維持する。

これにより「Planを眺める」と「実行Contextへ潜る」のsemantic roleを分離する。

## 3. Plan Workspace

L2 Plan Intentではselected Planだけをspatial centerとして残す。

operational detailはNode化せずPaletteとして表示する。

MVP:

- Classic Planの進捗summary metrics
- Classic Planで利用しているRoadmap partial
- 実行Mapへの導線
- Classic Planへの導線
- owner向けPlan編集

### Classic reuse

進捗summaryを:

`resources/views/plans/partials/summary-metrics.blade.php`

へ切り出す。

Classic `plans.show` とMap Plan Workspaceの双方が同じpartialをrenderする。

Roadmapは既存:

`resources/views/plans/partials/roadmap.blade.php`

をそのまま利用する。

Map専用の類似cardをコピーしない。

## Projection

Plan Workspace payload:

- plan
- progress
- roadmap
- can_edit
- can_manage
- execution_url

Projection keyにはuser contentを追加せず:

- plan updated timestamp
- task count / latest task timestamp
- work log count / latest work log timestamp
- progress structural summary

を含め、Instant Navigation cacheで古いPaletteを出し続けない。

## Density

L1 PlanではPlanを直接配置する。

現時点でCategory clustering thresholdは設けない。

Plan数が増え、直接配置のsignal-to-noiseが悪化した実データを確認してから:

- viewport-aware clustering
- collapsible group
- search/filter

を検討する。

見た目の都合だけでCategory階層を復活させない。
