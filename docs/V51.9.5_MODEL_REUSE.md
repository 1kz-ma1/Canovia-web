# V51.9.5 Model Reuse & Dependency Hydration

## 背景

V51.9.4でPrimary Homeの未使用membership projectionとWorkLog.task再取得を削除した。

V51.9.2 production Homeは23 queriesだったため、V51.9.4後は同じaccount shapeで約21 queriesが目安になる。

さらにコード監査すると、既に同じrequest内で取得済みのPlan / Task modelを使えるのに、relation hydrationのためremote MySQLへ再SELECTしている箇所が残っていた。

remote MySQL roundtripは直近実測で約78〜85ms/queryだったため、同じmodelの再取得を避けること自体が体感速度へ直結する。

## 1. Home Continuity model reuse

HomeはCoreContextで:

- owned Plans
- Plan.tasks

を既にloadしている。

しかし `ContinuityService::homeContext()` はactive/pending/latest WorkSessionを取得したあと:

`loadMissing(['plan', 'task'])`

を呼び、典型Homeで:

- plans SELECT x1
- tasks SELECT x1

を追加していた。

V51.9.5ではWorkSessionの `plan_id / task_id` を、Homeから渡された既存Plan / Task modelへ直接関連付ける。

- matching Planが既に存在: `setRelation('plan', $plan)`
- matching Plan.tasksがload済み: existing Taskを `setRelation('task', ...)`
- task_id=null: task relationをnullとして確定
- current Home context外のSession: 従来どおり `loadMissing()` fallback

これにより一般的なHomeではcontinuity relation hydration用のPlan / Task SELECTが0になる。

WorkSession自体の2つのquery scopeは意味が異なるため今回維持する。

## 2. Task dependency hydration from loaded Task models

CoreContextの `task_dependencies` featureでは、先に全Taskをload済みなのに:

- legacy `prerequisite` 用Task SELECT
- canonical `prerequisites` 用Task SELECT

を実行していた。

V51.9.5では:

1. loaded Taskをidでindex
2. `task_dependencies` pivotだけ1 queryで取得
3. `depends_on_task_id` からlegacy prerequisiteを既存Task modelで設定
4. pivot edgesからcanonical prerequisitesを既存Task model collectionで設定
5. Task resourcesのみ従来どおりload

とする。

canonical dependency source of truthは `task_dependencies` のまま維持する。

`Task::dependencyIds()`、Roadmapのdependency title、Execution Orchestrationのblocked dependency判定はrelationLoaded状態の既存contractをそのまま使う。

## 3. Expected query effect

V51.9.4後の典型Homeからさらに:

- continuity Plan SELECT: -1
- continuity Task SELECT: -1
- dependency Task再SELECT 2本 → pivot 1本: net -1

合計で約3 DB roundtrip削減を見込む。

V51.9.2の23 query baselineから:

- V51.9.4: 約21
- V51.9.5: 約18

が同account shapeでの目安。

remote roundtrip約80ms基準では、V51.9.5単体で約240ms相当のDB待ち削減余地がある。

## 4. Compatibility boundary

以下は変更しない。

- task_dependencies schema
- Task dependency write path / sync semantics
- Roadmap ordering semantics
- Recommendation dependency blocking
- Execution Orchestration dependency display
- Continuity latest-session scope
- active/pending WorkSession scope

current CoreContext外のPlan/Task relationは従来どおりDB fallbackでhydrateする。

## 5. DB Persistent status

`DB_PERSISTENT=true` はproductionで有効。

V51.9.5はpersistent PDOとは独立したquery count削減であり、`DB_PERSISTENT=false` へrollbackしても機能する。

## 6. Regression contract

testsで:

- task_dependencies featureでもTask table SELECTは1回
- pivot SELECTは1回
- legacy prerequisite / canonical prerequisitesがrelationLoaded
- canonical dependencyIdsが維持される
- Home Continuityへloaded Plan/tasksを渡した場合plans/tasks SELECTは0
- Home Continuityの2 WorkSession scopesは維持

を固定する。

## DB migration

なし。
