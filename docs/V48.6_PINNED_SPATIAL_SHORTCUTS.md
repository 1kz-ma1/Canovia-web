# V48.6 Pinned Spatial Shortcuts

> **V48.7 update:** L0へまだpromotionされていないPersonal Planでも、L2/L3のcanonical Plan ContextからPin / Unpinできるようになった。inactiveなstale PinもPlan Contextから解除できる。最新UI契約は `docs/V48.7_CONTEXTUAL_SHORTCUT_PINNING.md` を参照。

## 目的

V48.5のExplainable Spatial Personalizationへ、ユーザー自身の明示的な意思を追加する。

自動signalだけで決まるShortcutに対して、

- このPlanは常に近道として残したい
- ただしPlan / Task本体や優先度は変えたくない

という要求を、正しいserver Projection contractで扱う。

## Principle

Pinはcanonical Plan mutationではない。

保存するのはaccount-level presentation preferenceだけ。

```text
canonical Plan / Task
        +
behavior signals
        +
account pinned shortcut IDs
        ↓
eligible candidate enumeration
        ↓
pinned override + automatic promotion
        ↓
L0 Spatial Projection
```

変更しない:

- Plan priority
- Task status
- Task progress
- Dependency
- Evidence
- Roadmap
- absolute Map position

## Preference schema

`users.map_personalization_preferences` にversioned JSONを保存する。

```json
{
  "version": 1,
  "pinned_node_ids": [
    "satellite:plan:12"
  ]
}
```

保存しない:

- Plan title
- Task title
- promotion score
- signal values
- absolute coordinates
- user content
- AI output

## Eligible candidate identity

Pinは存在しないContextを作らない。

V48.6でPinできるのは、既存 `PersonalizedSatelliteCandidateService` が列挙できるPersonal Planのみ。

したがって:

- user自身のPersonal Plan
- 未完了Taskを持つ
- Shared Planではない

というcandidate eligibilityを満たす必要がある。

Pin後に全Taskが完了・cancelledとなった場合、preferenceは残っていてもProjectionはそのShortcutを復活させない。

これは「Pin = candidate existence override」ではなく、

> Pin = eligible candidateに対するpromotion threshold override

という契約。

## Promotion precedence

V45.6のdensity contractを維持する。

- max = 2
- same semantic anchor = max 1
- automatic threshold = 0.55

Promotion順:

1. eligible + pinned
2. eligible + automatic threshold通過
3. same anchorをdedupe
4. max 2へcap

現在のPersonal Planは全て `intent:plan` anchorなので、Plan Pinは実質1件。

別PlanをPinした場合、以前のPlan Pinをaccount preference上で置き換える。

## Explainability

Pinned Shortcutはbehavioral signal理由を表示しない。

`personalization.mode`:

`manual_pin`

`strength`:

`pinned`

表示:

- 固定中
- 「このPlanを固定しているため、利用状況に関係なく近道として表示しています。」

raw scoreやweightは表示しない。

## Account / device boundary

Pin:

- server-side
- account preference
- deviceを跨ぐ

Hide:

- localStorage
- device-local
- presentation-only

両方が同じNodeへ適用された場合はdevice-local Hideを最終表示overrideとして優先する。

したがって:

> アカウントでは固定しているが、この端末では隠す

を許可する。

HideはPinを解除しない。

## UI

Personalized Plan ShortcutのDetail Paletteへ:

- 未固定: `このShortcutを固定`
- 固定中: `固定を解除`
- `この端末では非表示`

を表示する。

Pin / Unpinはserver request後にL0 Mapへ戻り、最新Projectionを再構築する。

## Privacy / telemetry

Pin stateをBehavior telemetryへ追加しない。

保存するのはstructural Node IDのみ。
