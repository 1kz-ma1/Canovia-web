# V43.2 Home Surface Entry

## Goal

Classic HomeとCanovia MapをShell上で競合する2つの入口として見せない。

Homeは1つ、その表示SurfaceとしてClassic / Mapを切り替える構造へ整理する。

## Shell

Desktop / Mobile navigationから独立したMap tabを削除する。

Shellの「ホーム」は以下を同じ領域としてactive扱いする。

- Classic Home /
- Canovia Map /map
- 既存のHome配下画面

root / は引き続きClassic Home。
Primary Homeの強制変更はしない。

## Surface switcher

Classic HomeとMapの両方に共通switcherを表示する。

- Classic
- Map BETA

URLは維持:

- Classic: /
- Map: /map

Map側のClassic linkには既存 data-map-home-fallback を移し、V42.4 telemetryを維持する。

## Instant Navigation

/map をCore pathへ追加する。

Map viewは X-Canovia-Instant-Navigation の prefetch / navigate で layouts.instant を使う。

Classic ⇄ Map切替はfull reloadせず、既存Instant Navigationでpage bodyを差し替える。

## Lifecycle boundary

MapをInstant対象にすると、document / windowへ登録したMap listenerを離脱時に破棄する必要がある。

Instant Navigationはpage replacement直前に:

- canovia:before-page-replace

をdispatchする。

Living Mapはこのeventで destroy() する。

これにより古い:

- keydown
- popstate
- pageshow
- Instant Navigation integration listener

を残さない。

## Telemetry boundary

Instant Navigationはcapture phaseでclickを処理するため、Mapのbubble clickより先に遷移する。

遷移直前に:

- canovia:before-instant-navigation

をdispatchする。

Living Mapはこのeventで:

- map_classic_home_opened
- map_classic_action_opened
- pending reevaluation

を従来どおり記録する。

Classic画面へ出た後のCore Surface間移動はapp.jsが同eventを使い、Map flow stepを継続する。

## Companion

MapのInstant fragmentでもglobal floating Companionは表示しない。

Map内のContextual Companionのみを正とするV42.3境界を維持する。

## Non-goals

- / をMapへredirect
- user preferenceによるdefault surface変更
- Telemetry結果の自動判定
- Classic Home削除
- MapのPrimary Home昇格


## Instant cache revalidation

Instant NavigationはMap HTMLをcacheできるため、Classic操作後に戻ると古いProjectionが一瞬復元される可能性がある。

Instant renderされたpage rootへ data-canovia-instant-rendered を付与する。

Living Map mount時に:

- pending reevaluation がある
- Instant renderされたMapである

の両方を満たす場合だけ MapProjection を再検証する。

新規Map訪問では追加fetchを発生させない。
