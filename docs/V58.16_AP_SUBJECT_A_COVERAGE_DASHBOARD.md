# V58.16 AP Subject A Coverage Dashboard

Status: implemented / validated  
Branch: `feature/v58-16-ap-subject-a-coverage-dashboard`

## 1. Goal

Provide a Plan-wide AP Subject A analysis surface from real assessed Question Bank activity across Tasks.

```text
AP Subject A Plan
→ assessed Question Bank Sessions across Tasks
→ selected question domain / parent topic
→ question_feedback correctness
→ official-pack unique coverage
→ Plan-wide observed correctness
→ Study Analysis
```

This is descriptive analysis. It is not a new mastery or routing authority.

## 2. AP / actor boundary

V58.16 is available only when the Plan contains a Task recognized by the existing `StudyPracticeExamProfileService` as `ap_subject_a_exam`.

Only the current actor is included:
- authenticated → `user_id`
- anonymous → `actor_token`

All Tasks in the selected Plan may contribute. No cross-user aggregation is allowed.

## 3. Bounded Session scan

The latest at most `200 StudyPracticeSession` rows are scanned.

A Session contributes only when:
- it has a matching Attempt;
- `selected_questions.question_id` is a numeric Question Bank id;
- `selection_domain` is present;
- `question_feedback.question_id` matches `selected_questions.question_ref`;
- correctness is `correct`, `partial`, or `incorrect`.

Unassessed Sessions and Native/External AI questions without a Question Bank id do not count.

## 4. Official reference Pack

When available, use the published AP / 科目A Pack with `metadata.content_kind = official_past_exam_curated`, preferring highest `selection_priority`, then latest id.

Current source-domain mapping:

```text
technology → テクノロジ
management → マネジメント
strategy   → ストラテジ
```

The bundled 2025 autumn Pack currently exposes 20 / 5 / 10 questions respectively, total 35. These are installed-Pack counts, not universal exam weights.

If no published official Pack exists, observed performance can still be shown but official coverage percent remains unavailable.

## 5. Two distinct measurements

### Official Pack unique coverage

Per domain:

```text
unique assessed questions from the reference official Pack
/
reference Pack domain question count
```

Repeated exposure never increases unique coverage.

### Plan-wide assessed performance

Across all Question Bank packs used in the Plan, including curated core packs:
- assessed_exposure_count
- unique_question_count
- correct_count
- partial_count
- incorrect_count
- observed_correct_rate_percent
- latest_assessed_at

Core Pack questions therefore affect observed performance but not official-Pack coverage.

## 6. Correctness / display status

Observed correct rate is `correct / (correct + partial + incorrect)`. Partial is not counted as correct.

Broad-domain status is display-only:
- 0 graded → unobserved
- 1–2 → observing
- >=3 and <60% → needs_attention
- >=3 and 60–79% → developing
- >=3 and >=80% → stable

These labels do not modify routing, Task progress, Study Method selection, or mastery.

## 7. Parent-topic observations

When `selection_parent_topic` exists, the same correctness observations are aggregated inside the broad domain. Parent-topic rows also expose `unique_question_count` so repeated exposure of one Bank question can be distinguished from evidence across multiple questions. Up to five parent topics are shown. One observation remains low-confidence and is not treated as a confirmed weakness.

## 8. Study Analysis surface

New registered surface: `ap_subject_a_coverage`.

Study Analysis order includes:

```text
current_state
readiness
biggest_gap
ap_subject_a_coverage
weaknesses
recent_results
scope_coverage
```

The surface shows reference Pack, official unique coverage, assessed exposure count, unique Bank questions, assessed Sessions, broad-domain cards, and parent-topic observations.

With no assessed Bank activity it shows an explicit waiting state instead of inventing zero mastery.

## 9. Across-Task weakness boundary

V58.16 gives a Plan-wide weakness observation view but does not replace the Task-local `StudyWeaknessPrioritizationService`.

V58.16 itself remains read-only. V58.18 separately consumes only a strict subset of these observations after the current Task reaches 100 graded questions: parent topic >=3 exposures, >=2 unique Bank questions, <60% observed correctness, and only inside bounded broad General Practice recheck allocation.

## 10. Provider / mutation boundary

DB-only, deterministic, read-only, provider-free. No migration.

Opening Analysis does not create Sessions, Attempts, Evidence, change Task progress, change routing, or call AI/providers.
