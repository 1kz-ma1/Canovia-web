# V58.6 Recall Task Progression

Status: implemented / validated  
Branch: `feature/v58-6-recall-task-progression`

## 1. Goal

Connect the existing Recall learning loop to Study Task progression without
treating self-rated Recall as equivalent to objective Question Practice.

```text
Recall reviews
→ deterministic deck mastery state
→ Task completion candidate
→ explicit user confirmation
→ Task done
→ canonical next eligible Study Task
```

A Recall review never completes a Task by itself.

## 2. Existing Recall mastery remains authoritative

V58.6 reuses the V41.11 card mastery definition:

```text
repetitions >= 3
AND interval_days >= 7
```

It does not add a second spaced-repetition mastery model.

A card counts as "reviewed at least once" from `last_reviewed_at`, not from
`repetitions`.

This distinction matters because an `Again` review is a real review but
intentionally resets repetitions to 0.

## 3. Applicability boundary

Recall completion is valid only when
`StudyActivityPolicyService::forPlanTask()` selects Recall as the Task's
primary Study Activity.

A Recall deck used as a secondary tool for Question Practice or Resource Study
remains supplementary and cannot complete that Task.

This preserves the existing Task-semantic Activity Policy rather than allowing
the existence of a Recall deck to redefine the Task.

## 4. Ready-to-complete policy

`StudyRecallProgressionService` marks a Recall Task as `ready` only when:

1. the Task is not done or cancelled;
2. Recall is the primary Study Activity;
3. at least one active Recall card exists;
4. every active card has `last_reviewed_at`;
5. every active card satisfies `StudyRecallItem::isMastered()`;
6. no active card is currently due.

Projection states:

```text
completed
cancelled
supplementary
empty
learning
retaining
review_due
ready
```

The projection is deterministic and provider-free.

## 5. Human confirmation boundary

When the deck reaches `ready`, Recall UI shows:

`Recall定着を確認してTask完了`

The user must explicitly submit this action.

The server does not trust the rendered state. Inside the mutation transaction it:

- locks the Task;
- re-queries active Recall cards;
- locks the Recall cards;
- re-runs `StudyRecallProgressionService`;
- blocks completion if the deck is no longer eligible.

Therefore an old browser page cannot complete a Task after the underlying
Recall state has become stale.

## 6. Task completion

After explicit confirmation:

- `progress_percent = 100`
- `remaining_minutes = 0`
- `status = done`
- `progress_reason` records deterministic Recall mastery counts
- `next_action_note` points to the next eligible Task when available

V58.6 does not create a Recall-specific next-Task selector.

`StudyTaskProgressionService::afterVerifiedCompletion()` reuses the existing
dependency / ordering rules already used by Question Practice.

If a next eligible Task exists, the user is redirected to that Task's Study
Activity page. Otherwise the user returns to the Study Work surface.

## 7. Evidence and idempotency

Explicit confirmation records native Task Evidence:

- type: `study_recall_mastery_confirmed`
- external key: `study-recall-mastery-confirmed:task:{task_id}`
- aggregate reviewed / mastered / total / due metrics
- `completion_confirmed_by_user = true`
- confidence: `0.8`

Recall review Evidence remains confidence `0.75`.

The completion Evidence confidence remains below objective Study Practice
assessment confidence `1.0`.

Repeating the completion action on an already completed Task does not create a
second mastery-confirmed Evidence row.

## 8. Recall UI

The Recall page now shows a compact Task Progression section with:

- reviewed / total cards
- mastered / total cards
- currently due count
- deterministic progression reason
- Task completion candidate state

The completion CTA appears only when the deck is eligible and the actor can
edit the Plan.

For a non-Recall-primary Task, the UI explicitly explains that Recall is
supplementary.

## 9. Boundaries

V58.6 does not:

- change Recall scheduling;
- change `StudyRecallItem::isMastered()`;
- auto-complete from a review;
- increase Task progress from study time;
- treat self-rated Recall as objective scoring;
- change Question Practice mastery verification;
- call AI or another provider;
- add a database migration;
- change entitlement or billing behavior.

## 11. Result

Recall is no longer an isolated learning loop.

```text
Recall-primary Task
→ learn the full deck
→ spaced repetition reaches existing mastery
→ no card is due
→ user confirms completion
→ Task completes
→ next eligible Study Task
```

Canovia gains a real progression path for memorization Tasks while preserving a
stricter human-confirmed boundary than objective Question Practice.
