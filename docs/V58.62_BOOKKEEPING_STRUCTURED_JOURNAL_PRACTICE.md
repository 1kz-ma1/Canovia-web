# V58.62 — Bookkeeping Journal Entry Practice (structured answers)

## Purpose

A four-choice mini-diagnostic cannot show whether someone can **actually construct a journal entry**. This slice provides original bookkeeping exercises with debit/credit, selected account, and integer JPY amount on each line. It is optional and adjacent to the V58.61 foundation check.

## Working vertical slice

- Study Workspace → 学習準備 → `仕訳を直接入力して練習する` for Plans whose Study category and title/description mention 簿記.
- Four original questions across simple journal entries, cash/accounts-receivable sales, principal + interest repayment, and equipment purchase with unpaid balance.
- Per problem, up to four lines of `side, account, amount`; empty rows are ignored. A partially filled row is rejected with validation feedback and nothing saved.
- Deterministic, server-owned grading in `BookkeepingJournalEntryGrader`. Exact aggregate posting by side/account/amount determines correctness, independent of row order or equivalent split postings.
- Incorrect postings are classified as `unbalanced`, `side_mismatch`, `account_mismatch`, or `amount_mismatch`. This is a **mechanical** error category, not a claim to know the learner's reasoning.
- The learner receives correct-example postings after submitting, explanation and specific next-review suggestions, plus a manual link back to Plan Tasks. Plan/Task progress does **not** change automatically.
- Each explicit submission records a practice score with the original and normalized learner responses and grader results. Revisit renders the last recorded result; same UUID retry is idempotent. Other Plan/actor UUID replay returns HTTP 409.

## Data and provenance boundary

The previous V58.61 diagnostic reused the already existing `study_score_observations` table. The V58.62 result is stored in that same table using an **independent, internal** metric:

```text
metric_key: bookkeeping_journal_practice_percent
metric_label: 簿記仕訳入力演習
source_kind: mock_exam
source_label: Canovia仕訳入力演習
score_value: percentage correct (0..100, 4 questions)
components: { version: 1, result: { details: [...], topic_scores: {...}, error_types: {...}, next_actions: [...] } }
```

The generic `StudyScoreController` (external scale/result) and `StudyWorkspaceStateResolver` external score projection **exclude both** the V58.61 foundation metric and V58.62 practice metric. A Canovia in-app practice percentage is not an externally certified exam score, Readiness proof, or Task completion.

Ownership: existing `PlanOwnershipService` view/edit checks; actor-scoped record querying; UUID uniqueness. No new schema, no PDF/AI calls, no payment changes and no externally triggered writes. The result contents are user learning history and must be treated as private.
