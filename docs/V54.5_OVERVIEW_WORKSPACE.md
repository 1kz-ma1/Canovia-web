# V54.5 Overview Workspace

## Goal

V54.5 turns Overview into a thin cross-Mode command surface.

Overview does not become another dense dashboard.

It answers only:

```text
What is the single highest-priority Action now?
What is the current state of Study and Development?
What is waiting in Inbox?
What important state changed?
```

Study and Development remain the specialized Workspaces.

V54.5 does not introduce a new priority model, Readiness model, or AI traffic.

## Entry

Overview Workspace canonical route:

```http
GET /workspace/overview
```

named:

```text
workspace.overview.index
```

Overview Mode selection redirects to this route.

The route is a strong Overview semantic context. A stored Study or Development preference does not override it, and visiting Overview does not erase that stored preference.

The root `/` Home remains compatible and unchanged in V54.5.

## Highest-priority global Action

Overview reuses the existing Action Home selection authority through `HomePageDataService` and `IntelligenceHomeActionService`.

Selection semantics remain:

- supported Study / Development Intelligence can own priority when existing Home rules select it
- otherwise existing Dashboard Guidance owns priority
- existing Plan priority semantics remain authoritative
- Overview does not add a second global ranking algorithm

Overview calls Home projection in non-recording/prefetch mode so merely viewing Overview does not emit DashboardViewed / RecommendationShown telemetry or capture a periodic behavior state snapshot.

### Intelligence Action

When the current global Action is Intelligence-backed, show:

- Plan
- domain
- Readiness
- Biggest Gap
- Current Action
- existing Action CTA
- Workspace CTA

### Task Guidance Action

When the current global Action is ordinary Dashboard Guidance, show:

- Plan
- Task
- current status
- recommended execution tool
- existing execution CTA semantics

Overview does not project new Tasks.

## Mode summaries

Overview shows at most one Study summary and one Development summary.

For each Mode:

1. choose the highest-priority accessible Plan in that profile
2. priority → deadline → stable Plan ID
3. evaluate only that Plan
4. render a compact summary

### Study summary

When confirmed Study Scope exists:

- Exam Readiness
- current state
- Biggest Gap
- Current Action title

When confirmed Study Scope does not exist:

- show setup-needed state
- do not show a fake numeric Readiness
- CTA to Study Workspace

### Development summary

When a Release Candidate / focus task state exists:

- Release Readiness
- current state
- Biggest Release Gap
- Current Action title

When Release Evidence does not exist:

- show setup-needed state
- do not show a fake numeric Readiness
- CTA to Development Workspace

Overview evaluates at most two domain Plans for Mode summaries.

## Inbox

Overview shows a bounded Inbox summary for the current identity:

- pending count for `new` / `review`
- up to four latest pending items
- source type
- Plan label when available
- CTA to Inbox

Identity semantics match existing Inbox / Space Station:

- authenticated user items
- actor-token items associated with the same identity
- guest actor-token items

No AI routing is triggered by Overview.

## Important changes

Overview reuses `ActionHomeProjectionService` signals from the existing Home projection.

Show up to four current important signals such as:

- pending Plan update
- Plan status / status change
- collaboration activity

Overview does not create a second notification system.

V54.6 remains responsible for domain-specific before/after Readiness feedback.

## Performance

Overview:

- reuses one existing Home projection in prefetch/non-recording mode
- evaluates at most one Study Plan and one Development Plan for summaries
- loads at most four pending Inbox items
- renders at most four important signals

It must not evaluate every Intelligence-supported Plan.

No new OpenAI or GitHub provider request is made.

## Authorization

Overview uses existing Plan ownership/access semantics.

Mode summaries can represent accessible Plans.

Mutation remains on destination surfaces and respects their existing edit authorization.

Inbox summary is identity-scoped and never shows another actor's item.

## Compatibility

V54.5 preserves:

- root Action Home
- Study Workspace
- Development Workspace
- Workspace Mode persistence
- Study / Development Intelligence
- Inbox
- Map / Space Station
- existing Action Home signals
- existing Task execution routes
- existing telemetry semantics on root Home

## Non-goals

V54.5 does not:

- replace root Home
- become a Plan browser
- show every Plan
- show every Task
- show every Inbox item
- create a new ranking model
- create a new Readiness model
- create new notification/history tables
- persist Intelligence on GET
- invoke AI
- invoke GitHub API
- mutate Task progress
- change billing
