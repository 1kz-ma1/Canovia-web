# V50.2 Plan Dashboard Information Board

> **V50.3 update:** Plan DashboardはMap-owned Surfaceから独立し、`/plans/{plan}/dashboard` をcanonical Dashboard Document routeとする。V50.2のInformation Board compositionは維持し、Spatial Roadmapは内部Structure Regionとして残る。旧Map L2 Plan Dashboardは互換用。詳細は `docs/V50.3_STANDALONE_PLAN_DASHBOARD.md`。

## 目的

Plan Dashboardを縦スクロール中心の情報列ではなく、複数情報へ一度に目を通せる一枚のInformation Boardへ再構成する。

V50.1 Dashboard Document Foundationを実際のPlan Dashboardへ適用する最初の移行Phase。

## Surface contract

Plan Dashboardは引き続きMap-owned Dashboard Documentとして動作する。

```text
Fixed Chrome
└ Document Canvas
   └ 12-column Information Board
      ├ Overview
      ├ Progress
      ├ Next Action
      ├ Attention
      ├ Activity
      └ Spatial Roadmap
```

Document Camera:

- initial fit
- explicit zoom
- pinch
- trackpad pinch
- pan
- whole-document reset

はV49.9/V50.1の既存契約を維持する。

## Board composition

### Row 1

Overview: 4 columns

- Plan description
- Task count
- completed count
- active count
- Classic / Edit actions

Progress: 8 columns

- period
- remaining days
- required minutes
- Plan status

既存 `summary-metrics` partialを再利用する。

### Row 2

Next Action: 4 columns

- Current / primary Task
- progress
- remaining minutes
- next_action_note
- additional ready Tasks

Attention: 4 columns

- deterministic attention message
- ready count
- blocked count
- parallel cluster count
- blocked Task shortcuts

Activity: 4 columns

- latest four WorkLogs
- Task title
- date
- actual minutes
- progress delta

### Row 3-4

Spatial Roadmap: 12 columns / 2 rows

- Phase
- Cluster
- dependency
- parallelism
- semantic depth
- Task detail

RoadmapはDashboard全体ではなくInformation Board内のStructure Regionとして扱う。

## PlanDashboardBoardService

`PlanDashboardBoardService` はread-only projectionを生成する。

Input:

- Plan
- PlanProgress
- canonical Roadmap
- Spatial Roadmap

Output schema v1:

- overview
- progress
- next
- ready
- blocked
- activity
- signals

### Next Action

優先順:

1. Spatial Roadmap current
2. doing Task
3. ready Task
4. canonical Roadmap current

Roadmapが決めた現在地と矛盾しない。

### Ready

`visual_state=ready` からCurrentを除外し、

- priority
- activation_cost
- sort_order

で安定ソートし、Boardでは最大3件表示する。

### Blocked

`visual_state=blocked` をpriority / sort_orderで安定ソートし、最大3件表示する。

### Activity

既存Plan WorkLog relationから最新4件。

Plan Workspace側ですでに:

- worked_on desc
- id desc

でloadしているため、新規Queryは追加しない。

## Attention contract

V50.2ではAI生成を使わない。

Attentionはcanonical stateから決定論的に生成する。

優先順:

1. blocked Taskあり -> alert
2. Plan statusが期限切れ / 作業時間不足 / 遅れ気味 -> alert
3. current Taskあり -> primary
4. ready Taskあり -> primary
5. その他 -> quiet

「AI Insight」と表示して推測結果を見せない。

将来AI Insightを追加する場合も、このdeterministic Board dataとは別sourceとして明示する。

## Task interaction

Next / Ready / Blocked Taskは既存:

`data-roadmap-task-detail-open`

を使い、V49.9 Task Detail Surfaceへ接続する。

新しいTask Detail UIは複製しない。

Task Detailを閉じた場合、Plan Document Camera位置は維持する。

## Stable document geometry

Plan Dashboard Canvasは70rem固定幅をPrimaryとする。

MobileでもRegionを縦一列へreflowしない。

```text
Desktop -> whole board / zoom if needed
Mobile  -> initial fit -> pinch / zoom to desired region
```

位置関係:

- Overview + Progress
- Next + Attention + Activity
- Spatial Roadmap

を端末間で維持する。

## Spatial Roadmap role

RoadmapはBoard下段のStructure Region。

巨大RoadmapをDashboardそのものにしない。

Roadmap内部のauto-fitも維持するため、

```text
Dashboard Document fit
  └ Spatial Roadmap internal fit
```

の二段階overviewになる。

外側はPlan全体、内側はTask構造全体を一望する。

## Persistence

追加DBなし。

Boardは既存canonical stateからrequest時に生成するread-only projection。

新規保存なし:

- Board layout
- Region position
- Next selection
- Attention state
- Camera state

## Non-goals

- AI Insight生成
- Region drag/drop
- user-custom dashboard layout
- layout persistence
- Home Dashboard移行
- Inbox Command Center移行
- Map runtime ownership解除
- Automatic Dashboard/Scroll判定
