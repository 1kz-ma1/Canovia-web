# V46.2 GitHub Repository Overview

## Goal

GitHub Repository URLをCanoviaへ追加したとき、
Repository自体を「今やる / レビュー待ち / 修正必要 / マージ待ち / 完了」の1作業として扱わない。

Repositoryは開発全体のRoot / Contextとして扱い、
その下にCanoviaが把握しているPR / Issue / Branch / Commit / Actionsと、
Canovia上の作業状態・Task接続をまとめて見せる。

## UX decision

Repository URL:

```text
https://github.com/owner/repo
```

はWorkflow Laneへ入れない。

代わりにRepository Overviewへ表示する。

```text
Repository
  ├─ Known GitHub structure
  │    PR / Issue / Branch / Commit / Actions
  ├─ Canovia flow
  │    今やる / レビュー待ち / 修正必要 / マージ待ち / 完了 / 未整理
  └─ Connected work
       linked Tasks / recent references
```

これによりRepositoryそのものと、
Repository内で「次の判断が必要な作業」を分離する。

## Repository grouping

`GitHubWorkflowService` は同じ:

- Plan
- repo_full_name

を持つGitHub Artifactを1つのRepository Overviewへgroupする。

Repository Artifactが明示登録されていなくても、
PR / Issue / Branch URLからrepo_full_nameが判明している場合は
Canovia-known RepositoryとしてOverviewを構築できる。

明示的Repository Artifactが存在する場合は、
そのArtifactをRepository Rootとして扱う。

## Repository capture

Quick CaptureでRepository URLが入力された場合:

- artifact_type = repository
- github_workflow_state は保存しない
- Repository Overviewへ表示
- Workflow Laneには表示しない

既存データにRepository Artifact + github_workflow_stateが残っていても、
表示ProjectionではRepositoryをLaneから除外する。
データmigrationは不要。

PR / Issue / Branch等では従来どおりCanovia workflow stateを使用する。

## Overview content

Repository Overviewは以下を表示する。

### Known structure

Canoviaへ登録済みURLだけからcountする。

- Pull Request
- Issue
- Branch
- Commit
- Actions
- Other GitHub references

### Canovia flow

Repository配下の非Repository Artifactを:

- 今やる
- レビュー待ち
- 修正必要
- マージ待ち
- 完了
- 未整理

でcountする。

### Connected work

同RepositoryのArtifactへ明示linkされたTaskをdeduplicateして表示する。

直近のGitHub referenceも最大5件表示し、
Workflow Lane上の該当Cardへ移動できる。

## Remote data boundary

V46.2でもGitHub API / OAuth / Webhookは導入しない。

Repository URLを貼っただけで以下を自動取得・推測しない。

- 全Branch
- 全PR
- 全Issue
- default branch
- commit count
- open / merged
- review state
- CI state
- repository visibility
- collaborators

Overviewは明示的に:

> Canoviaへ登録済みのGitHub URLから構成した全体像

である。

将来authoritative GitHub connectorを接続した場合も、
remote objectをそのまま画面へ増やすのではなく、
このRepository Overviewへnormalizeして投影する。

## Summary semantics

Hub上部のRepository数はRepository Overview group数。

Workflow summaryの対象は非Repository Artifactだけとする。
Repository Rootは作業件数へ含めない。

## Safety / permissions

既存PlanOwnershipServiceを維持する。

Repository Overviewは既存ArtifactのProjectionであり、
新DB table / migrationは追加しない。

Repository groupingやOverview表示だけで:

- Task progress
- Plan state
- workflow state
- Task Evidence

を変更しない。

## Non-goals

- GitHub live repository browser
- file tree viewer
- GitHub API polling
- OAuth
- Webhook
- branch / PR / Issue自動作成
- remote status推測
- RepositoryをTaskとして扱うこと
