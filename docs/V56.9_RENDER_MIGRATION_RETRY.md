# V56.9 Render Migration Retry

## Goal

Make Render startup resilient to short-lived Aiven MySQL communication failures without masking deterministic migration errors.

## Incident follow-up

After V56.8 repaired the orphaned `intelligence_decision_traces` migration, a fresh Render container failed before Laravel could inspect the migration repository:

`SQLSTATE[08S01] [1159] Got timeout reading communication packets`

The failing query was Laravel's initial `migrations` table existence check. This is a connectivity failure between a new Render instance and the remote Aiven MySQL service, not an application schema error.

## Startup contract

`docker/render-start.sh` keeps migrations before cache building and before the HTTP server starts.

Migration execution is retried only when command output contains a known transient MySQL connectivity signature:

- SQLSTATE 08S01
- MySQL 2002
- MySQL 2006
- MySQL 2013
- "Got timeout reading communication packets"

Default policy:

- maximum attempts: 5
- delay between attempts: 8 seconds
- override through `CANOVIA_MIGRATION_MAX_ATTEMPTS`
- override through `CANOVIA_MIGRATION_RETRY_DELAY_SECONDS`

Any other migration failure exits immediately.

## Safety

The retry loop does not:

- skip migrations
- start the web server before migrations finish
- suppress deterministic schema failures
- mutate database credentials
- change application query behavior
- alter production data directly

Laravel migrations remain the only schema mutation path.
