# V56.0 Study Exam Convergence Policy

## Goal

V56.0 fixes a failure mode in Canovia Study Practice:

```text
weakness detected
→ focused practice
→ learner improves
→ AI can still invent another pattern
→ focused practice continues
→ general/exam practice is delayed
```

The objective is not to eliminate every weakness.

The objective is:

> move the learner toward the exam date while maximizing expected total score under limited remaining time.

The first concrete validation target is AP Subject A.

## Problem in the current system

Current V41.4 already prevents obvious over-focus:

- one mistake does not become Primary weakness
- careless / calculation slip is low weight
- saturation reduces repeated-topic priority
- diagnostic questions stay in the mix
- recent Question Bank question IDs are avoided

But saturation is only a priority penalty.

There is no deterministic concept of:

- weakness graduation
- mandatory return to general practice
- graduated-topic cooldown
- weakness re-entry
- exam-date phase transition

Also `StudyTaskProgressionService` currently accepts:

```text
AI next_step.kind = practice
→ reinforce_current
```

unless Task completion flow takes precedence.

This means AI can continue proposing focused practice even after enough evidence exists.

## Responsibility boundary

V56.0 makes the boundary explicit.

### AI owns

- question wording
- question generation inside the allowed scope
- difficulty inside the Exam Profile
- answer assessment
- error classification
- weakness-topic labels
- suggested next action

### Canovia Policy owns

- current study phase
- whether reinforcement is allowed
- which weakness topics are active
- graduation
- overtraining cap
- mandatory General Practice return
- weakness re-entry
- exam-date convergence
- final question mix

Canonical rule:

```text
AI recommendation
→ Canovia deterministic phase policy
→ allowed Study Practice strategy
```

AI cannot extend Weakness Reinforcement only because more question patterns exist.

## Study phases

V56.0 uses four Study Practice phases.

### DIAGNOSIS

Purpose:

- establish current level
- sample broadly
- discover repeated weakness signals

Question mix:

```text
diagnostic = 100%
```

No single Topic is allowed to dominate.

### WEAKNESS_REINFORCEMENT

Purpose:

- repair a confirmed, bounded weakness
- collect enough evidence to decide whether to graduate it

Only Policy-approved active topics may be targeted.

AI may choose variants **inside those topics**, but may not expand the intervention to sibling topics simply because they exist.

### GENERAL_PRACTICE

Purpose:

- return to broad exam coverage
- re-measure overall performance after targeted intervention
- discover whether a weakness truly persists outside the focused context

Question mix:

```text
diagnostic = 100%
```

The Question Bank's existing domain round-robin is reused.

### EXAM_MODE

Purpose:

- converge toward real exam behavior
- prioritize balanced exam-format questions over new micro-weakness exploration

V56.0 Exam Mode uses balanced 10-question blocks because the existing Study Practice contract is designed around 1–20 questions.

V56.0 does **not** introduce a new 50/80/100-question full-exam UI.

Multiple blocks can accumulate exam-like evidence without breaking existing Session UX.

## Phase precedence

The deterministic phase policy applies the following order.

### 1. Exam Mode window

If a valid exam date exists and:

```text
days_until_exam <= 14
```

use:

```text
EXAM_MODE
```

This has priority over new fine-grained weakness reinforcement.

### 2. Mandatory General Practice return

If a weakness was just graduated or an intervention hit its overtraining cap and no broad practice has occurred afterward:

```text
GENERAL_PRACTICE
```

must run before another focused weakness intervention.

### 3. General Practice window

If:

```text
15 <= days_until_exam <= 30
```

prefer:

```text
GENERAL_PRACTICE
```

New micro-weakness exploration is not allowed to dominate this window.

### 4. No usable history

If there is no meaningful practice history:

```text
DIAGNOSIS
```

### 5. Confirmed eligible weakness

Outside the deadline windows, if one or more Policy-approved weaknesses remain active/reopened:

```text
WEAKNESS_REINFORCEMENT
```

### 6. Otherwise

```text
GENERAL_PRACTICE
```

## Exam-date authority

Use the same semantics as Study Intelligence.

Priority:

1. exactly one unique confirmed `StudyScopeCapture.exam_date`
2. Plan deadline
3. unknown

If confirmed captures conflict, the phase policy does not silently choose one date.

Conflict behaves as "date unavailable" for automatic exam-window transition.

## Weakness unit

V56.0 does not introduce a new Category/Topic/Subtopic database hierarchy.

The bounded intervention unit is the normalized weakness topic label already emitted by:

```text
question_feedback.weakness_topics
```

Summary-level `attempt.weaknesses` remains a weaker compatibility signal.

Prompt guidance should prefer the smallest useful exam concept.

Good:

- DNS
- CNAME
- 正規化
- LEFT OUTER JOIN
- MTBF / MTTR
- 品質特性

Too broad when a more concrete error is known:

- Network
- Database
- Calculation

The system can support a formal topic taxonomy later without making V56.0 depend on one.

## Blocking errors

Graduation and re-entry distinguish meaningful understanding errors from minor slips.

Blocking:

- knowledge_gap
- concept_gap
- reasoning_gap
- condition_reading
- unit_error
- unknown

Non-blocking for graduation by themselves:

- calculation_slip
- careless
- none

This reuses the existing V41.4 error taxonomy.

## Weakness detection

A single mistake does not create focused reinforcement.

A weakness requires repeated evidence across distinct Attempts, consistent with current Weakness Priority behavior.

AI `next_step.focus_topics` alone never confirms a weakness.

## Weakness reinforcement accounting

For a targeted Topic, V56.0 tracks an intervention cycle using durable StudyPracticeSession strategy snapshots.

A Session contributes to the Topic budget when the Topic was in:

- Primary reinforcement topics
- Secondary reinforcement topics
- legacy `focus_topics` fallback

Estimated targeted question budget is derived from the stored question mix.

This is intentionally called a **question budget**, not exact Topic-level answered-question count.

Current historical data does not always contain authoritative Topic labels for every correctly answered question.

V56.0 avoids inventing false question-level precision.

## Weakness Graduation

A Topic graduates when all conditions are true within the current intervention cycle:

1. at least 2 targeted reinforcement Attempts exist
2. estimated targeted question budget is at least 8
3. the latest 2 targeted Attempts each have overall score >= 80%
4. neither of those latest 2 targeted Attempts contains a blocking error for that Topic

Conceptually:

```text
enough targeted exposure
AND stable session performance
AND no recent serious Topic-specific error
→ graduated
```

AI opinion is not a graduation input.

## Graduation semantics

Graduation means:

> stop deliberately drilling this Topic now.

It does **not** mean:

- permanently mastered
- never test it again
- remove it from General Practice
- Task automatically complete

The Topic remains eligible to appear naturally in General/Exam Practice.

## Overtraining prevention

A reinforcement cycle cannot grow without bound.

If either limit is reached before graduation:

```text
targeted sessions >= 3
OR
targeted question budget >= 20
```

the Topic becomes:

```text
capped / monitoring
```

and focused reinforcement must stop.

This is an overtraining guard, not a mastery claim.

If another weakness exists, V56.0 still requires a General Practice return before moving directly into another focused weakness.

## Mandatory General Practice return

After:

- weakness graduation
- reinforcement cap

the next eligible Practice phase must include at least one:

```text
GENERAL_PRACTICE
```

block before a new focused intervention.

This prevents:

```text
Database
→ graduate
→ Network
→ graduate
→ Availability
→ ...
```

without re-checking total exam performance.

## Weakness re-entry

A graduated/capped Topic can re-enter reinforcement only from broad evidence.

Eligible broad phases:

- GENERAL_PRACTICE
- EXAM_MODE

Re-entry requires:

```text
same Topic has blocking error
in >= 2 distinct Attempts
within the latest 3 broad Attempts
```

One broad-practice mistake is not enough.

### Single mistake

```text
graduated
→ one general-practice miss
→ monitoring only
```

### Repeated collapse

```text
graduated
→ broad miss
→ broad miss again
→ reopened
```

## General Practice

General Practice deliberately clears focused Topic allocation.

Strategy:

```text
focus_topics = []
question_mix:
  primary = 0
  secondary = 0
  diagnostic = 10
```

Question Bank behavior already supports this:

- all matching AP pack questions become eligible
- domain grouping is round-robin
- recent Question Bank IDs are deprioritized

Hybrid AI generation must fill only missing balanced coverage.

## Exam Mode

Exam Mode also avoids focused weakness drilling.

For AP Subject A:

- single-choice 4-option remains preferred
- awkward arithmetic remains prohibited
- Question Bank / past-question-derived structure is preferred
- all questions should approximate exam frequency and breadth
- graduated weaknesses may appear naturally
- AI must not create a micro-topic drill

V56.0 uses 10-question exam blocks.

A later version may add full-length timed mock exams with authoritative timing.

## 50 / 100 question checkpoints

V56.0 does not create a 50- or 100-question single Session.

The existing Session contract is retained.

Conceptually:

```text
10-question blocks
→ accumulated evidence
→ visible 50 / 100 checkpoints
→ later policy may use those checkpoints for re-evaluation
```

V58.17 implements the visible cumulative checkpoint layer for the current Practice Task.

It counts provider-neutral graded `question_feedback`, freezes deterministic first-50 / first-100 snapshots, and separates Question Bank unique / repeated exposure where durable Bank ids exist.

V58.17 deliberately does **not** make checkpoint attainment a Plan-level routing authority. Plan-wide re-evaluation / across-Task weakness handoff remains a separate future policy decision.

See `docs/V58.17_STUDY_PRACTICE_CUMULATIVE_CHECKPOINTS.md`.

## AI generation constraints

Generation Prompt must include:

- current Canovia phase
- active reinforcement topics
- graduated/capped topics
- whether focused expansion is allowed

### Weakness Reinforcement prompt

AI must:

- stay inside the Policy-approved active Topic
- vary problem pattern only inside that boundary
- not expand into sibling Topics merely because they are related
- preserve the Canovia question mix

### General Practice prompt

AI must:

- not intentionally target the last weakness
- distribute across the exam scope
- avoid resurrecting graduated Topics as focused practice
- preserve exam-relevant frequency and difficulty

### Exam Mode prompt

AI must:

- prioritize AP Subject A exam-like format
- avoid excessive personalization
- avoid low-frequency detail expansion
- avoid above-exam arithmetic difficulty
- return balanced exam-style questions

## AI assessment constraints

Evaluation Prompt should explicitly state:

- `next_step` is a suggestion
- Canovia decides whether reinforcement continues
- do not recommend continued drilling only because more variants exist
- `weakness_topics` should identify the smallest practical concept
- one isolated slip should not be upgraded to a persistent weakness

## Task progression interaction

Task completion and exam-convergence phase are separate concerns.

Current `StudyTaskProgressionService` mastery verification remains valid.

However:

```text
AI next_step = practice
```

must not force:

```text
reinforce_current
```

when the convergence Policy has selected General Practice or Exam Mode.

The Practice Strategy / progression presentation should use the Policy-selected continuation.

## Compatibility

No historical Attempt or Session rewrite is required.

V56.0 should derive state from existing history.

For historical Sessions without a V56.0 phase snapshot:

- baseline_assessment → diagnosis
- weakness_reinforcement → weakness_reinforcement
- retention_and_transfer / task_mastery / mastery_verification → general-compatible evidence
- unknown → conservative general-compatible evidence

New Sessions persist the V56.0 phase snapshot inside existing:

```text
StudyPracticeSession.selection_context.strategy
```

No migration is required for learning phase state.

## History window

Existing weakness priority continues to use its own current bounded recent history.

V56.0 convergence analysis may inspect up to 16 recent Attempts to determine:

- intervention cycle
- graduation
- cap
- broad-practice re-entry

Prompt history can remain shorter.

## AP validation case

Primary real-world case:

```text
diagnostic:
42 / 50 = 84%

known weakness areas:
- Network
- Database
- Performance / Availability calculations
- Quality characteristics
```

This is not a beginner state.

Expected V56.0 behavior:

```text
confirmed narrow weakness
→ short bounded reinforcement
→ graduation or cap
→ General Practice
→ broad re-measurement
→ reopen only if repeated broad failure
→ General Practice increasingly dominates near exam
→ Exam Mode dominates in final 14 days
```

The system must not restart all AP domains from zero.

## Definition of Done

V56.0 is complete when:

1. Weakness Reinforcement has deterministic exit conditions.
2. AI cannot extend reinforcement indefinitely by proposing new variants.
3. A graduated/capped intervention returns to General Practice.
4. Re-entry requires repeated broad-practice evidence.
5. One mistake does not immediately reopen a Topic.
6. Exam date changes phase priority.
7. General / Exam Practice uses balanced coverage.
8. Existing history remains compatible.
9. Code and specification agree.
10. AP Study Practice can converge toward the exam instead of remaining trapped in weakness drilling.

## Final principle

Canovia should not optimize for:

```text
find every possible weakness
```

It should optimize for:

```text
use limited remaining time
→ improve total exam performance
→ converge toward the real exam date
```


## V56.4 compatibility overlay

V56.4 does not change V56.0 exam-date windows, graduation thresholds, overtraining cap, or broad-practice re-entry rules.

Instead, it adds deterministic routing after the V56.0 convergence decision:

```text
V56.0 convergence phase
→ V56.4 Task intent + mastery/cooldown routing
→ final Question Mix
```

Compatibility rules:

- ordinary/adaptive Tasks keep the V56.0 phase behavior
- generic `総合演習` remains adaptive
- an explicitly broad Task such as `分野横断` may convert a V56.0 weakness-reinforcement recommendation into General Practice routing with only 1–2 weakness recheck questions
- a V56.0 active Topic that satisfies V56.4 cooldown/mastery evidence may be removed from active focused routing
- structured `question_feedback` is authoritative over summary prose when determining modern weakness evidence
- the established public strategy key `general_practice` is preserved; the internal Task mode is stored in `routing_policy.task_mode`

V56.0 remains responsible for exam convergence. V56.4 decides how much of the next block may be spent on an already-known weakness.

Detailed overlay contract: `docs/V56.4_STUDY_ROUTING_MASTERY_COOLDOWN.md`.
