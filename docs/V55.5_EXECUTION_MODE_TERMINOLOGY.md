# V55.5 Execution Mode Terminology & Surface Handoff Clarity

## Goal

V55.5 continues the pre-iOS UX Completion phase by removing a vocabulary collision between:

- global Workspace Modes
- the legacy V51.2 "Execution Workspace" selector inside /navigate

Both currently use Study / Development / Career vocabulary, but they represent different concepts.

The product contract becomes:

```text
Workspace Mode
→ What domain state am I looking at?
→ Readiness / Gap / Decision / Current Action

Execution Mode
→ How should this selected Task be carried out?
→ Study activity / development orchestration / career operation / timer
```

The user must not be asked to "choose a Workspace" inside the Execution surface.

## Canonical vocabulary

Use:

- Workspace / Workspace Mode
  - Overview
  - Study
  - Development
  - Career
  - owns Intelligence / state / setup / history

- Execution Mode / 実行タイプ
  - study
  - development
  - career
  - general
  - owns Task execution routing

Do not use "Execution Workspace" in current user-facing UI.

## Execution surface

Route remains:

```text
/navigate
route = navigation.index
```

Internal request/query contract remains:

```text
mode=study|development|career|general
```

No route or controller rename is required.

### Header

Selected mode:

```text
EXECUTION / STUDY
学習モード
```

No selected mode:

```text
EXECUTION / MODE SELECT
実行方法を選ぶ。
Planの種類に合わせて、実行タイプを切り替えます。
```

### Picker

Old:

```text
CHOOSE WORKSPACE
```

New:

```text
CHOOSE MODE
```

Supporting copy uses "実行タイプ".

### Switcher

ARIA:

```text
Execution Modeを切り替える
```

Plan rail:

```text
この実行タイプのPlan
この実行タイプの全Planから選ぶ
```

### Specialized handoff

The selected Task is not "handed to another Workspace".

Instead:

```text
このTaskを専用フローへ引き継ぐ
Task Contextを保ったまま、<mode>の実行フローで進めます。
```

The action label should describe the actual operation:

Study:
```text
学習Activityで進める
```

Development:
```text
開発フローで進める
```

Career:
```text
Career管理で進める
```

General:
```text
このまま開始
```

## Relationship to specialized Workspace

Execution and Workspace remain connected but not conflated.

```text
Home
→ Current Action

Workspace
→ Why this action / domain state

Execution
→ Choose or confirm how to execute a Task

Operation surface
→ Actually perform the work
```

Examples:

Study:

```text
Study Workspace
→ Exam Readiness / Gap / Current Action

Execution
→ 学習 mode

Study Activity
→ Practice / Recall / Material
```

Development:

```text
Development Workspace
→ Release Readiness / Gap / Current Action

Execution
→ 開発 mode

Execution Orchestration
→ GitHub / Packet / Evidence
```

Career:

```text
Career Workspace
→ Process State / Gap / Current Action

Execution
→ キャリア mode

Career operation
→ Application / Interview / Capture
```
