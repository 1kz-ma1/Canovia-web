# V58.1 Developer Workspace Navigation IA

## Goal

V58.1 keeps the V58.0 rule:

> one screen = one information / operation lineage

while removing the assumption that every Developer surface should remain a
peer-level horizontal tab forever.

The current five real surfaces are reorganized into lifecycle categories and
selected from one compact grouped View control.

## Current information architecture

Only implemented surfaces are shown.

```text
実行
└─ 今やること

設計
└─ 改善

プロジェクト
├─ リポジトリ
└─ チーム

観測
└─ プレビュー
```

The future `自動化` category is intentionally **not** rendered yet because
there is no standalone Automation settings surface in the current product.

Likewise, future design/observation surfaces are not shown as disabled teaser
items.

## Navigation shell

V58.0 used five horizontal surface tabs.

V58.1 replaces that row with one compact navigation form:

```text
DEVELOPER  [category badge]
Plan: [ Canovia ...            ▾ ]
View: [ grouped surface view   ▾ ]
```

The View select uses semantic option groups:

```html
<optgroup label="実行">...</optgroup>
<optgroup label="設計">...</optgroup>
<optgroup label="プロジェクト">...</optgroup>
<optgroup label="観測">...</optgroup>
```

This preserves the selected `?surface=` URL contract while making the shell
stable as more screens are added later.

## Category projection

The category is metadata on the existing surface registry/projection.

Each surface defines:

- `category_key`
- `category_label`
- `category_order`
- `surface_order`

There is no second category query parameter.

The URL remains:

```text
/workspace/development?plan_id=...&surface=repository
```

The category is derived from the selected surface.

This avoids category/surface mismatch states and keeps old links valid.

## Plan + View behavior

Plan and View share one compact GET form.

Changing either control submits the canonical Developer Workspace URL with both:

- `plan_id`
- `surface`

Therefore switching Plan preserves the currently selected Developer screen, and
switching screen preserves the current Plan.

With JavaScript enabled, the form submits immediately on select change.
A `noscript` submit button remains as fallback.

## Current location

The Developer identity block shows a compact category badge and current screen
description.

Example:

```text
DEVELOPER   [プロジェクト]
Canoviaを事業として成功させる
リポジトリ · 構成・Activity・Release
```

This gives location context without reintroducing a large header or breadcrumb
stack.

## Growth model

V58.1 is deliberately structured for later expansion.

Potential future lifecycle categories may include:

- 実行
- 設計
- プロジェクト
- 観測
- 自動化

but a category is rendered only when at least one real surface exists.

Future additions should extend the surface metadata rather than add another
global tab row.

## Daily-use density

V58.1 removes:

- five persistent peer-level horizontal tabs
- their per-tab descriptions occupying a full row
- desktop horizontal expansion pressure

The shell retains only:

- Developer identity
- current category / screen
- Plan selector
- View selector

All selected surface content remains exactly one server-rendered stream.

by this navigation change.
