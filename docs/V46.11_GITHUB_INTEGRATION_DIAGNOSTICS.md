# V46.11 GitHub Integration Diagnostics

## Goal

V46.4〜V46.10で追加したGitHub App / Webhook / Queue / Return Evidenceを、
Canovia運営者が「設定済みか」「実際に処理できているか」「どこで止まっているか」
を1画面で確認できるようにする。

```text
GitHub App config
        +
Webhook secret
        +
Async Queue
        +
Connected Repository
        +
Webhook Delivery
        +
Return Evidence
        ↓
GitHub Integration Diagnostics
```

Diagnosticsは運営監視用であり、
ユーザーのRepository操作やTask状態を変更する機能ではない。

## Admin surface

新規route:

```text
GET /admin/github
```

route name:

```text
admin.github.index
```

既存 `admin.access` boundary配下に置き、
通常ユーザーはアクセスできない。

Admin navigationとAdmin Dashboardから遷移できる。

## Configuration checks

表示する:

- GitHub App configured
  - App ID + Private Keyがserver側に存在するか
- Webhook configured
  - `GITHUB_APP_WEBHOOK_SECRET` が存在するか
- Queue driver
  - `sync` / `null` 以外の非同期Queueか
- Connected Repository count
  - Canovia Repository Artifactで `github_app_connection.status=connected`

表示しない:

- App Private Key
- Webhook Secret
- GitHub installation token
- raw environment value

「設定済み / 未設定」というboolean projectionだけを公開する。

## Webhook endpoint

管理画面に現在のWebhook endpointを表示する。

```text
https://<current-canovia-host>/api/integrations/github/webhook
```

GitHub App側へ設定する値としてコピー可能なテキストにする。

Secretそのものは表示しない。

## Worker observation

ProcessのPIDやOS-level healthをCanovia DBだけから断定しない。

観測する:

- pending GitHub Queue Job count
- oldest pending GitHub Job
- failed GitHub Job count
- accepted / processingのまま5分以上残ったdelivery
- 直近30分以内のprocessed delivery

状態:

### not_configured

Webhook Secret未設定。

### attention

- Queue driverがsync / null
- 5分以上のdelivery滞留
- 5分以上のGitHub Job滞留

等を確認。

### observed

直近30分以内にWebhook deliveryがprocessed。

これは「最近Workerが処理した」観測であり、
常時生存を保証するheartbeatではない。

### unknown

設定はあるがrecent processed deliveryがない。

Webhook trafficがないだけでもunknownになり得るため、
異常とは断定しない。

## Delivery diagnostics

`github_webhook_deliveries` から表示:

- total
- accepted
- processing
- processed
- ignored
- failed
- last received
- last processed
- stuck count

Recent Delivery最大30件:

- received time
- repo_full_name
- event
- action
- PR number
- status
- synced task count
- entitlement skip count
- attempts
- error有無

表示しない:

- `last_error` 本文
- raw payload
- PR body
- review comment
- signature
- token

errorはboolean indicatorだけにする。

## Queue diagnostics

Laravel `jobs` / `failed_jobs` が存在する場合だけreadする。

GitHub webhook jobはserialized payload内の:

`ProcessGitHubWebhookDelivery`

をbounded pattern matchして集計する。

表示:

- pending GitHub Job count
- oldest pending time
- failed GitHub Job count

failed jobのexception本文やpayload本文は画面へ出さない。

## Repository diagnostics

GitHub Repository Artifactのうち:

```text
provider = github
artifact_type = repository
metadata.github_app_connection.status = connected
```

を接続済みRepositoryとして表示する。

表示:

- repo_full_name
- Plan title
- connected status

installation IDはroutingには必要だが、
Diagnostics UIには表示しない。

## Overall state

### setup_required

以下のどれか:

- GitHub App未設定
- Webhook Secret未設定
- 非同期Queue未設定

### attention

- failed GitHub Queue Jobあり
- failed webhook deliveryあり
- stuck deliveryあり
- worker observation = attention

### unverified

設定はあるが:

- connected Repositoryなし
- または最近のWorker処理を観測できない

### healthy

- App configured
- Webhook configured
- async Queue configured
- connected Repositoryあり
- recent processed deliveryあり
- attention signalなし

Healthyは「現在観測できるCanovia側の境界が正常」という意味であり、
GitHub / Render infrastructure全体のSLA保証ではない。

## Operator checklist

管理画面に本番有効化までの作業を表示する。

1. GitHub App ID / Private KeyをRender等へ設定
2. Webhook SecretをGitHub AppとRender等へ設定
3. 非同期Queue driverを設定
4. 対象RepositoryへCanovia GitHub Appをinstall
5. 実WebhookでWorker処理を確認

各項目は現在設定 / 観測からcheck表示する。

一般ユーザー向けのsetupではない。

## Privacy

Diagnosticsは運営面の観測だけに限定する。

表示しない:

- secrets
- Private Key
- access token
- webhook signature
- raw webhook body
- failed_jobs.exception
- GitHub API response body
- Task / Evidence本文

Repository名とPlan titleはAdmin-only surfaceで表示できる。

## Mutations

V46.11のDiagnostics画面はread-only。

行わない:

- Queue retry
- failed_jobs削除
- Webhook redelivery
- GitHub App permission変更
- Repository installation
- Task / Evidence変更
- Return Sync強制実行

運用操作を追加する場合は、
状態確認とmutationを分離して別Human Confirmationを設ける。

## Migration

V46.11単独のmigrationなし。

V46.10の:

`github_webhook_deliveries`

とLaravel既存:

- jobs
- failed_jobs

をreadする。

## Non-goals

- Render API process health取得
- GitHub App設定の自動変更
- secret表示
- failed job自動retry
- Webhook自動redelivery
- monitoring SaaS代替
- uptime SLA判定
