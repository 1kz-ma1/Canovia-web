# V46.6 Execution Result → GitHub Review Handoff

## Goal

Execution Orchestrationで作った指示と、担当者 / AIが実際に作った成果を分離したまま、
成果をGitHubへ安全に返す。

```text
Execution Request
      ↓
Execution Packet
      ↓
担当者 / AIが実行
      ↓
実際のfile content
      ↓
GitHub Change Candidate
      ↓
Human Confirmation
      ↓
GitHub App
  branch → commit → Pull Request
      ↓
Canovia「レビュー待ち」
```

Execution Packet自体をGitHubへ書き込まない。

## Core distinction

### Execution Packet

「何をどう進めるか」の実行指示。

- session projection
- Plan / Task / Dependency / Evidenceから導出
- actual code / file resultではない

### GitHub Change Candidate

「実際にRepositoryへ反映しようとしている内容」。

- target Repository
- target file path
- 完全なproposed file content
- commit message
- Pull Request title / body
- preview時点のfile SHA
- source Execution Packet hash
- source context fingerprint

Candidateを作っただけではGitHub writeを行わない。

## Candidate source boundary

V46.6のGitHub Change Candidateは、
現在のTaskに有効なExecution Packetが存在する場合だけ作れる。

Candidate prepare時に:

1. 現在Plan / Task Contextを再構築
2. Execution Packetのcontext_fingerprintと一致することを確認
3. Packet全体をcanonical JSON化してSHA-256 hashを作成
4. Candidateにpacket hashとcontext fingerprintを保持
5. GitHubから対象fileの現在状態をread-only取得

する。

Execution Packetがない場合、
External Promptだけがある場合、
Packet生成後にContextが変わっている場合はCandidateを作らない。

## Repository selection

反映先RepositoryはAIに選ばせない。

Plan内の:

- provider = github
- artifact_type = repository
- github_app_connection.status = connected

のRepositoryから人が選択する。

CandidateにはRepository Artifact ID / repo_full_name / URLを保持する。

confirm時にRepository Artifactが同じPlanに存在すること、
URLがpreview時から変わっていないことを再確認する。

## GitHub preview

`GitHubRepositoryWriter::previewFileChange` を追加する。

previewはGitHub App installation / permissionを確認したうえで:

- default branch
- file exists / new
- current file SHA
- current bytes
- proposed bytes

を取得する。

branch / commit / PRは作らない。

既存file contentをGitHub APIがbase64で返せる場合、
proposed contentと完全一致ならno-opとしてCandidateを作らない。

## Human confirmation

Candidate UIでは最低限:

- Repository
- file path
- new / update
- base branch
- size before / after
- PR title
- commit message
- optional review body
- proposed full file content

を表示する。

人が:

`確認してレビューに出す`

を押すまでremote writeしない。

Candidateはsession-scopedであり、
独立したcanonical DB Entityを追加しない。

実際のsource contentはsession backendへ平文保存せず、Laravel CryptでCandidate内だけ個別暗号化する。
画面表示 / confirm時にserver-sideで復号し、PR Artifact / PlanActivity / Repository metadataへsource content本文を複製しない。

## Confirm-time revalidation

confirm時に以下を再確認する。

1. Candidate target Plan / Taskが現在routeと一致
2. current context fingerprintがCandidateと一致
3. active Execution Packet hashがCandidate source hashと一致
4. Repository Artifactが同じPlanに存在
5. Repository URLがpreview時と一致
6. DeveloperGithubWrite entitlementが現在もある
7. GitHub App installation / Contents write / Pull requests writeが現在も有効
8. target fileの現在SHAがpreview時と一致

どれかが変わればGitHub writeを止める。

## Optimistic concurrency

preview時:

```text
existing file SHA = abc123
```

confirm時:

```text
current file SHA = abc123
  → write可能

current file SHA = def456
  → STOP
```

new file candidateの場合も:

```text
preview: file absent
confirm: still absent
  → create可能

preview: file absent
confirm: file exists
  → STOP
```

これによりCandidate確認中に他担当が更新したfileを上書きしない。

V46.4のRepository Overviewから直接出すwrite formは従来互換のため
`enforceExpectedFileState=false` のまま。

Execution Handoffだけは必ずpreview → expected file state → confirmを通る。

## PR projection

GitHubでPull Request作成成功後のみPlanArtifactを作る。

```text
provider = github
artifact_type = link
github_workflow_state = review
github_write_origin
  source = execution_github_handoff
  repository_artifact_id
  target_task_id
  requested_by_user_id
  executed_by = github_app
  context_fingerprint
  base_branch
  branch
  file_path
  file_action
  commit_sha
```

PR Artifactは元Taskへ明示linkする。

Repository Rootの `github_last_write` にも同じsource / Task / PR要約を保持する。

## Progress / Evidence boundary

Pull Request作成だけでは:

- Task progressを変更しない
- Taskをdoneにしない
- Plan progressを変更しない
- TaskEvidenceを作らない

PRができたことと、
Taskの成功条件を満たしたことは別事実。

次段階でGitHub review / CI / merge等のauthoritative eventを取得し、
Task mappingを確認してEvidenceへ昇格させる。

## Orchestration result state

PR作成成功後、
既存 `execution_orchestration.{plan}.{task}` sessionへ
`github_handoff_result` の非secret要約だけを保持する。

- repo_full_name
- file_path
- branch
- commit_sha
- PR number / URL
- confirmed user / timestamp

これはUI continuity用でありcanonical GitHub stateではない。
Canonical remote stateはGitHub、Canovia側の永続参照はPlanArtifact。

## Failure behavior

### Candidate prepare failure

GitHub read / permission確認に失敗した場合:
- Candidateを確定しない
- branch / commit / PRを作らない

### Confirm failure before branch

context / packet / Repository / file SHAがstale:
- GitHub writeしない
- Candidateを残して理由を表示
- 現在状態から作り直す

### Remote partial failure

V46.4と同じ。
branch作成後にcommit / PRが失敗した場合はremote rollbackを自動実行しない。
branchが残る可能性を明示し、GitHubで確認する。

## UX language

GitHubを詳しく知らないユーザー向けのprimary wording:

- 実行結果をGitHub変更候補にする
- 変更候補を準備
- この内容をGitHubへ送りますか？
- 確認してレビューに出す

branch / commit / Pull Requestは処理内容の説明として補助表示する。

## Security

- AIはRepository IDを選択しない
- AI / Packetから自動writeしない
- Candidate作成はread-only
- confirmはexplicit POST
- GitHub App secret / tokenをCandidateへ保存しない
- staged source contentはsession内でも個別暗号化
- source content本文をArtifact / Activity metadataへ保存しない
- Repository URLをconfirm時に再確認
- context fingerprint / Packet hash / file SHAの3層stale guard
- default branch direct push / merge / force push / deleteは禁止のまま
- `.github/workflows/**` write禁止を継承

## Non-goals

- AI autonomous commit
- AI autonomous PR creation
- multi-file candidate
- patch/diff apply
- binary file
- merge
- review approval
- CI resultから自動Task完了
- automatic Evidence
- automatic Distribution target return
