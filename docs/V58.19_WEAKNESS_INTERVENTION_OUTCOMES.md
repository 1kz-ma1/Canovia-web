# V58.19 Weakness Intervention Outcome Observation

Status: implemented / validated  
Branch: `feature/v58-19-weakness-intervention-outcomes`

## 1. Goal

Observe whether focused weakness reinforcement is followed by better performance on the same Topic after the learner returns to broad Practice.

```text
broad Topic observations before reinforcement
→ focused weakness_reinforcement cycle
→ return to General / Exam Practice
→ broad Topic observations after reinforcement
→ before / after observation
```

This is observational. It does not claim that the intervention caused the change.

## 2. Scope

Measurement is limited to the same:
- Plan
- Task
- actor

It is not AP-only. Any Study Practice Task can participate when question metadata identifies the Topic.

Latest maximum 120 Attempts are scanned. If more history exists, `history_truncated=true` is exposed.

## 3. Reinforcement cycle

A cycle starts when saved Practice strategy is in `weakness_reinforcement` and the Topic appears in one of:

- `weakness_control.active_topics`
- `weakness_priority.primary_topics`
- `focus_topics`

The cycle ends when Practice returns to General Practice or Exam Mode.

A later reinforcement of the same Topic starts another cycle.

Study Analysis surfaces the latest cycle per Topic, up to five Topics.

## 4. Topic attribution

Question outcome is attributed only when the question itself carries identifiable Topic metadata.

Sources:

1. Attempt question `topic`
2. Attempt question `parent_topic`
3. Session selected question `selection_parent_topic`

A question can match both its subtopic and parent Topic.

`question_feedback.weakness_topics` alone is not used as the sole attribution source because correct answers usually do not carry a weakness label.

## 5. Baseline

Baseline uses up to the latest five mapped graded Topic questions before reinforcement, from non-reinforcement Practice.

Minimum usable baseline:

- at least 2 graded Topic questions
- at least 2 unique question references

Otherwise the cycle remains `waiting_baseline`.

## 6. Intervention context

Mapped Topic questions during weakness reinforcement are shown as intervention context.

They are not used as the after measurement.

This prevents a high score on a focused/easier drill from being interpreted as durable improvement.

## 7. After observation

After reinforcement ends, V58.19 uses up to the first five mapped Topic questions from General Practice or Exam Mode.

Minimum usable after sample:

- at least 2 graded Topic questions
- at least 2 unique question references

Until then the cycle remains `waiting_recheck`.

## 8. Correctness

Accepted feedback:

- correct
- partial
- incorrect

Observed correct rate:

`correct / total`

Partial is not counted as correct.

## 9. Outcome classification

Once both sides are measurable:

- delta >= +15pt → `improved_observation`
- delta <= -15pt → `regressed_observation`
- otherwise → `stable_observation`

The ±15pt band is intentionally wide because sample sizes are small.

Confidence:

- 2–3 questions on either side → `low`
- at least 4 questions on both sides → `moderate`

V58.19 does not emit `high` confidence.

## 10. In-progress boundary

If reinforcement is still active:

`status = reinforcing`

Even a 100% focused-reinforcement score does not produce an improvement observation until broad recheck exists.

## 11. Study Analysis surface

New registered surface:

`weakness_intervention_outcomes`

It shows:

- Topic
- cycle count
- status
- baseline broad correctness
- focused reinforcement context
- post-reinforcement broad correctness
- observed delta
- baseline / after question counts
- unique question counts
- targeted Session count
- confidence
- waiting reason or observation note

UI explicitly states that the result is a before/after observation, not causal proof.

## 12. Authority boundary

V58.19 does not modify:

- StudyWeaknessPrioritizationService
- StudyExamConvergencePolicyService
- StudyPracticeRoutingPolicyService
- V58.18 Plan-wide weakness handoff
- Study Method Recommendation
- Task progress / completion
- mastery

It does not automatically extend, suppress, or restart reinforcement.

## 13. Provider / storage boundary

DB-only, deterministic, read-only.

No extra AI/provider call.
No migration.
