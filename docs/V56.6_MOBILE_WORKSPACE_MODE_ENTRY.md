# V56.6 Mobile Workspace Mode Entry

## Goal

The Study / Development / Career Workspace implementations and Workspace Mode resolver already exist, but the mobile real-device shell must expose the switcher directly in the fixed top bar.

V56.6 is a shell-entry fix. It does not add a new Workspace, change Intelligence, or change Mode persistence.

## Problem

The mobile header showed the current app section such as Home together with guide / release notes / feedback / settings, while the Workspace Mode control was implemented as a separate row.

On the current real-device layout that entry was not reliably visible as part of the fixed top bar, making the existing Study and Development dedicated Workspaces effectively undiscoverable.

## Contract

Mobile:

- keep the existing fixed mobile header
- render the existing registry-driven Workspace Mode switcher inside the top header identity area
- use a compact trigger so header width does not grow materially
- keep the current section label (Home / Execution / Timeline etc.) unchanged
- open the same Workspace menu and submit to the same persistence endpoints
- remove the duplicate full-width mobile Mode row

Desktop:

- keep the existing second-row Workspace Mode Bar unchanged

Shared invariants:

- options continue to come only from `WorkspaceModeRegistry`
- resolver precedence is unchanged
- manual preference semantics are unchanged
- Study / Development / Career Workspace destinations are unchanged
- Focus Mode continues to hide the normal app shell
- Instant Navigation continues to synchronize every rendered `data-workspace-mode-bar`

## Mobile menu placement

The compact trigger lives inside the header identity block.

Its menu is viewport-bounded below the fixed top row and respects left/right safe-area insets. This avoids anchoring a full-width menu to the narrow trigger and prevents clipping on iPhone / PWA / WKWebView surfaces.
