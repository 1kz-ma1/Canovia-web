# V41.20 — Canovia Instant Navigation

## Goal

HomeのPlan切替のような「待たずに画面が変わる」体験を、
主要なCanovia画面へ段階的に拡張する。

対象:

- Home `/`
- Inbox `/inbox`
- Roadmap `/roadmap`
- Timeline `/timeline`
- Calendar `/calendar`

管理画面、AI演習、設定、Plan編集などはこのStepでは通常navigationを維持する。

## Architecture

全面SPA化はしない。

Laravelを引き続きserver-side source of truthとし、
共通Shellだけブラウザに残してPage領域を差し替える。

Hard load:

`Laravel full HTML -> Canovia Shell + Page`

Core navigation:

`tap -> in-memory cached Pageを即描画 -> history.pushState -> Laravelをbackground revalidate`

Cache miss:

`tap -> Laravel GET -> Page描画`

cache miss時だけ従来のloading overlayを120ms後に表示する。

## Stable shell

`layouts.app` に以下の境界を追加した。

- `data-canovia-main`
- `data-canovia-page`
- `data-canovia-companion-slot`
- `data-mobile-section-label`
- `data-canovia-nav-key`

Page領域には:

- flash status
- guest protection
- sync status
- page content
- offline snapshot

を含める。

Companion entryはPageとは別slotとして同期し、
Roadmap等で現在Contextが変わっても古いentry contextを残さない。

## Prefetch

Core pageを開いた後、主要nav destinationを1件ずつbackground prefetchする。

- Save Data時は自動prefetchしない
- 2G相当では自動prefetchしない
- pointer / focus / touch intentでもprefetch可能
- 同一URLの重複fetchはinflight mapで抑止
- cacheはmemory only

ユーザー固有HTMLをlocalStorage / IndexedDBへ永続保存しない。

## Human-action boundary / analytics

Prefetchは実際の閲覧ではない。

`X-Canovia-Instant-Navigation: prefetch` を付与し、Homeではprefetch時:

- DashboardViewedを記録しない
- RecommendationShownを記録しない
- UserStateSnapshotを書き込まない

実際にcached pageへ移動した後、
`X-Canovia-Instant-Navigation: navigate` でbackground revalidateし、
実訪問として通常のserver-side処理を通す。

Performance logにも `instant_navigation=prefetch|navigate` を追加する。

## Dynamic lifecycle

Shellのglobal listenerは残し、Page swap後だけ:

`canovia:page-ready`

を発火する。

V41.20ではHomeとRoadmapのpage-specific interactionを再初期化する。

Home:

- Plan tab
- task view event
- navigation context
- dashboard idle signal
- current tab state restoration

Roadmap:

- map/list view
- map stop detail
- plan pager swipe / keyboard
- overview action
- mobile supporting-link density

offline snapshotもswap後に再保存する。

## History

`history.pushState` と `popstate` に対応する。

ブラウザBack/ForwardでもHard reloadせず、
memory cacheがあればPageを即復元する。

## Correctness boundaries

- POST / mutationはinterceptしない
- non-core page navigationは通常browser navigation
- external link / download / new tabはinterceptしない
- core pageでもcache miss時は通常のloading feedbackを残す
- fetch/parse失敗時は `window.location.assign` へfail open
- auth redirect等でcore responseでなくなった場合もfull navigationへfallback

## Current limitation

V41.20はFull HTMLをbackground fetchして必要Page部分を抽出するPhase 1。

そのためLaravel側のPage生成コスト自体は残る。
ただしユーザーはcached Pageを先に見るため、server待ち時間をnavigation latencyから分離できる。

次段階では必要に応じて:

- Core fragment endpoint
- shared core context payload
- server queryの共通化
- stale pageのsilent refresh

へ進められる。
