# V58.37 Repository Structure Breadth Signal

## Goal

既存のGitHub Repository snapshotから、Repositoryの構造が複数の観測可能な側面を持つ事実をDevelopment Personalization Evidenceとして利用する。

これはcomplexity / quality / seniorityのscoreではない。

## Source

既存 `metadata.github_repository_snapshot` のみを使う。追加GitHub API requestは行わない。

Observed dimensions:

- repository.language is present
- branches >= 2
- open pull requests >= 1
- open issues >= 1
- recent Actions runs >= 1

各Repositoryについて観測されたdimension数を数え、connected Development Repositoryの最大値を利用する。

## Evidence

```text
repository_structure_breadth >= 3
-> repository_structure_breadth_3_plus
```

## Signal policy

Breadth evidence単独はsignal strength 2まで。

strength 3へ寄与する場合はrecent PR / Commit observations >= 2も必要。

Repository snapshotだけでhigh confidenceへ昇格しない。

## Living Profile

```text
observed_context.development_behavior.repository_structure_breadth
```

へ0..5の集約値を保存する。

## Trust boundary

Breadthは以下を意味しない:

- user authorship
- code quality
- repository difficulty
- professional experience
- seniority
- experience level

変更しない:

- self-reported experience
- Guidance Level
- Plan / Task
- confirmation requirement
- V58.32 dismiss/reopen semantics
- V58.35 confidence calibration

## Privacy / cost

既存snapshotだけを利用し、新規remote fetchを追加しない。
repository contentやfree textをLiving Profileへ複製しない。

## Migration

None.
