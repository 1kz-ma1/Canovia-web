# V58.76 — Quiet, once-only Plan Draft Spotlight

## CURRENT behavior
- Owner of a Plan with a **current, proposed, 3-step** action draft gets a
  compact guide on Plan detail. A merely proposed one-line Draft is not
  described as a completed 3-step plan. Drafts with stale candidate,
  domain, or source revision do not trigger the guide.
- The guide is an inline, non-modal section, **not** a toast or blocking
  overlay. It does not interfere with any current Task execution.
- Two explicit POST actions: “review proposal” opens the existing owner
  Draft page, “dismiss” returns to the Plan. Both acknowledge the guide.
  Just viewing/reloading the Plan performs **no write**.
- One per Plan lifetime: `plans.action_draft_spotlight_acknowledged_at`.
  Server-side persistence means opening iOS WKWebView, PWA and desktop
  does not reset an acknowledged guide. Later Drafts do not repeatedly
  spotlight the same Plan.
- The action-drafts navigation link on Plan detail stays available
  indefinitely, so a dismissed guide never hides access to the proposal.
- Owner-only projection: collaborators and public visitors neither see
  the private proposal status nor acknowledge the guide.
- Motion is a one-time neutral outline for 850ms, entirely absent for
  prefers-reduced-motion. Text/buttons remain usable without animation.
- No new external APIs, recurring notifications, AI inference, source
  data mutation or automatic Task acceptance. Existing form CSRF and
  throttle apply; repeated acknowledgement is inert.

## Deferred
Cross-Plan notification inbox / telemetry and redesign of home entry are
deliberately outside this unobtrusive first slice. P1.2 optional bounded AI
and richer branching remain follow-up work. Browser/PWA/WKWebView E2E and
Render production deployment are not verified by GitHub CI.
