# V47.0 Execution Orchestration Layer

## Goal

CanoviaがTaskを単独で推薦するだけでなく、Plan全体のDependency・現在状態・Evidence・制約を保ったまま、

> 今このExecution Nodeへ何をさせるべきか

を判断できる最小基盤を追加する。

HINANEXのA〜E担当は実証ケースだが、Coreは開発用途に限定しない。

## Architectural decision

Execution Packetは新しいTaskでも永続Entityでもない。

```text
Plan / Task / Dependency / Context / Evidence
                    ↓
ExecutionOrchestrationContextService
                    ↓
deterministic boundary
                    ↓
ExecutionPacketService
                    ↓
Native AI or external-AI handoff
                    ↓
ephemeral Execution Packet
```

Packetはsession上の表示状態としてのみ保持する。
DBへ保存せず、TaskをSource of Truthとする。

Task / Planの変更は既存のPreview / Confirm / Apply経路へ戻す。

## Multiple dependency foundation

従来の `tasks.depends_on_task_id` は1件しか表現できなかった。

V47.0では `task_dependencies` を追加する。

- task_id
- prerequisite_task_id
- unique(task_id, prerequisite_task_id)

既存 `depends_on_task_id` はrolling deploy / legacy import互換のため残し、
`TaskDependencyService` が最初のDependencyをmirrorする。

Canonical graphはpivot。

Safety:

- 自己依存禁止
- cross-plan dependency禁止
- cycle禁止
- duplicateは正規化
- Recommendation / Dashboard / Roadmap / Study progressionは全Dependency完了を要求

## Orchestration Context

`ExecutionOrchestrationContextService` は既存 `CoreContextService` を利用して以下を集約する。

- Plan / Goal Context
- selected Task
- dependencies / blockers / dependents
- available Resource / Artifact
- current active Tasks
- protected scope
- confirmed constraints
- known unknowns
- recent Evidence
- recent results
- existing personalization signals

Contextには決定論的な `context_fingerprint` を付ける。

時刻はfingerprintへ含めない。

Task / Dependency / Evidence等の意味のある状態が変わればfingerprintが変わり、
既存Packetをstaleとして表示できる。

## Dependency state

V47.0のdeterministic stateは:

- ready
- blocked

のみ。

`blocked` をTask statusとして保存しない。

AIはblocked Taskについて:

- prepare
- coordinate
- clarify
- wait

などを選べる。

未完了Dependencyの成果が存在すると仮定して本作業を開始してはいけない。
confirmed inputだけで安全に進められるfixture / validation foundation / preparation等は先行可能。

## Execution Packet

Generic schema:

- summary
- execution_mode
- current_situation
- role
- objective
- reason
- actions
- inputs
- outputs
- dependencies
- assumptions
- do_not_touch
- completion_criteria
- confirmation_required
- next_phase

GitHub / PR / branch等はCore fieldにしない。
Contextに存在する場合だけ通常の文字列としてPacketへ現れる。

## Actor

V47.0では独立PlanActor modelを追加しない。

generation request上でのみ:

- human
- ai
- human_ai
- external

を指定できる。

TaskとActorの1:N管理が必要になった段階でPlanActorを検討する。

## Native AI / Free boundary

External AI handoffはFree pathとして維持する。

```text
Canovia Context
  ↓
Prompt copy
  ↓
external AI
  ↓
Execution Packet JSON
  ↓
Canovia import
```

Native AI direct generationは既存 `AutomaticAiExecution` entitlementを利用する。

新しい課金境界は作らない。

## Map integration

L3 Current Task / Next Task Context Surfaceから:

`今やることを生成`

へ遷移できる。

Next Taskが現在Task以外の未完了Dependencyを持つ場合:

- 前提待ち件数
- 先行可能作業を確認できること
- 直近の未完了Dependency Node（最大3件）

をSurface / L3 Mapへ投影する。

現在Taskを待つことは通常のsequenceとして扱い、追加Blocker件数には含めない。これにより既存のCurrent → Next文法を維持しながら、D待ちのCのような横断Dependencyだけを可視化する。

Map自体はmutationしない。

## Living Reevaluation

既存原則を維持する。

```text
canonical mutation
      ↓
Plan / Task / Evidence
      ↓
Map Projection / Orchestration Context
      ↓
projection_key / context_fingerprint
      ↓
reevaluation
```

Polling / WebSocket / Packet自動mutationは追加しない。

## Return flow

Packet完了後は既存機能へ戻す。

- Plan / Task変更 → Plan Review Assistant
- Artifact / File / URL → Plan Artifact
- Evidence / 実績 → 既存Evidence / Review flow

PacketからTaskを自動大量生成しない。

## Non-goals

- Agent framework
- autonomous multi-agent execution
- GitHub-specific Core model
- durable Execution Packet table
- Taskとの二重管理
- Map全面再設計
- AIによる自動Plan mutation
- PlanActor model
