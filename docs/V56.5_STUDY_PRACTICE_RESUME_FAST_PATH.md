# V56.5 Study Practice Resume Fast Path

## Goal

Separate "create a new practice set" from "continue an existing practice set" in both controller responsibility and UI.

The intended flow is:

```text
new practice
→ Study Practice setup
→ Canovia Strategy / Provider selection
→ prepare
→ answering

existing unfinished practice
→ Study Practice entry
→ resume route
→ restore existing StudyPracticeSession snapshot
→ answering immediately
```

Resume must not re-run question generation, Question Mix allocation, provider selection, or V56.4 routing.

## Problem

V40.7.1 already persists draft answers and can silently recover a durable StudyPracticeSession.

However the main Study Practice `show()` action still serves both purposes:

- new-practice setup
- unfinished-practice recovery

Even when an existing Session is being continued, `show()` still builds the same orchestration preview used for new generation, and the page renders the large Practice Strategy / Reliability / step-progress setup UI above the existing questions.

This makes resume feel like passing through question generation again even though no new questions should be generated.

## Responsibility split

### New practice

```text
GET study-practice
→ no resumable READY / IN_PROGRESS Session
→ previewHandoff()
→ setup UI
→ prepare/import
→ one-request freshly-prepared flash state
→ canonical show URL
→ normal answering UI
```

A Session that was created in the immediately preceding prepare/import request is explicitly marked with transient flash state. It must not display resume continuity UI merely because its status is `ready`. The browser URL stays canonical; no internal mode query parameter is exposed.

### Resume

```text
GET study-practice
→ resumable READY / IN_PROGRESS Session exists
→ redirect to dedicated resume endpoint
→ restore questions_snapshot + draft_answers
→ redirect back with resume mode
→ render answering UI directly
```

The resume path uses the Session's stored:

- selection_context.strategy
- question_provider / mode
- provider_payload
- questions_snapshot
- draft_answers

It does not call `StudyPracticeOrchestrator::previewHandoff()`.

## Resumable Session

A Session is resumable as an answer Session only when:

- actor ownership matches
- Plan / Task matches
- status is `ready` or `in_progress`
- `questions_snapshot` is present and non-empty

`answered` and `assessed` continue using the existing V40.7.3 recovery flow rather than the answer-resume fast path.

`completed` and `abandoned` are never resumed.

## Route

Add:

```text
GET /plans/{plan}/tasks/{task}/study-practice/resume
plans.tasks.study_practice.resume
```

The normal Study Practice entry remains canonical. It automatically redirects to the resume route when a resumable Session exists.

This means existing links from Home / Plan / Workspace do not need to know Session state.

## UI

### Resume mode

Do not render the new-practice setup experience above the questions.

Instead render one compact continuity card:

```text
CONTINUE PRACTICE
<exercise title>
保存済みの回答を復元しました
answered / total
Session #
[Planへ戻る] [新しい演習を作る]
```

Then jump directly to `#practice-questions`.

The normal four-stage progress strip is hidden in resume mode because showing "問題準備 → 回答" recreates the generation mental model.

Inside the answer section:

- step badge becomes resume/continue semantics rather than "2"
- existing autosave remains unchanged
- all current draft values remain restored

### New-practice mode

Existing Strategy / Reliability / source-selection UI stays unchanged.

## New exercise from resume

"新しい演習を作る" uses the existing reset endpoint.

The current resumable Session becomes `abandoned`, browser state is cleared, and the user returns to new-practice setup.

No second active answer Session is created implicitly.

## Backend fast path

When the request is in explicit resume mode and a current StudyPracticeSession is present:

- do not call `previewHandoff()`
- use stored strategy
- use stored provider identity
- use stored provider generation payload only if needed for legacy evaluation handoff
- keep progression/reliability calculations that operate on the already-selected Session

This ensures reopening a Session cannot change:

- phase
- focus topics
- question allocation
- parent caps
- selected source
- selected questions

## Progress indicator

Resume UI may show:

```text
answered_question_count / total_question_count
```

A question counts as answered when at least one stored response field has a non-empty scalar value or a non-empty multiple-choice array.

This is display-only and does not replace final required-field validation.

## Compatibility

No database migration.

Keep:

- V40.7.1 local/server autosave
- V40.7.3 ANSWERED / ASSESSED recovery
- V40.7.4 result/evaluation stage model
- existing StudyPracticeSession statuses
- existing Home / Plan / Workspace Study Practice links
- current reset semantics

## Tests

At minimum:

1. normal Study Practice entry with READY/IN_PROGRESS Session redirects to resume
2. resume restores durable draft answers and opens answering UI
3. resume page omits new-practice Strategy / Reliability / four-step setup UI
4. resume page jumps to `practice-questions`
5. resume does not call `previewHandoff()`
6. READY Session with no answers is still resumable
7. ANSWERED / ASSESSED are not routed through answer-resume endpoint
8. abandoned/completed Sessions are ignored
9. another actor's Session cannot be resumed
10. reset from resume abandons current Session and returns to setup
11. existing V40.7.1 autosave/recovery tests remain green
12. V56.4 Study Routing tests remain green

## Definition of Done

V56.5 is complete when:

- reopening an unfinished answer Session goes directly to questions
- no question generation/selection preview runs during resume
- the learner does not see new-practice setup UI before the resumed questions
- existing draft answers are restored
- starting a new practice is an explicit destructive choice
- old evaluation/result recovery remains compatible
- no migration is required
- relevant regressions pass
