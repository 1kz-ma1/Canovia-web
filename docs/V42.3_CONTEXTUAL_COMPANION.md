# V42.3 Contextual Companion

## Goal

Canovia Mapで「今見ている世界」について、そのままCompanionと話せるようにする。

MapとCompanionを別々のUIとして扱わない。

\`\`\`
Map Focus
  ↓
Selected Node
  + 1-hop Surroundings
  + Primary Action
  ↓
Existing Companion Thread
\`\`\`

## Entry contract

ブラウザからCompanionへ送るMap固有情報は \`map_node_id\` だけ。

Nodeのlabel、周辺Node、Primary Action、Plan/Task IDをhidden inputへ詰め込まない。

POST後にMapProjectionServiceが最新Projectionを再構築し、指定Nodeが本当に現在のMapへ存在する場合だけContextを作る。

これにより:

- stale Map
- 改変されたPOST
- 他ユーザーのID
- Map上に存在しない古いNode

をAI Contextとして信用しない。

## Server Map Context

Companionへ渡すContext:

- projection_key
- selected_node
  - id
  - type
  - entity_id
  - label
  - subtitle
  - state
  - position_role
  - importance
- surrounding_nodes
  - relation
  - direction
  - node
- primary_action

surrounding_nodesは選択Nodeから直接つながる1-hopだけ。

## Thread continuity

Map専用Conversationを別に量産しない。

Canonical contextごとの既存threadを再利用する。

- Task / Tool / Evidence -> Task thread
- Plan / Goal -> Plan thread
- Inbox -> Inbox thread

再利用したthreadの \`context_scope.entry_type\` は \`map\` へ更新し、その時見ていたMap Contextを保存する。

## UI

MapのContextual Classic Surface内に:

\`✦ このContextについて相談\`

を追加する。

Map画面では従来のglobal floating Companion launcherを隠す。
選択ContextなしのDetached Companionを避けるため。

Companion画面のCONTEXT INHERITEDには:

- FocusしていたNode
- Node subtitle
- 直接つながる周辺Node

を表示する。

## AI prompt

\`entry.type=map\` の時:

- selected_node = 今Focusしている対象
- surrounding_nodes = 直接関係する1-hop
- primary_action = Map全体の現在Action

として扱う。

Mapに表示されていない関係を「見えている」と推測しない。

## Mutation boundary

MapからCompanionへ入っても従来と同じCandidate制御を使う。

AIが直接:

- Task
- Plan
- Evidence
- Inbox

を書き換えることはできない。

Mutation CandidateのtargetはMap POST内のIDではなく、CompanionEntryServiceがサーバー側で解決したPlan / Task Contextから決める。

## Non-goals

- Map内チャットUI
- Nodeごとの独立AI人格
- 周辺全GraphのPrompt投入
- クライアント生成Contextの信用
- MapからAIによる直接mutation
