# V52.1 iOS Shell Prototype

## Goal

V52.0で固定したWeb / PWA / Native境界を、実際のiOS shell sourceへ接続する。

V52.1はApp Store production buildではなく、CanoviaのWeb coreがSwiftUI + WKWebView内で成立することを確認するprototype。

## Source layout

`ios/CanoviaNative`

- `project.yml`: XcodeGen source of truth
- `Resources/Info.plist`
- `Sources/CanoviaNativeApp.swift`
- `Sources/CanoviaRootView.swift`
- `Sources/CanoviaWebView.swift`
- `Sources/CanoviaWebViewModel.swift`
- `Sources/CanoviaEnvironment.swift`
- `Sources/WeakScriptMessageHandler.swift`
- `Sources/SafariView.swift`

Generated `.xcodeproj` はcommitしない。

## Runtime

Initial URL:

`https://pacekeeper-d3mm.onrender.com`

WKWebView:

- persistent `WKWebsiteDataStore.default()`
- one long-lived WKWebView instance
- `allowsBackForwardNavigationGestures=true`
- interactive keyboard dismissal
- content inset adjustment disabled so Web safe-area contractがsource of truth

## Native identification

WKWebView configuration:

`applicationNameForUserAgent = CanoviaNative/iOS/<version>`

document-start injection:

```js
window.__CANOVIA_NATIVE__ = {
  platform: "ios",
  bridgeVersion: 1,
  appVersion: "..."
}
```

Web側V52.0 runtime detectionは両方を受け付ける。

## Bridge

WKUserContentControllerへweak proxy経由で:

`canovia`

handlerを登録する。

Native receives:

- ready
- navigationState
- openExternal
- fileInputRequested
- requestClose

Web commands:

- openPath
- back
- appBecameActive

Native shell側にPlan / Task / authのbusiness stateを持たない。

## Navigation

### Web history

WKWebViewのback-forward listを維持し:

`allowsBackForwardNavigationGestures=true`

によりiOS edge swipeをWeb historyへ直接接続する。

### Deep link prototype

custom scheme:

`canovia://open?path=/roadmap`

をInfo.plistへ登録する。

同時にCanovia production originのhttps URLもsame-origin pathへ正規化できる。

Nativeから任意cross-origin URLをWebViewへinjectしない。

Universal Links / Associated Domainsはprototype後のV52.2候補。

## External links

Web bridgeの `openExternal` を:

`SFSafariViewController`

で開く。

Web側V52.0 contractによりsame-origin target=_blankはcurrent WKWebViewへ残る。

## Session

Native側でtoken storageやcookie copyは行わない。

`WKWebsiteDataStore.default()`

内のLaravel session cookieをsource of truthにする。

Safari/PWAとWKWebViewは同じcookie jarであるとは仮定しないため、prototype初回はNative app内で一度loginする。

以後app再起動時もpersistent website data storeによりsession維持を確認する。

## File / Photo

HTML `input[type=file]` をそのままWKWebViewへ委譲する。

Web bridgeの `fileInputRequested` はV52.1ではinformational only。

Native custom camera/file pickerはまだ実装しない。

Info.plistにはprototype実機確認用として:

- NSCameraUsageDescription
- NSPhotoLibraryUsageDescription

を定義する。

## Project generation

XcodeGenを使用する。

```bash
cd ios/CanoviaNative
make project
open CanoviaNative.xcodeproj
```

generated projectはsource of truthではない。

## Signing boundary

repositoryへ:

- Development Team ID
- certificate
- provisioning profile
- production signing secret

をcommitしない。

prototype Bundle ID:

`app.canovia.prototype`

実機signing時にApple Developer Teamが所有するIDへ変更可能。
