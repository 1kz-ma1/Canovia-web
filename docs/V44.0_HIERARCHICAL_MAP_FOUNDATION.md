# V44.0 Hierarchical Map Foundation

## Goal

Canovia Mapを「現在おすすめされている1 Plan周辺のExecution Map」から、今後L0〜L3を持つ階層型Navigation Layerへ拡張できる構造へ変更する。

V44.0ではUIを変更しない。V43.5の表示・Focus・Companion・Living Reevaluation・Telemetry・Primary Action launch・非Primary Node direct navigationをそのまま維持し、内部責務だけを分離する。

## Core principle

Mapでは次を別の責務として扱う。

### Navigation Graph

「何が存在し、何につながっているか」を表す。

- Node existence
- semantic relation
- canonical destination
- Contextual Classic Surface
- entity identity

Navigation Graphは重要度、Glow、位置、Node sizeなどのAttentionを決めない。

### Attention State

「同じGraphの中で、今何を目立たせるか」を表す。

- importance
- state
- position_role
- size_weight
- projected position
- edge strength
- primary node
- primary launch

V44.0ではV43の見た目を完全維持するため、Attention presetはV43の値をそのまま使う。

将来はDashboard Guidance、importance、usage frequency、urgency、contextなどを入力としてAttentionを変化させる。

原則は以下。

> おすすめだからNodeが存在するのではない。おすすめだから目立つ。

## Map levels

`App\Enums\MapLevel`で階層境界を固定する。

- L0 / `l0`: Intent
- L1 / `l1`: Domain
- L2 / `l2`: Plan
- L3 / `l3`: Execution

V44.0で実際にprojectionするのはL3のみ。

L0〜L2は不完全なUIを先行公開せず、Projection boundaryだけ予約する。V44.1以降で各Level用Projectionを追加する。

## Service boundary

### MapProjectionService

Hierarchical MapのFacade。

- `build()` は後方互換のためL3 Executionを返す
- `project(Request, MapLevel)` がLevel-aware boundary
- Companionのserver-authoritative context再構築APIを維持

L0〜L2のGraphロジックはここへ直接追加しない。

### MapExecutionContextService

V43互換のL3 scopeを解決する。

- Core Context
- editable Plans
- DashboardGuidanceService
- current Plan / Task
- recommended Tool
- next Task
- pending Inbox
- latest Evidence eager load

ここで決めるのは「現在どのExecution contextを開いているか」であり、Map Nodeの描画や位置ではない。

V44.0ではV43挙動維持のためcurrent execution scopeの選択に既存Dashboard Guidanceを使い続ける。

### ExecutionNavigationGraphService

L3 scope内のsemantic graphを構築する。

このServiceはDashboardGuidanceServiceを参照しない。

出力Nodeは次を持つ。

- id / type / entity_id
- eyebrow / label / subtitle
- available_action
- classic_surface
- internal attention_role

この段階では以下を持たない。

- importance
- state
- position_role
- size_weight
- position

Edgeもsemantic relationのみ作り、strengthは持たない。

### MapAttentionStateService

semantic graphへV43-compatible Attentionを重ねる。

Nodeへ:

- importance
- state
- position_role
- size_weight
- position

Edgeへ:

- strength

を与える。

internal attention_roleは最終Projectionへ漏らさない。

### ExecutionMapProjectionService

L3 composer。

1. Execution Contextをresolve
2. Navigation Graphをbuild
3. Attention Stateをapply
4. V43.5 direct navigationを付与
5. projection_keyを生成

最終的なProjection shapeはV43と同じ。

## L3 scope and global graph

V44.0の画面はV43互換のため、既存Guidanceが選んだcurrent execution scopeだけを表示する。

これは「おすすめ以外のEntityが存在しない」という意味ではない。

V44.1以降ではL0/L1/L2のNavigation Graph builderがCanovia全体のPlan / Feature / Shared context等を列挙し、RecommendationはAttentionやSatellite promotionとして作用させる。

L3はそのGlobal GraphからExecution contextへSemantic Zoomした局所Projectionとして扱う。

## Existing behavior kept intact

V44.0では以下を変更しない。

- Map Blade markup / visual layout
- Living Map JS
- Focus Mode
- one-hop layout
- Contextual Classic Surface
- Companion entry and authoritative context rebuild
- Living Reevaluation
- projection_key semantics
- Telemetry event types / safe metadata whitelist
- Primary Action direct launch
- non-Primary Focus / direct-open split
- Classic Home
- no-JS fallback

## Data / persistence boundary

追加しないもの:

- Graph DB
- Graph専用domain entity
- absolute node position persistence
- AI-generated layout
- user text in Telemetry

Node / Edge / positionは引き続きcanonical domain stateから都度投影する。

## Tests

V44.0では以下を固定する。

1. L0〜L3 enum contract
2. Execution Navigation GraphにはAttention fieldが存在しない
3. Attention適用後にV43のimportance / position / strengthが復元される
4. internal attention_roleはfinal projectionへ漏れない
5. /mapはV43互換のCurrent Task中心L3を表示する
6. 未実装Levelはpartial projectionを返さない
7. V42〜V43既存Map / Companion / Telemetry / Direct Navigation regressionを継続実行する
