# V53.1 State / Evidence Foundation

## Goal

V53.1 turns the V53.0 Intelligence contract into a usable State/Evidence pipeline without creating a second raw evidence system.

The first validation domain is Study.

```text
existing TaskEvidence
      ↓
TaskEvidenceAdapter
      ↓
EvidenceObservation
      ↓
StudyStateBuilder
      ↓
StateSnapshot
      ↓
StateSnapshotStore
      ↓
intelligence_state_snapshots
```

V53.1 still does not calculate Readiness or choose a Next Action. Those remain V53.2 responsibilities.

## Evidence boundary

Existing `TaskEvidence` remains the durable source for Task-linked observations.

V53.1 introduces `TaskEvidenceAdapter` to translate that existing record into the provider-neutral `EvidenceObservation` contract.

The adapter deliberately does not copy arbitrary `metadata`.

Only fields with known decision meaning cross the boundary.

Examples currently normalized:

- Study practice score / strengths / weaknesses / attempt references
- Study recall rating / interval
- Focus session duration / interruption
- GitHub PR CI state
- GitHub PR merge state
- GitHub review state
- Artifact provider/type/version/action
- Guided execution outcome rating

Unknown TaskEvidence types still retain their origin identity, source, type, occurrence time and confidence, but arbitrary metadata is not copied.

## Raw data exclusion

Intelligence records are not a mirror of provider or user raw payloads.

Do not copy the following into Intelligence State by default:

- Study question bodies
- Study answer bodies
- provider request / response payloads
- full prompts
- cookies / session / CSRF values
- private URLs
- arbitrary free-text metadata
- third-party raw webhook payloads

Raw source data remains in the source subsystem when it is needed for its own feature.

The Intelligence layer receives normalized decision facts only.

## Fingerprints

V53.1 introduces canonical fingerprints so later Decision/Outcome records can point to stable inputs.

### Canonical JSON

`CanonicalJson` recursively sorts associative keys while preserving list order.

This prevents semantically equivalent associative payloads from producing different hashes because of key ordering.

### Evidence fingerprint

`IntelligenceFingerprint::evidence()` hashes:

- origin reference
- source
- type
- occurred-at
- confidence
- normalized facts
- related references

`evidenceReference()` produces a stable trace reference:

```text
evidence:<source>:<sha256>
```

### State fingerprint

`state()` hashes semantic State content:

- domain
- scope
- metrics
- facts
- Evidence references

It intentionally excludes `capturedAt`.

If the same State is observed later, its semantic state fingerprint remains the same.

### Snapshot fingerprint

`snapshot()` hashes:

- semantic state fingerprint
- captured-at

This means the same State observed at a different time becomes a separate snapshot.

`stateReference()` produces:

```text
state:<domain>:<snapshot-sha256>
```

This split supports both:

- idempotent retries for the exact same snapshot
- time-series history when unchanged State is re-observed later

## Study State V1

`StudyStateBuilder` is the first concrete implementation of the V53 `StateBuilder` contract.

V53.1 only derives factual State, not Readiness.

Current metrics:

- Evidence count
- Practice attempt count
- Recall review count
- Latest practice score
- Average practice score
- Best practice score

Current facts:

- whether practice Evidence exists
- whether recall Evidence exists
- observed strengths
- observed weaknesses

Task progress is intentionally not imported into these State metrics.

A Task may be 95% complete while practice Evidence still shows weak mastery. V53 State must be able to represent that disagreement.

## Evidence trace inside State

Each State evidence reference contains:

```json
{
  "trace": "evidence:native:<sha256>",
  "origin": "task_evidence:<id>"
}
```

The hash pins the exact normalized Evidence version.

The origin preserves auditability back to the existing source record.

## Durable State storage

V53.1 adds `intelligence_state_snapshots`.

Stored fields:

- user_id (nullable)
- plan_id (nullable)
- domain
- scope_type
- scope_id
- state_fingerprint
- state_reference
- captured_at
- metrics
- facts
- evidence_references
- small controlled metadata

The store does not accept arbitrary metadata.

Only these metadata keys are currently persisted:

- schema_version
- builder
- builder_version

This prevents provider payloads from leaking into State through a convenience metadata field.

## Idempotency

`state_reference` is unique.

Persisting the exact same StateSnapshot twice returns the same stored row.

The same semantic State at a later captured time creates a new row with:

- same `state_fingerprint`
- different `state_reference`

## Scope

V53.1 supports generic State scopes through:

- `scope_type`
- `scope_id`

Study initially uses scopes such as:

```text
scope_type = plan
scope_id   = <plan id>
```

Later phases may introduce narrower subject/unit scopes without changing the persistence contract.

## Why no duplicate Evidence table

Canovia already has useful durable sources:

- TaskEvidence
- StudyPracticeAttempt
- StudyRecallReview
- GitHub return data
- GuidedExecution
- WorkSession

V53.1 normalizes those sources instead of copying every raw source event into a new generic table.

A future generic Evidence store should only be added if a real domain requires durable observations that do not naturally belong to an existing source system.

## Non-goals

V53.1 does not implement:

- exam Readiness score
- release Readiness score
- Decision selection
- OpenAI reasoning
- automatic replanning
- automatic Task mutation
- user-facing State UI
- test-range image/PDF capture
- GitHub webhook expansion
- model training

## Next

V53.2 should consume StateSnapshot and implement:

- explainable gaps
- deterministic Readiness primitives
- confidence-aware Readiness
- Decision candidate selection
- durable Decision trace suitable for later Outcome evaluation

Study remains the first validation domain before the same mechanism is extended to Development.


## Adaptive Context v0.5 / Phase 0 G1 — actor-bound Snapshot reads (2026-10-12)

The existing V53 evidence and Snapshot storage contract remains the source of truth.
For a **Plan-scoped read**, the supported service entry point is now:

```php
$store->latestForPlan($request, $plan, IntelligenceDomain::Study, 'study_plan');
```

`StateSnapshotStore::latest(domain, scopeType, scopeId)` (caller-selected scope with no actor authorization) is retired. The new reader first invokes `PlanOwnershipService::authorizeView()` against the current request actor; its query filters `plan_id`, `domain`, `scope_type`, and `scope_id == plan.id`. Callers cannot supply a foreign Plan's numeric ID as an unrestricted snapshot lookup. Existing domain Snapshot writers and V53 fingerprint semantics are unchanged.

`IntelligencePresentationHistoryService::forPlan()` and `IntelligenceStateChangeFeedbackService::latestForPlan()` likewise require the `Request` and check Plan view authorization internally before accessing persisted Plan intelligence. Study, Development, Career, Scope Capture, GitHub and Overview presentations pass the current request actor.

Explicit role semantics are unchanged: Plan owner and authorized collaborative viewer/editor can read; guest-owned Plans require their owner cookie; a foreign actor or a revoked member must not read. No new public/MCP endpoint is exposed.

During `persist()`, if an existing `state_reference` points to a different `user_id`, `plan_id` or scope, the service fails closed instead of returning that other actor's record. This guards reference reuse, but is **not** a substitute for actor-qualified Plan-free Snapshot identifiers: valid Plan-free activities remain on their existing `ExecutionActivity` source path, and cross-actor Plan-free Snapshot collision support is deferred to the separate G6/Fact lifecycle contract.

Negative acceptance coverage is recorded in `StateSnapshotActorIsolationG1Test` for A01/A02, including direct service access, team viewer and revocation, guest owner, Plan isolation and same-reference collision. CI passing is distinct from runtime production rollout or confirmation that every future Resolver/cached response is safe.


## Adaptive Context v0.5 Phase 0 / G3 slice 2 — V53 TaskEvidence freshness (2026-10-12)

**Verified dependency scope:** selected V53 `StateSnapshot` → `IntelligenceDecisionTrace` → `IntelligenceActionProjection` paths, where stored `evidence_references` identify `TaskEvidence`. This does **not** certify all Career capture/application fields, Plan/Task fields, provider privileges or independently copied external/AI responses.

Existing TaskEvidence is the authority; no duplicate raw evidence store is introduced.

- A new `StateSnapshotStore::persist()` materializes only normalized TaskEvidence fingerprint hashes in the existing Snapshot metadata (`evidence_signatures`), without copying question answers, prompts, private source text or provider payload.
- `IntelligenceEvidenceFreshnessGuard` checks that every referenced TaskEvidence ID still belongs to the same Plan. **Structured Study references** (`{trace,origin}`) must also match the current normalized `IntelligenceFingerprint::evidence` hash, including for pre-G3 rows.
- For newly persisted **plain-reference Development/Career** snapshots, the current normalized fingerprints must match `evidence_signatures`. Pre-G3 plain-reference rows lack this historical fingerprint; the compatibility gate can verify *existence and Plan ownership only*. These legacy rows require separate migration/re-materialization for full correction detection and cannot be claimed universally secure against edit.
- Fail-closed query and mapping errors invalidate reads. The authorized `StateSnapshotStore::latestForPlan()` returns **null rather than an older fallback** when the newest referenced Evidence is stale.
- `IntelligencePresentationHistoryService::forPlan()` masks invalid State/Decision/Action objects on read after the existing Plan authorization check. `IntelligenceStateChangeFeedbackService::latestForPlan()` returns null if either comparison snapshot is invalid. `ActionProjectionStore::latestActiveForPlan()` does not return an active projection whose linked trace is stale. Historical DB rows remain intact for audit, but are no longer presented by these paths.
- **No automatic retry/recompute, Task completion, Action acceptance or history rewriting** occurs during these GET reads. Reassessment must explicitly use current source evidence.

**Limitations:** A newly added/unreferenced piece of evidence, a modified Task, a Career application/capture, authorization to the upstream GitHub repository, and disconnected provider evidence are not proven fresh by this reference-specific check. Source reads and downstream disclosures are not yet locked in a common transaction; queued recalculations and subsequent independent consumers need their own authorization/source-revision gate. V53 historical legacy string-only references cannot retrospectively reconstruct a source content fingerprint from an ID. All these items remain G3 follow-up; this PR is not a general Context Resolver release.

**Acceptance:** synthetic record after deletion/correction/reassignment, strong Study `trace` hashing, Development string metadata signing and stale Decision/Action/feedback masking, historical record retention, actor isolation regressions and GitHub/MCP read boundaries. CI results are distinct from production deploy/database inspection and user device verification.
