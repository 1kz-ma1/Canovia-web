# V54.1 Fixed Workspace Mode Bar

## Goal

V54.1 makes the active Workspace visible and switchable from the global Canovia app shell.

The control is intentionally a dropdown rather than a horizontal tab strip so future Workspace Modes can be added without consuming header width.

Current public modes remain:

- Overview
- Study
- Development

The fixed bar is navigation, not a Plan filter and not a billing selector.

## Placement

The Mode Bar is rendered inside the existing sticky app header as a second, narrow row.

Desktop:

```text
Canovia   primary navigation   utilities
────────────────────────────────────────
WORKSPACE   [ Study ▾ ]
```

Mobile:

```text
Canovia / current section / utilities
──────────────────────────────────────
WORKSPACE   [ Study ▾ ]
```

Because the bar is inside the sticky header, it remains visible while scrolling without introducing a second independently sticky element that can overlap the existing shell.

Focus Mode intentionally hides the entire normal app header, including the Workspace Mode Bar.

## Registry-driven dropdown

The dropdown options come only from `WorkspaceModeRegistry`.

Blade does not hard-code the list of public Modes.

Each option renders:

- semantic icon
- Mode label
- Mode description
- current-state marker

The current Mode is exposed through stable data attributes:

- `data-workspace-mode-bar`
- `data-current-workspace-mode`
- `data-workspace-mode-source`
- `data-workspace-mode-option`
- `data-workspace-mode-label`

These attributes support testing, Instant Navigation synchronization and later telemetry.

## Mode entry routing

Public entry route:

`GET /workspace/{workspaceMode}`

handled by:

`WorkspaceModeController::enter`

V54.1 behavior:

### Overview

Redirect to Canovia Home.

### Study

If the actor has an accessible Study Plan, select the most relevant existing Study Plan and redirect to:

`plans.study_scope.index`

Selection is deterministic:

1. Plan priority
2. nearest deadline
3. stable Plan ID

If there is no Study Plan, redirect to Home with an ephemeral `workspace_mode=study` context and a status message.

### Development

If the actor has an accessible Development Plan, redirect to:

`github_workflow.index?plan_id=...`

using the same deterministic Plan selection.

If there is no Development Plan, redirect to Home with an ephemeral `workspace_mode=development` context and a status message.

This gives V54.1 a meaningful switch destination without prematurely implementing the full Study/Development Workspace Homes that belong to V54.3/V54.4.

## Access boundary

Mode entry uses `PlanOwnershipService::ownedPlans()`.

This keeps:

- owned Plans
- accessible collaborative Plans
- guest-owned Plans

inside the same existing authorization model.

The Mode switcher does not bypass downstream page authorization.

## Ephemeral explicit mode

V54.1 adds an optional query context:

`?workspace_mode=study`

or:

`?workspace_mode=development`

The resolver treats a valid public query Mode as `WorkspaceModeSource::Explicit`.

This exists only for the current request.

It is not persisted to:

- User
- DB
- localStorage
- cookie
- session preference

A later request without the query returns to normal route/profile inference.

Persistent manual preference remains V54.2.

## Resolver precedence in V54.1

```text
explicit caller Mode
→ valid ephemeral workspace_mode query
→ strong domain route hint
→ current Plan profile
→ Overview
```

Only values registered as public Workspace Modes are accepted.

For example, `career` remains a valid Plan profile but is not a public Workspace Mode, so `/workspace/career` returns 404.

## Instant Navigation synchronization

Canovia's core surfaces can use Instant Navigation without replacing the global app shell.

Therefore V54.1 adds Workspace metadata to instant fragments:

```json
{
  "workspaceMode": {
    "key": "study",
    "label": "学習",
    "source": "..."
  }
}
```

`instant-navigation.mjs` synchronizes the retained Mode Bar after page replacement.

It updates atomically:

- body current Mode
- page current Mode
- bar current Mode
- current label
- current icon
- active dropdown option
- current marker
- dropdown open state

This prevents stale header state after an Instant Navigation transition.

## Responsive design

The Mode Bar uses one shared semantic partial:

`resources/views/layouts/partials/workspace-mode-bar.blade.php`

Desktop and mobile shells both render the same partial.

The dropdown itself uses native `<details>/<summary>` semantics so the core switch remains usable even without custom JavaScript.

Mobile adjustments:

- full-width-friendly trigger
- larger touch targets
- menu constrained to viewport width
- header scroll offset increased to include the Mode Bar

The existing mobile safe-area behavior remains on the parent sticky header.

## Visual identity

Modes share the Canovia shell and typography.

Only a restrained accent changes by Mode.

This is deliberate:

> different Workspace context, same Canovia product.

The UI must not look like three unrelated applications.

## V54.1 non-goals

V54.1 does not:

- persist selected Mode
- add a User preference column
- add localStorage Mode persistence
- implement a full Study Workspace Home
- implement a full Development Workspace Home
- redesign Overview
- change V53 Intelligence calculations
- change Plan category
- change Task progress
- introduce AI traffic
- introduce Mode-specific billing

## Next: V54.2 Mode Context & Persistence

V54.2 should add stable manual selection semantics:

```text
user manual preference
> unambiguous deep-link / current Plan context where appropriate
> automatic inference
> Overview fallback
```

The exact precedence must avoid surprising oscillation.

Persistence should support:

- authenticated account preference
- guest fallback
- explicit reset to automatic behavior
- deep links that remain semantically correct
- no duplication of Workspace definitions outside the registry
