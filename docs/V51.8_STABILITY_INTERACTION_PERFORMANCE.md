# V51.8 Stability & Interaction Performance

## 目的

iOSアプリ化へ進む前に、Web/PWA上の操作遅延を「体感」ではなくクライアント/サーバー両側の計測で分解し、明確な無駄を削る。

V51.8は新しいProduct Surfaceを追加しない。

対象:

- Core Surface間のタップ→操作可能までの時間
- Instant Navigationのcache / prefetch / network差
- HTML fetch / parse / DOM replace / Surface mount
- main thread long task
- 初回load
- 不要なtimer / background work
- revalidate / prefetchの競合

## 1. Client Performance Telemetry

新規endpoint:

`POST /performance/client`

DBへ保存しない。

`canovia.client_performance` structured logへ安全な数値情報だけを送る。

送信可能event:

- initial_load
- instant_navigation
- surface_mount

保持しない:

- user入力
- Task title
- Plan title
- query string
- arbitrary metadata

環境情報:

- surface: web / pwa
- device: mobile / desktop
- platform: ios / android / other
- route
- pathname

metrics:

- total_ms
- wait_ms
- fetch_ms
- parse_ms
- render_ms
- mount_ms
- frame_ready_ms
- response_bytes
- long_task_count
- long_task_ms
- layout_shift

## 2. Instant Navigation Measurement

Instant Navigation runtimeは各navigationについて:

1. navigation start
2. cache / prefetch / network source
3. wait
4. render
5. `canovia:page-ready` Surface mount
6. next two animation frames

を計測する。

最終的に `canovia:instant-navigation-performance` eventをdispatchする。

## 3. Surface Mount Measurement

`initializeInstantCorePage()` の同期mount時間を計測し:

`canovia:surface-mounted`

をdispatchする。

Instant Navigation runtimeはこのeventを次のnavigation telemetryへ統合する。

## 4. Long Task / Layout Shift

PerformanceObserverが利用可能なブラウザでは:

- longtask
- layout-shift

をリングバッファへ保存する。

各navigation window内の合計だけを送る。

未対応Safariでは値を0として正常動作する。

## 5. Work Timer Ticker

現在の全page共通1秒intervalを廃止する。

Tickerは次の場合だけ動く:

- `[data-work-timer]` が存在
- documentがvisible

以下ではintervalを停止する:

- timer要素なし
- hidden
- Instant NavigationでtimerのないSurfaceへ移動

これによりHome / Constellation / Execution / Timeline等で毎秒DOM queryを行わない。

## 6. Deferred Offline Snapshot

Instant Navigation直後のIndexedDB snapshot保存を同期mount直後に開始しない。

- requestIdleCallback
- fallback timeout

へ移し、次の入力と競合しない。

新しいnavigationが来た場合、未実行snapshot taskは置換する。

## 7. Revalidate Scheduling

cached / prefetched fragment表示後のnavigate revalidateは必要なserver-side visit semanticsを維持する。

ただしrender直後に即開始せずidleへ送る。

目的:

- DOM replacement直後のnetwork / HTML parse競合を避ける
- Home side effect captureは維持
- cache refreshは維持

## 8. Dashboard Overview Fit

Roadmap overviewが存在しないSurfaceでは2回目のrequestAnimationFrame fitを予約しない。

## 9. Runtime Lifecycle

Performance instrumentation自体がボトルネックにならないよう:

- no DB write
- keepalive POST
- bounded metrics
- bounded long-task buffer
- unsupported PerformanceObserverはsilent fallback
- telemetry failureはUIへ影響させない

## 10. iOS Readiness Boundary

V51.8ではNative bridgeは作らない。

ただしtelemetryへplatform=iosを記録し、今後Web / PWA / iOS shellの差を比較可能にする。

V52 iOS Foundation前に、Web側のinteraction latency基準値を得る。

## Non-goals

- Native iOS shell
- WKWebView bridge
- App Store metadata
- server APM replacement
- persistent analytics database
- user behavior scoring
