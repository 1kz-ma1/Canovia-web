# V45.4 Map Runtime Performance

## Goal

Canovia Mapの操作感を改善するため、
Pan / Pinch / Focus / Resize時のRuntime costを下げる。

対象:

- pointermove hot path
- Map Scene transform writes
- viewport layout reads
- node position writes
- SVG edge writes
- Context template lookup
- active gesture paint cost

V45.4ではNavigation GraphやUI semanticsは変更しない。

## Principle

> 同じMapを、より少ないread/writeで動かす。

機能を削って速くするのではなく、
同一Frame内の重複処理をまとめる。

## Pointer event pipeline

V45.3以前:

```text
pointermove
  -> layout read
  -> transform calculation
  -> style write x
  -> style write y
  -> style write scale
  -> class write
  -> control write
```

高refresh-rate端末ではpointer eventが描画frameより多く発生し、
不要なDOM writeが発生する。

V45.4:

```text
pointermove
  -> JS state update
  -> schedule requestAnimationFrame
       ↓
  latest state only
       ↓
  one transform commit / frame
```

## createFrameBatcher

`createFrameBatcher()`を追加する。

契約:

- 同じframe内の複数scheduleを1回へcoalesce
- 最後のvalueだけflush
- flushNowでpointerup等の最終stateを同期確定
- destroy時cancel可能
- requestAnimationFrame非対応環境では16ms timerへfallback

Map Runtime以外でも再利用可能な小さいprimitiveとする。

## Viewport geometry cache

Gesture中に`getBoundingClientRect()`を呼ばない。

Viewport geometryは:

- initial mount
- first pointerdown
- resize / orientation change
- pageshow
- double-tap zoom開始

でのみrefreshする。

cache:

- left
- top
- width
- height

pointermoveではcacheだけを利用する。

これによりPinch中のforced layout readを避ける。

## Transform write batching

Map SceneのPan / Zoomは1つのtransform propertyへまとめる。

```css
translate3d(x, y, 0) scale(s)
```

旧方式の:

- --map-pan-x
- --map-pan-y
- --map-view-scale

3 write / updateから、
1 transform write / animation frameへ変更する。

Map state自体はpointer eventごとにJS上で最新化するため、
次eventの計算は最新stateを使用できる。

## Render diff

### Map transform

前回commitと:

- x
- y
- scale

が同じならstyle.transformを書かない。

### View controls

以下の状態signatureが変わったときだけ更新する。

- min zoom reached
- max zoom reached
- view changed from origin

### Node base position

`x:y` signatureをnode objectへruntime cacheし、
同じ座標ならCSS custom propertyを書き直さない。

### SVG edges

各edgeへruntime-only cache:

- renderedVisibility
- renderedGeometry

を保持する。

visibilityが同じならclass toggleを行わない。

geometry:

```text
x1:y1:x2:y2
```

が同じなら4 SVG attributeを書き直さない。

これらruntime cacheはProjectionへ書き戻さない。

## Template lookup

Context Surface templateを毎回Array.findしない。

mount時に:

- templateByNodeId
- globalTemplateByDockId

Mapを構築する。

Node選択時はO(1) lookup。

## Active gesture paint mode

Gesture開始中のみ:

`is-map-gesture-active`

をMap Shellへ付与する。

Gesture中:

- Map Sceneにwill-change: transform
- Node shadowを簡略化
- Node/Glyph transition停止
- Edge shape-renderingをoptimizeSpeed

pointerup / cancel後:

- final pending frameをflush
- gesture classを解除
- V45.3の通常Visual Grammarへ復帰

will-changeを常時指定しないため、
不要なcompositor memory占有を避ける。

## CSS containment

Map Sceneへ:

`contain: layout paint`

を追加する。

Map Scene内部のlayout / paint影響が
Fullscreen ShellやTop Barへ伝播しにくくする。

## Focus / Semantic Zoom

変更しない:

- Desktop one-hop Focus
- Mobile stable selection
- Context Surface behavior
- Semantic Zoom
- Spatial Memory
- history state
- Living Reevaluation

Focus layoutが変化した場合のみNode / Edge差分がDOMへ反映される。

## Persistence

保存しない:

- viewport cache
- rendered transform signature
- edge geometry cache
- node layout cache
- RAF queue
- gesture performance class

すべてmount lifetime内のruntime state。

DB / sessionStorage / Projection Keyへ追加しない。

## Telemetry

V45.4ではperformance timingやgesture coordinateを
BehaviorEventへ追加しない。

既存Telemetry contractを維持する。

実際のperformance計測基盤が必要になった場合は、
user contentを含まない専用metricとして別versionで設計する。

## Compatibility

維持:

- V45.3 Node Visual Grammar
- V45.2 Fullscreen Map Shell
- V45.1 Pan / Pinch / Reset
- V45.0 Mobile Spatial Projection
- V44 hierarchy / Space Station / Satellites / Collaboration
- V42-V43 Focus / Context Surface / Telemetry
- Classic Home
- Instant Navigation

## Tests

JS:

- repeated schedule -> one frame
- latest payload wins
- flushNow commits once
- cancel drops pending work
- existing Pan / Zoom bounds
- existing Semantic / Focus tests

Feature:

- Projection semantics remain unchanged
- runtime cache fields do not appear in server graph
- Fullscreen / Gesture / Visual Grammar regressions

## Non-goals

V45.4では行わない:

- WebGL rendering
- Canvas rewrite
- virtualized graph
- worker-based layout
- persistent client graph cache
- AI layout
- server-side graph cache
- external performance analytics

Node数が大幅に増える段階で必要なら、
V46以降にviewport culling / graph virtualizationを検討する。

## Resulting runtime model

```text
Pointer Events
     ↓
JS Map State
     ↓
requestAnimationFrame batch
     ↓
single Scene transform write

Hierarchy / Focus change
     ↓
deterministic positions
     ↓
diff node coordinates
     ↓
diff edge geometry
```

操作頻度の高いPan / Pinchと、
頻度の低いGraph layout更新を明確に分離する。
