# V41.5 Canovia Economy Foundation

## Goal

V41.5 turns the V40.6 Entitlement boundary into a real product-grant foundation without implementing payment processing.

The economy rule is:

> Freeでも、自分で動けば目標へ到達できる。  
> 課金すると、整理・転記・解析・判断・自動化をCanoviaがより多く引き受ける。

This continues:

> 努力する権利には課金しない。努力を加速する価値に課金する。

## Product shape

```text
FREE
│
└─ PREMIUM CORE
      ├─ Study Pack
      ├─ Career Pack
      ├─ Developer Pack
      ├─ Creator Pack
      ├─ AI Capacity Boost
      └─ All Access
```

Billing, Entitlement and AI Capacity remain separate.

```text
Billing != Entitlement
Entitlement != AI Capacity
Pack ownership != unlimited AI
```

## Existing boundary kept

V41.5 does not replace `FeatureAccessService`.

```text
Product Grant
  -> Economy Catalog
  -> source-specific Product Grant resolvers
  -> FeatureAccessService
  -> Feature code
```

Feature code continues to ask only:

> May this actor use this FeatureKey?

Feature code does not know Product names, StoreKit, Stripe, prices or receipts.

## Economy Catalog

Canonical product keys are defined by `ProductKey` and `config/economy.php`.

- `premium_core`
- `study_pack`
- `career_pack`
- `developer_pack`
- `creator_pack`
- `all_access`
- `ai_capacity_boost`

Purpose Packs require Premium Core.

All Access expands to Premium Core plus the purpose Packs.

All Access does **not** include AI Capacity Boost.

Creator Pack currently has no runtime FeatureKey because its concrete workflow is not finalized.

## Product grants

Durable provider-neutral projection:

`user_product_grants`

Fields:

- user_id
- product_key
- source
- starts_at
- expires_at
- metadata

Allowed initial sources:

- manual
- subscription
- gift
- sponsor
- migration

This table is not billing storage.

Receipts, transaction payloads, prices and provider-specific identifiers must not be stored as FeatureAccess metadata.

Future StoreKit/Stripe adapters synchronize verified product state into this projection.

## Capability-level FeatureKeys

Existing Free behavior remains unchanged.

Existing Free keys:

- `ai_practice`
- `advanced_analytics`
- `question_pack`
- `project_artifact`
- `automatic_ai_execution`

New Pack capability keys start denied for Free users:

- `study_long_term_weakness_profile`
- `career_native_capture_analysis`
- `developer_github_evidence`
- `developer_github_write`

Mappings:

```text
Premium Core
  -> automatic_ai_execution

Study Pack
  -> study_long_term_weakness_profile

Career Pack
  -> career_native_capture_analysis

Developer Pack
  -> developer_github_evidence
  -> developer_github_write
```

The existing `automatic_ai_execution` key remains Free in V41.5 so current behavior is not reduced. It can become the Premium Native-AI gate when the actual Native path is introduced.

## Coin separation

`coin` is removed from `EntitlementSource` as a direct Feature unlock source.

Coin remains a separate future economy for:

- support
- Gift
- self-expression
- cosmetic presentation
- milestone celebration

If Coin later funds a Premium experience pass, runtime access must arrive through Gift/Product Grant semantics.

Coin must not directly alter `FeatureAccessService`.

## Product Grant Entitlement resolvers

Product Grant resolvers run with higher priority than Free while preserving the V40.6 rule that one resolver declares one `EntitlementSource`.

- `ProductGrantEntitlementResolver`: manual / subscription / migration -> Premium
- `GiftProductGrantEntitlementResolver`: Gift
- `SponsorProductGrantEntitlementResolver`: Sponsor

Each resolves active Product Grants and returns an ordinary `FeatureAccessDecision`.

Safe metadata:

- product_key
- effective_product_key
- product_grant_id
- grant_source

Grant sources map to runtime Entitlement sources:

- manual / subscription / migration -> premium
- gift -> gift
- sponsor -> sponsor

No billing payload is exposed.

## Grant activation

A grant is active when:

```text
starts_at is null OR starts_at <= now
AND
expires_at is null OR expires_at > now
```

Removing a grant immediately removes its Product access.

## AI Capacity

`AiCapacityService` is separate from Feature access.

Current policy tiers:

- standard
- boosted

AI Capacity Boost requires Premium Core and changes only AI capacity.

It does not grant Study/Career/Developer FeatureKeys.

Persistent token/cost metering remains deferred until the first real Native AI executor exists.

## Recommendation Engine v1

`EconomyRecommendationService` is deterministic.

It may use:

- Plan category/profile
- AI Practice attempts
- Career Capture
- completed Interview Review
- Project Artifact / GitHub Artifact

Rules:

- Free is a valid result.
- No Pack is recommended without a meaningful domain signal.
- Single-domain use does not recommend All Access.
- All Access requires meaningful Study + Career + Developer use in v1.
- No price/savings claim is produced before prices exist.
- Creator Pack is not recommended until concrete Creator capabilities exist.

The service optimizes fit and friction reduction, not revenue.

## Admin Economy Inspector

Internal route:

`/admin/economy`

It shows:

- selected user
- active Product Grants
- effective Products
- resolved FeatureKey access
- access source
- AI Capacity
- deterministic recommendation
- unused Pack disclosure

Admin may add/revoke development grants.

There is no public Pricing page or Paywall in V41.5.

## Free invariants

V41.5 does not gate:

- Goal
- Plan
- Task
- Roadmap / Next Action
- Evidence recording
- Progress understanding
- Reflection
- manual execution
- External AI interoperability
- AI Practice baseline
- Career manual capture / review
- Project Artifact manual linking
- V41.4 balanced Weakness Priority

Premium/Packs are reserved for automation, Native AI, automatic capture, cross-context analysis, longitudinal intelligence and external integrations.
