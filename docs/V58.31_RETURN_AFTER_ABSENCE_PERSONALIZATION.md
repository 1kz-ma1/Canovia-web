# V58.31 Return-after-Absence Personalization Trigger

## Goal

Living Profileへ「長期間利用後の復帰」をContext Refresh Triggerとして追加する。

目的:

> 古いContextを永久に新鮮なものとして扱わず、意味のある復帰時に再評価できるようにする。

V58.31は復帰したユーザーを再診断したり、Plan/Guidanceを自動変更する機能ではない。

## Source of truth

- `docs/CANOVIA_PERSONALIZATION_SPEC.md`
- `docs/V58.27_LIVING_PROFILE_FOUNDATION.md`
- `docs/V58.29_PLAN_LIFECYCLE_PERSONALIZATION.md`
- current tracked Home / Workspace entry routes

No migration is added.

## Presence Context

V58.31 uses account-scoped Personalization observed context:

```text
observed_context.presence
```

Fields:

```text
last_seen_at
previous_seen_at
last_return_after_absence_at
last_absence_days
last_absence_bucket
```

This avoids relying only on browser-scoped actor tokens.

## Baseline

If a Personalization Context exists but `presence.last_seen_at` does not:

```text
first tracked visit
→ set last_seen_at
→ no return-after-absence trigger
```

This is intentionally conservative.

V58.31 does not infer historical absence from incomplete pre-V58.31 telemetry.

## Daily update

Tracked surfaces already using `early_access.visit` provide the observation boundary:

- Home
- Overview Workspace
- Study top / workspace
- Development top / workspace
- Career workspace when available

On the first tracked GET of a new day:

```text
previous last_seen_at
→ previous_seen_at

now
→ last_seen_at
```

Same-day navigation does not update Context again.

## Prefetch boundary

Requests with:

```text
X-Canovia-Instant-Navigation: prefetch
```

do not update Presence and do not trigger a return refresh.

A browser prefetch is not considered a real return.

## Long absence threshold

Initial deterministic threshold:

```text
14 calendar days
```

Condition:

```text
current day - previous seen day >= 14
→ return_after_absence
```

This is an MVP product heuristic, not a universal behavioral truth.

Future versions may calibrate the threshold from evidence.

## Absence buckets

Observed Context stores exact day count for the user-specific state.

Telemetry uses a coarse bucket:

- `14_29`
- `30_59`
- `60_plus`

Full timestamps and exact absence days are not copied into Behavior Event metadata.

## Trigger

When threshold is met:

```text
presence updated
→ LivingProfile.refresh(
     trigger = return_after_absence
   )
```

Existing deterministic Living Profile rules are re-evaluated.

No new inference rule is introduced by V58.31.

## Same-day dedupe

After the first real return request:

```text
last_seen_at = today
```

Further tracked routes on the same day do nothing.

Therefore one long-absence return produces at most one V58.31 refresh.

## What does NOT change

V58.31 does not automatically modify:

- self-reported Context
- Guidance Level
- experience level
- Plan
- Task
- recommended Plan direction
- Entitlement
- Release Level

It only updates Presence observation and requests deterministic re-evaluation.

## No silent profile creation

If the authenticated user has no Personalization Context:

```text
tracked visit
→ no presence profile created
→ no return refresh
```

Users who skipped or never entered Personalization are not silently enrolled.

## Telemetry

Existing event:

- `context_refresh_triggered`

Metadata:

```text
trigger = return_after_absence
absence_bucket = 14_29 | 30_59 | 60_plus
```

No free text is recorded.

## Existing Early Access telemetry

`TrackEarlyAccessVisit` keeps its existing daily session telemetry behavior.

Ordering:

```text
ReturnAfterAbsencePersonalizationAdapter
↓
EarlyAccessTelemetryService::recordDailyVisit
↓
Controller
```

This ensures Presence is evaluated before today's daily visit event is recorded.

V58.31 Presence itself is account-scoped and does not use Early Access session events as its source of truth.

## Release boundary

Minimum:

```text
L1 Early Access Core
```

No new public route / migration.

Manual review:

- `return_after_absence_personalization`

Check:

- first tracked visit → baseline only
- <14 days → last seen update only
- >=14 days → one refresh
- same-day navigation → no duplicate
- prefetch → ignored
- self-reported Context preserved
- Guidance preserved
- no Personalization Context → no silent profile creation
- mobile / desktop

## Non-goals

Not implemented:

- forced re-onboarding
- periodic questionnaire
- Context expiry engine
- field-level freshness policy
- automatic Guidance reset
- automatic Plan replanning
- return Growth Experience UI
- push/email re-engagement
- AI inference
