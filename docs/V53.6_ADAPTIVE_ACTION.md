# V53.6 Adaptive Study Action

## Goal

V53.6 converts Study Intelligence into the smallest useful current Action.

```text
Confirmed Scope
+ Practice / Recall Evidence
        ↓
Study State
        ↓
Exam Readiness / Gap
        ↓
Decision
        ↓
Current Action
        ↓
execute
        ↓
Evidence
        ↓
State / Action refresh
```

Task is not the source of truth.

```text
Action = what Canovia currently believes is best
Task   = optional durable/executable projection of that Action
```

## Decision policy

`StudyAdaptiveDecisionEngine` ranks deterministic candidates.

Current candidate order:

1. `capture_scope`
2. `reduce_deadline_risk`
3. `establish_scope_baseline`
4. `reinforce_scope_mastery`
5. `verify_scope_retention`
6. `resolve_exam_date`
7. `maintain_readiness`
8. `continue_study`

The policy uses confirmed scope existence, per-scope remaining Study Units, observed/unobserved scope, Mastery, Retention, deadline pressure, exam-date conflict, and Exam Readiness.

Task progress is not used to determine Study truth.

## Scope targeting

The selected Decision may carry controlled target metadata:

- target_scope_item_id
- target_task_id
- subject
- unit
- remaining_unit
- mastery_score_percent
- retention_score_percent

Existing unfinished Tasks are considered execution candidates only when the same conservative scope matcher can associate them with the target scope. Completed/cancelled Tasks are never reused as current execution targets.

## Action generation

`StudyAdaptiveActionGenerator` converts the selected Decision into one primary `ActionProposal`.

Current Action kinds:

- `study_scope_capture`
- `study_deadline_recovery`
- `study_baseline_check`
- `study_mastery_reinforcement`
- `study_retention_check`
- `study_exam_date_review`
- `study_readiness_maintenance`
- `study_continue`

Each Action contains title, intent / why now, confidence, success signals, target scope / Task when known, and execution route kind.

V53.6 does not fabricate an estimated duration. `estimatedMinutes` remains null at the Intelligence Action level.

## Action persistence

V53.6 adds `intelligence_action_projections`.

An Action projection records Plan / user / domain / scope, exact linked Decision trace, semantic State fingerprint, semantic Action fingerprint, Action reference, kind / title / intent, confidence, success signals, controlled metadata, status, and optional projected Task.

Statuses:

- `active`
- `superseded`
- `dismissed`

Only one current active Action should exist for the same Plan/domain/scope.

```text
old active Action
→ superseded

new Action
→ active
```

## Semantic Action identity

Action history must not grow merely because the user reopened a page later.

```text
action_fingerprint
= semantic Action

action_reference
= semantic State fingerprint + semantic Action fingerprint
```

Therefore:

- same semantic State + same Action later => reuse current Action row
- different observed State snapshot but unchanged semantic State => Decision trace may advance, Action history does not duplicate
- changed State / changed Action => new Action projection

## Task projection boundary

V53.6 deliberately does not create a Task merely because an Action exists.

```text
Current Action
├─ suitable existing Task exists
│    → reuse Task
│
├─ Scope/date Action
│    → open Study Scope
│
└─ no suitable Task
     → user presses execute
     → create Task projection
```

Task creation is explicit/user-triggered.

New projected Tasks use progress=0, status=todo, estimated_minutes=0, remaining_minutes=0. Zero is intentional: V53.6 does not invent a duration to satisfy the legacy Task shape.

The Task description records that it came from an Intelligence Action and that Task progress is not Study State truth.

## Projection refresh

Creating a Task changes execution reality. Immediately after Task projection, Canovia refreshes State/Decision/Action so the current Action no longer says that a Task must be created.

```text
Action A: execute target scope; Task projection required
→ user executes
→ Task created
→ Action A superseded

Action B: same learning goal; matching Task now available
→ active
```

## Evidence-triggered refresh

The adaptive loop refreshes after factual Study changes:

- Study Scope confirmation
- Practice assessment Evidence
- Recall review Evidence

Those mutations remain the primary product operations. If Intelligence refresh fails, the primary user operation is not rolled back. Failure logging contains only controlled identifiers / exception class.

## Home integration

V53.6 begins staged migration of Home from Task-first to Action-first.

When the highest-priority current Plan is a Study Plan:

- Study Intelligence Action is shown first in NEXT ACTION
- same-Plan Task guidance is removed from the rail
- other Plan candidates remain visible
- the card shows Readiness / confidence
- `なぜこのAction？` exposes intent and Decision rationale
- if Task projection would be needed, the UI explains that it is created only after execution

A Study Plan with no Task can still own the Home Action when its Plan-level priority genuinely outranks the existing task-based primary Plan.

At V53.6 time, a Study Plan whose current Tasks were all completed did not receive a new Home Action.

V53.9 supersedes that temporary rule. Task completion is not Goal/Readiness completion, so current Task status no longer suppresses Intelligence for supported domains. A future explicit Plan-completion concept must be modeled independently from "all current Tasks are done."

Other domains continue to use existing task-based Home guidance until their domain Intelligence is implemented.

## Study Scope UX

Study Scope now shows current Action, why now, Readiness, Action confidence, execute CTA, and recent Action history.

History distinguishes current vs superseded / changed. The V53.5 readiness diagnostics remain available below it.

## Trust model

V53.6 improves trust through inspectability rather than by forcing the user to obey a hidden recommendation.

```text
current State
→ Readiness
→ Decision reason
→ Current Action
→ Action history
```

Task remains useful for durable execution, but it no longer represents Canovia's immutable plan.

## Privacy / persistence boundary

Action projection metadata is allowlisted.

It may contain policy / reason code, target scope / Task IDs, subject / unit, remaining unit, Mastery / Retention, Readiness, and deadline pressure.

It does not persist raw questions, raw answers, provider payloads, source documents, or arbitrary private free text.

## Deterministic policy

V53.6 Study Adaptive Action is deterministic.

OpenAI is not required for Gap ranking, Decision selection, Action generation, or Task projection decision.

The V53.3 Reasoning Router remains available as a future Decision boundary, but V53.6 does not add model traffic or cost by default.
