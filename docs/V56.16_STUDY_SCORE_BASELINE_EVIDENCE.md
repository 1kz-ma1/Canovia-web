# V56.16 Study Score / Baseline Evidence

## Goal

Store external learning scores as first-class Study Evidence without conflating them with Study Practice accuracy.

Examples:

- TOEIC 480 → target 600
- IELTS 5.5 → target 6.5
- school test previous score 62 → target 80
- mock / official score observations

Canonical separation:

```text
Study Practice score_percent
= accuracy inside a Canovia Practice set

StudyScoreObservation.score_value
= score on an external / declared score scale
```

These values are never converted into one another.

## Persistence

Add Plan-level `study_score_observations`.

Stored facts:

- Plan
- actor identity
- metric key / label
- score value
- scale min / max when known
- unit
- source kind / optional source label
- observed date
- bounded component scores when the score system supports them
- request UUID for idempotent capture

The observation is Plan-level because a TOEIC/IELTS/test score describes the learning goal's current position, not completion of one Task.

## Initial scale profiles

### TOEIC

- metric: `toeic_total`
- total range: 0–990
- integer step
- optional components:
  - Listening 0–495
  - Reading 0–495

### IELTS

- metric: `ielts_overall`
- range: 0–9
- 0.5 step
- optional components:
  - Listening
  - Reading
  - Writing
  - Speaking

### School test

- metric: `school_test_score`
- range: 0–100
- integer step

### Other score exams

Use a generic score metric.

Do not invent a scale conversion.

If a known bounded scale is not available, the score is stored as reported and no artificial 0–100 normalization is created.

## Source kinds

Initial source kinds:

- self_reported
- official_result
- mock_exam
- school_result
- imported

## State First integration

StudyWorkspaceStateResolver exposes:

- score_observation_count
- has_external_score_baseline
- latest_external_score
- external_score_history

An external score makes current position known.

For `score_exam` specifically:

```text
Practice history exists
+
no external score
≠ current exam score known
```

The Workspace therefore keeps asking for a current external score until a StudyScoreObservation exists.

## Score Exam Current State

Score Exam Current State shows distinct cards:

- CURRENT SCORE
- TARGET
- GAP
- PRACTICE ACCURACY

Practice Accuracy is explicitly labeled as a separate scale.

Example:

```text
CURRENT SCORE   480
TARGET          600
GAP             あと120
PRACTICE ACC.   84%
```

No statement implies that 84% converts to TOEIC 480.

## Missing-context behavior

Before a Score Exam baseline exists:

```text
CURRENT POSITION
現在スコアがまだ分かりません

[現在スコアを記録]
```

Primary CTA routes to score capture.

Question Practice remains available as a separate Study method, but it does not manufacture an external score.

## Capture UI

Add:

- GET `plans.study_scores.index`
- POST `plans.study_scores.store`
- DELETE `plans.study_scores.destroy`

The page shows:

- score profile / target
- latest observation
- history
- source + observed date
- component inputs when supported
- add and delete controls

## Target score

V56.16 continues using StudyLearningTypeRouter target parsing for score exams and extends school-test titles such as:

`数学II 中間テストで80点`

to expose target_score=80.

The target is Plan intent, not an observation.

## Validation / safety

- no external score is inferred from Practice percentage
- no score observation mutates Task progress
- no AI call
- no provider call
- bounded profiles reject out-of-range values
- IELTS values must respect 0.5 increments
- unsupported component keys are discarded/rejected
- observed date may not be in the future
- request UUID makes retries idempotent
- actor-scoped reads prevent one actor's baseline from becoming another actor's current score

## Non-goals

V56.16 does not:

- import official provider score APIs
- estimate TOEIC/IELTS score from Canovia questions
- alter V56.0 Practice convergence rules
- replace Practice accuracy
- add Learning Type override (Phase 4)
