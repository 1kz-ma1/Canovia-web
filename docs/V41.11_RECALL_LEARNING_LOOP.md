# V41.11 Recall Learning Loop

## Goal

Study Activity PolicyでRecallがPrimaryになったTaskを、AI問題生成ではなく「思い出す練習」へ接続する。

V41.11ではRecallをTask単位の永続学習ループとして実装する。

## Flow

```text
Study Activity Policy
  ↓
Recall
  ↓
Task Recall Deck
  ↓
Frontを見て想起
  ↓
答えをReveal
  ↓
Again / Hard / Good / Easy
  ↓
Deterministic Scheduler
  ↓
次回due_at
  ↓
Task Evidence
```

## Card model

1 Taskを1つのRecall Deckとして扱う。

`study_recall_items` は以下を保持する。

- prompt
- answer
- tags
- repetitions
- lapse_count
- interval_days
- ease_factor
- due_at
- last_reviewed_at
- fingerprint

同じTask内でprompt + answerが同じカードはfingerprintで重複登録しない。

## Review rating

### Again

思い出せなかった。

- repetitions = 0
- lapse_count + 1
- interval = 0日
- 約10分後に再確認
- ease factorを下げる

### Hard

思い出せたが負荷が高い。

- repetitions + 1
- intervalは短めに伸ばす
- ease factorを少し下げる

### Good

通常の想起成功。

- 初回: 1日
- 2回目: 3日
- 以降: interval × ease factor

### Easy

余裕を持って想起できた。

- 初回: 3日
- 2回目: 7日
- 以降: Goodより長いinterval
- ease factorを少し上げる

## Idempotency

各review formは `review_request_id` を持つ。

同じrequest idが再送されても、

- Reviewを二重作成しない
- repetitionsを二重加算しない
- intervalを二重更新しない

## Evidence

Recall reviewは `study_recall_reviewed` としてTask Evidenceへ記録する。

Evidenceは「Recallを実行した事実」と自己評価結果を示す。

ただしV41.11ではRecallを行った時間だけを理由にTask進捗を自動で上げない。

自己評価は客観テストより弱いSignalのためconfidenceは0.75とする。

## Mastery candidate

カードは以下を満たすと定着候補として表示する。

- repetitions >= 3
- interval_days >= 7

これはTask完了条件ではなく、Recall UI上の学習状態である。

## Card creation

V41.11では手動一括追加を提供する。

```text
front | back
front<TAB>back
```

一度に100件まで。

AIによる教材抽出・自動カード生成は後続で扱う。

## V58.6 Task progression update

The V41.11 follow-up "実Recall成績をTask progressionへ使うPolicy" is implemented
in V58.6.

Recall reviews still do not directly raise Task progress. Only a Recall-primary
Task whose entire active Deck satisfies the existing mastery boundary and has no
currently due card becomes a completion candidate. The user must explicitly
confirm completion, after which Canovia reuses the canonical Study next-Task
selector.

See `docs/V58.6_RECALL_TASK_PROGRESSION.md`.
