# V48.5 Explainable Spatial Personalization

## 目的

Canovia MapのPersonalizationを「おすすめNodeを追加する」段階から、
既存Contextの **位置・強調・説明** を利用状況に応じて変えるSpatial Attentionへ進める。

V48.5はAI layoutではない。

既存の:

- Plan priority
- BehaviorEvent
- WorkSession
- Task progress / status

からV44.4/V45.6で計算している4軸signalだけを使い、
決定的にPresentationを変える。

```text
canonical Plan / Task
      +
existing behavior signals
      ↓
PersonalizedSatelliteCandidateService
      ↓
PersonalizedSatellitePromotionService
      ↓
position / emphasis / explanation
      ↓
Map presentation
```

Plan / Taskの存在・状態・優先度そのものは変更しない。

## Fixed semantic structure

L0の固定5 Nodeは維持する。

- Space Station
- 計画
- 実行
- 振り返り
- 共同

Personalized Shortcutはこれらを置き換えない。

V45.6のdensity contractも維持する。

- promotion threshold = 0.55
- max = 2
- same semantic anchor = max 1
- Shared PlanはL0 Shortcutにしない
- Task-bound ToolはL0 Shortcutにしない

## Anchor-aware placement

V44.4ではpromotion rank順にSatellite slotを割り当てていた。

V48.5ではsemantic anchorをplacementの基準にする。

```text
intent:plan          -> satellite-1 / 上
intent:execution     -> satellite-2 / 右
intent:reflection    -> satellite-3 / 下
intent:collaboration -> satellite-4 / 左
```

これによりrankが入れ替わっても、同じ意味領域のShortcutが突然別方向へ飛ばない。

絶対座標は保存しない。

## Score-sensitive distance

promotion scoreはNodeの存在判定だけでなく、
anchor slot内でのcenter distanceへ弱く反映する。

- threshold付近 -> 外側
- signalが強い -> 少しcenter側

変化幅は小さく限定する。

目的は「重要だから画面中央を奪う」ことではなく、
固定Intentより外側にあるShortcutのattention強度を空間距離でも表すこと。

Desktop:

- server Projectionのpositionをそのまま使う

Mobile:

- serverのscore-sensitive radiusをpixel distanceへ変換
- tall viewportでも円形距離になるようwidth基準で補正
- V47.7/#153のmobile box fittingを最後に適用

したがってPersonalizationによってスマホNodeが画面外へはみ出す設計にはしない。

## Explainability

Personalized Shortcutにはpresentation-only metadata:

`personalization`

を付加する。

内容:

- mode
- strength
- semantic anchor
- reason keys
- user-facing reason labels
- explanation

理由は既存4軸signalのweighted contribution上位から最大2件を選ぶ。

例:

- 優先度が高い
- 最近よく使っている
- 最近開いている
- 継続して進めている

AI reasoningは生成しない。

Detail Paletteでは:

`ここにある理由`

として表示する。

raw promotion scoreや内部weightをユーザーへ読ませない。

## Visual emphasis

Personalized Shortcutはstrengthを:

- active
- strong

の2段階へ丸めて表示する。

Canvasでは:

- glow
- border emphasis

だけを変える。

Node本文へsignalやpercentageを詰め込まない。

Clean Mapを維持する。

## Device-local hide

ユーザーはDetail Paletteから:

`この端末では非表示`

を選べる。

保存先:

`canovia.map.personalization.v1`

schema:

```json
{
  "version": 1,
  "hidden_node_ids": [
    "satellite:plan:12"
  ]
}
```

これはpresentation preferenceだけ。

変更しない:

- Plan
- Task
- priority
- BehaviorEvent
- promotion score
- server Projection
- Map Page canonical route

L0 Canvasには非表示件数だけをcompact表示し、
`戻す`
で端末内設定をclearできる。

## Why hide but not pin

V48.5ではmanual pinを実装しない。

現在のPersonalized Shortcutはserver側promotion thresholdを満たしたContextだけがProjectionされる。

device-local pinだけを追加すると、
次requestでserver candidateから外れたContextをclientが復元できず、
「固定したのに消える」という不正確な契約になる。

Pinを導入する場合は:

- eligible candidate identity
- server Projection override
- account/device preference境界

を先に定義する。

V48.5では嘘のpin semanticsを作らない。

## Instant Navigation

Map DOM cacheへruntime initialization stateを保存しない。

V48.4 fixと同じく:

`data-map-personalization-initialized`

はInstant Navigation snapshotから除去する。

cached Map復帰後もlocal hide preferenceを再適用する。

## Telemetry / privacy

Behavior telemetryへ追加しない:

- promotion score
- signal values
- reason labels
- hidden node IDs

既存Telemetry whitelistを維持する。

localStorageにはNode structural IDだけを保存し、
Plan title / Task title / user content / AI outputは保存しない。

## Canonical boundary

V48.5で自動変更しない:

- Plan priority
- Task status
- Task progress
- Dependency
- Evidence
- Map Page
- Roadmap
- GitHub state

PersonalizationはNavigation / Presentation layer。
