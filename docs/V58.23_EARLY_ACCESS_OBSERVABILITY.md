# V58.23 Early Access Observability

## Goal

L2 Product Previewを実装したEarly Access候補に対し、公開後に必要な最低限の運営基盤を追加する。

V58.23の対象:

- Early Access disclosure
- 即時Feedback導線
- registration cohort telemetry
- daily return telemetry
- activation funnel
- D1 / D7 retention
- Product Preview demand
- Feedback mix
- Admin observability

## Product principle

Early Accessは未完成を隠すものではない。

ユーザーには:

> 先行公開中で仕様が変わり得ること

を明示し、問題や要望をその場で送れるようにする。

運営側には:

> 登録数だけでなく、最初の価値へ到達したか、戻ってきたか

を観測できる状態を作る。

## Early Access activation

対象actor:

- Public Release Level L1〜L3
- またはUser Access OverrideでL1〜L3
- Super Adminは除外

Default Public L4では通常ユーザーのEarly Access計測を開始しない。

## Disclosure

Early Access actorの通常画面上部へ小さなDisclosureを表示する。

表示内容:

- Early Accessであること
- 仕様が変更される可能性
- Feedbackへの即時CTA
- L2以上ではProduct Previewへのリンク

Focus execution / Admin / Legalでは表示しない。

## Feedback

既存Feedback基盤を再利用する。

新規Feedback systemは作らない。

既存Contextへ追加:

```text
early_access
release_level
```

本文、rating、page、route、app version等の既存契約は維持する。

## Telemetry

### early_access_registered

Account registration時にserver-side記録。

Safe metadata:

- release_level
- claimed_guest_data

### early_access_session_started

主要entry route到達時にserver-side記録。

- Home
- Overview
- Study
- Development
- Career Beta

同一actor / 日は1回に圧縮する。
Instant Navigation prefetchは記録しない。

Safe metadata:

- release_level
- account_age_days

## Activation source of truth

Plan / Task creationはTelemetry eventを各実装経路へ埋め込まない。

理由:

- manual creation
- AI task generation
- Chat
- import / template

など複数経路が存在し、event instrumentationでは漏れやすいため。

Adminでは既存DB factを正にする。

```text
User registration
→ first_run_completed_at
→ User-owned Plan
→ Plan Task
→ WorkStarted event
→ WorkCompleted event
```

## Retention

D1 / D7は:

```text
early_access_registered actor
+
early_access_session_started actor
```

から算出する。

Cookie削除 / 端末変更でactorが変わるため、厳密なAccount retentionではなくEarly Access運用指標として扱う。

## Admin

Canonical route:

```text
GET /admin/early-access
route = admin.early_access.index
```

7日 / 30日切替。

表示:

- Public / Target Release Level
- Release Gate state
- Activation funnel
- D1 / D7 retention
- daily active
- Product Preview unique actor / views
- Feedback count / type / rating

Feedback本文は集計画面へ表示しない。

Admin Dashboardにも7日概要を表示する。

## Release Gate

L1 structural required routesへ追加:

- `feedback.store`
- `admin.early_access.index`

既存:

- `feedback.index`
- `behavior_events.store`

も維持する。

これによりFeedback送信経路とEarly Access観測画面が削除された場合、Release Gateで検知できる。

## Privacy

Early Access aggregate画面では以下を表示しない。

- Plan title
- Task title
- Feedback本文
- Prompt / AI body
- email
- user name

Behavior Event metadataも明示したsafe fieldsに限定する。

## Non-goals

V58.23では実装しない:

- Product analytics SaaS連携
- push notification
- email lifecycle campaign
- exact cross-device retention
- pricing / checkout
- automated release promotion
- manual Release Gate checklist persistence
- Public Release Level変更

## Next

V58.23後のL2 Manual Release Gate残作業は主に:

- mobile / desktop実機first-use確認
- blocker 500 / unintended 403確認
- L2 → L1 / L0 downgrade確認
- Product Preview copy最終確認
- Early Access disclosure copy最終確認
- Telemetry / Feedback payload実データ確認

これらを確認後、Public LevelをL2へ変更するかProduct Ownerが判断する。
