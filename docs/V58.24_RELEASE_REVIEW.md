# V58.24 Release Review

## Goal

V58.23までにL2 Early Access候補の構造・観測基盤が揃ったため、
Release GateのManual Checkを実際に運用できる状態へ進める。

V58.24では:

- Manual Checkへstable keyを付与
- Passed / FailedをDB保存
- review note / reviewer / reviewed_atを保存
- Pendingへ戻す
- cumulative Level reviewを判定
- Automatic Gate + Manual Reviewから最終Decisionを表示
- L2 → L0 downgrade smokeを自動回帰化

## Status model

Manual Review:

```text
Pending
Passed
Failed
```

DBにはPassed / Failedだけを保存する。

rowなし:

```text
Pending
```

Reset時はrowを削除する。

## Stable keys

Manual Checkは表示文言ではなくstable keyで識別する。

例:

```text
L0
core_flow_smoke
account_recovery
core_http_errors

L1
specialized_first_use
early_access_copy
downgrade_core
feedback_telemetry

L2
product_preview_copy
product_preview_no_checkout
product_preview_clarity
```

表示文言変更でReview履歴が壊れないようにする。

## Persistence

Table:

```text
release_review_checks
```

fields:

- release_level
- check_key
- status
- note
- reviewed_by_user_id
- reviewed_at
- timestamps

unique:

```text
release_level + check_key
```

## Decision

Release targetの最終表示は:

```text
automatic blocked
→ BLOCKED

automatic ready + failed > 0
→ REVIEW FAILED

automatic ready + pending > 0
→ MANUAL REVIEW

automatic ready + all manual passed
→ READY FOR RELEASE
```

重要:

```text
READY FOR RELEASE
!=
Public Release Level changed
```

Public Levelは自動変更しない。

## Admin UI

Existing route:

```text
GET /admin/release-gate
```

Manual Reviewで:

- Passed
- Failed
- note
- reviewer
- reviewed_at
- Pending reset

を操作できる。

Levelカードにも:

- Automatic check count
- Manual passed / total
- BLOCKED / MANUAL REVIEW / REVIEW FAILED / READY

を表示する。

## Cumulative review

L2 Product Previewを公開候補とする場合、L2だけではなく:

```text
L0
+
L1
+
L2
```

のManual CheckをすべてPassedにする必要がある。

V58.24 initial L2 cumulative check count:

```text
10
```

## Downgrade smoke

Automated regression:

```text
Public L2
→ user owns Study Plan + Task
→ Public L0
→ Study / Development dedicated workspace entries hidden
→ Home remains usable
→ Plan detail remains accessible
→ Plan / Task rows remain intact
```

Release Level downgradeはdata deletionではなくSurface visibility changeであることを固定する。

## Security

Review write:

- Admin access required
- configured manual check only
- release_level 0..4
- status passed / failed only
- reviewer is authenticated Admin account
- Public Level mutation is not part of Review endpoint

## Non-goals

V58.24では実装しない:

- Public Level write from Release Gate
- automatic production promotion
- scheduled release
- rollback automation
- release approval by multiple reviewers
- external QA tooling
- screenshot evidence upload

## Next

L2 Release Reviewの残りは実際の確認作業。

主に:

- Core flow smoke
- account recovery
- blocker 500 / 403
- Study / Development mobile + desktop first-use
- Early Access copy
- Feedback / telemetry payload
- Product Preview copy / clarity

全項目Passed後、Release GateはREADY FOR RELEASEになる。

その後に初めて:

```text
CANOVIA_PUBLIC_RELEASE_LEVEL=2
```

をProductionへ適用するかProduct Ownerが判断する。
