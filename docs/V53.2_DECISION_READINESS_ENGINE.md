# V53.2 Decision & Readiness Engine

## Goal

V53.2 turns normalized State into an explainable Readiness assessment and a selected Decision, then persists a reproducible trace.

The pipeline becomes:

```text
Evidence
  ↓
StateSnapshot
  ↓
ReadinessEvaluator
  ↓
ReadinessAssessment
  ↓
Decision candidates
  ↓
selected Decision
  ↓
DecisionTraceStore
```

V53.2 is deterministic and provider-neutral.

OpenAI is intentionally not used here. V53.3 can route harder reasoning behind the same Decision boundary.

## Why deterministic first

Canovia must retain a decision baseline that remains:

- explainable
- inexpensive
- reproducible
- testable
- independent of one model provider

Later AI or Canovia-owned models can be evaluated against this baseline rather than becoming the only source of truth.

## Readiness meaning in V53.2

Study Readiness V1 is **evidence-based study readiness**.

It is not yet:

- exam pass probability
- predicted final score
- full syllabus coverage
- remaining workload estimate

Those stronger meanings require Study Capture / Study Intelligence data in later V53 phases.

V53.2 answers a narrower question:

> Based on the study Evidence Canovia currently has, how prepared does the observed learning state look, what is still unknown, and what gap deserves attention next?

## StudyReadinessEvaluator

`StudyReadinessEvaluator` implements the generic `ReadinessEvaluator` contract.

Inputs come only from normalized `StateSnapshot`.

Current State inputs:

- practice attempt count
- recall review count
- latest score
- average score
- observed weaknesses

Task progress is not an input.

### No practice Evidence

When no usable practice score exists:

- readiness score = null
- level = unknown
- confidence = 0.20
- gap = `practice_evidence_missing`

Canovia must not manufacture a readiness number when it has insufficient Evidence.

### Performance score

When practice Evidence exists:

```text
performance
= latest score × 0.65
+ average score × 0.35
```

Observed weaknesses apply a small capped penalty:

```text
weakness penalty
= 3 points per observed weakness
= maximum 12 points
```

This is a conservative V1 heuristic, not a learned model.

### Confidence

Confidence is based on observation sufficiency.

Current policy:

- 0 attempts: 0.20
- 1 attempt: 0.45
- 2 attempts: 0.60
- 3 attempts: 0.72
- 4 attempts: 0.78
- 5+ attempts: 0.82
- at least one recall review: +0.08
- maximum: 0.90

Confidence describes how much Canovia should trust this assessment, not how likely the user is to pass an exam.

## Readiness levels

### Unknown

No usable practice Evidence.

### Blocked

Observed readiness score is below 50.

### Developing

There is useful Evidence, but Ready conditions are not all satisfied.

### Ready

All current V1 conditions must be satisfied:

- readiness score >= 80
- at least 3 practice attempts
- at least 1 recall review
- no currently observed weakness

This deliberately makes Ready harder than merely receiving one high score.

## Explainable gaps

V53.2 emits structured Gap records.

Current Study gap codes:

- `practice_evidence_missing`
- `practice_evidence_thin`
- `mastery_below_target`
- `retention_unverified`
- `observed_weaknesses`

A Gap can contain:

- code
- dimension
- severity
- observed value
- target value
- normalized weakness labels where applicable

These are machine-readable facts for later UI explanation and Decision selection.

## Decision candidates

`StudyDecisionEngine` builds deterministic candidates before selecting one.

Current candidate types:

### collect_baseline_evidence

Used when Canovia does not yet have a practice baseline.

### reinforce_observed_gap

Used when an observed weakness exists or performance is below the current target.

### expand_practice_sample

Used when some practice Evidence exists but the sample is still thin.

### verify_retention

Used when performance exists but delayed recall has not been observed.

### advance_scope

Used when V1 Readiness reaches Ready.

### continue_observation

Fallback when no dominant gap exists.

Candidates contain:

- type
- reason code
- stable summary
- priority
- confidence
- reasons
- controlled metadata

Selection is deterministic:

1. higher priority
2. higher confidence
3. stable type ordering

## Decision fingerprints

V53.2 extends `IntelligenceFingerprint`.

### readiness fingerprint

Hashes the complete normalized ReadinessAssessment:

- score
- level
- confidence
- components
- gaps
- metadata

### decision input fingerprint

Hashes:

- exact State snapshot reference
- readiness fingerprint

Because it includes the exact State snapshot reference, the same semantic State observed at a later time produces a separate Decision trace.

### decision fingerprint

Hashes semantic Decision fields:

- type
- reason code
- confidence
- input fingerprint
- reasons
- metadata

The presentation summary is intentionally excluded.

Changing copy alone should not create a new semantic Decision identity.

### decision reference

```text
decision:<sha256>
```

## Durable Decision trace

V53.2 adds `intelligence_decision_traces`.

A trace persists:

- user / plan references when available
- linked State snapshot
- State reference and fingerprint
- Readiness fingerprint
- Readiness score / level / confidence
- Readiness components
- structured gaps
- controlled Readiness policy metadata
- Decision reference
- Decision type
- reason code
- stable summary
- Decision confidence
- exact input fingerprint
- reasons
- controlled candidate-selection metadata
- controlled engine metadata

The table is designed for future evaluation of:

```text
State before
→ Readiness
→ Decision
→ later Action
→ Outcome
→ State after
```

## Trace safety

Arbitrary provider payloads are not persisted through V53.2 convenience metadata.

Readiness metadata whitelist:

- policy
- target_score_percent
- meaning

Decision metadata whitelist:

- policy_version
- candidate_count
- candidate_types
- selected_priority
- weakness_count

Trace metadata whitelist:

- engine
- engine_version
- policy_version

## Idempotency

`decision_reference` is unique.

Running the same exact State snapshot + Readiness + selected Decision again returns the existing trace.

The same semantic State observed later has a different State reference, therefore a different Decision input fingerprint and a new trace.

This preserves time-series history while protecting against retry duplication.

## DecisionOrchestrator

`DecisionOrchestrator` provides the generic execution path:

```text
StateSnapshot
+ ReadinessEvaluator
+ DecisionEngine
      ↓
ReadinessAssessment
      ↓
Decision
      ↓
persist trace
      ↓
DecisionEvaluationResult
```

Domain code can reuse this orchestration without coupling feature code directly to a model provider.

## Non-goals

V53.2 does not implement:

- OpenAI reasoning
- natural-language explanation generation
- Action generation
- automatic Task mutation
- automatic replanning
- exam pass probability
- workload estimation
- syllabus coverage
- user-facing Readiness UI
- Developer Readiness
- Outcome learning

## Next

V53.3 should introduce the provider-neutral Reasoning Router.

The router should be able to choose among:

- deterministic logic
- domain rules
- OpenAI
- future Canovia-owned models

The deterministic V53.2 output remains a baseline and fallback.

Natural conversation and decision reasoning should remain separate concerns.
