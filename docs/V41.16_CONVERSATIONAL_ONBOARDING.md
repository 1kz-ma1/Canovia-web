# V41.16 Conversational Onboarding / Invisible Memory

更新日: 2026-09-27

## 1. Purpose

V41.14〜V41.15でCanoviaは、

```text
Goal Context
→ Guided Execution / Evidence
→ Companion
→ Contextual Entry
→ Continuity
```

まで「現在のCanovia stateを読んで伴走する」基盤を持った。

V41.16では最初の入口も同じ思想へ揃える。

従来:

```text
New User
→ Plan作成
→ Goal Discovery
→ AI handoff
→ Task
```

V41.16:

```text
New User
→ First Companion Conversation
→ Goal Context
→ Known / Unknown
→ Provisional Plan
→ Execution
```

ユーザーへ「Canoviaを設定してから使う」ことを求めず、
**話しているうちにCanoviaが必要なContextを構造化する**ことを目標とする。

---

## 2. First Companion is Free

継続的なCanovia CompanionはPremium Coreの価値として維持する。

一方、最初の伴走体験はFree Goal Pathに含める。

Feature:
- `conversational_onboarding`: Free
- `canovia_companion`: Premium
- `automatic_ai_execution`: Premium

Conversational OnboardingがNative AIを使うことは、
Automatic AI Execution全般をFreeへ戻すことを意味しない。

初回体験だけを独立Capabilityとして公開する。

Providerが未設定・停止中でもGoal Discoveryを止めない。
既存のdeterministic Goal Discoveryへfallbackし、Freeの目標達成経路を維持する。

Free Native AI経路を無制限API入口にしないため、
Goal Discovery開始POSTは1分12回、回答POSTは1分30回のHTTP rate limitを置く。
これは課金境界ではなく乱用防止である。

---

## 3. Conversation + deterministic Goal Context

Native AIへGoal Contextの決定権を渡さない。

```text
User message
    ↓
GoalDiscoveryConversationService
    ↓
Native AI: conversational reply
    ↓
GoalDiscoveryPolicyService: next question
    ↓
Human answer
    ↓
GoalContextService: confirmed / unknown fact
```

AIの役割:
- ユーザーの言葉を自然に受け止める
- 現在のdeterministic questionへ自然につなぐ
- Goal Contextにない事実を作らない
- 不明なことを不明のまま扱う

Canovia側の役割:
- 質問順を決定
- quick / text / skipを処理
- confirmed / unknownを保存
- Readinessを決定論的に計算
- Provisional Planへ進める条件を決める

会話らしさとSource of Truthを分離する。

---

## 4. Persistence

`goal_discovery_messages`

- goal_context_id
- user_id nullable
- native_ai_run_id nullable
- role: user / assistant
- content
- metadata

初回Goalと各回答をConversationとして保存する。

AI provider失敗時もassistant fallback messageを保存できるため、
画面上のConversation体験を壊さない。

---

## 5. New user entry

新規AccountにGuest Planがない場合:

```text
Register
→ /plans/create
→ First Companion
```

Guest Planをすでに持っている場合は、
従来通りclaim後Homeへ戻し既存作業を中断しない。

HomeにPlanがない場合もPrimary CTAを
「計画を作る」ではなく「Canoviaと始める」とする。

詳細Plan Formは削除しない。
`/plans/create/manual` を明示fallbackとして維持する。

---

## 6. Invisible Memory

従来のFuture Memoは、
ユーザーが別画面で入力・分類・管理することを前提にしていた。

V41.16では通常UXから退役させ、
内部互換を保った **Canovia Memory** として扱う。

DB/table/serviceを即削除しない理由:
- 既存データ互換
- 既存AI promptとの互換
- Human-controlled delete / legacy accessを失わない
- migration riskを増やさない

通常画面からは:
- Home quick actionを外す
- Empty HomeのFuture Memo誘導を外す
- Manual Plan作成のFuture Memo誘導を外す
- Inboxの公開routing destinationからFuture Memoを外す
- Inbox AIのrouting schemaからFuture Memo分類項目を外す
- AI Task / Plan Reviewではread-only Contextとして見せる
- Memoryを入力するための管理を要求しない

Inboxのlegacy `future_memo` POST destinationは既存互換のためserver-sideに残すが、
通常UIやAI suggestionから新たに選ばせない。

---

## 7. Automatic memory capture boundary

MemoryはAIの推測で登録しない。

Native AIは候補として:

- kind
- category
- source_quote

だけを返せる。

server-side条件:

1. source_quoteが空でない
2. 4文字以上
3. **直近User Inputに連続した原文として実在する**
4. kindがallowlist内
5. 同じactorに同一正規化contentがない

を満たした時だけ保存する。

対象:
- want_to_do
- future_self
- interest
- concern
- value

主Goal / selected Plan / selected Task自体を
重複Memoryとして保存しないようPromptで制約する。

診断、人格推定、属性推定、暗黙の意図推定はMemoryへ入れない。

---

## 8. Companion integration

Premium Companionでも、
ユーザーが会話中に明示した incidental future context を同じ境界でMemoryへ保存できる。

例:

```text
「今はCanoviaを作ってるけど、いつかゲーム開発もやりたい」
                                  ↑
                         literal source_quote
```

保存後はCompanion Contextへ最大8件だけ渡す。

AIへ渡すMemory:
- kind
- category
- content
- source
- captured_at

Memory IDや全履歴は渡さない。

これによりユーザーが「未来メモを更新」しなくても、
必要な時に以前の明示的な希望をContextとして再利用できる。

---

## 9. Mutation boundary

Invisible Memoryは、
Plan / Task mutationとは扱いを分ける。

- incidental Memory: literal-quote gateを通して内部保存
- Plan / Task / Goal Fact変更: 従来通りMutation Candidate + Human confirmation
- `create_future_memo` Candidate: 互換のため残すが、明示的に「メモとして残して」と依頼された場合の経路とする

Memory自動保存をTask ProgressやPlan変更へ広げない。

---

## 10. Safety / Product principles

1. 最初に設定を要求せず、会話からContextを作る。
2. AIはGoal Context Factを勝手にconfirmedにしない。
3. 不明な情報を埋めるために推測しない。
4. Memoryはユーザー本人の明示文だけから保存する。
5. Memory保存とPlan / Task mutationを分離する。
6. 初回伴走体験はFree Goal Pathに含める。
7. 継続CompanionのPremium価値は維持する。
8. Provider停止時もGoal Discovery自体を止めない。
9. 旧Future Memoデータは破壊しない。
10. ユーザーへ情報整理のための別作業を増やさない。
