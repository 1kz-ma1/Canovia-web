# V48.8 Reflection Candidate Expansion

## 目的

V48.5〜V48.7でPersonalized Shortcutの:

- semantic placement
- explainability
- device-local hide
- account-level pin
- contextual pin entry

まで整った。

一方、production candidateはPersonal Planだけで、V48.5で用意したReflection / Collaboration / Execution方向のsemantic anchorを実利用していなかった。

V48.8ではCandidate Expansionを最小単位で開始する。

追加するのは:

> 既存Reflection Lens「最近の実績」へのShortcut

1種類だけ。

Tool / Collaboration candidateはまだ増やさない。

## Candidate principle

L0を埋めるためにcandidateを増やさない。

Recent Reflection Shortcutは:

- canonical WorkLog / TaskEvidenceが存在する
- 一定量のrecent signalがある
- existing Reflection Lensへ複数階層を飛ばす

場合だけcandidateになる。

新しいReflection entityは作らない。

destination:

```text
/map?level=l2
    &intent=reflection
    &reflection_context=recent
```

semantic anchor:

`intent:reflection`

position role:

`satellite-3`

## Eligibility

対象window:

14日。

最低record:

2件。

record source:

- WorkLog
- TaskEvidence

Task title / Evidence summary等のuser contentはcandidate scoringへ保存しない。

1件だけの単発recordではcandidate自体を作らない。

## Signals

V45.6の4軸とweightを変更しない。

### importance

recent recordに含まれるPlanのeffective priorityの最大値。

表示理由:

`重要なPlanの実績がある`

### usage_frequency

14日以内のcanonical record数を6件で1.0へ正規化。

表示理由:

`実績がまとまっている`

### recency

最新record時刻を既存bucket decay相当で評価。

表示理由:

`最近実績が増えた`

### continuity

recordが存在するdistinct day数を4日で1.0へ正規化。

表示理由:

`継続して積み上がっている`

Promotion thresholdは既存:

`0.55`

のまま。

Candidateが存在してもscore不足ならL0へ表示しない。

## Explainability

V48.5のweighted contribution上位最大2件という仕組みを維持する。

ただしCandidateごとにsignalの意味が違うため、V48.8ではcandidate-specific reason labelを許可する。

Plan Shortcutの既存理由:

- 優先度が高い
- 最近よく使っている
- 最近開いている
- 継続して進めている

は変更しない。

Reflection Shortcutだけ上記Reflection用理由を使用する。

AI reasoningは使わない。

## Density

維持:

- max 2
- same semantic anchor max 1
- Plan anchor = satellite-1
- Reflection anchor = satellite-3

したがって強いPlan ShortcutとRecent Reflection Shortcutは同時に最大2件まで共存できる。

同じReflection anchorへ将来candidateを増やしても1件だけ。

## Telemetry

structural node type:

`satellite_reflection`

を追加する。

許可する既存structural fields:

- node_type
- position_role
- action_role

保存しない:

- promotion score
- record count
- Plan title
- Reflection label
- Evidence summary
- user content

## Persistence

なし。

candidate row / score history / absolute positionは保存しない。

request時にcanonical recordsから決定的に再計算する。
