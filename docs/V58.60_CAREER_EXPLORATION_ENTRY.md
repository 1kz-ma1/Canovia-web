# V58.60 — Career Exploration Entry / Complementary Assessment Foundation

## Product intent

Career must be useful **before** the user knows which occupation they want. Do not force a job seeker to create a preselected-occupation Plan or infer "unsuitable" careers.

First use has exactly three principal paths:

1. **職種が決まっている** → existing editable Career Plan creation.
2. **Canoviaで診断する** → self-reflection, exploration directions, editable Career Plan.
3. **MATCH plusで診断する** → official Mynavi 2028 information/assessment page in a separate tab.

Official URL verified 2026-10-08:
`https://job.mynavi.jp/conts/2028/cs/matchplus_consent_2/`
Mynavi's 2027 MATCH plus FAQ confirms `結果PDF作成`; this does **not** imply Canovia imports PDFs in V58.60.

## V58.60 implementation

- Dedicated `CareerExplorationController` under the existing `release.level:3` gate. **No release level change.**
- Four bounded, optional-in-content (allow `unsure`), validated self-reported axes: interest in activities, work values, working style, location preference.
- No predictive suitability/employment score, personality classification, hiring prediction, employer ranking or automated job application.
- A deterministic list of **example fields to investigate** with concrete next research steps; directions are not recommendations with validated fit scores.
- Browser session draft, no new database tables, no automatic Living Profile mutation. An explicit POST copies the user's answers into **editable** Career Plan create prefill.
- The three-path entry is shown when Career has no existing Plan. When a Plan exists with no observed Career signal, a link to exploration remains available alongside existing Career Capture onboarding.

## Complementary assessment contract

`CareerExplorationAssessmentService::confirmedCoverage` accepts a future **server-owned**, per-field reviewed import:

```json
{
  "interest_activity": {
    "value": "support",
    "confirmed": true
  }
}
```

A field suppresses the corresponding Canovia question **only if**:

- the external import has actually been reviewed and explicitly confirmed by the user;
- the field key matches a Canovia question;
- the value exactly matches the same question's enumerated semantics.

A MATCH plus numeric score or broad trait label is **not automatically equivalent** to a Canovia interest/preference answer. Unrecognized, partial or unconfirmed fields never suppress questions. The session key `canovia.career.import.confirmed.v1` is reserved for the trusted future importer and has no writer in V58.60.

## Next implementation slices

1. **V58.61 Study Adaptive Starting Point**: from learner goal + actual diagnostic/assessment evidence + topic prerequisites, determine targeted review vs two-grade stretch. Never assume "all of Grade 3 mastered" from an overall self-rating. Do not force a Grade 3 → Grade 2 fixed ladder.
2. **V58.62 Career PDF import (manual-merge risk gate)**: accept user-provided PDF only after validating MIME/signature, size/pages and ownership; run a sandboxed bounded text extraction; present original source text vs parsed claims, explicit corrections, user confirmation, and data deletion. Original PDF is private/short-lived and not stored in unprotected session or published URLs. Text extraction failures must not fabricate structured data. Do not automatically submit to external AI without informed user consent. Add protection and privacy tests. **Do not mark PDF import available before this is complete.**
3. **V58.63 Job exploration feedback**: after employer research/briefings/interviews, record explicit user impressions and revise exploration hypotheses while preserving sources and user choice. Keep Career Intelligence's Process Readiness distinct from employability scoring.
4. **Later**: explicit opt-in voice dictation of post-interview personal reflection; recording actual interviews requires participant consent/privacy review.

Career stays Level 3 Beta until product owner manually approves level change after release review.
