# V53.9 Intelligence UX

## Goal

V53.9 makes the V53 Intelligence loop the primary presentation model for the first two validated domains, Study and Development.

The user-facing questions are shared:

~~~text
今どんな状態？
↓
目標に対してどれくらいReady？
↓
一番大きいGapは？
↓
次に何をすればいい？
↓
なぜそれが今の最善Action？
~~~

The domain logic remains different. The presentation contract becomes shared.

~~~text
Study Intelligence ──────┐
                         ├→ PlanIntelligencePresentation
Development Intelligence ┘
                                  ↓
                    Home / domain detail surfaces
~~~

V53.9 does not flatten Study and Development into one scoring model.

## Core UX rule

Canovia presents the current judgment before the task tree.

Default hierarchy:

~~~text
Current State
→ Readiness
→ Biggest Gap
→ Current Action
→ Why now?
~~~

Task / Evidence / Decision history remains inspectable detail.

This preserves trust without making the user maintain a large Task list as the application's source of truth.

## Shared presentation contract

PlanIntelligencePresentation is the UI-facing contract. It contains:

- domain
- Plan
- normalized State
- Readiness
- Decision
- Current Action
- domain-specific headline and source explanation
- user-facing State label
- Biggest Gap label / detail
- domain detail URL
- Action URL / method / label
- compact domain metrics
- optional related Task
- whether explicit Task projection is required

PlanIntelligencePresentationService selects the adapter by PlanCategoryProfile.

Supported V53.9 domains:

- study
- development

The generic UI never needs to interpret Study weakness rules or Development release gates directly.

## Study adapter

Study presentation maps the existing Study State / Exam Readiness / Decision / Action into:

- 試験に向けた現在地
- Exam Readiness
- Study-specific current-state label
- user-facing Biggest Gap
- Current Action
- Coverage / Mastery / Retention / Remaining metrics

Study source explanation explicitly states that Task progress is not the truth source.

The Study detail surface remains responsible for domain-specific evidence detail such as confirmed scope count, remaining Study Units, deadline pressure, Speed being unmeasured, and high-remaining-load scopes.

The previous separate CURRENT ACTION and STUDY INTELLIGENCE cards are replaced by one shared summary so the user does not read the same judgment twice.

## Development adapter

Development presentation maps the existing Development State / Release Readiness / Decision / Action into:

- Releaseに向けた現在地
- Release Readiness
- release-state label
- user-facing Biggest Gap
- Current Action
- passed / failed / pending / unknown gate metrics

Development source explanation states that Release State comes from same-Task GitHub Evidence plus explicit confirmations, not Task progress.

Development-specific detail remains the seven Quality Gates:

- implementation
- CI / Test
- Review
- Merge
- Production Deploy
- verification
- specification synchronization

V53.8 Verification / Spec Sync controls and stale-release protection remain unchanged.

## Home selection

V53.9 replaces the Study-only Home Intelligence selector with IntelligenceHomeActionService.

Home evaluates at most one supported Plan to keep the common path bounded.

Selection policy:

1. if the current primary Dashboard Guidance Plan supports Intelligence, use that Plan
2. otherwise a Study/Development Plan may replace task guidance only when it genuinely outranks the current primary Plan by existing Plan priority semantics
3. stable tie-breaking uses deadline and Plan ID

This preserves the existing Plan priority system rather than introducing an independent Intelligence priority universe.

## Task completion is not Goal completion

V53.6 temporarily suppressed Study Home Intelligence when every Task was completed.

V53.9 removes that rule.

~~~text
all current Tasks done
≠ Goal achieved
≠ Exam Ready
≠ Release Ready
~~~

For Intelligence-supported Plans, Task completion is not used to suppress State / Readiness / Action.

If a future explicit Plan-completion concept is introduced, it must be modeled independently from “all current Tasks are done.”

This is a deliberate V53 semantic correction, not a regression.

## Home card

When Study or Development owns current priority, Home shows one Intelligence card before same-Plan Task guidance.

The card contains:

- Plan
- domain Intelligence label
- Current Action
- Readiness
- Current State
- Biggest Gap
- primary CTA
- detail CTA
- expandable なぜ今これ？
- Decision summary
- confidence

Same-Plan Task guidance is removed from the horizontal candidate list while that Plan's Intelligence Action is primary, avoiding duplicate instructions.

Other Plans remain horizontally browsable through existing Home guidance.

## Action routing

Study:

- Study Action execution remains POST to the existing explicit Study Action route
- merely viewing Home / Study Scope never creates a Task
- Task projection remains explicit and user-triggered

Development:

- task-execution Actions route to the target Task's Execution Orchestration surface
- Verification / Spec Sync Actions route to the Development Quality Gates anchor
- GitHub workflow Actions route to the GitHub Workflow board anchor

Development V53.9 does not introduce automatic Task creation.

## Shared detail summary

The shared Intelligence summary partial shows:

- domain headline
- source-of-truth explanation
- Readiness
- Current State
- confidence
- compact metrics
- Biggest Gap
- Current Action
- relevant CTA

Expandable explainability shows:

- current Decision summary
- current State Evidence reference count
- related Task, if any
- whether the Action is Task-free / requires Task projection
- recent Decision traces
- recent Action changes
- recent State snapshots and Evidence counts

The UI does not expose raw provider payloads or private Evidence content.

## Inspectable history

V53.9 reuses the durable V53 stores:

- intelligence_state_snapshots
- intelligence_decision_traces
- intelligence_action_projections

IntelligencePresentationHistoryService reads a bounded recent history by Plan/domain.

No new history table or migration is added.

The purpose is trust and auditability:

~~~text
何を観測した？
→ どうStateが変わった？
→ 何を判断した？
→ Actionがなぜ変わった？
~~~

The detail surface intentionally shows bounded summaries/counts, not full raw Evidence data.

## Domain-specific detail remains domain-specific

V53.9 unifies presentation order, not the underlying model.

Study retains:

- confirmed Scope
- Coverage
- Mastery
- Retention
- remaining Study Units
- deadline pressure
- Study-specific Decisions

Development retains:

- same-Task Evidence correlation
- implementation generation / SHA semantics
- reviewer decision semantics
- CI / Merge / Deploy state
- explicit Verification / Spec Sync
- release-generation invalidation

Adding a future domain should implement its own Intelligence contracts plus a presentation adapter instead of putting domain rules in the shared Blade surface.

## Offline snapshot

Home offline snapshot exposes only a bounded presentation of the current Intelligence Action:

- domain
- action kind
- title
- intent
- readiness score
- gap label

It does not serialize the entire State, Decision trace, Evidence references or provider data.

## Telemetry

Home RecommendationShown telemetry now uses:

- source = intelligence_action
- domain
- selection = state_readiness_decision
- decision type
- reason code
- action kind
- readiness score
- readiness confidence

The previous Study-only telemetry label is replaced by the cross-domain label.

## Performance rule

Home must not evaluate every Intelligence-supported Plan.

IntelligenceHomeActionService determines one candidate from already-loaded Plans / existing guidance, then evaluates only that Plan.

V53.9 does not load Decision/State/Action history on Home. History is loaded only on the selected domain detail surface.

Existing Home density/query regressions remain required.

## No new AI traffic

V53.9 is presentation/orchestration work.

It introduces no new OpenAI request and does not change Reasoning Router escalation policy.

Study and Development deterministic baselines remain authoritative unless an existing reasoning policy explicitly routes otherwise.

## Compatibility

V53.9 preserves:

- Plan / Task CRUD
- Task execution
- Study Scope Capture
- Study Practice / Recall
- GitHub Workflow
- GitHub Evidence sync
- V53.8 Quality Gate confirmation
- Action Projection history
- existing Home alternate Plan guidance
- iOS SwiftUI + WKWebView architecture

Task remains fully inspectable and usable.

The change is that Task is no longer the first thing the product asks the user to trust.

## V53 completion

With V53.9, the first-domain loops are complete.

### Study

~~~text
Scope Capture
→ confirmed Scope
→ Practice / Recall Evidence
→ Study State
→ Exam Readiness
→ Gap
→ Decision
→ Current Action
→ explicit execution
→ new Evidence
→ re-evaluation
~~~

### Development

~~~text
GitHub / explicit confirmation Evidence
→ Task-correlated Development State
→ Release Readiness
→ Gap
→ Decision
→ Current Action
→ GitHub / execution / confirmation
→ new Evidence
→ re-evaluation
~~~

The shared product model is now:

~~~text
Goal
→ State
→ Readiness / Gap
→ Decision
→ Action
→ Evidence
→ State update
~~~

Task remains an optional durable execution projection / correlation surface.

V53 completes the architectural transition; it does not imply that the domain products are finished.

The next work should be driven by real Study / Development usage:

- improve weak Readiness dimensions with better Evidence
- improve Action quality from observed outcomes
- refine acquisition/onboarding for Study and Development
- measure activation, retention and Premium intent independently by domain
- expand to additional domains only after the first two loops are useful in practice
