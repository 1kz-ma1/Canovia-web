# V43.3 Home Surface Preference

> **V55.4 update:** Home Surface Preferenceはproduct featureとして退役した。旧cookie/localStorageは互換期間中残り得るが入口決定には使わず、ログイン後のcanonical entryは常にAction Home `/`。SettingsのClassic / Map選択UIも削除した。Mapは明示的なExplore Surface `/map` として開く。詳細は `docs/V55.4_MAP_EXPLORATION_SURFACE.md` を正とする。

## Goal

Mapを全ユーザーへ強制的にPrimary Home化せず、使いたいユーザーだけがこの端末の既定Home Surfaceとして選べるようにする。

DefaultはClassicのまま。

## Preference model

既存のTheme / Accent / Densityと同じく端末ごとのUI preferenceとして扱う。

Storage:

- localStorage: pacekeeper.ui.home_surface
- cookie: canovia_home_surface

Values:

- classic
- map

unknown / missingは必ずclassicへfallbackする。

DB migrationは行わない。

## Why localStorage + cookie

localStorage:

- Settings UI
- 即時link更新
- 既存の端末UI preferenceとの一貫性

cookie:

- login後redirect
- guest middlewareのauthenticated redirect
- full page render時のbrand / Home nav destination

cookieは表示設定だけを持ち、認証・所有権情報は含まない。
JSから書ける必要があるためLaravel EncryptCookiesのexceptへこの1 cookieだけを追加する。

## Preference-aware entry

以下だけがpreferred Home URLを使う。

- Desktop brand
- Desktop Home nav
- Mobile brand
- Mobile Home tab
- Existing-account login default redirect
- authenticated userがguest-only auth screenへ来た時のredirect

## Explicit routes remain stable

Preferenceがmapでも:

- / はClassic Home
- /map はCanovia Map

Surface switcherも常に明示的な2 URLを指す。

## Safety boundaries

Preferenceを適用しない:

- error recovery
- logout
- PWA manifest start URL
- PWA handoff fallback
- First-run / Welcome
- explicit back-to-home flows that are recovery semantics

unfinished first-run accountのloginも従来どおりClassic Homeへredirectし、その後Welcome gateへ戻す。

## Client synchronization

Settingsで変更すると:

1. localStorage更新
2. readable cookie更新
3. data-preferred-home-link のhrefを即時更新
4. Settingsのaria-pressed / active state更新

現在表示中Surfaceは自動切替しない。
「既定入口を変える」ことと「今のSurfaceを変える」ことを分離する。

## Non-goals

- 全員をMapへ移行
- account-wide preference sync
- / をMapへredirect
- Classic Home削除
- Telemetry結果による自動opt-in
