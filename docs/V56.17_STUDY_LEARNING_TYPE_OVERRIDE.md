# V56.17 Study Learning Type Confirmation / Override

## Goal

Stop treating deterministic classification as permanent truth when a Study Plan is ambiguous.

V56.17 adds a Plan-level explicit Learning Type override above the existing heuristic router.

Canonical precedence:

```text
explicit Plan override
>
deterministic heuristic
```

Workspace Mode and Learning Type remain separate concepts.

## Supported Learning Types

- score_exam — スコアを上げる
- school_test — 学校のテスト
- certification_exam — 資格に合格
- skill_learning — スキル習得
- memorization — 暗記・定着
- general_learning — その他の学習

## Confirmation Rule

Do not ask on every Study Plan.

Show the confirmation surface only when:

- no explicit override exists
- heuristic confidence is below 0.80
- the alternative Learning Type would materially change Study surfaces / methods

Initial low-confidence cases:

- generic skill wording such as 「学ぶ」「身につける」「習得」
- fallback general learning classification

Strong deterministic signals do not ask:

- TOEIC / IELTS / TOEFL / GRE / GMAT
- school-test keywords
- qualification / certification keywords
- memorization keywords
- concrete programming-language / programming keywords

Examples:

```text
「英語を学ぶ」
→ generic skill inference
→ ask once

「Pythonを習得する」
→ strong skill signal
→ no confirmation

「AP対策」
→ certification
→ no confirmation

「TOEIC 600」
→ score_exam
→ no confirmation
```

## Persistence

Add nullable Plan fields:

- study_learning_type_override
- study_learning_type_confirmed_at

No per-user classification is created.

The Learning Type describes the Plan itself.

## Explicit Override

An explicit override:

- is validated against the supported Learning Types
- sets confidence to 1.0 for downstream Study routing
- carries source=explicit_override
- suppresses future confirmation prompts
- may be edited later
- may be reset to automatic inference

The router still exposes the underlying inferred key for debugging / UI context.

## UI

### Low-confidence confirmation surface

Render:

```text
この学習はどれに近い？

○ スコアを上げる
○ 学校のテスト
○ 資格に合格
○ スキル習得
○ 暗記・定着
○ その他の学習

[このタイプで進める]
```

This surface does not block execution.

It exists because the choice materially changes State First surfaces and recommended methods.

### Editability

Goal Summary always exposes a compact Learning Type editor for editable Plans.

When an override exists:

- show 「手動設定」
- allow switching to another type
- allow 「自動判定に戻す」

Strong heuristic classifications can therefore still be corrected without waiting for a low-confidence prompt.

## Router compatibility

V56.17 does not replace V56.13 StudyLearningTypeRouter.

It extends it:

```text
StudyLearningTypeRouter
├─ explicit override
└─ heuristic inference
```

Target-score parsing remains type-aware:

- score_exam → TOEIC / IELTS / other score target parsing
- school_test → explicit point target parsing
- other types → no artificial target

## Downstream Effects

Because all Study State First consumers already use StudyLearningTypeRouter, an override automatically changes:

- Missing Context
- Study Method Recommendation
- Score Baseline behavior
- Scope requirements
- Recall vs Practice vs Practical Evidence
- Score Exam Current State
- Study Activity page

No duplicate override logic should be added to downstream services.

## Authorization

Learning Type override changes Plan-level Study behavior.

Initial implementation allows actors who can edit the Plan to update/reset the override.

Read-only viewers cannot mutate it.

## Safety / Compatibility

V56.17:

- no AI call
- no provider call
- no Task mutation
- no Practice Session mutation
- no Evidence mutation
- no Workspace Mode mutation
- preserves all existing strong heuristic routes
- explicit general_learning is a valid intentional choice and must not trigger confirmation again
