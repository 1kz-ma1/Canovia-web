# V41.19 — Session / Service Worker / Home Performance Step 2

## Purpose

V41.18のproduction再計測で、Canovia側のDB往復削減は効果を確認できた。

- Roadmap: 約2.18s / 21 queries → 約1.70s / 16 queries
- Timeline: 約1.26s → 約1.09〜1.14s
- Inbox: query数は減少したが、database sessionだけで約0.5s残る
- Home: 約3.2〜4.0s / 32〜34 queries。Task Evidence N+1等が残る
- Navigation Preload由来の二重GETが二重タップ防止後も残る

V41.19では次の3点を分離して改善する。

1. 古いService Worker登録に残るNavigation Preloadを確実に無効化
2. production sessionをRedisへ移せるruntime / config基盤
3. Home Current Task EvidenceのN+1削減

## Service Worker

### Registration repair

public/sw.js のCACHE_VERSIONを canovia-shell-v41-19-1 へ更新し、
既存端末へ新workerのinstall / activateを強制する。

Navigation Preloadは以下の3段階でdisableする。

- worker install
- worker activate
- mountInstantStartServiceWorker() でregistration直後

これにより、過去versionでnavigation preloadがONになったregistrationも
新しいページが起動した時点で修復する。

Instant Startの対象route / offline fallback / mutation境界は変更しない。

## Redis session readiness

V41.17〜V41.18の実測では、database session read/writeだけで
1 requestあたり約0.5sを占めるケースが継続した。

### Config

productionでdatabase driverを強制していたsession configを変更し、
SESSION_DRIVER をproductionでも尊重する。

defaultは引き続き database なので、
このPRをmergeしただけではsession storageは変わらない。

### Runtime

Render Key Valueへ切り替えられるよう、production Docker imageへ
phpredis extensionを追加する。

.env.exampleには以下を追加する。

- SESSION_CONNECTION
- REDIS_URL
- Redis session切替例

実際のRender Key Value作成とenvironment切替は、
コードdeploy後の独立したinfra stepとして行う。

### Local cache permission

storage と bootstrap/cache を www-data 所有へ統一する。

V41.18で追加したRelease Notes file cacheがproductionでwriteできず
毎request DBへfallbackしている可能性があるため、
同時にruntime file cacheの書込条件を保証する。

## Home Evidence batching

V41.18 production logでCurrent Task Evidenceの同一query shapeが
Plan数分繰り返されていた。

V41.19では、

$currentTask->evidences()->take(8)->get()

をPlanごとに実行するのをやめる。

Guidance / fallback選定後のCurrent Task群をEloquent Collectionへまとめ、
evidences をeager loading limitで各Task最大8件だけ一括取得する。

これにより:

- Plan数に応じたEvidence N+1を1 queryへ
- Taskごとの最大8件という既存UI境界を維持
- 全Evidence履歴の無制限ロードを回避

Recommendation / Goal / Progress / Evidence semanticsは変更しない。
