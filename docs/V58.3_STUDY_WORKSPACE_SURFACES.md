# V58.3 Study Workspace Focused Surfaces

Status: implemented / validated  
Branch: `feature/v58-3-study-workspace-surfaces`

## 1. Goal

Apply the same daily-use information architecture used by Developer Workspace
to the Study Plan Workspace:

> one screen = one information / operation lineage

V58.2 already moved Study Plan selection and mode-level preparation to Study
Top. V58.3 now reduces the Study Plan Workspace from one long mixed page into
focused, selectable Study views.

The Study State First engine remains authoritative.

---

## 2. Canonical hierarchy

```text
Study Top
→ choose / create / prepare Plan
→ open one Study Plan

Study Plan Workspace
→ current Plan
→ choose one Study View
→ render only that information / operation stream
```

Study Top remains responsible for multi-Plan selection.

The Plan Workspace keeps:

- `← 学習トップへ`
- current Plan identity
- one compact View selector

No multi-Plan dropdown returns to the Plan Workspace.

---

## 3. Initial implemented Study views

Only real current capabilities are exposed.

```text
実行
└─ 今やること

準備
└─ 学習準備

分析
└─ 学習分析

記録
└─ 履歴
```

Canonical query contract:

```text
/workspace/study?plan_id=...&surface=work
/workspace/study?plan_id=...&surface=preparation
/workspace/study?plan_id=...&surface=analysis
/workspace/study?plan_id=...&surface=history
```

Missing / unknown `surface` falls back to `work`.

Existing `?plan_id=` deep links remain valid.

---

## 4. Study State First preservation

V58.3 must **not** replace:

- `StudyAdaptiveActionService`
- `StudyLearningTypeRouter`
- `StudyWorkspaceStateResolver`
- `StudyWorkspaceRecommendationService`
- `StudyMethodRecommendationService`
- `StudyWorkspaceSurfacePolicy`
- `StudyIntelligencePresentationAdapter`

The current composition is still built once for the selected Plan.

V58.3 only projects the composed surfaces into one selected Study View.

No second recommendation or readiness algorithm is introduced.

---

## 5. Surface-to-view mapping

The existing composition surface keys are assigned as follows.

### 実行 / work

Purpose:

> What should I do now, and how do I start?

Composition surfaces:

- `missing_context`
- `study_method_recommendation`
- `study_recommendation`
- `current_action`
- `study_methods`

Additional execution-local content:

- existing Execution Setup when applicable
- latest Intelligence state-change feedback when useful

Blocking missing context remains visible here because it directly changes
whether the learner can execute now.

### 準備 / preparation

Purpose:

> What inputs and study material should I prepare or correct?

Composition surfaces:

- `goal_summary`
- `learning_type_confirmation`

Existing real navigation cards:

- Study Scope
- Resources
- Study Scores
- Plan detail

No new Study provider or preparation model is invented.

If preparation is already sufficient, the page still acts as the stable place
to maintain these inputs.

### 分析 / analysis

Purpose:

> What does Canovia currently know about my learning state?

Composition surfaces:

- `current_state`
- `readiness`
- `biggest_gap`
- `weaknesses`
- `recent_results`
- `scope_coverage`

This view is observation/analysis only.

Opening it must not mutate Task progress or create Tasks.

### 記録 / history

Purpose:

> What decisions, actions and state changes have already happened?

Content:

- existing Intelligence Decision history
- existing Action history
- existing State / Evidence history
- links to Study Scores where applicable

No new history table is introduced.

## 6. View navigation

The Study Plan Workspace shell uses the same growth pattern as Developer:

```text
STUDY   [実行]
Plan title

VIEW [ 今やること ▾ ]
```

The select is grouped with semantic categories:

```html
<optgroup label="実行">
<optgroup label="準備">
<optgroup label="分析">
<optgroup label="記録">
```

Only implemented views are shown.

Future Study screens can extend metadata without adding another global
horizontal tab row.

---

## 7. View projection service

Add a small Study Workspace navigation/projection service.

Proposed:

```php
StudyWorkspaceViewService
```

Responsibilities:

- validate / resolve selected `surface`
- define current View metadata
- group View metadata for the selector
- filter existing composition surfaces by surface key

It must not:

- call AI
- query GitHub
- alter Study Intelligence
- mutate Plan / Task
- create Evidence

---

## 8. Work surface behavior

The default Study View is `work`.

The learner should see the smallest useful execution stream.

Execution Setup remains here because it changes how the current Task is run.

The current State dashboard, full Readiness metrics, weakness cards, recent
scores and history do not render on the default Work view.

This is the primary vertical-scroll reduction.

Practice / Recall / Guided Execution continue to use their existing dedicated
routes and focused UIs.

---

## 9. Preparation surface behavior

The preparation surface reuses existing routes:

- `plans.study_scope.index`
- `plans.resources.index`
- `plans.study_scores.index`
- `plans.show`

It may show factual counters from existing selected-Plan state, but should not
introduce expensive remote reads or AI.

Study Top remains the mode-level Plan preparation overview.

This Plan-level preparation view is for maintaining inputs of the currently
selected Plan.

---

## 10. Analysis surface behavior

The Analysis page should contain only analytical state.

Important distinction:

```text
Work
→ decide / execute now

Analysis
→ inspect why / where / how ready
```

Current State and Readiness are not duplicated into Work merely for
orientation.

If a blocking missing context exists, Work shows the actionable missing-context
surface; Analysis can still show the state facts available to Canovia.

---

## 11. History surface behavior

Move the existing always-visible History section to the `history` view.

This removes a large permanent page tail from all other views.

The data source remains:

`IntelligencePresentationHistoryService`

No provider / AI calls are added.

---

## 12. Empty states

If the selected View has no composed surfaces:

- render a specific, honest empty state
- preserve relevant existing navigation links
- never invent analysis or learning evidence

Examples:

```text
分析:
まだ分析できる学習Evidenceがありません。
→ 今やることへ

履歴:
保存済みのStudy Intelligence履歴はまだありません。
```

---

## 13. Performance boundary

V58.3 initially preserves the current single selected-Plan Study Intelligence
evaluation path for compatibility.

It does not add additional evaluations per View.

Important:

- one Study Plan only
- one current composition only
- no AI call added by View selection
- no remote provider read added by View selection

A future optimization may selectively avoid unnecessary projections, but that is
not required for V58.3.

---

## 14. URL / compatibility boundary

Existing links without `surface`:

```text
/workspace/study?plan_id=123
```

continue to work and resolve to:

```text
surface=work
```

Existing external routes remain unchanged:

- Study Scope
- Study Practice
- Study Recall
- Study Activity
- Study Scores
- Resources
- Guided Execution

No redirect migration is required.
