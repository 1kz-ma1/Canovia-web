# V51.10 Interaction Smoothness

## Purpose

V51.9.8でWeb/PWAの実機UIを仕上げた後、V51.10では操作感のhot pathを改善する。

V51.8 client telemetryでは、iOS PWAのcache hitは:

- Home: 92〜108ms
- Constellation: 73〜92ms
- Surface mount: 0〜5ms
- Long Task: 0
- Layout Shift: 0

まで下がっている。

一方でprefetchがtap直前に始まったcaseでは:

- Roadmap prefetch navigation: 約1.6〜1.9s
- Home prefetch navigation: 約2.3s

のwaitが観測された。

したがってV51.10ではDOM mountを再設計せず、navigation orchestrationを優先して改善する。

## 1. History Scroll Restoration

従来のInstant NavigationはBack / Forwardでも:

`scroll: true`

を渡し、常にpage topへ戻していた。

V51.10ではhistory entryごとに:

`canoviaScroll: { x, y }`

を保存する。

### Push navigation

新しいcore Surfaceへ移動する直前に現在entryへ現在scroll位置を:

`history.replaceState()`

で保存する。

新しいentryは初期scroll:

`{ x: 0, y: 0 }`

を持つ。

### Popstate

Back / Forwardでは:

`event.state.canoviaScroll`

をrestoreする。

存在しないlegacy entryはtopへfallbackする。

### Browser contract

core Instant Navigation mount中は:

`history.scrollRestoration = 'manual'`

とし、browser自動復元との二重適用を避ける。

memory only / history state onlyであり、DB / localStorage / IndexedDBへscroll位置は保存しない。

## 2. Touch Intent Prefetch

従来はdocument `touchstart` captureで即prefetchしていた。

これはhorizontal rail / page scroll開始時でも、指がlink上に触れただけでnetwork requestを開始し得る。

V51.10ではtouch intentをgesture-awareにする。

### Start

single touchかつcore link上だけintentを作成。

90ms静止した場合にprefetchする。

### Move

start pointから:

`hypot(deltaX, deltaY) > 12px`

でintentをcancelする。

これにより:

- Home horizontal Plan deck
- Home attention rail
- Execution candidate rail
- Constellation rail

のswipeで不要prefetchを始めにくくする。

### End

90ms未満のtapでもtouchend時にmovement cancelされていなければprefetchを開始する。

直後のclick navigationは同じinflight requestをreuseする。

### Pointer / keyboard

mouse/pen pointeroverとkeyboard focusinは従来どおりintent prefetch。

touch pointeroverはignoreし、touch-specific pathへ一本化する。

## 3. Revalidate Coalescing

V51.8でcache / prefetched page表示後のserver-side navigate semanticsをidle revalidateへ移した。

V51.10では同じURLへ複数のidle revalidateが予約されるのを防ぐ。

`revalidateByKey` Mapでcache keyごとに最大1 pending handleとする。

run時:

- Setからhandle削除
- Mapからkey削除
- `fetchPayload(target, 'navigate')`

を実行する。

このためV41.20のhuman-action boundaryは維持する。

つまりcache/prefetch表示後も実訪問としてnavigate requestは残すが、同一URLへの重複予約だけを削る。

## 4. Cleanup

dispose時は:

- pending idle revalidate cancel
- revalidateByKey clear
- touch intent timer cancel
- touchstart/move/end/cancel listeners remove
- popstate listener remove

を行う。

Instant Navigation remount時にlistener / timerが累積しない。

## 5. Non-goals

V51.10では以下を行わない。

- DOMParserの全面廃止
- SPA化
- client-side source of truth化
- server visit semanticsの削除
- cache persistence
- DB migration
- native iOS bridge

Telemetry上render/mountは現在主因ではないため、DOMParser / render architectureは実測が悪化した場合のみ次段で扱う。
