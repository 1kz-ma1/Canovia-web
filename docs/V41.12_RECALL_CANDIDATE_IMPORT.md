# V41.12 Recall Candidate Import

## Goal

RecallカードをAIが自動生成して即Deckへ入れるのではなく、教材を根拠にCandidateを作り、人が確認したものだけ学習資産へ昇格する。

V41.9のQuestion Candidateと同じく、AI出力と正規の学習資産の間にHuman Review境界を置く。

## Flow

```text
Reference book photo / Screenshot / PDF / pasted text
  ↓
private StudyRecallSource
  ↓
Canovia Native AI
  ↓
StudyRecallCandidate (pending)
  ↓
Human Review
  ├─ edit front / back / note
  ├─ promote selected
  └─ reject selected
  ↓
StudyRecallItem
  ↓
Recall Learning Loop
```

## Source

`study_recall_sources` はTask単位で以下を保持する。

- source_type: image / pdf / text
- original_name
- mime_type
- private storage path
- pasted source_text
- Native AI run ID
- extraction status
- newly created candidate count

画像/PDFはpublic storageに置かず、所有権チェック付きrouteからのみ閲覧する。

### Upload limits

Canovia側ではV41.12時点で以下に制限する。

- PDF / JPEG / PNG / WEBP
- 1ファイル最大10MB
- pasted text最大50,000文字

大きな参考書全体ではなく、カード化したいページを絞ることを推奨する。

## Native AI input

既存 `NativeAiGateway` を拡張し、従来のtext-only呼び出しを壊さずoptional `inputParts` を受け取る。

- image: Responses API `input_image` + Base64 data URL
- PDF: Responses API `input_file` + Base64 `file_data`
- text: 従来どおりinput_text

NativeAiRunのrequest_hashにはBase64本体を保存せず、入力partのSHA-256のみ利用する。

## Candidate contract

AIは最大30件を返す。

各Candidate:

- prompt
- answer
- note
- tags
- source_excerpt
- confidence 0-100

Rules:

- Sourceにない知識を推測しない
- 1カード1論点
- Frontに答えを含めない
- Backは短くする
- 根拠が曖昧なら生成しない
- quantityよりquality

`task_id + fingerprint(prompt|answer)` で重複Candidateを防ぐ。

## Human Review

Candidateは初期状態 `pending`。

ユーザーはReview UIで:

- candidateを選択
- frontを修正
- backを修正
- noteを修正
- 選択したものを一括Promote
- 選択したものをReject

できる。

Promote時もStudyRecallItem側のfingerprintを再計算し、既存Deckに同一カードがあれば新規作成せず既存Itemへ紐づける。

AI Candidateが自動でRecall Deckへ入る経路は作らない。

## Entitlement

Recall Learning Loopと手動カード追加はAutomatic AIを必要としない。

教材からの自動Candidate抽出だけを `AutomaticAiExecution` entitlement配下に置く。

Freeでも努力そのものは可能で、Premiumは教材からカードへ整理する摩擦を引き受ける。

## Privacy / storage

- API credentialはserver-sideのみ
- Source uploadはprivate storage
- Source閲覧はPlan/Task authorization必須
- NativeAiRun metadataにはsource ID / type / MIME等のみ
- Base64 source bytesをDBへ保存しない

## V58.7 Retry update

The V41.12 follow-up "failed Sourceの再抽出UI" is implemented in V58.7.

A failed Source can be explicitly retried from its existing private text/image/
PDF material. The same Source row and existing Candidate extraction service are
reused, and the Candidate Human Review boundary remains unchanged.

V58.7 does not fetch Plan Resource URLs. Plan Resource material ingest remains a
separate follow-up because current Resources store shared references rather than
trusted local file bytes.

See `docs/V58.7_RECALL_SOURCE_RETRY.md`.
