# V46.9 GitHub Decision → Execution Coordination Bridge

## Goal

V46.8で人がGitHub Evidenceを確認してTask状態を確定した後、
そのTask完了がDependency graphと既存Execution Packet / Distributionへ与える影響を、
自動実行せずに可視化する。

```text
GitHub Evidence
  ↓
Human-confirmed Task Decision
  ↓
Task complete
  ↓
Execution Coordination Projection
  ├─ ready direct dependents
  ├─ still-blocked direct dependents
  ├─ stale individual instructions
  └─ stale distribution targets
        ↓
Human chooses next target / actor / generation mode
        ↓
Execution Packet / Distribution regenerated
```

Coordinationは「次に誰へ何を渡すべきかを自動決定するAgent」ではない。
現在のcanonical Task / Dependency / Evidenceとsession上の生成済み指示から、
人が次の分配判断をしやすくするProjectionである。

## Source boundary

Source of Truth:

- Task
- task_dependencies
- TaskEvidence
- Plan / Resource / Artifact
- current Execution Context

短命なexecution session:

- individual Execution Packet / External Prompt
- Distribution Bundle

Coordination専用DB Entityは追加しない。

## Trigger

V46.9のCoordination Projectionはsource Taskが:

- status = done
- または progress_percent >= 100

の場合だけ表示する。

GitHub由来の完了に限定しない。
V46.8が最初の入口だが、将来ほかのHuman-confirmed completion pathからも再利用できる。

unfinished / cancelled sourceから後続実行を解放したとは扱わない。

## Direct dependents

source Taskをdependencyに持つ同Plan内Taskをdirect dependentとして再評価する。

active dependentだけを:

- ready
- blocked

に分類する。

### ready

全dependencyが:

- status = done
- または progress_percent >= 100

を満たす。

UIでは「次に実行できるTask」として表示し、
個別Execution Orchestrationへの導線を出す。

Task自体をdoingへ変更しない。

source Taskが完了・中止済みの場合は、個別Execution Orchestrationの新規Packet生成 / External Packet importもserver-sideで拒否する。過去に生成済みのPacket / Promptは履歴として読めるが、次の実行対象はCoordinationから選ぶ。

### blocked

source以外にも未完了dependencyが残る。

UIでは残っているblocker:

- Task title
- status
- progress

を表示する。

「sourceが完了したから後続も開始可能」と短絡しない。

## Existing individual instruction staleness

direct dependentに既存の:

- Execution Packet
- External AI Prompt

がsession上に存在する場合、
保存されているcontext_fingerprintとcurrent canonical fingerprintを比較する。

一致しなければ:

`stale_individual_instructions`

として表示する。

古いPrompt / Packet本文は:

- 自動削除しない
- 自動再生成しない
- 自動実行しない

人が現在Contextで再生成する。

## Distribution Bundle staleness

Planにsession-scoped Distribution Bundleが存在する場合、
既存 `ExecutionDistributionService::refreshStaleness()` を再利用する。

source完了後のcanonical Contextで各targetを再評価し、
stale flag / dependency_stateをsession Projectionへ更新する。

変更しない:

- target Task
- actor label
- actor type
- Packet
- Prompt
- generation mode

つまり古いBundleは「何を渡していたか」の確認用として残り、
再生成は人がDistribution画面で行う。

## Recommended distribution targets

CoordinationからDistribution画面へ渡すのはTask IDのsuggestionだけ。

候補:

1. ready direct dependents
2. stale Distribution targetのうちactive + dependency_state=ready
3. stale individual instructionのうちdependency_state=ready

最大8件。

このsuggestionは永続化しない。
GET queryの `suggested_task_ids` としてDistributionへ渡す。

DistributionControllerは:

- current Planのactive Taskだけ
- MAX_TARGETS以内

へserver-sideでintersectする。

他Plan / done / cancelled / 不正IDは無視する。

suggestionだけではPacket / Promptを作らない。
Distribution画面で人が:

- target
- actor label
- actor type
- available minutes
- Native / External generation

を確認してsubmitして初めて生成する。

## UI

Execution Orchestrationへ `EXECUTION COORDINATION` を追加する。

Summary:

- READY NEXT
- STILL BLOCKED
- INDIVIDUAL STALE
- DISTRIBUTION STALE

Ready direct dependent:

- Task title
- status / progress
- ready state
- 個別Orchestration

Blocked dependent:

- remaining blocker list

Stale instruction:

- Task / actor label
- stale reason
- current Contextへの導線

Primary coordination action:

`次の担当候補を分配画面で確認`

これは再分配ではなく、Distribution画面のpreselection。

## Human agency boundary

V46.9は以下を自動実行しない。

- 後続Taskをdoingへ変更
- Task priority変更
- actor assignment
- Packet再生成
- External Prompt再生成
- Native AI call
- Distribution submit
- Dependency追加 / 削除
- Task作成 / 完了

Canoviaは「今readyな後続」と「古くなった指示」を提示するだけ。

## Relationship to V47 Context fingerprint

source Taskが完了すると、
V47 canonical Execution Contextの:

- selected Task state
- dependencies
- current_tasks
- Evidence

等が変わる。

その結果、既存Packet / Distribution targetは通常のcontext_fingerprintでstaleになる。

V46.9は新しいstaleルールを作らず、
V47.0 / V47.2の既存契約をCoordination UXへ接続する。

## Performance

direct dependentのreadiness判定はPlan tasks + dependency graphから行う。

current context fingerprintの再構築は:

- 生成済みindividual instructionがあるdirect dependent
- active Distribution target

に限定する。

Distributionは既存MAX_TARGETS=8の上限を維持する。

## Non-goals

- autonomous multi-agent loop
- automatic assignment
- automatic Packet regeneration
- automatic Distribution
- Task auto-start
- transitive dependency traversalによる大量自動展開
- webhook
- background polling
- new durable coordination entity
