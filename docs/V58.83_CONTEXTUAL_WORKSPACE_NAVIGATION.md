# V58.83 Contextual Workspace Navigation (2026-10-08)

## Intent / scope
- Home is cross-domain Overview, never a redirect based on Workspace preferences.
- Within dedicated activity routes, the primary header/footer switches from global nav to fixed-order Study → Development → Career; no Overview mode or global selector within that strip.
- A visible header-level 「← ホーム」 exit returns to cross-domain status without resetting a LearningRun or stopping Exam time.
- Global nav: Home / Workspace / Timeline / More. 「星座」「従来の実行」「カレンダー」 move into More; their routes and DB are retained.
- Existing WorkspaceMode registry and old mode persistence endpoints remain backward-compatible internally, but the old selector is no longer in the global header.

## Resume
- GET /workspace chooses the last visited **visible** Workspace; GET /workspace/mode/{mode} returns to that mode's last permitted visited screen, falling back to its top.
- Only whitelisted successful GET routes are saved in a session entry namespaced by authenticated user ID or guest. Instant navigation prefetch/fragment, POST, arbitrary query inputs are ignored.
- Before reentry, saved Plan/Task membership is validated. Destination controllers remain the final authorization authority.
- This stores navigation history only, not study answers, active exam timer, UI draft data, or a cross-device preference.
- Fixed tab order to preserve muscle memory. Drag-reordering and cross-device persistent history are later proposals.

## Remaining verification
- GitHub CI covers controller and DOM render behavior; iOS WKWebView, mobile tap targets, modal layering, and production Render E2E are not yet verified.
- External important-notification dot is not implemented (needs reliable signal aggregation).
- Review all legacy nav contract tests and downstream onboarding selectors before production release.
