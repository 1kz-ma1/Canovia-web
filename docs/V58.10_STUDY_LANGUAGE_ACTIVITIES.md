# V58.10 Study Language Activities

Status: implemented / validated  
Branch: `feature/v58-10-study-language-activities`

## 1. Goal

Add real executable Study Activities for language listening work without
pretending Canovia already has speech recognition or pronunciation grading.

Implemented first-class Study Activity keys:

```text
listening
dictation
shadowing
```

They join the existing:

```text
question_practice
recall
resource_study
```

Flow:

```text
Task semantics
→ Study Activity Policy
→ state-aware Study Method Recommendation
→ dedicated language Activity surface
→ learner opens existing Resource
→ performs Activity
→ explicit self-report
→ Task Evidence
```

## 2. Semantic routing

### Listening

Strong Task terms include:

- リスニング
- listening
- 聴解
- 聞き取り
- 聞き取る
- 音声を聞く

### Dictation

Strong Task terms include:

- ディクテーション
- dictation
- 書き取り
- 聞き取って書く
- 音声を書き取る

### Shadowing

Strong Task terms include:

- シャドーイング
- shadowing
- 音声に続いて
- 復唱
- 発音練習

Explicit scored-practice intent remains stronger.

Examples:

```text
TOEICリスニング問題演習
→ Question Practice

TOEIC音声を聞いて内容を理解する
→ Listening

英文をディクテーションする
→ Dictation

英語音声をシャドーイングする
→ Shadowing
```

This keeps "listening questions" distinct from "listening practice".

## 3. State-aware Study Method Recommendation

V56.15 Study Method Recommendation now preserves explicit language Task
semantics.

After resume continuity / required school Scope organization, a Task whose
semantic primary Activity is Listening / Dictation / Shadowing keeps that
Activity rather than being collapsed into plan-level memorization, exam-mode
Question Practice or generic defaults.

This protects the Task's concrete execution intent.

## 4. Execution capability

V58.10 adds:

```text
study.language
```

Listening / Dictation / Shadowing all resolve to this capability.

Native provider:

```text
canovia.study.language
```

No external language provider is added.

The existing execution ecosystem can therefore reason about language execution
as a semantic capability instead of treating it as generic Question Practice.

## 5. Dedicated execution surface

Routes:

```text
GET  /plans/{plan}/tasks/{task}/study-language/{activity}
POST /plans/{plan}/tasks/{task}/study-language/{activity}
```

Supported `activity` values:

- listening
- dictation
- shadowing

The surface is native, server-rendered and provider-free.

It shows:

- selected Activity
- Activity-specific execution steps
- Task-scoped Resources when present
- otherwise Plan Resources
- explicit self-report form
- recent Evidence from the same Activity type

No microphone permission is requested.

No audio is uploaded to Canovia.

## 6. Activity guidance

### Listening

1. first listen without transcript / answer;
2. identify the main meaning and missed sections;
3. replay only difficult sections;
4. compare with transcript/material only after attempting to listen.

### Dictation

1. listen to a short segment;
2. write only what was actually heard;
3. compare against transcript/material;
4. retry difficult sound / word-boundary sections.

### Shadowing

1. listen once for rhythm and stress;
2. repeat immediately after the audio;
3. split difficult chunks;
4. repeat until timing feels stable.

The guidance avoids claiming automatic correctness.

## 7. Existing Resource usage

The surface opens existing PlanResource URLs in the browser.

Task-linked Resources are preferred; otherwise Plan Resources are shown.

Canovia does not server-fetch the Resource URL or inspect its contents in
V58.10.

This preserves the existing Resource security boundary.

## 8. Explicit Evidence

Submitting the outcome form records:

```text
study_language_activity_completed
```

Known metadata:

- activity_type
- rounds
- outcome_rating
- resource_count

Optional user reflection is also stored in TaskEvidence metadata.

Outcome values:

```text
struggled
partial
comfortable
```

Evidence confidence:

```text
0.6
```

This is intentionally below objective Question Practice assessment.

Stable idempotency key:

```text
study-language:{activity}:{request_uuid}
```

A repeated form submission with the same UUID therefore does not duplicate the
Evidence row.

## 9. Intelligence normalization

`TaskEvidenceAdapter` allows only these language Activity facts across the
normalized Intelligence boundary:

- activity_type
- rounds
- outcome_rating

It does not expose:

- reflection
- Resource URL
- arbitrary Resource metadata

The free-text reflection remains local Evidence context.

## 10. Progress boundary

Language Activity Evidence confirms that the learner performed the Activity.

It does not automatically:

- change `progress_percent`
- change `remaining_minutes`
- mark the Task done
- satisfy Question Practice mastery
- satisfy Recall mastery

A self-reported language session is not treated as objective Task completion.

## 11. Evidence readability

`TaskEvidence::typeLabel()` renders this Evidence as:

`語学Activity`

`TaskEvidence::summary()` renders:

- Activity name
- rounds / sets
- self-rated outcome

This makes Timeline / Evidence surfaces understandable without exposing raw
reflection text as normalized intelligence.

## 12. Free path

Listening / Dictation / Shadowing execution is native non-AI Study behavior.

It does not require:

- Automatic AI Execution
- AI Practice entitlement

The user can perform and record the Activity with existing Resource links.

## 13. No speculative audio features

V58.10 intentionally does not add:

- speech recognition
- microphone recording
- pronunciation scoring
- automatic dictation grading
- audio waveform analysis
- background transcription
- remote Resource fetching

These need separate capability / privacy / quality contracts before
implementation.

## 14. No migration

No database migration is required.

Existing TaskEvidence and PlanResource contracts are sufficient.

