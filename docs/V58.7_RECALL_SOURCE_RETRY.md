# V58.7 Recall Source Retry

Status: implemented / validated  
Branch: `feature/v58-7-recall-source-retry`

## 1. Goal

Allow a failed Recall material extraction to be retried from the already saved
private `StudyRecallSource` without making the learner upload or paste the
same material again.

```text
saved StudyRecallSource
→ extraction failed
→ source remains private + failed
→ explicit Retry
→ existing extraction service
→ pending Recall Candidates
→ Human Review
```

There is no background retry.

## 2. Supported sources

V58.7 reuses the V41.12 source contract:

- text
- image
- pdf

`StudyRecallSource::hasStoredMaterial()` defines whether the original material
is still available.

Text requires non-empty `source_text`.

Image / PDF requires an existing private `storage_path`.

No remote URL is fetched.

## 3. Retry eligibility

Retry is accepted only when:

1. the selected Plan is Study;
2. the Task belongs to that Plan;
3. the actor can edit the Task;
4. Automatic AI Execution is available;
5. the Source belongs to the same Plan and Task;
6. Source status is `failed`;
7. saved source material still exists.

The server rechecks all of these conditions on the POST action.

## 4. Reuse, not replacement

Retry reuses the same `study_recall_sources.id`.

It does not create a replacement Source and does not ask the user to duplicate
the material.

The existing `StudyRecallCandidateExtractionService` remains the single
candidate extraction path.

On success:

- Source status becomes `ready`;
- latest Native AI run ID is stored;
- `candidate_count` stores newly created candidates;
- existing Human Review flow is unchanged.

On another Native AI failure:

- Source remains `failed`;
- the latest failed run is retained by the existing extractor;
- the learner may retry again after resolving the provider/configuration issue.

## 5. Duplicate safety

The existing candidate uniqueness rule remains authoritative:

```text
task_id + fingerprint(prompt|answer)
```

If a retry returns candidate content that already exists for the Task, a second
candidate row is not created.

V58.7 does not reset pending, promoted or rejected candidate state.

## 6. Recall UI

The "最近取り込んだ教材" section now projects Source status explicitly:

- 抽出失敗
- 抽出済み
- 処理中

A failed Source shows the `再抽出` action only when:

- the saved material is still available; and
- Automatic AI extraction is currently available.

Ready / pending Sources never expose the retry action.

Private file access still uses the existing authorized Source file route.

## 7. Security and privacy

V58.7 intentionally does not implement Plan Resource URL fetching.

Current Plan Resource is a reference URL contract, not a trusted local file
contract. Server-side fetching arbitrary Resource URLs would introduce SSRF,
authentication and provider-page ambiguity.

Therefore:

```text
saved Recall Source bytes/text → retry allowed
arbitrary Plan Resource URL    → not fetched
```

This keeps V41.12 private material handling unchanged.

## 8. Entitlement

Recall learning and manually created Recall cards remain available without
Automatic AI.

Retrying AI extraction uses the same `AutomaticAiExecution` entitlement as the
original material extraction.

V58.7 introduces no new capability or billing rule.

## 9. No migration

No database migration is required.

Existing Source, Candidate and Native AI Run state is sufficient.

Failed extraction is now recoverable without repeating material intake:

```text
upload / paste once
→ extraction fails
→ fix provider/config issue
→ Retry
→ Candidate review
→ Recall Deck
```

The retry path stays inside the existing private Source and candidate Human
Review boundaries.
