# V49.8 Dashboard Surface Refinement

## 目的

V49.7でPlan / Task detailをDashboard × MapのDocument Canvasへ移行した結果、Mobileでも情報を1枚の広い資料として扱えるようになった。

実機確認では次の問題が残った。

- DocumentとNavigation Chromeが同じhorizontal scrollへ入り、戻る・タイトルまで画面外へ流れる
- Dashboard中もGlobal Navigation / Page / Data Layer等のMap chromeが残り、情報閲覧面積を圧迫する
- 固定幅Canvasは成立しているが、単に横長Webページをスクロールしているように見える
- Task DashboardのSummaryとActionsが離れすぎ、一枚のDashboardとしてまとまりに欠ける
- standalone PWAのleft-edge backとDocument horizontal panが競合し得る
- 現在Documentのどの横位置を見ているか分かりにくい

V49.8では、Documentを見るためのUIとDocument本体を明確に分離する。

## 1. Document structure

Plan / leaf Detailは次の3層とする。

```text
Document Viewport
├─ Fixed Document Chrome
│  ├─ Back
│  ├─ Context title
│  └─ Primary / Close action
├─ Scroll Viewport
│  └─ Document Canvas
└─ Position HUD
```

DOM contract:

- `data-map-document-viewport`: Document surface全体
- `data-map-document-chrome`: Viewport固定navigation
- `data-map-document-scroll`: pan対象
- `data-map-document-canvas`: 1枚の資料本体
- `data-map-document-position`: horizontal position HUD

Back / title / closeはDocument Canvasへ入れない。

## 2. Compact Document Mode

Plan Dashboardはfirst paintから:

- `is-document-mode`
- `is-plan-document-mode`

を持つ。

leaf Detailを開いた間だけ:

- `is-document-mode`
- `is-detail-document-mode`
- Detail Surface `is-dashboard-document`

をruntimeで付与する。

leaf以外のUtility Surface / Space StationはCompact Document Modeへ入れない。

### Mobile chrome

Document Mode中は:

- Fullscreen Topbarを1行のcompact barへ縮退
- hero kickerを非表示
- Map Global Navigationを非表示
- Page / Data Layer controlsを非表示
- Map gesture controlsを非活性化
- Spatial Dockを非活性化

Document Chromeがnavigation責務を持つため、Dashboard閲覧中にMap chromeを重複させない。

Classic / Map surface switchはcompact sizeで残す。

## 3. Plan Dashboard

Plan DashboardのDocument Chrome:

- Back: Plan一覧
- title: Plan title
- metadata: category
- primary action: 実行へ

編集 / Classic Plan等のsecondary actionはDocument内Overviewへ移す。

Mobile Document Canvas:

- width: 約52rem
- outer sheet border / shadow / internal marginを持つ
- Summary rail + Roadmap main area

Document Chrome自体はhorizontal panしない。

## 4. Leaf / Task Dashboard

V49.6のleaf detail-first contractを維持する。

leaf Detailを開くと、templateのcanonical titleを `data-map-document-title-source` からfixed Chromeへ同期する。

Mobile Document Canvas:

- width: 約46rem
- Summaryは全幅
- Context / Metaをmain column
- Actionsをside rail

grid:

```text
┌────────────────────────────┐
│ Summary                    │
├─────────────────┬──────────┤
│ Context         │ Actions  │
├─────────────────┤          │
│ Meta            │          │
└─────────────────┴──────────┘
```

fixed Chromeにcanonical titleを表示するため、Mobile Dashboard bodyでは重複するlarge titleを非表示にしてよい。

## 5. Document position

`data-map-document-scroll` の:

- `scrollLeft`
- `clientWidth`
- `scrollWidth`

から:

- `progress`
- `viewportRatio`

を計算する。

Position HUDのthumb:

- width = viewportRatio
- left = progress × (1 - viewportRatio)

として、現在Documentのどの範囲を見ているかを示す。

scroll position自体は永続化しない。

## 6. PWA edge-back safety

Safari/browserでは引き続きnative edge navigationをCanoviaが奪わない。

standalone PWAでCanovia側left-edge backをarmする条件:

- Document Mode中
- authoritative parent URLあり
- touch primary pointer
- gesture start x <= 28px
- active Document `scrollLeft <= 1px`

commit条件:

- horizontal distance >= 72px
- vertical drift <= 56px
- horizontal > vertical × 1.25

Documentが1pxより右へpanされている場合はedge-backを発火させない。

つまり:

```text
Documentを横に読んでいる
    -> pan

Document左端でさらに右へ引く
    -> parentへ戻る
```

という境界にする。

## 7. Global depth label

V49.7 plan-first hierarchyに合わせてGlobal Navigationのdepth labelも更新する。

Execution:

```text
全体 -> Plan -> 実行
```

Plan:

```text
全体 -> Plan -> Dashboard
```

内部MapLevel enumのDomain / Plan名は互換のため維持するが、UI上のsemantic hierarchyには露出させない。

## 8. Persistence

追加永続化なし。

保存しない:

- document scroll position
- document position HUD
- dashboard mode class
- fixed chrome title
- edge gesture state

## 9. Tests

- left-edge backはscrollLeft=0で成立
- scrollLeft>1では同gestureでも成立しない
- documentScrollMetricsがviewportRatio / progressを返す
- Plan DashboardにChrome / Scroll / Canvas / Position contractが存在
- Detail DashboardにChrome / Scroll / Canvas / dynamic title source / Position contractが存在

## Non-goals

- PDF renderer
- freeform dashboard editor
- document scroll persistence
- Map soft-settle
- gesture physics全面改修
- Desktop全体Navigation再設計

Map soft-settleはDocument Surfaceが安定した後の別改善サイクルで扱う。
