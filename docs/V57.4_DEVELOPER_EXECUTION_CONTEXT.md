# V57.4 Developer Execution Context

## Goal

V57.4 makes the V57.3 Next Action materially more useful by attaching
repository-aware, Task-scoped development context to it.

Canonical flow:

```text
Development Adaptive Action
+ target Task
+ confirmed Task ↔ GitHub Artifact links
+ persisted authoritative TaskEvidence
→ DevelopmentExecutionContextService
→ Action Context / Handoff surface
```

V57.4 is not a second decision engine.

The existing V53.8 Development Adaptive Action remains authoritative for:

- what to do next
- why that action is next
- which Task / Gate is targeted
- what success means

V57.4 only answers:

- which repository / branch / PR is this about?
- what do CI / Review / Deploy currently say?
- what Evidence is already known?
- what Evidence should exist when this Action is done?

## Source authority

Developer Home GET reads only already-persisted Canovia data.

Task-scoped GitHub context may use:

- `pull_request_observed`
- `pull_request_review_submitted`
- `pull_request_ci_observed`
- `pull_request_merged`
- `github_issue_observed`
- `github_branch_observed`
- `github_commit_observed`
- `github_deployment_observed`
- explicitly linked GitHub `PlanArtifact` records

No GitHub REST request is performed by V57.4 Workspace GET.

Webhook / explicit sync services remain responsible for authoritative remote
re-fetch.

## Task scope

Context is always bounded to one unfinished Task.

Selection priority:

1. Development Action target Task
2. Development Intelligence focus Task
3. first active Task using the existing Developer Home ordering

Evidence from another Task must not leak into the selected Task context even
when both Tasks use the same repository.

## Context projection

Initial projection contains, when available:

- repository full name
- branch
- latest commit SHA / verification state
- Pull Request number / state / draft / URL / head/base
- CI state / head SHA
- latest Review state / reviewer
- Issue number / state
- Deployment environment / status / production flag
- up to six explicitly linked GitHub Artifacts
- up to five recent GitHub Evidence summaries

The surface intentionally does not store a new summary row.

It is a read projection over durable Evidence.

## Action handoff

The handoff card reuses the canonical Action:

- title
- intent
- route kind
- success signals

V57.4 adds a deterministic Evidence hint for the current Action.

Examples:

```text
fix CI
→ same Task / PR / head SHA
→ CI success Evidence

review feedback
→ updated Review Evidence
→ approved or newly-requested changes

deploy
→ merge SHA
→ Production deployment success

verification
→ current Release
→ explicit Verification Gate result

spec sync
→ current implementation
→ explicit Spec Sync result
```

These hints are presentation guidance. They do not change Gate evaluation.

## Developer Home UI

The top Next Action surface gains an Action Context area.

The user can see the execution target without leaving Developer Home:

```text
Task
Repository
Branch / Commit
PR
CI
Review
Deploy
Done when
Recent Evidence
```

Unknown facts remain visibly unknown rather than being inferred.

## Privacy / bounded data

V57.4 does not persist or display:

- source code
- diff / patch
- PR body
- Issue body
- commit message
- raw webhook payload

Only bounded state facts already allowed by V53.7 / V57.1 are used.

## Mutation / cost boundary

Developer Home GET does not:

- call GitHub
- call AI
- create TaskEvidence
- create Task associations
- change Task progress
- change Task status
- change remaining minutes
- persist a context snapshot

V57.2 local deterministic suggestion refresh remains the only existing
Workspace GET metadata mutation.

## Compatibility

V57.4 preserves:

- V53.7 Development Evidence
- V53.8 Development Readiness / Adaptive Action
- V57.0 GitHub stabilization
- V57.1 Activity Observation
- V57.2 Human-confirmed Task Association
- V57.3 Developer Home ordering
- existing execution orchestration
- existing GitHub Workflow
