# V58.21 Release Gate / Feature Inventory

> **V58.22 supersession:** `product.preview.index` はV58.22で実装済み。V58.21時点のL2 Blocked記述は当時のRelease Gate状態を示す履歴として残す。現行判断は `docs/V58.22_PRODUCT_PREVIEW.md` と `docs/CANOVIA_RELEASE_LEVEL_SPEC.md` を優先する。

## Goal

V58.20で追加したRelease Level Foundationを、Early Access前の実際の判断に使える状態へ進める。

V58.21では:

- FeatureKeyごとのminimum Release Levelを確定する
- L1 / L2の構造契約を明示する
- 自動検証と手動Release確認を分離する
- Adminから現在のBlockerを確認できるようにする

Canonical contract:

- `docs/CANOVIA_RELEASE_LEVEL_SPEC.md`
- `docs/CANOVIA_MONETIZATION_SPEC.md`
- `docs/CANOVIA_PRODUCT_SPEC.md`

## Responsibility

V58.21で追加するRelease Gateは、公開成熟度だけを判定する。

```text
Release Level
= publication maturity

Feature Flag
= individual runtime publication switch

Entitlement
= actor usage right

Ownership
= resource authorization
```

Release Gateが通ってもPremium / Pro利用権は付与されない。

## Feature maturity inventory

### Level 1 — Early Access Core

現在の安定Coreとして公開可能:

- AI Practice
- Advanced Analytics
- Question Pack
- Project Artifact
- Conversational Onboarding
- Study Scope Capture

ただしFeature Flagを持つ機能は個別Flagの状態を別途尊重する。

L1 promotionで必須扱いするFeature:

- AI Practice
- Question Pack
- Project Artifact
- Study Scope Capture

Conversational Onboarding / Advanced AnalyticsはL1で公開可能だが、L1成立の必須条件にはしない。

### Level 2 — Product Preview

Feature capability unlockは**0件**。

Early AccessのL2は:

- Premium Coming Soon
- Pro Coming Soon
- Dev Pro Coming Soon
- Study / Development experience preview

を表示するpresentation-only Levelとする。

有料CapabilityをL2へ割り当てない。

Canonical Product Preview Surface:

```text
route = product.preview.index
```

V58.21ではこのSurfaceをまだ作らない。
そのためL2 Release Gateは意図的にBlockedとなる。

### Level 3 — Beta Expansion

Beta / pre-release capability候補:

- Automatic AI Execution
- Canovia Companion
- Study Long-term Weakness Profile
- Career Native Capture Analysis
- Developer GitHub Evidence

これらはminimum maturityであり、EntitlementやFeature Flagを迂回しない。

### Level 4 — Internal Preview

- Developer GitHub Write

Repository mutationはrollback / safety contractが別途承認されるまでInternal専用とする。

## Release Gate

Admin route:

```text
GET /admin/release-gate
route = admin.release_gate.index
```

Read-only。

Public Level、Feature Grant、Feature Flagを変更しない。

### Automated checks

- every FeatureKey has one release minimum
- every FeatureKey has an entitlement policy
- every WorkspaceMode has one release minimum
- required Workspace maturity
- required Feature maturity
- required canonical route existence

### Manual checks

- blocker 500 / unintended 403
- mobile / desktop flow
- downgrade / rollback
- disclosure copy
- telemetry / feedback path
- UI理解性
- Beta support boundary

Manual checksは自動承認しない。

## Initial expected state

V58.21実装直後:

```text
L0: automatic checks pass -> manual review
L1: automatic checks pass -> manual review
L2: BLOCKED -> product.preview.index missing
L3: BLOCKED cumulatively because L2 contract is incomplete
L4: BLOCKED cumulatively because L2 contract is incomplete
```

これは正常。

Release Levelは積み上げ構造なので、上位Levelは下位Levelの契約を満たす必要がある。

## Early Access target

Initial target:

```text
Level 1 — Early Access Core
```

V58.21ではPublic Levelは変更しない。

## Non-goals

V58.21では実装しない:

- Product Preview UI
- Premium / Pro / Dev Pro checkout
- pricing
- interest / notification capture
- Public Release LevelのAdmin変更
- automatic promotion
- manual checklist persistence
- Career public promotion
- GitHub Write beta promotion

次段階はL2 Product Preview Surfaceの実装、またはL1手動Release Gateの実機検証。
