# V49.7 Dashboard Map / Document Canvas

> **V49.8 update:** Document ChromeをCanvas scrollから分離し、Mobile Dashboard中はMap chromeをcompact化した。leaf Detailは約46remのDashboard、Planは約52remのsheetとし、horizontal position HUDとscrollLeft=0限定のPWA edge-backを追加した。詳細は `docs/V49.8_DASHBOARD_SURFACE_REFINEMENT.md` を参照。

## 目的

V49.6でSemantic Zoomとleaf detailの責務を分離した結果、スマホでもMapを潜る操作自体は成立した。一方、Plan / Taskなど具体Contextを読む段階では、狭い画面幅へ情報を縦一列に押し込むほどMapとの連続性と一覧性が失われる。

V49.7では詳細表示を「マスの拡大」ではなく Dashboard × Map と定義する。

- Mapは位置関係・Contextを残す
- 詳細情報はDocument CanvasとしてMap上へ開く
- MobileでもDocument自体を画面幅へ縮めず、広い1枚の資料をviewport越しに上下左右へパンして読む
- Plan / Taskで同じDocument interactionを共有する

同時にExecution Intentからcategory/domain navigationを外し、Planを直接配置する。

## 1. Execution hierarchy

### Before

```text
実行
  -> Category / Domain
      -> Plan
          -> Execution
```

### V49.7

```text
実行
  -> Plan
      -> Execution
```

`Plan.category` は削除しない。Node subtitle、filter、将来のclusterなどで使えるmetadataとして保持するが、通常Navigationの1階層にはしない。

L1 technical routeは互換性のため `level=l1` のままだが、意味上は Execution Plan Selection とする。

Execution Plan Nodeからは:

```text
/map?level=l3&intent=execution&plan=<id>
```

へ直接進む。`domain` queryは必須にしない。

Execution Contextのsemantic depthは:

- depth 0: Intent
- depth 1: Plan
- depth 2: Execution

とする。

Executionからのauthoritative parentは:

```text
/map?level=l1&intent=execution
```

とし、戻ると必ずPlan選択へ復帰する。

## 2. Dashboard × Map

具体Contextの詳細はMap Nodeそのものを巨大化しない。

```text
Map
  + selected context
  + Dashboard Document
```

Mapは背景/周辺Contextとして残り、Documentが情報閲覧とActionのsurfaceになる。

### Detail document regions

Node detailは次のregionへ整理する。

- Summary: role / title / summary
- Context: ここにある理由、personalization等
- Meta: 状態・関連情報
- Actions: 次にできること、Companion

Mobile DocumentではSummary/Context/Metaを主領域、Actionsを右側railとして配置する。

## 3. Document Canvas

MobileでDashboardをviewport幅へ強制reflowしない。

Plan Dashboard:

- canvas width: 約54rem
- summary metrics rail + Roadmap main area
- two-dimensional native pan

Node Detail:

- canvas width: 約52rem
- dashboard gridを維持
- viewport height: 約70dvh
- Mapの上部・背面を残す

Document Viewport:

```text
data-map-document-viewport
```

Document Canvas:

```text
data-map-document-canvas
```

とする。

CanvasはDBへサイズやscroll positionを保存しない。

## 4. Back interaction

戻り先は画面の見た目ではなくhierarchyのauthoritative parent URLを使う。

### Explicit control

Plan Dashboard:

- `← Plan一覧`

Execution Detail:

- `← Plan選択`

を常設する。

### Left-edge swipe

Safariブラウザではnative history gestureを妨げない。

standalone PWAのみ、左端28px以内から右方向へ十分な距離をswipeした場合にCanovia側でparent navigationを補完する。

Default recognition:

- horizontal distance >= 72px
- vertical drift <= 56px
- horizontal > vertical * 1.25

Navigationはauthoritative parent URLへ行い、外部ページへ誤って戻らない。

## 5. Plan Dashboard

L2 Plan WorkspaceはPlan Dashboardとして扱う。

既存Classic資産:

- summary-metrics
- Roadmap

を引き続き再利用する。Map専用の進捗計算やRoadmap modelは作らない。

MobileではsummaryとRoadmapを縦一列へ潰さず、広いDocument上で左右に配置する。

## 6. Task / leaf Detail

V49.6のleaf detail-first契約を維持する。

TaskをtapしてもSemantic Zoomしない。

代わりにContext SurfaceをDocument Dashboardとして開く。

選択TaskのMap位置は背面Contextとして維持し、詳細Documentが情報とActionを担当する。

## 7. Compatibility

旧 `execution -> domain -> plan` URLは即削除しない。

L2 execution routeは既存link / bookmark互換のため読める状態を維持してよいが、通常Navigationからは生成しない。

`domain` query付きL3 Executionも引き続きresolve可能。

## 8. Persistence

追加DB persistenceなし。

保存しない:

- document scroll x/y
- document canvas size
- edge swipe state
- dashboard region placement

Plan categoryは既存canonical metadataとして従来通り保存する。

## 9. Tests

- Execution L1にPlanが直接存在する
- Execution L1にDomain Nodeが存在しない
- Execution Plan URLはL3 + plan idへ直接進む
- L3 Execution parentはL1 Execution Plan Selection
- semantic depthはL3 technical routeでも2
- Plan WorkspaceにDocument Viewport / Canvasが存在する
- Detail PaletteにDocument Viewport / Canvas / Back controlが存在する
- edge swipeはleft edge + horizontal deliberate gestureだけ成立する

## Non-goals

- MapLevel enumの即時rename
- category field削除
- old URL migration / redirect強制
- document position persistence
- full freeform dashboard editor
- PDF file rendering
- mobile native navigation stackの置換

V49.7の「PDF-like」はPDF rendererではなく、固定幅の大きな情報資料をviewport越しに読むinteraction modelを指す。
