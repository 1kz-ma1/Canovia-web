# V58.69 — Development Team: recorded Task prerequisites and blockers

## Purpose

P1.1 complements the previously merged intent-first Plan classification (V58.67), explicit owner domain correction (V58.68) and the reversible HINANEX legacy-Creative rescue (V58.63).

The current Team surface shows real users, roles, assigned **artifacts** and activity, but the Task prerequisite graph remains invisible. A team Plan should show a useful read-only work overview **without pretending that an artifact assignee is a Task assignee**.

## Implemented

- Development Workspace → **チーム** only for `is_collaborative=true`.
- `DevelopmentTeamTaskProjectionService` projects **existing** open Tasks (`todo`, `doing`, `paused`), completed count, recorded `prerequisites()` and legacy `depends_on_task_id`.
- A Task is labeled **前提待ち** only when a recorded **same-Plan** prerequisite is incomplete. Completed prerequisites no longer block a Task. Two dependency representations are deduplicated.
- Show the actual prerequisite title and status. Cross-Plan dependency references are omitted from the read-only projection and do not reveal private Task names.
- No Task assignee is inferred from PlanActivityLog, artifact ownership, or GitHub; the Task model has no direct assignee field. Member permissions and existing Team UI remain unchanged.
- Cap DB projection to 80 priority-ordered open Tasks; show first 8 cards. If there are more than 80, communicate that blocker/paused counts are only for the inspected sample; total open and completed counts still cover the Plan.
- Solo Plans are unaffected. The projection runs **only** on the selected Team surface, not for every Work/Home render.
- No Task, Plan, membership, classification, progress, or dependency is written; no new schema or external AI/GitHub requests.

## Acceptance & tests

## Follow-ups

- Current specialization is **a nonpersistent inference hint** from `PlanIntentClassificationService::suggest()`, not a proven subject classification. Separate specialization persistence/UI requires explicit decision and tests.
- User-confirmed direct Task assignments must have their own explicit model and permissions design; avoid inferring from artifacts or activity.
- Improve dependency graph handling at larger scales, ordering and team-specific recommendations after validating actual team usage.
- P1.2: state-backed draft plans arising from actions, with explicit user approval for persistent Task changes.
