# V42.4 Living Map Validation Telemetry

> **V50.0 update:** V42.4で設定した「MapをPrimary Home候補として検証する」という目的は、現在のContextual Map方針では一般化された。Telemetry flow自体は維持するが、V50.0以降はGlobal / Plan / Collaboration / Reflection / Execution等のSurface Role別に適合性を観測し、Map / Classicの優先Surfaceを自動決定しない。現在仕様は `docs/V50.0_CONTEXTUAL_MAP_FOUNDATION.md` を参照。

## Goal

Canovia MapをPrimary Homeへ昇格させるかを、見た目や好みだけで決めない。

V42.4はMapの実利用をFlow単位で計測し、既存Classic HomeのWork開始時間と参考比較できる判断基盤を追加する。

Primary Homeへの昇格自体は自動化しない。

## Map flow

Mapを新しく開いた時に、sessionStorageへ30分有効な flow_id を作る。

同じMapからClassic Surfaceへ移動して戻る場合は同じFlowを維持する。

以下でFlowを終了する。

- Classic Homeへfallback
- Work開始フォームを送信
- 30分経過

ユーザー本文、Node label、AI promptなどはTelemetryへ保存しない。

## Events

Client:

- map_viewed
- map_node_focused
- map_back_used
- map_classic_action_opened
- map_companion_opened
- map_classic_home_opened
- map_reprojected

Server authoritative:

- map_execution_started

map_execution_started は実際にWorkSessionが新規作成された時だけWorkSessionControllerが記録する。

## Safe metadata

Map client telemetryはBehaviorEventControllerでwhitelistし、任意metadataを保存しない。

保存対象:

- flow_id
- surface
- device
- surface_role
- node_type
- position_role
- action_role
- is_primary
- elapsed_ms
- step_count

Node title / description / Evidence本文 / Inbox本文などは記録しない。

## Metrics

Flow単位:

- Map Flow数
- Node Focus率
- Focus -> Classic Action率
- Companion利用率
- Classic Home fallback率
- Work開始率
- Back / Flow
- Primary Action Focusまでの中央値
- Map -> Work開始までの中央値
- Map -> Work開始までのstep中央値
- Living Reevaluation発生率

Classic Home参考値:

既存 WorkStarted.metadata.start_latency_seconds のうち source=dashboard を使う。

これはランダム化されたA/Bテストではなく、入口条件も完全一致しないため参考比較に留める。

## Admin

Admin dashboardに7日 / 30日のLiving Map Validation summaryを表示する。

Primary Homeへの昇格は自動化しない。
十分なFlow数と、到達時間・fallback・Back・Work開始を合わせて人が判断する。

## Non-goals

- Primary Homeへの自動切替
- 強制A/B assignment
- user content analytics
- per-user ranking
- session replay
- heatmap SDK
