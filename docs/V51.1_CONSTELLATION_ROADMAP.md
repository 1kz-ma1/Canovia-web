# V51.1 Constellation Roadmap

> **V51.2 implemented:** Execution now derives Study / Development / Career / General modes, scopes Recommendation to the selected Mode, and hands the chosen Task to existing specialized Workspaces. See `docs/V51.2_EXECUTION_WORKSPACE_MODES.md`.

## 目的

RoadmapページをTaskカード中心の巨大なSpatial Mapから、Plan全体の形・完成度・現在地を確認するConstellation Surfaceへ置き換える。

Roadmapは「今何をすればいいか」を決めるSurfaceではない。

```text
Home / Execution
= WHAT SHOULD I DO?

Constellation Roadmap
= WHERE AM I?
= WHAT DOES THE WHOLE PLAN LOOK LIKE?
```

## Universe-first

`/roadmap` を開いた初期状態ではPlanを自動選択しない。

初期表示:

```text
              Plan Constellation

    Plan Constellation

             SPACE STATION

                       Plan Constellation
```

全Planを一つのUniverseとして見る。

`?plan_id=<id>` の時だけ1 Planを選択し、Constellationを少し拡大する。

## Information hierarchy

```text
Plan
└ Constellation
   └ Main Star
      └ Task Group
         └ Task List
```

TaskをMain Starへ1:1対応させない。

大きなPlanほどTaskをTask Groupへ圧縮し、初期俯瞰の情報量を制限する。

## Main Star count

Main Star数はTask数だけで決めない。

入力:

- non-cancelled Task count
- estimated minutes

Task数に応じたbase countへ、非常に大きいestimated costの場合だけ補正を加える。

最大10 Main Stars。

これにより「Taskを細分化するだけで星座が豪華になる」挙動を弱める。

数値scoreはユーザーへ公開しない。

## Stable grouping

Canonical Roadmapのexecution orderを維持しながら、estimated costが大きく偏りすぎないTask Groupへ分割する。

Groupはpresentation-only。

DBへPhase / Group / Starを新規保存しない。

## Shape

Main Starの位置は既存Spatial Roadmapのdependency depthを利用する。

- x = dependency depth
- y = 同一depth内のGroup分散
- small deterministic jitter = 見た目の硬さを軽減

完全ランダム配置は使わない。

Planを再表示しても同じcanonical structureなら位置関係は安定する。

## Pattern

Dependency topologyからpresentation patternを分類する。

- chain
- branch
- converge
- web

Patternは見た目のThemeではなく、構造の特徴を表すmetadata。

## Edges

Task dependencyをMain Star間へ集約する。

異なるStar間に実Dependencyがある場合:

`relation=dependency`

Dependencyがなく星座が完全分断される隣接Group間にはpresentation flowを補助線として追加する。

`relation=flow`

両端Main Starが完成した接続だけ発光する。

したがって実行が進むほど星と線が徐々に明るくなり、完成形が現れる。

## Completion

Plan completion:

```text
done non-cancelled tasks / total non-cancelled tasks
```

Main Star completionも同じTask Group内比率。

Selected Constellationのみ各Main Starに:

`completed / total`

を表示する。

Universe overviewでは数字を常時出さない。

## Current position

Current Main Starは:

1. canonical Roadmap currentを含むGroup
2. Spatial visual_state=currentを含むGroup
3. fallbackとして最初の未完成Group

現在地は軽いpulseで示す。

Execution recommendationそのものはRoadmapへ載せない。

## Richness

Constellation Richnessはpresentation metadata。

入力:

- Task count
- estimated minutes
- cross-group edge count

出力:

- richness tier 1〜4
- Main Star satellite count

Richness scoreそのものは保存・表示しない。

Task量と実行コストの両方を使い、単純なTask分割への報酬化を避ける。

## Space Station

Universe中央にSpace Stationを固定する。

V51.1 actions:

- Plan作成
- Plan一覧管理
- 選択中Plan更新
- 選択中Plan詳細

Space StationはPlan構造ではなくCanoviaへの操作拠点。

## Semantic zoom

### Level 0

Universe:

- Space Station
- Plan Constellations
- Plan title
- completion %

### Level 1

Plan selected:

- Constellation slight zoom
- Plan completion
- status
- Main Star counts
- current position

### Level 2

Main Star selected:

Task List dialog。

表示:

- Task title
- status
- progress
- remaining minutes

TaskをMap上へ全展開しない。

## Execution handoff

Task Group dialogから:

- このPlanを実行
- Plan詳細

へ移動可能。

「どのTaskを優先するか」はExecution Surfaceが決める。

## Mobile

Universeは画面幅へ縮小しない。

```text
Viewport
└ pannable Universe Stage
```

Stageはminimum widthを持ち、Mobileではnative panで空間を移動する。

Browser zoomとMap semantic zoomを混同しない。

## Existing Spatial Roadmap

`RoadmapSpatialProjectionService` は削除しない。

利用継続:

- Plan Dashboard Structure Region
- dependency projection
- constellation dependency depth input
- compatibility callers

変更したのはRoadmapページのPrimary presentation。

## Persistence

V51.1追加DBなし。

保存しない:

- Main Star group
- position
- richness
- pattern
- selected Plan
- selected Star

すべてcanonical Plan/Taskからrequest時に再生成する。

Achievement Constellation snapshotは後続Phase。

## Non-goals

- Achievement snapshot
- Timeline completion event
- user-selectable constellation skin
- drag/drop constellation
- manual star positioning
- Execution recommendation inside Roadmap
- 3D/WebGL
- Plan Detail redesign

## Tests

- large Plan is compressed below Task count
- same Task count can become richer with larger estimated cost
- no public richness score
- default Roadmap has no selected Plan
- selected Plan exposes Main Star counts
- Main Star opens Task List
- full/instant runtime mount
- old Spatial Projection remains available
