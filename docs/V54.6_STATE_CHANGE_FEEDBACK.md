# V54.6 State Change Feedback

## Goal

V54.6 explains meaningful Intelligence changes after new Evidence changes State / Readiness / Decision / Current Action.

The user should be able to answer:

```text
What changed?
Why did it change?
What changed in my next action?
```

V54.6 is a read model over existing persisted Intelligence history.

It does not introduce a new event store, scoring model, or AI call.

## Source of truth

Feedback compares the two most recent persisted `IntelligenceDecisionTrace` records for the same:

- Plan
- Intelligence domain

Each trace already points to its persisted State snapshot.

Current / previous Action is read from the corresponding `IntelligenceActionProjection`.

No live recomputation is used to manufacture historical before-state.

## Meaningful change policy

Feedback is rendered only when at least one is true:

1. Readiness level changed
2. Decision reason / biggest Gap changed
3. Current Action fingerprint changed
4. Readiness score moved by at least 5 points

A smaller score-only change is deliberately suppressed.

This keeps State Change Feedback focused on changes likely to matter to the user's understanding or next action.

## Feedback contents

When meaningful, feedback can show:

- Readiness: before → after
- Readiness delta
- State level: before → after
- Decision / biggest Gap summary: before → after
- Current Action: before → after
- newly added Evidence count
- bounded Evidence type labels

Evidence explanation is structural only.

Safe examples:

- Practice結果
- Recall確認
- Commit
- CI / Test
- Review
- Pull Request
- Production Deploy
- Quality Gate確認

V54.6 never renders:

- provider payloads
- commit messages
- GitHub issue / PR body text
- code diffs
- learner answer text
- raw Evidence metadata

## Surfaces

### Study Workspace

When the selected Study Plan has meaningful persisted change history:

- show one State Change card after Exam Readiness
- show before / after Readiness
- show Evidence labels
- show Decision / Current Action change when present

### Development Workspace

When the selected Development Plan has meaningful persisted change history:

- show one State Change card after Release Readiness
- same shared presentation contract as Study

### Overview

Overview shows up to two recent meaningful Intelligence changes from its representative Study / Development Plans.

It remains bounded and does not become a feed.

## Persistence boundary

Workspace GET routes do not persist new Intelligence history.

Feedback can only exist after an existing mutation flow already called:

```text
StudyAdaptiveActionService::refresh / tryRefresh
DevelopmentAdaptiveActionService::refresh / tryRefresh
```

Examples already covered by the product:

- Study Scope confirmation
- Practice assessment
- Recall review
- GitHub webhook Evidence sync
- Development Quality Gate confirmation

V54.6 does not add refresh calls to GET routes.

## Performance

For one Plan / domain, feedback reads:

- latest two Decision traces
- their State snapshots
- up to two Action projections
- only TaskEvidence IDs newly referenced by the latest State

Study / Development Workspace each request at most one feedback.

Overview requests at most two.

## Compatibility

V54.6 preserves:

- V53 Intelligence persistence semantics
- V54.3 Study Workspace
- V54.4 Development Workspace
- V54.5 Overview
- root Home
- existing mutation flows
- no new AI traffic
- no new GitHub network request

## Non-goals

V54.6 does not:

- create push notifications
- create a notification inbox
- persist a second change-event table
- compare ephemeral GET evaluations
- show all historical changes
- show raw Evidence
- add AI-generated explanations
- alter Readiness formulas
