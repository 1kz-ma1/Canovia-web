# V58.18 Plan-wide Weakness Handoff after 100 Questions

Status: implemented / validated  
Branch: `feature/v58-18-plan-wide-weakness-handoff`

## 1. Goal

Feed only sufficiently-supported AP Subject A Plan-wide weakness observations back into the next broad Practice block after the current Task reaches 100 graded questions.

```text
100 graded questions on current Task
+ same-Plan Question Bank observations
+ repeated weak parent-topic evidence
→ bounded Plan-wide handoff
→ at most 2 recheck questions
→ remaining questions stay broad
```

V58.18 does not turn Plan-wide observations into full focused remediation.

## 2. Eligibility

All conditions are required:

1. the selected Plan is AP Subject A;
2. the current Task has reached the V58.17 100-question checkpoint;
3. V58.16 Plan-wide AP coverage is available;
4. the candidate is a parent topic;
5. the parent topic has at least 3 assessed Question Bank exposures;
6. those exposures cover at least 2 unique Question Bank questions;
7. observed correctness is below 60%;
8. current Task routing mode is `broad_assessment`;
9. deterministic policy phase is `general_practice`;
10. the current Task is not in mastery verification.

If any condition fails, Plan-wide observations do not affect question allocation.

## 3. Candidate source

Candidates come from the same actor-scoped, same-Plan V58.16 projection.

Only parent-topic rows may become routing candidates. Broad domains such as `テクノロジ` are not promoted directly into focus topics.

Candidate order:

1. lower observed correct rate;
2. higher assessed exposure count;
3. topic label.

At most 5 candidates are carried into the handoff snapshot.

V58.16 parent-topic projection now also exposes `unique_question_count` so repeated exposure of a single question cannot satisfy V58.18 by itself.

## 4. Task-local authority remains first

V56.0 / V56.4 Task-local routing remains authoritative.

Existing local `broad_recheck_topics` keep precedence. Plan-wide candidates only fill unused seats in the existing broad-assessment recheck budget.

Default budget:

```text
broad weakness recheck <= 2 questions
```

Example:

```text
local recheck = [DNS]
plan-wide = [データベース, 性能・可用性]
budget = 2
→ applied = [DNS, データベース]
```

The Plan-wide signal cannot displace the local DNS recheck.

## 5. Mastery / cooldown guard

A Plan-wide candidate is rejected when the current Task routing policy marks the same topic as:

- cooldown;
- mastered.

This prevents older Plan-wide history from immediately resurrecting a locally stabilized topic.

## 6. Phase guard

Plan-wide handoff is not applied during:

- diagnosis;
- weakness_reinforcement;
- exam_mode;
- mastery verification.

Focused remediation remains Task-local. Exam Mode remains exam-balanced.

## 7. Question allocation

For eligible broad General Practice, V58.18 reuses the existing V56.4 allocation instead of inventing a new mix.

With the default 10-question block:

```text
primary recheck <= 2
retention <= existing limit
broad / diagnostic exploration >= existing minimum
```

`focus_topics` remains empty in General Practice.

Applied Plan-wide topics appear only through the bounded `weakness_priority.primary_topics` / `question_mix.primary` path.

Question Bank and AI generation therefore consume the same allocation contract.

## 8. Provider behavior

Question Bank already selects against `weakness_priority.primary_topics`.

Native / Hybrid / external-AI generation already receives:

- primary topics;
- secondary topics;
- question mix;
- broad-assessment rules.

V58.18 adds no extra AI call.

## 9. Actor boundary

The handoff service receives explicit current actor identity:

- authenticated → `user_id`;
- anonymous → `actor_token`.

No fallback to another user's Plan history is allowed.

## 10. Transparency / persistence

The applied decision is stored inside the normal strategy snapshot:

`selection_context.strategy.routing_policy.plan_wide_weakness_handoff`

Snapshot fields include:

- eligible;
- applied;
- reason;
- checkpoint assessed count;
- candidate topics;
- applied topics;
- local topics;
- maximum recheck questions;
- local-precedence guarantee.

Practice Strategy UI shows the handoff only when a Plan-wide topic was actually applied:

```text
100問後のPlan全体再確認: データベース
Plan全体で繰り返し弱かったTopicを最大2問だけ再確認します。
残りは分野横断の探索を維持します。
```

## 11. Mutation boundary

V58.18 does not:

- mutate Task progress;
- mark Task complete;
- create Evidence;
- change Study Method Recommendation;
- change mastery;
- change the V56.0 phase;
- create a new weakness-state table.

It only adjusts the next question allocation when all eligibility conditions are satisfied.

## 12. Storage / migration

Existing Attempt / Session / strategy JSON is reused.

No migration.
