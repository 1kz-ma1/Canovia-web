# V56.12 Workspace Resume & Session Scope Recovery

## Goal

Fix two production UX defects discovered after V56.11 became live:

1. a persisted Workspace Mode remains selected in the fixed Mode control after reopening the app, while the root `/` surface still renders generic Action Home
2. Action Home can expose an active WorkSession link that later returns HTTP 403 because the session is outside the actor's currently editable Plan scope

## Production evidence

Observed on the live iOS PWA flow on 2026-10-05:

- root `GET /` rendered successfully
- the fixed Workspace Mode context could remain `study`
- the visible body was still generic Action Home because `HomeController` always rendered `dashboard.index`
- `GET /work-sessions/21` returned 403 from a root Home referrer

The Workspace Mode mismatch is architectural: `WorkspaceModeResolver` correctly resolves the stored preference, but only the App Shell consumes it. The root controller does not route to the canonical Workspace Home.

The 403 is also architectural: `ContinuityService::homeContext()` queried active/pending WorkSessions only by `actor_token`. It did not limit those sessions to the editable Plans already supplied by `HomePageDataService`. `WorkSessionController` correctly applies edit authorization when the user follows the link, so an out-of-scope session can be rendered first and rejected second.

## Workspace resume contract

A stored manual Workspace Mode now controls app-root resume:

```text
manual overview     -> /workspace/overview
manual study        -> /workspace/study
manual development  -> /workspace/development
manual career       -> /workspace/career
automatic / null    -> /  (Action Home)
```

This applies only when `WorkspaceModeResolver` reports `manual_preference`.

Explicit root context remains stronger:

```text
/?workspace_mode=...
```

continues to render the root Action Home with that explicit context instead of being overwritten by the stored preference.

Strong route hints and Plan/Task/WorkSession deep links remain unchanged.

### Why the persisted Workspace wins on reopen

The fixed Mode selector is not decorative state. A user who explicitly selected Study, Development, Career, or Overview has chosen a Workspace. Reopening the app should therefore resume that Workspace's canonical Home rather than show a body belonging to another surface while the selector still says the persisted Mode.

Automatic mode remains the escape hatch to generic Action Home.

This intentionally supersedes the V54.5 statement that root Home is always unchanged. Root Action Home remains unchanged for automatic/no-preference operation; only manual persisted Workspace resume changes.

## WorkSession visibility contract

Action Home continuity is computed from `editablePlans`.

Therefore every WorkSession exposed by Home as:

- active / paused session
- pending Plan update
- continuity candidate

must belong to one of those supplied Plan IDs and match the current `actor_token`.

The Home query now applies both boundaries before selecting sessions:

```text
actor_token
AND plan_id IN editable_plan_ids
```

An actor-token match alone is not sufficient.

This keeps the Home presentation boundary aligned with `WorkSessionController::authorizeSession()`, which still remains the mutation/read authorization authority.

## Safety

V56.12 does not:

- weaken WorkSession authorization
- convert 403 into silent authorization bypass
- change Plan membership roles
- delete stale WorkSessions
- change Workspace deep-link precedence
- erase stored Workspace preference when a stronger route context is opened
- change Study / Development / Career Intelligence scoring

## Validation

Required regression coverage:

- each persisted public Workspace resumes its canonical Workspace Home from `/`
- automatic/no preference still renders Action Home
- explicit `workspace_mode` root context remains stronger than persisted preference
- Home continuity excludes an active session outside the supplied editable Plan scope
- V54.2 persistence/reset semantics
- Home cost/session reuse regression
- Study / Development / Overview / Career Workspace regressions
