# V41.4 Practice Calibration / Weakness Priority

## Goal

AI演習の難易度を「面倒な計算量」で上げず、実際の試験で必要な理解・判断へ合わせる。

同時に、弱点補強が一つの誤答へ吸い寄せられないよう、

```text
Answer
  -> Error Classification
  -> Weakness Signal
  -> Weakness Priority
  -> Question Mix
  -> Question Selection
```

へ変更する。

## Problem before V41.4

V41.3以前はStudyPracticeStrategyが、

- latest next_step.focus_topics
- latest weaknesses
- latest misconceptions
- repeated weakness strings

をmergeし、focus_topicsとしてQuestion Providerへ渡していた。

これは「古い一回のミスを永久に残さない」という改善は持っていたが、

1. 最新の1問を間違えただけでもそのtopicが次回focusへ入りやすい
2. AIのnext_stepをほぼそのまま次回へ引き継ぐ
3. Question Bank selectorがfocus_score順に並べるため、同系統が連続しやすい
4. 概念誤解と単純計算ミスの重みがほぼ同じ
5. 本番が4択でも、外部AIがnumber入力・複雑な小数計算を増やせる

という問題が残っていた。

## Exam Profile

新規 `StudyPracticeExamProfileService`。

Plan / Task文脈から試験形式を決める。

V41.4では最初の専用profileとして:

```text
ap_subject_a_exam
```

を追加する。

AP科目A profile:

- preferred response: single_choice
- preferred choices: 4
- reasoning: optional
- neat numeric values preferred
- numeric input is exception
- reasonable rounding allowed
- difficultyをawkward arithmeticで上げない
- concept depth / condition judgment / cross-concept reasoningで難易度を上げる

このProfileはQuestion selectionとは別責務。

将来別資格を追加する場合もProfileを増やし、Strategy / Providerは同じ契約を利用する。

## Error Classification

External AI assessmentへQuestion Feedbackの `error_type` を追加する。

allowed:

- none
- knowledge_gap
- concept_gap
- reasoning_gap
- condition_reading
- unit_error
- calculation_slip
- careless
- unknown

また `weakness_topics` をQuestion単位で返す。

### Rules

- correct -> none
- 原因が回答から分からない -> unknown
- calculation_slipは、式・考え方が正しく最後の算術だけを誤った場合
- carelessは明確な転記・選択・読み落とし等だけ
- 一回のcalculation_slip / carelessを恒常的弱点と断定しない

Canovia Question Bankのdeterministic graderは正誤は確定できるが、誤答理由は推測しない。

そのため不正解時:

```text
error_type = unknown
```

を返す。

reasoning入力が存在してAI評価へrouteされた場合だけ、AIがreasoningを見て分類できる。

## Weakness Priority

新規 `StudyWeaknessPrioritizationService`。

直近最大8 Attemptを使う。

弱点Topicごとに:

```text
severity
confidence
expected_gain
recovery_cost
value_per_cost
saturation
exam_relevance
dominant_error_type
weak_attempt_count
state
priority_score
```

を算出する。

### Error weight

概念誤解等は強いSignal、軽微な計算ミスは弱いSignalとして扱う。

概念的な順:

```text
concept_gap
  > knowledge_gap / reasoning_gap
  > condition_reading
  > unit_error / unknown
  > calculation_slip
  > careless
```

### Confidence

1回だけ:

```text
suspected
```

複数Attempt:

```text
confirmed
```

とする。

Primary reinforcementへ昇格するには、原則として複数AttemptのEvidenceが必要。

### Recovery cost

同じseverityでも、補強コストが違う。

例:

- simple calculation slip -> low cost
- knowledge gap -> medium
- concept / reasoning gap -> higher

Priorityは弱さだけでなく、改善期待と補強コストを合わせて算出する。内部Snapshotには `value_per_cost = expected_gain / recovery_cost` も残し、「弱い順」ではなく「今そこを補強する価値」も後から検証できるようにする。

### Saturation

直近3 Attemptで同じtopicが繰り返されている場合、saturation penaltyを掛ける。

「間違えたのでさらに同じ問題を出す」を無限に続けない。

### Resolution

古い1回の弱点があり、最新Attemptで同じtopicが明確なstrengthになった場合:

```text
resolved
```

として次回focusから外す。

複数回の弱点後に最新で改善した場合は `stabilizing` とし、PrimaryではなくSecondary側で軽く再確認できる。

## Question Mix

Weakness Priorityから次の3bucketへ配分する。

### Confirmed weaknessあり

通常:

```text
Primary     50%
Secondary   30% (存在する場合)
Diagnostic  remainder
```

Primaryが最近飽和している場合:

```text
Primary     40%
Diagnosticを増加
```

### Single / suspected weakness only

```text
Primary      0%
Secondary   40%
Diagnostic  60%
```

つまり1回間違えただけでは、そのtopicへ演習全体を固定しない。

### No active weakness

```text
Diagnostic 100%
```

## Question Bank selector v2

`QuestionBankStudyPracticeQuestionProvider`:

```text
bank-v1
  -> bank-v2-balanced
```

へ更新。

selection order:

1. Primary quota
2. Secondary quota
3. Diagnostic quota
4. sparse coverageの不足分をbalanced fill

### Diagnostic

active weaknessにmatchしない問題を優先する。

さらにQuestion metadataのdomainでround-robinし、同じ分野から診断問題が固まることを抑える。

### Primary / Secondary

複数topicがある場合、best matching topicごとにgroupし、round-robinで選ぶ。

一つのfocus termのscoreが高いだけで全問を占有しにくくする。

### Repetition

V41.4 originally used the latest 8 Question Bank Sessions on the same Task as a binary recent flag.

V56.3 supersedes that repetition rule with Plan-wide bounded exposure rotation:

```text
latest 24 Plan Sessions
→ latest 3 Sessions are recent
→ lower exposure count first
→ longer time since last exposure next
```

The V41.4 Primary / Secondary / Diagnostic quota and domain round-robin remain unchanged.
See `docs/V56.3_QUESTION_EXPOSURE_ROTATION.md`.

## Question Bank Coverage

Coverage判定もQuestion Mixを考慮する。

従来はfocusがある場合、原則3問以上のfocus matchを要求していた。

V41.4ではPrimary + Secondaryとして実際に要求している問題数を見てminimum matchを決める。

少数の再確認しか必要ないのにQuestion Bank全体をfallbackさせない。

## External AI Prompt

External AI selector:

```text
prompt-v41.4-calibrated
```

AP科目AではPromptへ明示する。

- 原則4択
- number inputは例外
- 綺麗な数値を優先
- 小数の桁数・筆算精度だけを難易度にしない
- 条件判断・概念統合で難易度を上げる
- Question Mixを守る
- 一つの弱点へ全問を寄せない
- Diagnosticで隠れた弱点も探す

## AI boundary

Canoviaが決定する:

- Exam Profile
- Weakness Priority
- Question Mix
- Primary / Secondary / Diagnostic allocation

External AIが提供する:

- 問題生成
- reasoningを含む回答のError Classification
- assessment / feedback
- next_step suggestion

AIのnext_step.focus_topicsは今後もSignalとして利用するが、CanoviaのWeakness Priorityを上書きしない。

つまり:

```text
AI recommendation
      ↓
Canovia policy
      ↓
balanced next practice
```

とする。

## No migration

V41.4は既存Attempt / Session JSONを利用するためDB migrationは不要。

Strategy v2の全Snapshotは既存 `StudyPracticeSession.selection_context` へ保存される。

既存V40 Attemptはerror_typeを持たないが、misconceptionsが残っていればmodest legacy signalとして利用する。

## V56.0 evolution note

V41.4ではWeakness Priority / saturation / balanced Question Mixまでを導入したが、focused reinforcementを**いつ終了するか**は定義していなかった。

V56.0ではその上位にdeterministicなStudy Exam Convergence Policyを追加した。

```text
V41.4
Weakness signal
→ priority / saturation
→ balanced reinforcement

V56.0
→ graduation or cap
→ mandatory General Practice return
→ broad re-evaluation
→ evidence-based re-entry
→ exam-date convergence
```

V41.4のWeakness Priorityは引き続き「どのTopicが補強候補か」を判断するSignal層として利用する。

V56.0が:

- focused reinforcementを許可するか
- active Topicをどこまで使うか
- graduated / capped Topicを除外するか
- General / Exam Practiceへ移るか

を最終決定する。

AI `next_step.focus_topics` は引き続きSignalであり、Weakness Reinforcementを無期限延長するauthorityを持たない。

See `docs/V56.0_STUDY_EXAM_CONVERGENCE_POLICY.md`.
