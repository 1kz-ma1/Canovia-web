# V48.0 Roadmap Spatial Map

## 目的

CanoviaのRoadmapを、一本道の縦スクロール表示から、並行Task・Dependency・Task群・分岐を空間的に把握できるMap Surfaceへ移行する。

V48.0では新しいPlan Phase / Task Group entityを作らず、既存のRoadmap / Task / task_dependenciesをsource of truthとして、read-onlyのSpatial Projectionを追加する。

## 基本構造

表示上の階層:

```
Dependency Phase
  -> Task Cluster
      -> Task
          -> Dependency Edge
```

### Dependency Phase

V48.0のPhaseはDBへ保存する業務Phaseではない。

TaskのDependency深度を使ったpresentation-onlyの段階。

- depth 0: 起点
- depth 1: 段階 2
- depth 2: 段階 3
- ...

横方向へDependency depthが深くなる。

将来canonical Phase entityを導入する場合、このpresentation phaseとは別契約として扱う。

### Task Cluster

同一Dependency Phase内で、同じ直接前提Task集合を持つTaskを1つのClusterとして表示する。

例:

```
A completed
  ├ B
  ├ C
  └ D
```

B/C/Dが同じAを直接前提に持つ場合、同じClusterに並べる。

Cluster内に複数Taskが存在する場合は「並行 N件」と表示する。

これは「必ず同時実行すべき」という判断ではなく、登録済みDependency上で同じ前提を共有していることを示す。

## Spatial layout

- 横軸: Dependency depth
- 縦軸: 同じPhase内のCluster / parallel Task
- Dependency: cyan edge
- lineage / continuation: violet dashed edge
- current Task:強調
- done:弱める
- cancelled:さらに弱める

Taskが少ないRoadmapはStage中央へ寄せる。

Task / Phaseが増えた場合はStageを横へ拡張し、Desktop / mobileともscroll可能にする。

## Dependency readiness

V46.9 Execution Coordinationと矛盾しないよう、Roadmap上のdependency stateは既存Executionと同じ明示ルールだけを使う。

Dependencyが満たされた条件:

- status = done
- または progress_percent >= 100

Active Taskについて:

- 未完了Dependencyが0件 -> ready
- 未完了Dependencyが1件以上 -> blocked

Roadmapはこのstateを表示するだけでTask status / progressを書き換えない。

blocked TaskにはRoadmapから直接Work Session開始ボタンを出さない。

代わりにExecution Orchestrationの「今やることを見る」は利用可能にし、safe preparation / clarify / wait等の既存Execution判断へ委ねる。

## Current Task

既存RoadmapServiceのcurrent selectionをそのまま利用する。

Spatial Mapを開いた際はcurrent Taskを自動でviewport中央付近へscrollする。

これは:

- full page load
- Canovia Instant Navigation後

の両方で行う。

## Mobile

Spatial Roadmapは横scrollを許可する。

既存のRoadmap Plan切替横swipeは、touch startがSpatial Roadmap内の場合は発火させない。

これにより:

- Mapを横へ見るgesture
- Planを横swipeで切り替えるgesture

を競合させない。

## Main / List relationship

`/roadmap` のMap panelはSpatial MapをPrimaryとして使う。

既存List panelはSecondaryとして維持する。

```
Map = Dependency / parallel / current context
List = dense data inspection
```

Classicとの二重UIを永続させるためではなく、Mapが一覧性を十分吸収するまでの補助Viewとして残す。

## Legacy fallback

shared partial `plans.partials.roadmap` は複数箇所で利用されている。

V48.0では `roadmapSpatial` が渡された場合だけSpatial Mapを使う。

未提供の場合は既存 `roadmap-map.blade.php` をfallbackする。

これにより:

- Plan Review before/preview
- Home上のPlan Review preview
- 既存Plan detail埋め込み

を壊さない。

## Map UI connection

Execution MapのPlan detail actionは:

`ロードマップMapを見る`

として `roadmap.index?plan_id=...` へ接続する。

Roadmap側からは:

`MapでPlanを見る`

でPlan-centered L3へ戻れる。

MapとRoadmapを別製品のように分離せず、同一Navigation Layer内のSurfaceとして往復できる状態にする。
