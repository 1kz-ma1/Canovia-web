# V58.38 Guidance Level Change Candidate — Contract Foundation

Status: FOUNDATION ONLY. No automatic Guidance Level mutation or new user-facing proposal is enabled.

## Purpose
Separate a user's explicitly chosen Guidance Level from observed behavior and future recommendations.

## Required contract before activation
- Observed behavior can suggest a change, but cannot change Guidance Level.
- Candidate must include current level, proposed level, bounded evidence, reason, version and risk.
- Explicit user confirmation is required for any change.
- Dismissal must persist; no repeated prompt for identical evidence.
- Evidence revisions must not silently overwrite a dismissed or confirmed choice.
- If the user's level changed after candidate creation, reject stale confirmation and require re-evaluation.
- Never infer experience or competence from GitHub structure or activity alone.
- User can choose a Guidance Level directly without accepting an inferred candidate.
- Feature readiness, plan, task and self-reported experience remain unchanged.
- Add tests for unauthorized access, stale candidates, duplicate prompts, dismissal and confirmation before activation.

## Future
Explicit product decision is required to define eligibility, candidate source, UX copy and risk tier. This document is not permission to implement behavior automatically.
