# V42.0 Canovia Living Goal Map Foundation

## Purpose

Canoviaの既存データ構造を「カードの一覧」ではなく、現在地・未来・過去・入力・実行手段の関係として見せる。

V42の中心原則は以下。

- Map = Context / Navigation / Priority
- Classic = Detail / Execution
- Mapで「どこへ行くか」を理解する
- Classicで「何をするか」を実行する
- Map自体を第二のデータモデルにしない

## Spatial contract

位置の意味は固定する。

- 中央: Now / Primary Action
- 上: Future / Goal / Plan / Next Task
- 下: Past / Evidence
- 左: Input / Inbox / External information
- 右: Action / Tool / AI / Execution method

位置はランダム化しない。状態変化は主に重要度、中心からの距離、強調度、Edge strengthで表現する。

## V42.0 scope

最初のSurfaceは読み取り専用とする。

表示対象:

- Goal Context（存在する場合）
- Primary Plan
- Current Task / Primary Action
- Next Task
- Primary Tool
- latest Evidence
- pending Inbox

Primary ActionはMap専用ロジックで再計算せず、Homeと同じ DashboardGuidanceService を使う。

Map Projectionは既存Modelから都度生成し、Node / Edge / positionを永続化しない。

## Node projection

Nodeの基本フィールド:

- type
- entity_id
- label
- importance
- state
- position_role
- size_weight
- available_action
- position (projection only)

Edgeの基本フィールド:

- source
- target
- relation
- strength
- secondary

## Classic boundary

V42.0ではMap内で編集しない。

ノード選択後の実操作は既存Classic画面へ遷移する。
V42.1以降で、Mapの選択Contextを保持したContextual Classic Surfaceを追加する。

スマホでは将来的にBottom Sheet、DesktopではSide Panelを第一候補とする。
複雑な操作はFull Screenへ昇格させる。

## Performance boundary

MapはNode単位でDBへ問い合わせない。

- Plan / TaskはCoreContextServiceからまとめて取得
- Goal Contextはまとめてeager load
- EvidenceはPrimary Taskだけ最新1件
- Inboxはpending count + latest item
- Node数が増えてもquery数がNode数に比例する設計を避ける

## Safe delivery phases

### V42.0 Foundation + Read-only Map

独立Surface /map を追加する。
既存Homeは変更しない。
決定論配置、Projection Service、既存画面への導線、First-run保護、Feature testまでを1単位とする。

### V42.1 Focus Mode + Contextual Classic Surface

ノード選択時に選択ノードを中央へ寄せ、1-hopの直接関係だけを表示する。
操作SurfaceはMobile Bottom Sheet / Desktop Side Panelを基本とする。

### V42.2 Living Reevaluation

Task完了、Evidence追加、Inbox整理などの意味のある更新後にProjectionを再評価する。
細かなスコア差だけで位置を頻繁に動かさない。

### V42.3 Contextual Companion

選択Node、周辺Node、Primary ActionをCompanion Contextへ渡す。
AIを別画面へ移動して使うのではなく、現在見ている世界について話せる状態へ近づける。

### V42.4 Validation / Home candidate

Classic Homeと比較する。

- Primary Action到達時間
- 誤タップ
- 戻る回数
- Mapからの実行率
- Classic fallback率

Mapの方が明確に良い場合だけPrimary Home候補へ昇格する。

## Non-goals

V42.0では以下をしない。

- Home削除
- 自由ドラッグ
- 無限キャンバス
- AIによるレイアウト決定
- 3D / 物理アニメーション
- Graph専用DB
- 全機能のノード化
- Map内での複雑な編集
