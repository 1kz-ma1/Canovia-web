# V47.7 Map Presentation Foundation

## 目的

Canovia MapをClassic UIの補助画面ではなく、将来Primary UIへ昇格できるPresentation Foundationへ進める。

V47.6まででSemantic Zoom / Plan-centered L3 / Task Focusは成立した一方、Node内に internal eyebrow・実データ名・subtitle・action text が同時に表示され、デバッグビューやカード一覧に見えやすかった。

V47.7ではキャンバスと詳細の責務を分離する。

    Map Canvas = どこに何の役割があるか
    Detail Palette = 具体的な名前・説明・状態・操作

## Node Presentation Grammar

### Container

Plan / Domain / Intent / Collaboration Contextなど、空間そのものを表すNodeは固有名を表示する。

- Plan: Plan名
- Domain: Domain名
- Collaboration Context: レビュー待ち / 相手待ち等のContext名
- Space Station: Space Station

内部の `eyebrow` と説明subtitleはCanvasでは原則表示しない。

### Leaf

Task / Evidence / Tool / Inbox / Collaboration Itemなど、内容が頻繁に変わるNodeは具体名ではなく役割を表示する。

- Primary Task -> おすすめ
- Next Task -> 次にやる
- Dependency Task -> 前提
- completed Task -> 完了Task
- Evidence -> Evidence
- Tool -> Tool
- Inbox -> Inbox
- review item -> レビュー待ち
- waiting item -> 相手待ち
- external item -> 外部確認
- my action item -> 自分が進める

実際のTask名 / Artifact名 / summary / progress / meta / actionはDetail Paletteで表示する。

`MapNodePresentation` はview-only変換であり、Navigation Graphのcanonical label / eyebrow / subtitleを変更しない。

## Palette-first Leaf Interaction

Leaf Node本体を押した場合はDetail Paletteを先に開く。

direct destinationを持つLeafでも、Node本体を即遷移には使わない。既存のsmall direct-open controlまたはPalette内ActionからExecution / external Toolへ進める。

ContainerのSemantic Zoom body entryは維持する。

これにより:

    おすすめ
      -> click
      -> Palette
           Task名
           summary
           progress / state
           そのまま進める
           補助Action

という操作に統一する。

## Detail Palette

内部名 `Context Inspector` / `Context Surface` のdata attributeやJS contractは互換性のため維持するが、ユーザー向け表示は次へ変更する。

- 見出し: 詳細
- caption: 選んだマスの内容と操作を確認できます

内部class / data attributeのrenameは今回行わない。

## Collaboration Empty Context

共同L2で選択ContextにArtifact / Taskが0件の場合、`共同Planを確認` というgeneric NodeからClassic一覧へ抜けない。

Shared Planが存在する場合は、そのPlan自体をHierarchy Childとして最大6件Mapへ投影する。

    レビュー待ち
      ├ Shared Plan A
      ├ Shared Plan B
      └ Shared Plan C

Shared Plan Nodeは `plan:<id>` identityを使用し、Semantic Zoomでcollaboration L3へ入る。
V47.5/V47.6と同じPlan identity continuityを利用できる。

Shared Planが1件も存在しない場合のみ、Plan作成を次の選択肢として投影する。Space Stationは既存Spatial Dockを利用し、同じ内容のNodeを二重に作らない。

## Classic UI Position

V47.7ではClassic routeを削除しない。

ただしMap上では `Classic Plans` のような内部的な呼称をやめ、`一覧で見る` として補助Viewへ降格する。

長期的には主要操作を Map -> Palette -> Action で完結させ、ClassicはData/List Viewとして残す。

## Future Extension

V47.7は次の拡張のPresentation基盤とする。

### Map Data Layers

進捗 / 期限 / 状態 / 担当 / Evidence / recommendation等をCanvasへ必要な時だけ重ねる。
Node本文を再び情報カード化せず、overlay / ring / badge / edge等でON/OFF可能にする。

### Map Pages / Presets

スマホのホーム画面のように複数のMap Pageを持てる構造へ拡張する。

例:

- 今日
- 開発
- 学習
- 共同
- 俯瞰

PageはPlan / Taskのsource of truthにならず、表示対象・layout preference・Layer設定だけを保持する。

### Roadmap Spatial Projection

現行Roadmapの縦スクロール表現は、並行Task / dependency / Task群を表現するため将来的にMap Projectionへ統合できる。

Roadmap Mapでは:

- Task group
- parallel lane
- dependency edge
- milestone
- blocked / ready state

を空間的に表現する。

V47.7ではRoadmap自体の実装変更は行わず、Node Presentation GrammarとDetail Paletteを共通基盤として再利用する前提だけを固定する。

## Compatibility

維持:

- V47.5 Semantic Zoom Spatial Continuity
- V47.6 Plan-centered L3
- Task Focus Mode
- Primary Action direct launch
- Living Reevaluation
- Projection Key
- Reflection Map
- Collaboration state ownership
- Space Station Spatial Dock
- BehaviorEvent structural telemetry

## Non-goals

- Roadmap Map実装
- Data Layer設定永続化
- Map Page永続化
- Drag & drop layout保存
- canonical Plan / Task / Evidence変更
- AI layout変更
- billing / entitlement変更
