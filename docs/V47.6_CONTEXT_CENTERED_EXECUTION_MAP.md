# V47.6 Context-Centered Execution Map

## 目的

V47.5の実機動画で残ったL2 Plan -> L3の違和感を解消する。

従来L3はCurrent Taskを常に中央へ置いていたため、ユーザーがPlan NodeをSemantic Zoomしても、Planを押した次画面でCurrent Taskが中央となり、Planは周辺へ移動していた。
これは「押した対象の内側へ潜る」というMap全体のInteraction Contractと矛盾していた。

V47.6ではL3を **Plan Context centered** に変更する。

## Core Contract

    L2 Plan
      -> Semantic Zoom
      -> L3 Plan Context centered
           ├ Current Task / Primary Action
           ├ Next Task
           ├ Tool
           ├ Evidence
           ├ Inbox / Dependency
           └ Goal

L3でCurrent Taskを押した場合のみ、既存Focus ModeでTaskを中央へ移す。

    Plan-centered L3
      -> click Current Task
      -> Task-centered Execution Focus
      -> close / back Focus
      -> Plan-centered L3

新しいL4 routeやDB Entityは作成しない。

## Center vs Primary

V47.6以降、Execution Mapでは次を明確に分離する。

- `center_node_id`: 今どのContextの中にいるか
- `primary_node_id`: 今おすすめするActionは何か

Planが解決できるL3では:

    center_node_id  = plan:<plan_id>
    primary_node_id = task:<current_task_id> | null

「中央にある = Primary Action」という旧契約は廃止する。
Current Taskが存在しない場合もPlanが存在すればPlan centerを維持する。

## L3 Attention Grammar

Desktop baseline:

- Plan Context: center
- Primary Action: upper-right / Action side
- Next Task: Future side
- Goal: Future side
- Tool: right / Action
- Evidence: bottom / Past
- Inbox / Dependency: left / Input

新しいposition role:

- `context-plan`
- `action-primary`

既存rolesは互換のためvalidation対象から削除しない。

## Mobile

Mobile L3でもPlanを50/50 centerに固定する。
Primary Actionは右上、Next Taskは上、Goalは左上、Toolは右、Evidenceは下、Inboxは左に配置する。
percent座標をそのままdesktopから縮小するのではなく、既存pixel-balanced mobile layoutでviewportに合わせて再計算する。

## Task Focus

Current Task / Next Task / Dependency TaskはLeaf NodeでありFocus-firstを維持する。

Primary Task Focus時:

- selected Task -> center
- Plan -> current-context neighbor
- Next Task -> Future
- Tool -> Action
- Evidence -> Past

Focus中はPlanのL3 center用visual emphasisを外し、Taskだけをcenterとして認識できるようにする。

## Visual Hierarchy

通常L3:

- Plan center: cyan context emphasis
- Primary Task: violet primary-action emphasis
- Primary Taskはcenterではなくてもrecommendationとして最も強いAction表現を維持
- `is-map-center` と `is-primary` を別の意味として扱う

これにより「場所」と「おすすめ」を混同しない。

## Semantic Zoom Continuity

V47.5のNode identity continuityをそのまま利用する。
L2の `plan:<id>` とL3の `plan:<id>` が一致するため、Plan Nodeが遷移元位置からL3 centerへ移動し、Task / Tool / Evidenceがその周囲へemergeする。
V47.6ではこの挙動が標準であり、Taskへ変身するfallbackは通常発生しない。

## Telemetry

新しいstructural position role `context-plan` / `action-primary` をBehaviorEventのallowlistへ追加する。
保存するのはrole等のstructural metadataのみ。Plan名 / Task名 / description等は追加しない。

## Compatibility

維持:

- Primary Action direct launch
- Task Focus Mode
- Context Inspector
- V47.3 gesture click fix
- V47.4 Reflection Map
- V47.5 Spatial Continuity
- Collaboration L3
- Execution Orchestration
- Living Reevaluation
- Space Station Spatial Dock
- Map Navigation Graph / Attention State separation

## Non-goals

- L4 hierarchy追加
- Current Task recommendation logic変更
- Task / Tool / Evidence existence logic変更
- Plan canonical state変更
- Map position永続化
- AI layout
- billing / entitlement変更
