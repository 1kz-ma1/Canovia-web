# V55.0 Career Intelligence Foundation

## Goal

V55.0 promotes the existing Career data loop into the shared Canovia Intelligence architecture before Career becomes a public Workspace Mode.

Career already has strong Reality / Evidence:

- Career Capture
- Application pipeline
- Selection Event
- Interview Review
- interview result TaskEvidence

V55.0 connects those facts to:

```text
Reality / Evidence
→ Career State
→ qualitative Process Readiness
→ Gap
→ Decision
→ Current Action
```

No Career Workspace Mode is added in V55.0.
That belongs to V55.1 after this domain contract is stable.

## Safety boundary

Career Intelligence must not estimate:

- probability of getting hired
- employability / market value
- candidate ranking
- company quality
- salary fairness
- whether an offer should be accepted
- whether the user should leave a job
- personality / protected-trait suitability

Career Readiness means only:

> how observable and actionable the current job-search process is from the facts already recorded in Canovia.

It is not an employment-success score.

For V55.0:

- `readiness.score = null`
- no numeric employability score is produced
- level is `unknown` when Career has no observable state
- observed Career state uses qualitative `developing`
- gaps and Current Action carry the useful meaning

## Intelligence domain

Add:

```php
IntelligenceDomain::Career
```

Persisted Intelligence records continue using the existing generic tables:

- `intelligence_state_snapshots`
- `intelligence_decision_traces`
- `intelligence_action_projections`

No migration is required.

Scope:

```text
domain = career
scope_type = career_plan
scope_id = Plan ID
```

## Source of truth

Career Intelligence reads structured Canovia records only.

### CareerCapture

Safe State fields:

- id
- status
- linked application id
- captured_at

Do not copy:

- source URL
- screenshot bytes/path/name
- raw note text
- extracted raw text

### CareerApplication

Safe State fields:

- id
- stage
- status
- result enum when present
- next_event_at

Do not copy:

- company name
- website
- role title
- arbitrary metadata

### CareerSelectionEvent

Safe State fields:

- id
- application id
- task id
- stage
- status
- scheduled_at
- completed_at
- result enum
- interview review status

Do not copy:

- notes
- company name
- interview answer text

### TaskEvidence

V55.0 normalizes these existing types:

- `interview_review_completed`
- `interview_result_recorded`

Only safe IDs / enums cross `TaskEvidenceAdapter`.

Interview answer text, company name, role title and free-text learning notes stay outside persisted Intelligence State / Decision / Action metadata.

## Qualitative Career Process Readiness

`CareerProcessReadinessEvaluator` returns no score.

### No observable Career state

```text
score = null
level = unknown
gap = career_signal_missing
```

### Observable state

```text
score = null
level = developing
```

Confidence rises only with structured observations.

Possible gaps:

- interview_review_due
- pending_capture_unorganized
- application_pipeline_missing

Upcoming interview and result waiting are State facts, not probabilities or negative judgments.

Metadata:

```text
policy = career_process_readiness_v1
meaning = career_process_observability_not_employability
```

## Decision policy

Deterministic priority:

1. interview review is due
2. pending Capture needs organization
3. upcoming interview needs preparation
4. Career signal exists but no Application is structured yet
5. active Offer needs condition review
6. candidate/preparing Application needs next-step organization
7. otherwise review the Career pipeline
8. no Career signal → capture one real opportunity / application fact

No AI provider is called.

### Offer boundary

The action may be:

> オファー条件を整理する

It must not be:

> この会社を選ぶ
> オファーを受ける / 断る

Decision authority remains with the user.

## Action projection

`CareerActionGenerator` creates one bounded Current Action.

Route kinds:

- career_workspace
- career_interview_review

Safe action metadata:

- target_capture_id
- target_application_id
- target_selection_event_id
- target_task_id
- career_stage
- route_kind
- reason_code
- projection_policy

No company / role / answer text.

## Persistence

`CareerAdaptiveActionService` mirrors Study / Development:

```text
CareerPlanIntelligenceService
→ CareerDecisionEngine
→ CareerActionGenerator
→ DecisionTraceStore
→ ActionProjectionStore
```

`evaluate(..., persist: false)` is read-only.

`refresh()` persists.

`tryRefresh()` is fail-safe and must not make a Career mutation fail if Intelligence projection fails.

## Mutation refresh points

Refresh after successful Career facts change:

- Capture created
- Capture deleted
- Application created
- Application updated
- Capture linked to Application
- Selection Event created
- Selection Event cancelled
- Selection result recorded
- Interview Review completed

GET Career Workspace does not persist Intelligence.

Draft Interview Review alone does not need to create a new Intelligence State.
