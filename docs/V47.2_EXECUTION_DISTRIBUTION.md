# V47.2 Execution Distribution Bundle

## Goal

V47.0 / V47.1で1つのTaskへExecution Packetを作れるようになった次段階として、
1つのPlan Contextを保ったまま複数の既存Taskへ実行指示を分ける。

HINANEXのA〜E担当のように、それぞれ別の責務を持つ担当へ同時にContextを渡す運用を、
Canovia Coreへ一般化する。

```text
Plan / Goal / Dependency / Evidence / Constraint
                      ↓
            target Task selection
                      ↓
          Execution Distribution Bundle
           ↙        ↓        ↘
        Task A    Task B    Task C
        Packet    Packet    Packet
```

## Architectural decision

Distribution BundleはDB Entityにしない。
session上のProjectionとしてのみ保持し、Task / Dependency / EvidenceをSource of Truthとする。

```text
execution_distribution.{plan_id}
  schema_version
  flow
  plan
  generation_mode
  targets[]
  bundle_fingerprint
```

担当ラベルも永続Actorではない。
V47.2では「A」「Validation担当」「Claude」などのラベルをgeneration session上でだけ利用する。

PlanActor modelは追加しない。

## Human-selected targets

AIにTask IDを選ばせない。

ユーザーが現在のPlanに存在する未完了Taskを最大8件選択し、
各Taskへ以下を指定できる。

- actor_label
- actor_type
- available_minutes

actor_typeは既存Execution Packetと共通。

- human
- ai
- human_ai
- external

Taskが別Planに属する場合、done / cancelledの場合、存在しない場合は分配対象として拒否する。

## Shared context

各担当向けPacket / Promptは、
そのTaskだけの文章を切り出して渡すのではなく、
既存 `ExecutionOrchestrationContextService` で再構築したPlan全体Contextを使う。

各targetは以下を持つ。

- task_id / task_title
- actor_label / actor_type
- available_minutes
- dependency_state
- context_fingerprint
- confirmed Execution Request（存在する場合）
- packet または handoff_prompt
- stale state

同じPlanから作られていてもselected_nodeは担当Taskごとに異なるため、
context_fingerprintもtargetごとに保持する。

## Generation

### External AI

Free pathとして、選択した担当ごとに独立Promptを生成する。

Promptには既存Execution Packet contractを使い、
追加で人が指定した担当ラベルを含める。

これによりユーザーはA〜Eの各AI / 担当チャットへ、
それぞれ専用Promptをコピーできる。

### Native AI

Automatic AI entitlementがありNative AIが利用可能なら、
選択Taskごとに既存 `ExecutionPacketService` を実行する。

1つの巨大なmulti-agent promptへまとめない。
各Taskのprotected scope / Dependency fail-safeを既存Packet単位で維持するため、
Taskごとに独立したExecution Packetを生成する。

Native生成が1件だけ失敗した場合、
Bundle全体を破棄せず、そのtargetだけ外部AI用Promptへfallbackする。

## Actor label

`actor_label` はPresentation / dispatch用の人間可読ラベルであり、
権限・所有権・Task担当者を意味しない。

Execution Packet promptには次の形で含める。

```text
【担当ラベル】
A / Validation担当
```

actor_labelからUser IDや権限を推測しない。

## Stale semantics

Distribution生成後に各Taskの以下が変われば、そのtargetだけstaleとする。

- Task
- Dependency
- Evidence
- Goal Context
- Resource / Artifact
- confirmed constraint等、既存Orchestration Context fingerprint対象

1担当がstaleになっても他担当のPacketは自動破棄しない。

UIではstale targetへ「再生成が必要」を表示する。

## Execution Request continuity

V47.1でTask単位のconfirmed Execution Requestが存在する場合、
Distributionから同じTaskへPacket / Promptを作るときもそのRequestを引き継ぐ。

Distribution自体は新しいExecution Requestを作らない。
Task選択と担当ラベル指定だけでTask description / next_action_note / progress等を変更しない。

## UI

Plan-level route:

```text
/plans/{plan}/execution-distribution
```

画面では未完了Taskを一覧し、

- 対象Task
- 担当ラベル
- actor type
- available minutes

を指定する。

生成後は担当ごとのcardを表示する。

- target Task
- actor label
- ready / blocked
- stale
- Native Packet または External Prompt
- 個別Execution Orchestrationへのリンク

## Safety

- Plan edit権限を要求
- selected TaskごとにTask ownershipを再検証
- cross-plan target拒否
- completed / cancelled target拒否
- AIによるTask ID選択なし
- Distribution生成だけではcanonical mutationなし
- Dependency変更なし
- progress変更なし
- actor_labelを権限根拠にしない
- Native AI障害時はtarget単位でfallback

## Non-goals

- durable Distribution Bundle table
- PlanActor model
- autonomous multi-agent runtime
- AI同士の自動メッセージ交換
- Slack / GitHub / ChatGPT等への自動送信
- 担当者アカウントへの自動割当
- Packet完了の自動Evidence化
- AIによるTask追加 / Task選択
