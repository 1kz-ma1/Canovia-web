# V50.3 Standalone Plan Dashboard

## 目的

Plan Dashboardを「Mapの中に開くDocument」から、独立したDashboard Document Surfaceへ昇格する。

V50.2でInformation Boardとしての中身は成立したため、V50.3ではSurface ownershipを分離する。

```text
Before
Map
└ Plan Dashboard Document
   └ Spatial Roadmap

After
Plan Dashboard Document
└ Spatial Roadmap Region

Map
└ launch Plan Dashboard
```

MapはPlan Dashboardを起動できるが、Dashboardのrender / camera / Task Detailを所有しない。

## Canonical route

Plan Dashboardの正規URL:

```text
GET /plans/{plan}/dashboard
route: plans.dashboard
```

Plan intentのMap L1 Plan nodeもこのrouteへ遷移する。

旧:

```text
/map?level=l2&intent=plan&plan={id}
```

はV50.3では互換Surfaceとして残す。既存bookmark / semantic routeを即時破棄しない。

## Surface responsibility

```text
Classic Plan
= 詳細管理・編集・各種操作

Plan Dashboard Document
= Plan全体の俯瞰・比較・判断

Spatial Roadmap
= Dashboard内でTask構造・依存・並行性を理解するRegion

Map
= Plan群や他Contextの構造探索 / Dashboardへの入口
```

Plan DashboardはMap backgroundやMap node projectionが存在しなくても完全に利用できる。

## Shared workspace projection

`PlanDashboardWorkspaceService` を追加し、Plan Dashboardに必要なrequest-time projectionを一箇所へ集約する。

Input:

- Request
- Plan

Output:

- Plan
- progress
- canonical Roadmap
- Spatial Roadmap
- Dashboard Board
- can_view
- can_edit
- can_manage
- execution_url

Standalone ControllerとLegacy Map L2 compatibility surfaceは同じServiceを使う。

これによりMap projectionがPlan Dashboard data assemblyを所有しない。

### Authorization

`canView` をrelations loadより先に確認する。

private Planを閲覧できないrequestではTask / WorkLog / availability等のDashboard relationを読み込まない。

## Shared Information Board

V50.2の6 Region markupは:

`resources/views/plans/partials/dashboard-information-board.blade.php`

へ抽出する。

両Surfaceが同じmarkupを利用する。

- Overview
- Progress
- Next
- Attention
- Activity
- Spatial Roadmap

Map compatibility側とStandalone側でBoardの二重実装を作らない。

## Generic Document ownership

Standalone Plan Dashboardは:

```html
data-dashboard-document
```

を持つが:

```html
data-dashboard-document-owner="map"
```

を持たない。

したがって `dashboard-document.mjs` が直接mountする。

利用するgeneric interaction:

- whole-document initial fit
- explicit zoom
- touch pinch
- trackpad pinch
- pan
- double-click zoom
- resize refresh
- Phase / Cluster region focus

## Region focus

V50.3ではGeneric Dashboard Document runtimeへRoadmap Region Focusを移植する。

`data-roadmap-region-focus` を押した場合:

1. rendered region boundsを取得
2. current document scaleからnatural boundsへ変換
3. `documentRegionFocusScale` でtarget scaleを算出
4. region centerをviewport centerへanchor
5. focused stateを付与

Manual fit / zoom / pinchを行った場合はRegion Focusを解除する。

Map-owned compatibility surfaceは既存Living Map runtimeを使うため二重handlerにはしない。

## Standalone Task Detail

Next / Ready / Blocked / Spatial Roadmap Taskは既存task templateを再利用する。

Template source:

`map.partials.roadmap-task-surface-templates`

Standalone runtime:

`resources/js/plan-dashboard.mjs`

Hash contract:

```text
#roadmap-task=roadmap-task:{taskId}
```

Behavior:

- Task tap -> Detail dialog
- browser Back -> Detail close
- Close / Backdrop / Escape -> Detail close
- direct hash entry -> Detail open
- open時Close controlへfocus
- close時は可能なら元のTask controlへfocusを戻す
- Detail close後もouter Document scale / scrollを変更しない

Task Detailのcanonical content/actionをMap用と別に複製しない。

## Navigation

Plan intentのMap node:

```text
Map L1 Plan
  -> plans.dashboard
```

navigation kindは `dashboard`。

Execution intentは従来通りExecution Mapへ進む。

Classic PlanからもDashboard actionを提供し、Classic <-> Dashboardを相互移動できる。

## Mobile

MobileでもInformation Boardをvertical feedへ戻さない。

- Canvas: 70rem
- initial fit
- pinch / pan
- fixed Dashboard chrome
- Task Detailはbottom-sheet presentation

情報配置はDesktopと同じ意味関係を維持する。

## Persistence

追加DBなし。

保存しない:

- Document Camera state
- Region Focus
- Task Detail state
- Board layout

Task DetailのHashはbrowser navigation stateでありdomain persistenceではない。

## Compatibility

V50.3で削除しないもの:

- Legacy Map L2 Plan Dashboard
- Living Map Document runtime
- Existing Spatial Roadmap projection
- Classic Plan
- V49.9 Task Detail template

移行完了を確認してからLegacy Map L2 Plan Dashboardの役割を再評価する。

## Non-goals

- Automatic Classic / Dashboard / Map selection
- Dashboard layout editor
- Region drag/drop / persistence
- AI Insight
- Classic Plan廃止
- Legacy Map L2 route削除
- Spatial RoadmapをDashboard全体へ戻す

## Tests

追加 / 更新するcontract:

- Standalone Dashboard routeをownerが開ける
- private Planは別userから404
- Generic Dashboard Document attrsを持つ
- Map owner attrを持たない
- 6 Information Board Regionを描画
- Spatial Roadmap Region Focusを維持
- Task template / Task Detail hostを描画
- Map L1 Plan nodeがStandalone Dashboardへ遷移
- Legacy Map L2 Plan Dashboardは互換表示可能
- Task Detail hash parser
- Shared Workspace ServiceをStandalone / Map両方が利用

## Product rule

V50.3以降のPlan Dashboardについて:

> DashboardはMapの最下層ではない。Planを判断する独立Surfaceであり、Mapは必要な構造だけDashboardの中に埋め込まれる。
