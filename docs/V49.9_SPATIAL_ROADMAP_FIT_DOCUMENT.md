# V49.9 Spatial Roadmap / Fit Document

## 目的

Plan Dashboardを「大きい既存Roadmapを横スクロールする画面」から、最初に全体構造を把握し、必要な場所へ段階的にズームするDocumentへ移行する。

V49.9は一度に全部を置き換えず、次のPhaseで進める。

## Phase 1 — Spatial Roadmap Primary

Plan Dashboard内のRoadmapは、既存の `RoadmapSpatialProjectionService` を正式なPrimary Projectionとして使う。

### Data flow

```text
RoadmapService
  -> canonical Roadmap
  -> RoadmapSpatialProjectionService
  -> Plan Dashboard roadmap_spatial
  -> roadmap-spatial-map
```

Plan Dashboardでは従来Roadmap fallbackを通常経路から外す。

### Dashboard overview contract

Plan Dashboard内は `roadmapSurfaceMode=dashboard-overview`。

- Map view固定
- List switchなし
- Roadmap toolbarなし
- Current Task自動センタリングなし
- Current Task自動openなし
- Task detail bodyは表示しない
- Phase / Cluster / Task / Dependencyを構造把握用に表示
- heightをDashboard向けに抑える
- Spatial Stage全体をDashboard Roadmap frameへ自動fit
- fit後は内部Roadmap scrollではなく「全体構造図」として見せる

`/roadmap` 本体は `standard` modeを維持する。

- Map/List切替あり
- Current Task自動センタリングあり
- Task detailあり
- Work Session actionあり

つまりDashboard RoadmapはRoadmapアプリの縮小コピーではなく、Plan資料の構造図として扱う。

## Phase 2 — Fit Document Camera

Plan / leaf Detail Documentを初期表示時にviewportへ全体fitする。

### Implemented contract

Documentは次の構造を持つ。

```text
Document Viewport
├ Fixed Chrome
│  ├ Back / Title
│  ├ −
│  ├ 全体
│  ├ ＋
│  └ Zoom %
└ Document Scroll
   └ Document Stage
      └ Document Canvas
```

- initial state = fit
- fixed Chromeはscaleしない
- Document Canvasだけscale
- Document Stageがscale後のlayout width / heightを持つ
- Stageがscroll geometryのsourceになる
- PanはDocument Scrollだけで行う
- `− / 全体 / ＋` をPrimary Zoom controlとする
- `全体` でfitへ戻る
- current倍率を%表示する
- fit scaleは100%を超えない
- fit scaleをmanual zoomの下限とする
- manual zoom上限は160%
- zoom stepは1.25倍
- manual zoom時は現在viewport中心をできるだけ維持する
- resize / pageshow時にCameraを再計測する
- leaf Detailを開くたびに新しいDocumentをfitから開始する

fit計算はDocument Scrollの利用可能width / heightとDocument Canvasのnatural sizeから求める。

```text
fit = min(
  available width / document width,
  available height / document height,
  1.0
)
```

Document Camera stateはruntimeのみで、DB / sessionStorageへ保存しない。

Phase 2ではgesture競合を避けるため、pinch zoomはまだ導入しない。

## Phase 3 — Direct Manipulation

Document Cameraを直接操作へ拡張する。

### Implemented interaction

- touch 2本指 pinch zoom
- desktop / trackpadの `ctrl+wheel` pinch zoom
- gesture中心を保ったanchored zoom
- Document上のdouble clickでpointer位置を中心に1段zoom
- Roadmap Phase tap -> Phase列へzoom-to-region
- Roadmap Cluster tap -> Clusterへzoom-to-region
- Roadmap Task tap -> zoomせずDetail Surface
- pinch直後のclickは短時間抑制して誤タップを防ぐ
- pinch中はCanvas transform transitionを停止する

Document上のpinch / trackpad gestureは背面Mapへ伝播させない。

### Semantic contract

```text
Phase / Cluster = Container = zoom
Task            = Leaf      = detail
```

Roadmap Container focusは対象DOMのrendered boundsからnatural Document座標を導出し、Document Cameraのfit scale〜160%の範囲で対象領域を中央へ寄せる。

### Task Detail

Plan DashboardのSpatial Roadmap Taskはhidden Task Detail templateを持ち、既存のMap Detail Surfaceを再利用する。

Task Detailには:

- Task summary
- Roadmap上のPhase / Cluster context
- status / progress / remaining / priority
- prerequisite / blocker state
- Execution Orchestration
- Task edit
- Classic Plan

を表示する。

Task Detail open時は `#roadmap-task=<template-id>` をHistoryへpushし、次の操作がすべて同じclose contractへ接続される。

- Safari/browser Back
- standalone PWA left-edge back
- fixed Back
- Close
- Escape

ブラウザReload等でhashから直接復元された場合も、close時にhashを除去する。

### Gesture boundary

single-finger panは従来のDocument Scrollへ任せる。

2本目のtouchが入った時点でDocument pinchを開始し、PWA edge-back armを解除する。

Trackpad pinchはDocument Scroll上ではDocument Cameraが先に処理し、Map cameraへbubbleさせない。

### Runtime-only state

追加永続化なし。

保存しない:

- pinch state
- focused Roadmap region
- current Document scale
- Roadmap Task Detail open state

History stateはnavigation stack整合のためのみ使用し、DB / sessionStorageへ保存しない。

## Phase 4 — Spatial depth polish

必要に応じてRoadmapの視覚奥行きを強化する。

- Current = foreground / strong glow
- Ready = near foreground
- Future = neutral
- Blocked = recessed
- Done = further recessed / low opacity
- Cluster = translucent spatial volume
- Dependency = depth-aware line

本物の3D engineは導入せず、2.5D presentationで情報階層を表現する。

## Phase 1 Persistence

追加DB変更なし。

`roadmap_spatial` はRoadmap canonical dataからrequest時に生成するread-only projection。

Plan Dashboard projection digestへSpatial projection keyを含め、Task構造変更時にProjection identityも更新する。

## Phase 1 Tests

- Plan Dashboard payloadに `roadmap_spatial.nodes` がある
- Spatial projection keyがある
- Dashboardでは `data-roadmap-fixed-view=map`
- `data-roadmap-spatial-mode=dashboard-overview`
- auto-center=0
- List panelを描画しない
- Dashboard Spatial Stageに `--roadmap-overview-scale` を計算して全体fit
- `/roadmap` standard modeはauto-center=1を維持

## Phase 2 Tests

- fit scaleはwidth / height両方へ収まる値を返す
- Documentがviewportより小さい場合は100%を超えない
- explicit zoomはfit scale未満へ縮小しない
- explicit zoomは160%を超えない
- Plan DashboardにCamera / Stage contractがある
- leaf DetailにCamera / Stage contractがある
- Camera用CSSはStage寸法とCanvas transformを分離する

## Phase 3 Tests

- pinch distance ratioがfit floor / 160% ceiling内でscaleへ反映される
- anchored zoomのscroll offsetが同じnatural pointをgesture中心へ維持する
- region focusはviewportへ収まる倍率をwidth / height両方から計算する
- Plan DashboardでPhase / Clusterにregion focus contractがある
- Taskにleaf detail-open contractがある
- Roadmap Task Detail templateが存在する
- standard `/roadmap` にはDashboard direct manipulation markerを出さない

## Remaining non-goals through Phase 3

- persistent document camera
- freeform drag-to-zoom selection
- nested Roadmap semantic hierarchyのDB化
- Spatial projection algorithm全面変更
- canonical Phase / Cluster model追加
- 2.5D depth polish
