# V49.9 Spatial Roadmap / Fit Document

## 目的

Plan Dashboardを「大きい既存Roadmapを横スクロールする画面」から、最初に全体構造を把握し、必要な場所へ段階的にズームするDocumentへ移行する。

V49.9は一度に全部を置き換えず、次のPhaseで進める。

## Phase 1 — Spatial Roadmap Primary

Plan Dashboard内のRoadmapは、既存の `RoadmapSpatialProjectionService` を正式なPrimary Projectionとして使う。

### Data flow

```text
RoadmapService
  -> canonical Roadmap
  -> RoadmapSpatialProjectionService
  -> Plan Dashboard roadmap_spatial
  -> roadmap-spatial-map
```

Plan Dashboardでは従来Roadmap fallbackを通常経路から外す。

### Dashboard overview contract

Plan Dashboard内は `roadmapSurfaceMode=dashboard-overview`。

- Map view固定
- List switchなし
- Roadmap toolbarなし
- Current Task自動センタリングなし
- Current Task自動openなし
- Task detail bodyは表示しない
- Phase / Cluster / Task / Dependencyを構造把握用に表示
- heightをDashboard向けに抑える

`/roadmap` 本体は `standard` modeを維持する。

- Map/List切替あり
- Current Task自動センタリングあり
- Task detailあり
- Work Session actionあり

つまりDashboard RoadmapはRoadmapアプリの縮小コピーではなく、Plan資料の構造図として扱う。

## Phase 2 — Fit Document Camera

Plan / leaf Detail Documentを初期表示時にviewportへ全体fitする。

予定contract:

- initial state = fit
- fixed Chromeはscaleしない
- Document Canvasだけscale
- scale後の実寸に合わせたDocument Stageを持つ
- Panで資料内移動
- 明示Zoom controlで拡大縮小
- `全体` controlでfitへ戻る

Phase 2ではgesture競合を避けるため、まず明示controlをPrimaryにする。

## Phase 3 — Direct Manipulation

Phase 2のCameraが安定した後に追加する。

- pinch zoom
- pointer中心を保ったzoom
- double tap / region focus
- Roadmap Phase / Clusterをtap -> zoom-to-region
- TaskはLeafとしてtap -> Detail

Canovia Mapと同じ:

```text
Container = zoom
Leaf = detail
```

をDocument内部にも適用する。

## Phase 4 — Spatial depth polish

必要に応じてRoadmapの視覚奥行きを強化する。

- Current = foreground / strong glow
- Ready = near foreground
- Future = neutral
- Blocked = recessed
- Done = further recessed / low opacity
- Cluster = translucent spatial volume
- Dependency = depth-aware line

本物の3D engineは導入せず、2.5D presentationで情報階層を表現する。

## Phase 1 Persistence

追加DB変更なし。

`roadmap_spatial` はRoadmap canonical dataからrequest時に生成するread-only projection。

Plan Dashboard projection digestへSpatial projection keyを含め、Task構造変更時にProjection identityも更新する。

## Phase 1 Tests

- Plan Dashboard payloadに `roadmap_spatial.nodes` がある
- Spatial projection keyがある
- Dashboardでは `data-roadmap-fixed-view=map`
- `data-roadmap-spatial-mode=dashboard-overview`
- auto-center=0
- List panelを描画しない
- `/roadmap` standard modeはauto-center=1を維持

## Non-goals for Phase 1

- Document fit
- pinch zoom
- region focus
- Task detail integration
- Spatial projection algorithm変更
- canonical Phase / Cluster model追加
