# V56.4 Study Routing Mastery / Cooldown

## Goal

V56.4 changes Study Practice routing so Canovia, not AI prose, decides when a weakness
should be reinforced, when it should be cooled down, and when practice should return to
cross-domain exploration.

The canonical loop is:

```text
discover weakness
→ bounded remediation
→ reproducibility check
→ cooldown / mastery
→ broad exploration
→ delayed retention check
→ reopen only when evidence fails again
```

V56.4 builds on:

- V41.4 weakness priority
- V56.0 exam convergence / graduation
- V56.3 Question Bank exposure rotation

No database migration is introduced.

## Problem

The current implementation already ignores `correct` question feedback as direct weighted error,
but two other paths can still keep a solved topic alive:

1. `assessment.weaknesses` is accepted as a summary weakness even when detailed feedback says
   the answer was correct.
2. `next_step.focus_topics` can create a new weakness candidate by itself.

Therefore an AI assessment such as:

```text
score = 100
correctness = correct
error_type = none
reasoning_feedback = "GROUP BY / HAVINGをより具体的に説明できる"
next_step.focus_topics = ["SQL"]
```

can still make SQL appear weak enough to influence subsequent generation.

V56.4 removes that authority from prose-level recommendations.

## Responsibility boundary

### AI owns

- question generation inside the Canovia allocation
- answer grading
- error classification
- concise weakness labels for actual errors
- feedback text
- suggested next action

### Canovia owns

- Task practice mode
- confirmed / suspected routing status
- remediation allocation
- mastery / cooldown
- delayed retention check
- parent-topic exposure control
- broad-assessment parent caps
- transition back to exploration

AI `next_step` remains advisory.

## Routing-grade evidence

Strong routing evidence:

- correctness = incorrect
- correctness = partial
- knowledge_gap
- concept_gap
- reasoning_gap
- condition_reading
- unit_error
- repeated calculation_slip / careless

Not routing evidence by itself:

- correctness = correct
- error_type = none
- reasoning_feedback that only asks for more precision
- more formal terminology
- explaining why every distractor is wrong
- assessment summary prose
- AI next_step focus without matching observed error evidence

For modern assessments with structured `question_feedback`, that structured feedback is
authoritative over summary `weaknesses`.

Legacy attempts that do not contain structured correctness/error classification may continue to
use summary `weaknesses` as a compatibility fallback.

## Practice Task mode

V56.4 derives one internal mode from Task title + description.

### focused_remediation

Typical intent:

- 弱点補強
- 弱点補完
- 重点補強
- 集中復習
- 克服

Allocation target:

```text
primary remediation ≈ 60%
related / retention ≈ 20%
diagnostic exploration ≈ 20%
```

Confirmed weakness may temporarily dominate.

### broad_assessment

Typical intent:

- 分野横断
- 横断問題
- 総合演習
- 全体確認
- 模試 / 本番演習
- 弱点探索

Allocation for a 10-question block:

```text
confirmed weakness recheck: 0..2
retention check:           0..2
cross-domain exploration:  at least 6
```

A confirmed weakness does not turn a broad Task into a 10-question single-domain drill.

### adaptive

When Task intent is not explicit, retain the existing V56.0 behavior while applying mastery,
cooldown and parent exposure safeguards.

Task-mode terms are configuration, not hard-coded scattered conditionals.

## Structured topic observations

V56.4 derives topic observations from existing durable data.

Priority for question topic identity:

1. Question Bank `learning_metadata.weakness_targets`
2. Question Bank specific `learning_metadata.concepts`
3. structured feedback `weakness_topics`
4. Session focus topic when a focused generated Session has one unambiguous focus
5. attempt `strengths` / legacy summary fallback

Correct feedback may be used as positive mastery evidence, but never as weakness evidence.

## Mastery / cooldown

Initial configurable defaults:

```text
remediation_correct_streak = 2
mastery_correct_count = 3
cooldown_sets = 2
mastered_cooldown_sets = 4
perfect_score_percent = 100
```

### cooldown

A subtopic enters cooldown when its latest routing observations contain at least two consecutive
correct results with no intervening failure.

During cooldown:

- it is removed from focused routing
- broad Question Bank selection strongly deprioritizes matching questions
- a broad parent may still contain at most the configured small number of questions

### mastered

A subtopic is considered mastered-for-routing when:

- at least 3 correct observations exist in the bounded history
- the latest sequence still contains at least 2 consecutive correct observations
- no newer failure supersedes them

Mastered is not permanent knowledge state. It means "do not deliberately drill now."

### retention_due

After the cooldown set count has elapsed without another exposure, the topic becomes eligible for
one small retention check.

If that check is correct:

- mastery confidence rises
- the topic returns to a longer cooldown

If it fails:

- normal weakness evidence rules apply
- repeated blocking failure can reopen focused remediation

## Confidence vs recent exposure

V56.4 exposes these separately.

### mastery_confidence

Derived from graded observations for the topic/parent.

It represents evidence that the learner can reproduce the knowledge.

### recent_exposure

Derived from recently selected questions.

It represents how much recent practice has already been spent on the topic/parent.

They are never the same number.

Conceptual routing preference:

```text
need ≈ weakness / uncertainty × (1 - recent_exposure)
```

The implementation may use deterministic ordering and caps rather than this exact formula.

## Parent-topic taxonomy

V56.4 adds a lightweight AP routing taxonomy in configuration.

Examples:

- データベース
  - SQL / GROUP BY / HAVING / JOIN / 副問合せ
  - トランザクション
  - 正規化
  - NoSQL
- ネットワーク
- セキュリティ
- アルゴリズム
- OS
- コンピュータ構成
- 性能・可用性
- 開発
- プロジェクトマネジメント
- サービスマネジメント
- システム監査
- ストラテジ
- 経営・法務

This is routing taxonomy only. It does not replace Question Bank learning metadata or create a
new normalized topic database.

## Parent recent exposure

Initial defaults:

```text
recent question window = 10
high exposure threshold = 0.40
broad normal parent cap = 2
high-exposure parent cap = 1
```

Example:

```text
latest 10 questions:
Database = 5
Database mastery confidence = high

→ Database recent_exposure = 0.50
→ next broad block caps Database at 0..1 preferred questions
```

The selector does not continue GROUP BY → HAVING → JOIN merely because all are distinct subtopics.

## Question Bank routing

V56.3 question-level exposure rotation remains in force.

V56.4 adds routing above it:

```text
Task mode / question allocation
→ subtopic cooldown suppression
→ parent-topic cap / exposure preference
→ V56.3 question exposure rotation
→ difficulty / sort order
```

Broad selection groups diagnostic candidates by parent topic rather than only a local domain key.

If hard caps make the current Bank unable to fill a Hybrid block, uncovered seats may be filled by
Native AI under the same Canovia routing constraints.

Bank-only mode may relax a cap only as a final fill to avoid failing the Session.

## Broad-assessment override

When V56.0 detects an active weakness inside a broad-assessment Task, V56.4 does not discard the
weakness.

Instead:

```text
active weakness
→ 1..2 recheck questions
+
remaining questions
→ exploration / low-confidence parents / retention
```

The effective routing phase is broad/general practice so an AI `next_step=practice` cannot turn
the next Session back into a full weakness drill.

## Focused remediation

Focused remediation keeps V56.0 targeted behavior.

However a focused topic that has satisfied V56.4 cooldown/mastery evidence is removed from the
active routing set.

If no eligible focused topic remains:

```text
focused remediation Task
→ General Practice / exploration return
```

AI cannot keep it active only because another variant exists.

## Assessment prompt boundary

Evaluation instructions explicitly state:

- a correct answer with `error_type=none` must not create routing weakness
- reasoning brevity / lack of distractor explanation alone is feedback only
- use partial / reasoning_gap only when the answer actually demonstrates a substantive reasoning error
- `weakness_topics` on a correct answer should normally be empty
- `next_step.focus_topics` must not be based only on prose-quality improvement

Normalization still forces:

```text
correctness = correct
→ error_type = none
```

for backward compatibility.

## Compatibility

Existing JSON fields remain unchanged:

- weakness_topics
- error_type
- strengths
- weaknesses
- recommended_task_progress_percent
- next_action
- next_step
- focus_topics

No new field is required from external AI for V56.4 to function.

New routing information is computed inside Canovia and stored in
`StudyPracticeSession.selection_context.strategy.routing_policy`.

New Question Bank selections may additionally persist:

- selection_parent_topic
- selection_parent_recent_exposure
- selection_parent_cap
- selection_cooldown_match

Historical Sessions without these fields remain valid.

## Tests

V56.4 must cover at least:

1. correct + error_type=none + reasoning improvement does not become weakness
2. two correct observations move a subtopic into cooldown
3. cooldown topic is strongly suppressed from the next broad Bank selection
4. high recent exposure suppresses the whole parent even for another subtopic
5. broad assessment does not allocate all 10 questions to one parent
6. focused remediation can still prioritize a confirmed weakness
7. one calculation_slip / careless is not confirmed
8. repeated same-concept error becomes confirmed / focused
9. sufficient remediation returns to exploration
10. AI next_step asking to continue a mastered/cooldown topic cannot override broad routing

Regression must also preserve:

- V56.0 convergence
- V56.2 official Pack priority
- V56.3 exposure rotation
- V41.4 weakness priority
- Hybrid assembly
- Native AI Study Practice
- Study Task progression

## Definition of Done

V56.4 is complete when:

- correct reasoning-improvement prose cannot keep a topic weak
- solved subtopics leave focused routing
- broad Tasks prioritize coverage over depth
- parent-topic overexposure is capped
- focused remediation still works when evidence is truly repeated
- isolated slips remain low-confidence signals
- AI continuation advice cannot override cooldown/mastery
- existing JSON remains compatible
- no migration is required
- relevant regression tests pass
