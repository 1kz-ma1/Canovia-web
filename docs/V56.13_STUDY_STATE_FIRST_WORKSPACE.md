# V56.13 Study State-First Workspace Composition

## Goal

Replace the Study Workspace's fixed "Study Plan → Study Scope Capture → Evidence" entry sequence with a state-first composition model.

The Study Workspace must answer:

```text
What kind of learning is this?
+
What does Canovia already know about the learner?
+
What information would actually change the next decision?
↓
Which Study surfaces should be shown now?
```

A Study Plan must not be forced through Study Scope Capture merely because no confirmed `StudyScopeCapture` exists.

## Architecture

```text
Plan / Tasks / Study Evidence / Practice Attempts / Deadline
↓
StudyLearningTypeRouter
↓
StudyWorkspaceStateResolver
↓
StudyWorkspaceSurfacePolicy
↓
StudyWorkspaceSurfaceRegistry
↓
prebuilt Blade surface partials
```

### 1. Learning Type Router

Initial deterministic types:

- `certification_exam`
  - AP / FE / qualification-style learning
- `score_exam`
  - TOEIC / TOEFL / IELTS / score-target learning
- `school_test`
  - midterm / final / regular school tests
- `memorization`
  - vocabulary / terminology / memorization-heavy goals
- `skill_learning`
  - learning a practical skill
- `general_learning`
  - fallback

The router is a UI/policy classifier, not a permanent Plan schema migration.

It uses existing Plan title / description / category and exposes reasons/confidence for debugging.

### 2. State Resolver

State is derived from durable Canovia facts:

- confirmed Study Scope count
- observed Scope count
- Practice Attempts
- Practice / Recall TaskEvidence
- recent scores
- structured weaknesses
- active Tasks
- deadline / days remaining

The resolver distinguishes:

- whether current position is already known
- whether Scope exists
- whether Practice history exists
- whether weaknesses are known
- whether the learner is in baseline / active practice / scope-informed state

A Practice Attempt or Study Evidence is enough to establish that the learner already has a usable current position even when confirmed Scope is absent.

### 3. Missing Context policy

Canovia asks only for context that materially changes the next action.

Initial rules:

#### Certification exam

If current position is known:

- do not require Scope
- continue from Practice / weakness / recent result state

If current position is unknown:

- prefer a baseline / diagnostic action
- Scope remains an optional learning method, not a mandatory gate

#### Score exam

If current position is unknown:

- ask for current score or diagnostic baseline
- do not ask for exam scope by default

The first implementation does not invent an absolute TOEIC/IELTS score from Practice percentage. Absolute score capture can be added later as a dedicated evidence surface.

#### School test

If Scope is missing:

- Scope is decision-changing context
- surface Scope Capture prominently

#### Memorization

Prefer Recall / retention state.

#### Skill learning

Prefer practical Evidence / current Task state.

### 4. Surface Registry

Prebuilt reusable Study surfaces:

- `goal_summary`
- `current_state`
- `missing_context`
- `readiness`
- `biggest_gap`
- `current_action`
- `weaknesses`
- `recent_results`
- `scope_coverage`
- `study_methods`

The registry maps stable keys to Blade partials.

The Policy selects and orders the surfaces. Blade does not branch on specific exams such as AP or TOEIC.

Future image / diagram / material viewers can be registered as additional surfaces without changing the learning-type architecture.

## AP behavior

For an AP Plan with durable Practice history but no confirmed Study Scope:

```text
Certification Exam
+
Practice history exists
+
recent score / weakness data exists
↓
Current position = known
↓
show:
  Goal Summary
  Current State
  Current Action
  Weaknesses
  Recent Results
  Study Methods

do not show:
  mandatory Scope onboarding
```

The primary action goes to the existing Task-scoped Study Practice flow when a suitable Task exists.

## New TOEIC 600 behavior

For a new `TOEIC 600` Plan with no Study history:

```text
Score Exam
+
target score = 600
+
current position unknown
↓
show:
  Goal Summary
  Current State
  Missing Context: current score / diagnostic
  Current Action
  Study Methods

do not show:
  mandatory Study Scope Capture
```

Practice percentage must not be interpreted as TOEIC scale score.

## School test behavior

For a new regular school-test Plan:

```text
School Test
+
confirmed Scope missing
↓
show:
  Missing Context: test range
  Scope Capture action
```

This is where the existing Study Scope capture experience remains first-class.

## Existing Study Intelligence

V53/V54 Study Intelligence remains authoritative when confirmed Scope exists.

In that case registered surfaces may reuse:

- Exam Readiness
- Biggest Gap
- Current Adaptive Action
- Coverage / Mastery / Retention
- Priority remaining Scope

V56.13 does not replace the existing readiness scoring model.

It changes whether that model is allowed to gate the whole Study Workspace.

## Workspace onboarding

Study Workspace onboarding becomes Plan creation only.

After a Study Plan exists, State First composition owns the next visible requirement.

The generic `WorkspaceModeOnboardingService` is no longer used to force:

- capture_study_scope
- record_study_evidence

for every Study Plan.

## Safety / compatibility

- no DB migration
- no new AI request
- no inferred absolute exam score
- no Task creation on GET
- no change to Study Practice routing
- no change to Study Recall scheduling
- no change to Study Scope Capture itself
- existing V53 Readiness remains when Scope is meaningful
- existing authorization and Plan selection remain unchanged

## Initial validation cases

1. AP + Practice history + no Scope does not show capture-first onboarding.
2. AP + Practice history shows recent score / weakness / Practice CTA.
3. certification exam with no history asks for baseline, not mandatory Scope.
4. TOEIC 600 is classified as score exam.
5. TOEIC 600 with no history asks for current score / diagnostic, not Scope.
6. school test with no Scope asks for test range.
7. skill learning with no Scope does not ask for exam range.
8. memorization type prioritizes Recall when Task context exists.
9. confirmed Scope still exposes existing Readiness / Gap / Scope surfaces.
10. no Study Plan still shows Plan-creation onboarding.
11. inaccessible/non-Study plan selection remains 404.
12. no GET request creates a Task.


## Implementation / Validation

Implemented:

- `StudyLearningTypeRouter`
  - deterministic Study Plan classification
  - score target extraction for supported score-exam titles
- `StudyWorkspaceStateResolver`
  - derives current-position state from Practice Attempts, Study Evidence, Scope, Tasks and deadline
  - extracts bounded recent scores and structured weakness topics
- `StudyWorkspaceSurfaceRegistry`
  - stable reusable Study surface keys mapped to Blade partials
- `StudyWorkspaceSurfacePolicy`
  - selects Missing Context, Current Action and supporting surfaces from type + state
  - keeps Scope mandatory only for school-test-style Plans where it materially changes the next decision
- Study Workspace
  - renders registry-selected surfaces instead of one fixed Scope-first page
  - no-Plan onboarding remains Plan creation
  - existing Plan immediately enters State First composition
- Study Plan creation copy
  - no longer promises that Scope Capture is always the next step
- existing V53 Scope-based Readiness
  - preserved and rendered when confirmed Scope exists

Initial registered surfaces:

- Current State
- Missing Context
- Readiness
- Biggest Gap
- Current Action
- Weaknesses
- Recent Results
- Scope Coverage
- Study Methods
