# V54.8 Workspace Mode Polish / Telemetry / iOS

## Goal

V54.8 closes the V54 Workspace Mode series.

It does not add a new Workspace, new Intelligence model, or new navigation authority.

The goals are:

1. make the fixed Workspace Mode control robust on real mobile / PWA / iOS surfaces
2. keep dropdown state coherent through Instant Navigation, viewport changes and native/PWA navigation
3. add bounded, privacy-safe telemetry for Mode selection and automatic Mode context
4. finalize permanent Workspace Mode documentation and remove the temporary implementation handoff after validation

## Product invariants

Workspace Mode remains:

- one Canovia product
- one Intelligence Core
- context/navigation, not a Plan filter
- context/navigation, not billing
- semantic route / Plan truth above manual preference

Resolver precedence remains unchanged.

No Readiness / scoring / ranking formula changes in V54.8.

## 1. Fixed header / safe-area contract

The existing parent mobile header already owns top safe-area.

V54.8 adds explicit horizontal safe-area handling to the Workspace Mode row itself.

On mobile:

- Mode Bar left padding respects `safe-area-inset-left`
- Mode Bar right padding respects `safe-area-inset-right`
- dropdown width is constrained inside the physical viewport
- dropdown height is bounded by dynamic viewport height
- dropdown content becomes internally scrollable when necessary
- touch scrolling uses iOS momentum scrolling
- menu overscroll is contained

The Mode Bar remains a child of the existing sticky header.
No second sticky layer is introduced.

## 2. Dropdown lifecycle

A small client runtime owns only ephemeral dropdown UI state.

It does not own Workspace selection or persistence.

Open dropdowns close on:

- outside pointer interaction
- Escape
- Instant Navigation page replacement
- Instant Navigation page ready
- pagehide
- orientation change
- VisualViewport resize

When one Mode switcher opens, the duplicate desktop/mobile switcher is closed so only one menu can be open.

When opened, the current option is brought into view without smooth scrolling.

This prevents stale overlays after:

- iOS rotation
- software keyboard / viewport changes
- PWA navigation
- Instant Navigation
- native WKWebView navigation changes

## 3. Telemetry

V54.8 uses the existing BehaviorEvent endpoint and table.

New client-recordable event types:

- `workspace_mode_selected`
- `workspace_mode_auto_context`

### workspace_mode_selected

Recorded when the user submits:

- a concrete Workspace selection
- reset to automatic Mode resolution

Safe metadata only:

- `selected_mode`: overview / study / development / auto
- `from_mode`: overview / study / development
- `from_source`: explicit / manual_preference / route_hint / plan_profile / default
- `surface`: web / pwa / native
- `device`: mobile / desktop
- `platform`: ios / android / other

No Plan title, Task title, URL, user text, raw query, or AI content is retained.

### workspace_mode_auto_context

Recorded when the rendered Mode context is not `manual_preference`.

Safe metadata only:

- `mode`
- `source`
- `surface`
- `device`
- `platform`

The client stores only the last emitted `mode:source` fingerprint in sessionStorage to avoid re-emitting the same automatic context on every page.

The server independently whitelists metadata values and discards arbitrary client metadata.

Telemetry is observational only.
Failure must never block navigation.

## 4. Instant Navigation synchronization

Instant Navigation already synchronizes:

- body Mode
- page Mode
- Mode Bar Mode
- label / icon / active option

V54.8 additionally synchronizes the body Mode source and dispatches the existing page-ready lifecycle into the Mode runtime.

This means automatic-context telemetry and dropdown cleanup stay correct after shell-retained navigation.

## 5. Native / PWA boundary

V54.8 does not change session ownership.

Still authoritative:

- Laravel session cookie
- existing CSRF
- persistent WKWebsiteDataStore for Native
- PWA Service Worker only outside Native runtime

The Mode runtime uses `canoviaClientSurface()` and `canoviaClientPlatform()` so the same telemetry differentiates:

- Web
- PWA
- Native

No bridge payload contains Workspace user content.

## 6. Performance

No new server work is added to Workspace GET.

Client telemetry:

- one automatic-context event only when the mode/source fingerprint changes within the browser session
- one selected event per explicit selection/reset

No all-Plan query.
No AI request.
No GitHub provider request.
