# V52.0 iOS Readiness Foundation

## Purpose

V51.9.8でWeb/PWA実機UIを仕上げ、V51.10でinteraction orchestrationを詰めた後、CanoviaをiOSへ段階的に載せるためのWeb側境界を固定する。

V52.0ではApp Store提出やNative UI再実装は行わない。

採用する構成:

`SwiftUI shell + WKWebView + existing Laravel/Blade/JS`

Web appを引き続きsource of truthとし、Native shellはOS境界だけを担当する。

## 1. Runtime identification

新規:

`resources/js/client-runtime.mjs`

Canovia runtimeを:

- web
- pwa
- native

へ分類する。

Native判定は2経路をサポートする。

### Preferred: document-start injection

Native shellがWKUserScriptで:

```js
window.__CANOVIA_NATIVE__ = {
  platform: 'ios',
  bridgeVersion: 1,
  appVersion: '...'
}
```

をdocument startでinjectする。

### Fallback: User-Agent suffix

WKWebViewのcustomApplicationNameForUserAgentへ:

`CanoviaNative/iOS/<app-version>`

を付与する。

Web側は両方を同じruntime contractへ正規化する。

## 2. Native bridge protocol

WKWebView message handler:

`window.webkit.messageHandlers.canovia`

を使用する。

Message envelope:

```json
{
  "version": 1,
  "type": "openExternal",
  "payload": {}
}
```

Web -> Native:

- `ready`
- `navigationState`
- `openExternal`
- `fileInputRequested`
- `requestClose`

Native -> Web:

`window.CanoviaNativeBridge.receive(message)`

supported:

- `back`
- `openPath`
- `appBecameActive`

Bridgeへcookie、session id、CSRF token本文、Plan title、Task titleは送らない。

ready messageは `csrf_present=true/false` だけを通知する。

## 3. Session / CSRF ownership

Native shellは独自authentication tokenを持たない。

source of truth:

- Laravel session cookie
- existing CSRF meta token
- same-origin Web requests

WKWebViewはpersistent `WKWebsiteDataStore.default()` を使用する前提。

Web側meta contract:

- `canovia-native-bridge-version=1`
- `canovia-native-session-mode=web_cookie`
- `canovia-native-deep-link-origin=<Canovia origin>`

Native shellはcookie内容をbridgeへコピーしない。

これによりWeb/PWA/nativeで認証ロジックを分岐させない。

## 4. Service Worker ownership

PWA:

- existing `/sw.js`
- Instant Start
- offline shell

Native:

- Service Workerを登録しない
- 既存registrationがWKWebsiteDataStoreに残っている場合はunregister
- navigation/cache lifecycleはWKWebView + serverへ一本化

理由:

PWA Service WorkerとNative shell cache/update policyを同時に持つと:

- stale HTML
- deploy反映差
- navigation ownership競合

が起きやすいため。

Native offline strategyが必要になった場合はV52.xでNative側の明示的契約として追加する。

## 5. External links

Native runtimeでcross-origin http/https linkを押した場合:

Web -> Native:

`openExternal { url }`

を送る。

V52.1 shellはSFSafariViewControllerまたはsystem browser policyで開く。

Bridge handlerが存在しないprototype環境ではcurrent WebView navigationへfail openする。

### Same-origin target=_blank

スクリーンショットや元教材などCanovia自身のsame-origin `target="_blank"` は新しいWKWebViewを要求しない。

current WebView内で `openPath()` する。

これによりWKUIDelegateでwindow.open用WebViewを大量に管理する必要をなくす。

## 6. Deep link boundary

Native shellがUniversal Link / custom entryを受けた場合、Canovia origin内のpathだけを:

`window.CanoviaNativeBridge.receive({ type: 'openPath', path: ... })`

へ渡す。

Web側はsame-origin validationを行う。

Core Surface:
- existing Instant Navigation

non-core same-origin:
- normal `location.assign`

へfallbackする。

arbitrary cross-origin URLをdeep linkとしてWebView内へinjectしない。

## 7. Back / edge swipe boundary

Web側:

`CanoviaNativeBridge.handleBack()`

を提供する。

historyがある:
- `history.back()`

historyがない:
- `requestClose` をNativeへ送る

既存mobile back buttonもnative runtimeでは同じAPIを使用する。

V52.1ではNative edge swipe / navigation itemをこのcontractへ接続する。

Web historyとNative navigation stackを別々のtruthにしない。

## 8. File / photo input boundary

V52.0ではWKWebView標準file inputを維持する。

Native runtimeで `input[type=file]` を押した時:

`fileInputRequested`

をNativeへ通知する。

payload:

- accept
- multiple
- capture

Web側はclickをpreventしない。

つまりV52.1ではまずWKWebView標準:

- photo library
- camera (OS behavior / input attributesに従う)
- Files

を利用する。

Native custom pickerが必要な要件が出た場合のみbridge overrideを追加する。

## 9. Telemetry

Client surface whitelistを:

- web
- pwa
- native

へ拡張する。

対象:

- Interaction Performance
- AI Plan Funnel
- Map telemetry / Behavior metadata

Native shell導入後:

- Web
- PWA
- Native

のlatencyを同じserver logで比較できる。

## 10. PWA install UX

Native runtimeはinstalled app扱いとし、PWA install promptを表示しない。

Native runtime detectionを既存standalone checkへ統合する。

## 11. Security boundary

Bridge rules:

- versioned message envelope
- same-origin deep link only
- external navigationはhttp/https cross-originだけ
- cookie / session secretをmessageへ含めない
- CSRF本文をNativeへ渡さない
- mutationは引き続きLaravel same-origin request
- file pickerはV52.0でWeb標準ownership
