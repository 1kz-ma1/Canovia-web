# V55.1 Career Workspace Mode

## Goal

V55.1 promotes Career into the public Workspace Mode system built in V54.

Public Modes become:

```text
Overview
Study
Development
Career
```

Career reuses the V55.0 Intelligence authority.

```text
Career Reality / Evidence
→ Career State
→ qualitative Process Readiness
→ Gap
→ Decision
→ Current Action
```

V55.1 does not introduce a second Career reasoning model.

## Canonical surfaces

### Career Workspace

Canonical:

```text
GET /workspace/career
route: workspace.career.index
```

Purpose:

- select the representative Career Plan
- show Career Process Readiness
- show Biggest Process Gap
- show Current Action
- show latest State Change
- show recent Career Intelligence history
- route the user into the existing Career operational surface

### Existing Career operational surface

Existing:

```text
/plans/{plan}/career
route: plans.career.index
```

remains authoritative for:

- Career Capture
- Application pipeline
- interview scheduling
- result recording
- Interview Review operations

The Workspace is the decision surface.
The existing Career page is the operation surface.

## Resolver contract

Strong route hints:

- `workspace.career.*`
- `plans.career.*`

resolve to Career before manual preference.

Career Plan deep links resolve by Plan profile as Career.

Manual Career preference is allowed after V55.1.

## Career onboarding

Career onboarding is self-completing.

Steps:

1. `create_plan`
2. `capture_career_signal`

`create_plan` completes when a selected Career Plan exists.

`capture_career_signal` completes when Career Intelligence reports:

```text
has_career_signal = true
```

A Career signal can come from:

- Career Capture
- Career Application
- Selection Event
- supported Career TaskEvidence

Once one real Career signal exists, onboarding disappears.

Application organization, interview preparation and interview review are not onboarding steps.
Those belong to normal Career Current Action.

## Career Plan creation

From Career Workspace:

```text
/plans/create/manual?workspace_mode=career
```

Prefill:

```text
category = 就活・キャリア
```

If the created Plan still resolves to profile `career`:

```text
create
→ /workspace/career?plan_id=...
→ capture_career_signal
```

If the user changes category, do not force Career Workspace.

## Career presentation contract

Career uses the common `PlanIntelligencePresentation`.

Readiness is qualitative.

```text
readiness.score = null
```

The Career Workspace must not render `未判定` as if a numeric score were missing after Career State exists.

Use:

- no Career signal: `未観測`
- Career signal exists: `観測中`

Readiness label:

```text
Process Readiness
```

Metrics:

- Capture
- Application
- Interview
- Review Due

No employability score is introduced.

## Career action routing

Career actions remain bounded to existing operations.

`career_interview_review`:

```text
→ plans.career.interview_reviews.show
```

Other Career actions:

```text
→ plans.career.index
```

No automatic application submission or employer communication.

## State Change Feedback

Career participates in V54.6 using the existing generic history.

Safe labels:

- Interview Review
- Selection Result

Career level labels:

- unknown → 未観測
- developing → 観測中
- blocked → 要整理
- ready → 整理済み

No raw company / role / answer content is shown.

## Overview

Overview gains:

- representative Career Plan
- Career Mode summary
- Career State Change candidate
- Career first-use option

Representative Plan ordering remains:

```text
priority
→ deadline
→ ID
```

Overview still shows at most two Intelligence Changes total, sorted by recency.

First-use Workspace chooser disappears when any specialized Plan exists:

- Study
- Development
- Career

## Telemetry

Existing V54.8 Workspace Mode telemetry expands its safe Mode allowlist to include:

```text
career
```

No new telemetry fields.

## Mode Bar

Career is shown in the fixed Mode Bar.

Career icon must be distinct from Overview / Study / Development.

Career accent uses emerald semantics.

## Safety boundary

Career Workspace must preserve V55.0 constraints.

It does not:

- estimate hiring probability
- calculate market value
- rank the user
- recommend accepting or rejecting an offer
- rate employers
- infer protected traits
- auto-submit applications
- auto-send employer messages
