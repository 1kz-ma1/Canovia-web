# V44.2 Space Station

## Goal

V44.1でL0中央に配置したSpace Stationを、単なるInbox / AIリンクから
Canovia全体への共通Input Hubへ進化させる。

V44.2の基本フロー:

```text
Space Station
  ↓
Capture
  ↓
InboxItem
  ↓
Context routing candidate
  ↓
Human Review
  ↓
existing canonical destination
```

自動Mutationは行わない。

## Core principle

Space Stationは新しいdomain storeを持たない。

Captureのcanonical sourceは既存`InboxItem`を再利用する。

理由:

- InboxとSpace Stationで同じ入力を複製しない
- screenshot / PDFのprivate storage境界を再利用する
- Inbox IntelligenceのAI安全境界を再利用する
- Human Review後のRouting Serviceを再利用する
- V44 Navigation Layerを新しいsource of truthにしない

## Capture

Space Station Contextual Surfaceから以下を入力できる。

- text
- URL
- image / screenshot
- PDF

POST先は既存`inbox.store`。

追加した`return_to=space_station`は表示復帰先だけを表し、
保存モデル・権限・validationはInboxと共通。

Capture直後:

- InboxItem status = new
- Plan / Task / Evidence / Resource等は作成しない
- Mapへ戻りSpace Station Focusを復元する

## SpaceStationContextService

L0の固定Navigation Graphとは別に、Space Stationの動的Surface状態を投影する。

含むもの:

- pending Inbox count
- latest pending InboxItem
- latest routing candidate
- editable Plans / Tasks
- Inbox AI availability
- Companion availability
- routing destination catalog
- safe structural state key

含まないもの:

-新規domain entity
- absolute Map position
- AIが決めたPlan / Task ID
- automatic mutation

固定L0 Nodeの存在はこのContextに依存しない。

## Routing candidate

既存`InboxIntelligenceService`を利用する。

AI schema:

- destination
- reason
- confidence
- suggested_plan_title
- suggested_task_title

AI schemaには引き続き:

- plan_id
- task_id

を持たせない。

候補生成後は:

```text
InboxItem.status = review
InboxItem.metadata.routing_suggestion = candidate
```

だけを行う。

Canonical dataは作らない。

## L0 connection projection

既存Inbox destinationをL0 intentへ投影して表示する。

| Inbox destination | L0 connection |
| --- | --- |
| task_evidence | 振り返り |
| recall_material | 実行 |
| career_capture | 計画 |
| plan_resource | 計画 |
| keep_inbox | Space Station |

これはNavigation表示用のprojectionであり、
AI destination enumやcanonical routing modelは変更しない。

V44.5以前にGitHub等を共同Nodeへ自動分類しない。

## Human Review

Space Station SurfaceにReview formを表示する。

ユーザーが確認するもの:

- destination
- Plan
- Task

AIのPlan / Task titleはhintとしてのみ表示する。

IDはユーザーが既存Canovia entityから選択する。

確定POSTは既存`inbox.route`。

その先は既存`InboxRoutingService`が処理する。

- Career Capture
- Recall Material
- Task Evidence
- Plan Resource
- Keep in Inbox
- legacy Future Memo server compatibility

## Return boundary

Inbox Controllerに限定enumを追加:

- inbox
- space_station

任意URLは受け付けないためopen redirectにはしない。

Space Stationからの:

- capture
- suggest
- route confirmation

成功後は:

`/map#focus=intent%3Aspace-station`

へ戻る。

通常Inbox UIのredirect behaviorは変更しない。

## Companion

認証済みかつ利用可能なユーザーはSpace Stationから既存Companionをglobal contextで開く。

```text
entry_type = global
source_route = map.index
source_path = /map#focus=intent:space-station
```

V44.2ではSpace Station専用Thread typeを増やさない。

既存global Companion threadを再利用する。

CompanionのMutation Candidateも従来どおりHuman confirmation boundaryを維持する。

## Projection key

L0 projection keyはSpace Station routing stateの変化を検知する。

ただしstate keyへuser content本文は直接含めない。

使用する構造情報:

- pending count
- latest InboxItem ID
- status
- destination
- L0 intent key
- confidence

これによりLiving Reevaluationはstate変化を検知できるが、
user contentをTelemetryや識別用payloadへ保存しない。

## UI

Space Station Focus Surfaceに3領域を持つ。

### Capture

入力をそのまま投げる。

### Latest Input / Routing

最新pending itemとrouting candidateを確認し、接続先をHuman Reviewする。

### Companion

global Companionへ相談する。

全Inbox確認へのescape hatchも残す。

## Architecture boundaries

### Navigation Graph

Space Station Nodeは常時存在する。

V44.2のpending item有無やAI availabilityでNodeを消さない。

### Attention State

V44.1の中央固定・位置・sizeを変更しない。

V44.2ではusage based promotionを導入しない。

### Space Station Context

Node内部Surfaceに必要な動的状態だけを扱う。

Navigation Graph / Attention Stateと分離する。

## Telemetry

V44.1のMap structural telemetryを継続利用する。

Capture本文、URL、ファイル内容、AI reason等をMap Telemetry metadataへ追加しない。

Inbox / Native AI側の既存security boundaryを変更しない。

## Compatibility

維持するもの:

- L0 fixed nodes
- L3 Execution Map
- Classic Home
- Inbox page
- Inbox manual routing
- Inbox AI suggestion entitlement
- Companion entitlement
- Focus Mode
- Contextual Classic Surface
- Living Reevaluation
- existing Telemetry whitelist
- no-JS fallback

## Non-goals

V44.2では以下を行わない。

- auto routing
- automatic Plan / Task selection
- automatic mutation
- L1 / L2
- Semantic Zoom
- Spatial Dock inheritance
- Personalized Satellite
- GitHub collaboration projection
- external connector ingestion
- Graph DB
- AI layout
