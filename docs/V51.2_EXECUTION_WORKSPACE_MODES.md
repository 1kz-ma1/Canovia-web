# V51.2 Execution Workspace Modes

> **V55.5 update:** V51.2で「Execution Workspace」と呼んでいた `/navigate` 内のStudy / Development / Career / General分類は、V54以降のglobal Workspace Modeと語彙が衝突するため、現在は **Execution Mode / 実行タイプ** と呼ぶ。内部class・query・session keyは互換のため変更しない。Study / Development / Career WorkspaceはIntelligence / State / Readinessを担当し、Execution ModeはTaskの実行方法を決める。詳細は `docs/V55.5_EXECUTION_MODE_TERMINOLOGY.md` を正とする。

## 目的

Executionを単なる「おすすめTask一覧」から、Planの性質に応じて実行方法そのものを切り替えるWorkspaceへ拡張する。

Constellationが「全体と現在地」を担当するのに対し、Executionは:

> 今、何を、どう進める？

へ答える。

## Execution flow

```text
Execution
├ Mode selection
├ Recommendation inside selected Mode
└ Specialized handoff
   ├ Study
   ├ Development
   ├ Career
   └ General
```

RecommendationアルゴリズムそのものはV51.2で変更しない。

変更するのは候補Planのscopeと、Task決定後の実行先。

## Execution Mode

ModeはDBへ保存するPlan属性ではない。

`ExecutionModeService` が既存Plan category / specialized capability boundaryからrequest時に導出する。

Current modes:

- study
- development
- career
- general

### Study

現在のspecialized Study ActivityはController側で `category=資格学習` を要求する。

そのためV51.2でもStudy Modeはexact `資格学習` のみ。

一般的な `学習` / `勉強` categoryは、PlanCategoryProfileServiceではstudy profileになってもExecutionではGeneralへfallbackする。

存在しないspecialized routeへ誘導しないことを優先する。

### Development

PlanCategoryProfileServiceの `development` profileを利用する。

例:

- 個人開発
- ゲーム開発
- 開発
- development
- software

### Career

PlanCategoryProfileServiceの `career` profileを利用する。

例:

- 就活
- 就職
- 転職
- キャリア
- career
- job

### General

上記specialized capabilityへ安全に接続できないPlan。

Creative / daily / generic learning等もV51.2ではGeneral。

## Multiple modes

ユーザーが2種類以上のMode対象Planを持つ場合、Execution初回表示でMode Pickerを出す。

例:

```text
Execution

[ 学習 ]
2 Plan

[ 開発 ]
3 Plan
```

Mode選択後はページ上部にSwitcherを残す。

毎回選択させない。

Session draftへ `execution_mode` を保持する。

## Single mode

利用可能Modeが1種類だけならMode Pickerを省略し、そのModeを自動選択する。

## Plan-context entry

Constellation / Dashboard等から:

`/navigate?plan_id=<id>`

で入った場合:

1. Planを確認
2. PlanのExecution Modeを導出
3. Modeを自動選択
4. そのPlanへscope
5. RecommendationをそのPlan内で生成

ユーザーへMode選択をやり直させない。

## Recommendation scoping

Selected Modeがある場合のみRecommendationを生成する。

```text
all owned editable Plans
↓
selected Mode filter
↓
optional Plan scope
↓
existing RecommendationService
```

RecommendationServiceの:

- priority
- time budget
- intent
- behavior
- exclusions

は変更しない。

ModeはRecommendation engineを置き換えるものではなく、その入力scopeを決める。

## Mode-specific Plan switcher

同じModeに複数Planがある場合のみ、Mode内Plan switcherを表示する。

- すべて
- Plan A
- Plan B
- ...

`すべて` は全Planではなく **selected Mode内の全Plan**。

## Specialized handoff

RecommendationでTaskが決定した後、ExecutionModeService::actionFor()が実行先を返す。

### Study

`plans.tasks.study_activity.show`

表示:

> 学習Workspaceで進める

既存Study Activityが:

- practice
- recall
- material

等をTask contextから判断する。

### Development

`plans.tasks.execution_orchestration.show`

表示:

> 開発Workspaceで進める

既存:

- Task Context
- Execution Packet
- GitHub handoff
- coordination
- evidence

を利用する。

### Career

`plans.career.index`

表示:

> Career Workspaceで進める

Career Pipelineへhandoffする。

V51.2ではTask単位専用Career executionを新設しない。

### General

既存WorkSession TimerをPrimary Actionとして利用する。

## Timer fallback

Study / Development / CareerのPrimary Recommendationではspecialized handoffに加えてTimer開始も残す。

Specialized toolを使わず、すぐ作業時間だけ記録したいケースを阻害しない。

## Filters and reset

Mode選択後:

- intent
- time
- preferred Plan
- alternative

はexisting flowを利用する。

`戻す` / resetはrecommendation configurationを消すが、現在Modeはqueryへ戻して維持する。

Mode Switcherで別Modeを選んだ場合はRecommendation draftを新Mode用に初期化する。

## Preferred Plan

`preferred` intentのPlan dropdownはselected Mode内Planだけを表示する。

Server-side validationでもselected Mode外Planを受け付けない。

UIだけのfilterにしない。

## Navigation responsibility

```text
Home
= 今やるべきことを知らせる

Constellation
= 全体と現在地を見る

Execution
= Taskを選び、実行方法へ入る

Specialized Workspace
= その作業を実際に進める
```

Execution自身へStudy UIやGitHub UIを全埋め込みしない。

ExecutionはMode-aware orchestration layer。

## Persistence

DB migrationなし。

保存しない:

- Plan execution_mode
- preferred execution mode profile
- mode recommendation score

Sessionのみ:

- execution_mode
- scope_plan_id
- existing navigation draft
