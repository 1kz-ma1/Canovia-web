# V41.23 — First-run Gate + Mobile Plan Actions + Clickable Today Card

## Purpose

実機確認で見つかった3つのUX課題をまとめて改善する。

1. 新規ユーザーの最初の説明画面を、閉じたりスキップして通常画面へ抜けるモーダルではなく、必ず通る専用入口にする。
2. Plan詳細上部の操作群がスマホ幅で細長い縦書き状になる問題を解消する。
3. Home「今日やること」のTaskカード自体をPlan詳細への自然な導線にする。

## 1. Dedicated First-run Gate

### Route

- GET `/welcome`
- POST `/welcome/start`

fresh GuestがHome / Inbox / Roadmap / Timeline / Calendar / Navigation / Plan creation / Goal Discoveryへ直接アクセスした場合は `/welcome` へ戻す。

専用画面には:

- はじめまして
- Canoviaの役割
- Canoviaと始める
- 既存アカウント向けログイン

だけを表示する。

× と「今はスキップ」は置かない。

### Existing users

既存ユーザーを新規ユーザーと誤判定しないよう、`users.first_run_completed_at` を追加する。

migration時点ですでに存在するUserは完了済みとしてbackfillする。
migration後に作成された新規アカウントはnullから始まり、First-run完了時にtimestampを保存する。

これにより新規アカウントは:

- Session喪失
- Logout / Login
- Browser restart

を挟んでもFirst-run完了前なら再びWelcomeへ戻る。

Test factoryのUserは既存ユーザー相当として `first_run_completed_at=now()` をdefaultにする。

### Guest compatibility

以下はGateしない。

- すでにFirst-runを通過したBrowser
- 既存Guest Plan ownership cookieを持つBrowser

GuestでFirst-runを通過した状態は1年cookieとsessionへ保存する。

### Registration / Login

新規登録:
- 既存Guest Planをclaimした場合は既存利用者としてHomeへ
- すでにBrowserでFirst-runを通過済みなら重複表示しない
- それ以外はWelcomeを必須化

Login:
- 既存Accountはmigration済みtimestampにより通常Homeへ
- First-run未完了の新規AccountはLoginし直してもWelcomeへ戻る
- Browser側で既にFirst-run通過済みならAccountへ状態を引き継ぐ

## Existing spotlight tutorial

First-run専用入口とは別に、既存の操作Spotlightは継続する。

First-run intro modal側の:

- ×
- 今はスキップ
- Esc close

は無効化する。

Spotlight各ステップ側のSkipは残す。これは「製品の入口」ではなく「操作説明」なので任意。

## 2. Mobile Plan Actions

Plan詳細上部をmobileでは:

```text
[      Primary Action      ]
[ Tools ] [ 計画を更新 ]
[ 関連資料 ] [ 制作ファイル ]
```

にする。

Primary Action:
- 2 column span
- full width
- minimum 48px height

Secondary:
- 2-column grid
- minimum 44px height
- centered label

md以上は従来どおりflex layoutへ戻す。

Action semantics / route / formは変更しない。

## 3. Clickable Today Card

HomeのGuidance CardへPlan URLを持たせる。

Card背景をtap/click:
- owning Plan detailへ遷移

カード内の明示Action:
- AI演習
- Career
- 制作ファイル
- 資料
- Guided Execution
- Timer
- 「なぜこの行動？」details
- button / form / link

を押した場合は既存Actionを優先し、Card navigationを発火しない。

Plan chip自体も通常のanchorにするため、keyboard / assistive navigationでもPlan詳細へ到達できる。
