# V58.5 Specialized Mode Top Daily-use Density

Status: implemented / validated  
Branch: `feature/v58-5-specialized-top-density`

## 1. Goal

V58.4 made Study / Developer Top the canonical mode entry. V58.5 makes those
Top pages light enough to use as a daily transition surface rather than a
large dashboard.

```text
Mode Top
→ compact mode identity
→ compact Plan list
→ Plan title + progress + state
→ Open Plan
→ disclose setup / detail only when needed
```

## 2. Shared Plan row

Each accessible Study / Development Plan remains server-rendered and shows:

- Plan title
- weighted progress percentage
- thin progress bar
- schedule/status facts
- deadline / remaining days when available
- active / total Task counts
- primary Open action

The old nested `page-card` per Plan is removed. The parent Top card owns the
visual container and Plan rows are separated by lightweight dividers.

## 3. Study Top

Always visible per Plan:

- Plan title / progress
- status / deadline
- Active / total Tasks
- Study Scope count
- Resource count
- `学習を開く`

Secondary preparation actions move behind a native `<details>` disclosure:

- 範囲
- 教材
- 成績
- Plan詳細

No JavaScript state or new persistence is added.

## 4. Developer Top

Always visible per Plan:

- Plan title / progress
- status / deadline
- Active / total Tasks
- Repository name or `Repository未登録`
- persisted GitHub connection label
- `開発を開く`

When GitHub Evidence is available, GitHub / connection setup remains a direct
secondary action. Plan detail moves into the compact disclosure.

Repository state is rendered inline instead of inside another nested dashboard
card.

## 5. Top chrome

Study / Developer introductory hero sections are reduced to compact mode
headers with:

- mode identity
- Plan count
- short purpose copy
- create Plan CTA

Developer actor-level GitHub Integration state is retained as a compact strip.

## 6. Provider and state boundaries

V58.5 is presentation-only.

It does not:

- change V58.4 mode routing
- change Plan ordering
- change PlanProgressService
- run Study / Development Intelligence for every Plan
- call AI
- perform remote GitHub reads
- mutate Task / Plan state
- change Workspace preference
- change entitlement / billing behavior

Development Top continues to derive Repository connection state from persisted
artifact metadata plus actor-level readiness only.

## 7. Mobile / disclosure safety

The shared Plan list does not use `overflow-hidden`, so native disclosure
menus are not clipped by the list container.

Rows may wrap on small screens while keeping the primary Open action and
secondary disclosure available.
