# V43.5 Map Node Direct Navigation

## Goal

Primary Action以外でも、目的地が明確なNodeに対して

Map Node → Focus → Context Surface → destination

を強制しない。

同時に、Node本体のFocusとInstant Navigationが競合する既存リスクを解消する。

## Interaction model

Nodeの操作をDOM上でも分離する。

- Node body / label: Contextを見る
- 「開く ↗」: canonical destinationへ直接移動

JavaScriptが失敗した場合もNode bodyの実リンクは残るため、従来のno-JS fallbackを維持する。

## Direct-open policy

直接遷移を出すNode:

- Goal → Goal Context
- Plan → Plan
- Tool → Tool
- Evidence → Timeline
- Inbox → Inbox

直接遷移を出さないNode:

- Current Task
  - V43.4 Toolbar Primary launchが既に存在する
- Next Task
  - Plan確認 / Task編集など複数の意味があり、一意なdestinationではない

direct destinationはMap専用に再定義しない。
各NodeのContextual Classic Surfaceで既にprimaryとしているactionを再利用する。

## Instant Navigation boundary

Map Nodeはno-JS fallbackのため実 href を持っている。

Core URL (/inbox, /timeline 等)の場合、Instant Navigationのcapture handlerがLiving Mapのbubble handlerより先にclickを取る可能性があった。

V43.5では:

- data-map-node-focus のlinkはInstant Navigation capture対象から除外
- Living Mapがclickを受けてFocus
- data-map-direct-navigation は通常どおりInstant Navigation対象

とする。

そのためCore URLを持つNodeでも:

- body = Focus
- open chip = Navigation

が必ず一致する。

## Telemetry

非Primary direct openも既存 map_classic_action_opened を利用する。

action_roleへ direct を追加する。

記録:

- node_type
- position_role
- is_primary=false
- action_role=direct
- flow / elapsed / step

user textは保存しない。

## Living Reevaluation

direct open前にsource Node IDをpending reevaluationへ保存する。

Classic destinationから戻った時は既存V42.2 revalidationを利用する。

## Non-goals

- Node上でmutation
- Next Taskの操作を1つへ決め打ち
- Contextual Classic Surface削除
- Map専用destinationロジック
- Companion変更
