# V58.4 Specialized Mode Top Canonical Entry

Status: implemented / validated  
Branch: `feature/v58-4-mode-top-entry-routing`

## 1. Goal

Study / Developer Mode Top is now the canonical entry point for entering or
resuming those Workspace modes.

```text
enter / resume Study or Developer mode
→ Mode Top
→ choose / inspect a Plan
→ open one Plan Workspace

explicit Plan deep link / Plan-local action
→ selected Plan Workspace directly
```

This completes the V58.2 responsibility split between mode-level navigation
and Plan-scoped daily work.

## 2. Canonical mode entry

Mode-level entry resolves as follows:

```text
Study       → workspace.study.top
Development → workspace.development.top
Overview    → workspace.overview.index
Career      → workspace.career.index
```

Applied to:

- persistent Workspace Mode selection
- ephemeral Workspace Mode entry
- root `/` resume from a manual Workspace preference
- Overview first-use mode choices using `workspace_modes.enter`

## 3. Ephemeral entry route

The generic mode-entry route is now distinct from concrete Plan Workspace URLs:

```text
GET /workspace/mode/{workspaceMode}
→ workspace_modes.enter
```

Previously the generic route used `/workspace/{workspaceMode}`, which collided
with concrete routes such as `/workspace/study` and `/workspace/development`.
That meant Laravel could dispatch directly to the concrete Workspace route
instead of `WorkspaceModeController::enter`.

The route name remains `workspace_modes.enter`, so internal callers follow the
new path without duplicating route construction.

## 4. Plan Workspace compatibility

These remain valid direct Plan Workspace routes:

```text
/workspace/study?plan_id=...&surface=...
/workspace/development?plan_id=...&surface=...
```

Plan-specific flows continue to open the selected Plan directly, including:

- explicit Plan deep links
- Plan creation completion
- Current Action / Plan-specific handoff
- Study Practice / Recall / Scope / Scores / Resources
- Developer Repository / Team / Improvements / Preview

V58.4 does not force Plan-local operations through Mode Top.

## 5. State and side-effect boundary

V58.4 is routing-only.

It does not:

- change Workspace preference persistence
- create or select a Plan
- alter Study / Development Intelligence
- add AI calls
- add GitHub provider reads
- mutate Task / Plan progress
- change entitlement or billing behavior
