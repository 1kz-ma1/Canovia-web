# TEMP V58.19 Weakness Intervention Outcome Observation\n\nStatus: implementation in progress  \nBranch: `feature/v58-19-weakness-intervention-outcomes`\n\n## Goal\n\nMeasure whether a completed focused weakness-reinforcement cycle is followed by better performance on the same Topic after the learner returns to broad Practice.\n\n```text\nbroad Topic observations before reinforcement\n→ focused weakness_reinforcement cycle\n→ return to General / Exam Practice\n→ broad Topic observations after reinforcement\n→ before / after observation\n```\n\nThis is observational. It does not claim that the intervention caused the change.\n\n## Scope\n\n- same Plan\n- same Task\n- same actor\n- latest bounded Practice history\n\nUnlike V58.18, this measurement is not AP-only. It can work for any Study Practice Task whose question metadata identifies the relevant Topic.\n\n## Reinforcement cycle\n\nA cycle starts when a Practice Attempt's saved strategy has:\n\n- `learning_phase.phase = weakness_reinforcement` or equivalent strategy key\n- and the Topic appears in one of:\n  - `weakness_control.active_topics`\n  - `weakness_priority.primary_topics`\n  - `focus_topics`\n\nThe cycle ends when Practice returns to General Practice or Exam Mode.\n\nA later reinforcement of the same Topic starts a new cycle.\n\n## Topic mapping\n\nQuestion outcome is attributed to a Topic only when the question itself carries identifiable Topic metadata.\n\nPriority:\n\n1. Attempt question `topic`\n2. Attempt question `parent_topic`\n3. Session selected question `selection_parent_topic`\n\nA question may match both its subtopic and parent topic.\n\n`question_feedback.weakness_topics` alone is not sufficient to map a correct question and therefore is not used as the sole before/after attribution source.\n\n## Baseline\n\nFor each Topic cycle, baseline uses up to the latest 5 mapped graded Topic-question events before the reinforcement starts, from non-reinforcement Practice.\n\nRequire:\n\n- at least 2 graded Topic questions\n- at least 2 unique question references\n\nOtherwise status remains waiting for a usable baseline.\n\n## After observation\n\nAfter the reinforcement cycle ends, use up to the first 5 mapped graded Topic-question events from General Practice / Exam Mode, before the next reinforcement cycle for the same Topic.\n\nRequire:\n\n- at least 2 graded Topic questions\n- at least 2 unique question references\n\nOtherwise status remains waiting for broad recheck.\n\n## Correctness\n\nOnly `correct / partial / incorrect` feedback is accepted.\n\nObserved correct rate:\n\n`correct / total`\n\nPartial is not correct.\n\n## Outcome classification\n\nWhen both sides are measurable:\n\n- delta >= +15pt → `improved_observation`\n- delta <= -15pt → `regressed_observation`\n- otherwise → `stable_observation`\n\nThe 15pt band is deliberately wide because the sample is small.\n\nConfidence:\n\n- 2–3 questions on either side → low\n- >=4 questions on both sides → moderate\n\nNo `high` confidence is emitted in V58.19.\n\n## Reinforcement-score boundary\n\nScores achieved inside weakness_reinforcement are displayed only as intervention context.\n\nThey are NOT used as the after score.\n\nThis prevents an easier focused drill from being mistaken for durable improvement.\n\n## History bound\n\nRead latest maximum 120 Attempts for the Task / actor.\n\nIf truncated, expose `history_truncated=true`.\n\n## Study Analysis UI\n\nRegister surface:\n\n`weakness_intervention_outcomes`\n\nShow up to 5 latest Topic intervention cycles with:\n\n- Topic\n- status\n- baseline observed correctness\n- post-reinforcement broad observed correctness\n- delta\n- baseline / after question counts\n- targeted session count\n- targeted mapped question count\n- confidence\n- waiting reason when not yet measurable\n\nExplicitly state that this is a before/after observation, not causal proof.\n\n## Authority boundary\n\nV58.19 does not modify:\n\n- StudyWeaknessPrioritizationService\n- StudyExamConvergencePolicyService\n- StudyPracticeRoutingPolicyService\n- V58.18 Plan-wide handoff\n- Study Method Recommendation\n- Task progress / completion\n- mastery\n\nNo automatic reinforcement extension or suppression is introduced.\n\n## Provider / storage\n\nDB-only, deterministic, read-only.\n\nNo extra AI/provider call.\nNo migration.\n\n## Validation\n\nRequired:\n\n1. no reinforcement cycle → surface unavailable / empty\n2. reinforcement with no baseline → waiting baseline\n3. baseline requires 2 unique question refs\n4. in-progress reinforcement → reinforcing\n5. completed reinforcement with <2 after → waiting broad recheck\n6. focused reinforcement score alone cannot produce improvement\n7. +15 or more → improved observation\n8. -15 or less → regressed observation\n9. within ±14 → stable observation\n10. partial is not correct\n11. same Task / actor isolation\n12. another Task does not contribute\n13. next reinforcement cycle closes previous after window\n14. latest cycle per Topic is surfaced\n15. latest maximum 120 Attempt bound\n16. Study Analysis surface renders\n17. GET is read-only/provider-free\n18. V56.0 convergence regression green\n19. V56.4 routing regression green\n20.
