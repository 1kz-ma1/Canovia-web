# V58.75 Plan Action Draft quality and revision integrity

## Active rules
- Every newly prepared 3-step bundle stores a proposal_fingerprint derived
  from the Plan's current effective Domain, evidence revision and the exact
  editable suggested action. The fingerprint must match on step updates,
  acceptance and repeat prepare; a mismatch requires explicit owner rebuild.
  Existing V58.74 step rows (nullable fingerprint) are treated as stale,
  **never auto-deleted or auto-imported**.
- Editable candidate and all three step titles use row-locked transactions.
  Current UI submits optimistic candidate / step checksums and evidence revision
  so simultaneous desktop/mobile views cannot silently clobber newer changes.
  Older clients omitting optional checks remain backward compatible.
- The single-task approval form also submits a candidate checksum and revision,
  preventing stale UI approvals. Legacy no-checksum submissions still work.
- Quality notice on proposed drafts shows how many source snapshots are present,
  whether the evidence includes a WorkLog or TaskEvidence, warns if candidate or
  any step title exactly matches an active existing Task, and calls out generic
  action wording as editable. Warnings do **not** automatically reject tasks:
  repeated practice can be intentional.
- No AI inference, proficiency assertions, auto corrections, or API expense.
  No canonical Plan/Task change except **explicit** Task approval unchanged.
