# V51.9.1 Server Cost Reduction

## 背景

V51.8/V51.9のproduction telemetryで、client renderよりserver DB roundtripが主要コストであることを確認した。

実測の代表値:

- database session: 1 requestあたり約430〜550ms
- Home: 約4.0〜4.4秒 / 32〜35 queries
- Core Bundle: 約2.5〜4.4秒 / 22〜34 queries
- Constellation cache hit: 約92ms
- Home cache hit: 約108ms

V51.9でExecutionのTask dependency N+1を解消した後、V51.9.1では「全request固定費」と「ユーザー意図なしに発生するserver cost」を削減する。

## 1. Production Session → Render Key Value

Render Singaporeへ `canovia-session` Key Valueを作成する。

- plan: free
- region: singapore
- maxmemory: noeviction
- persistence: off

production Web Serviceと同一workspace / regionのprivate networkを使う。

Environment:

- `REDIS_URL=redis://<key-value-resource-id>:6379`
- `SESSION_DRIVER=redis`
- `SESSION_CONNECTION=default`
- `REDIS_PERSISTENT=true`

既存Docker imageはphpredis extensionを含み、session configはSESSION_DRIVERをproductionでも尊重するため、application codeのsession semanticsは変更しない。

### Free tier boundary

free Key Valueはdisk persistenceを利用できない。

Key Value restart時にはlogin/session stateが失効する可能性があるが:

- Plan
- Task
- WorkLog
- Evidence
- DB-backed domain data

は失われない。

session stateをsource of truthにはしない既存設計を維持する。

rollback:

`SESSION_DRIVER=database`

へ戻す。

### Production verification

2026-10-03のinfra切替直後、production `/` requestで以下を確認した。

- session_driver: redis
- session_query_count: 0
- session_query_ms: 0
- DB query_count: 0
- elapsed_ms: 4.98

同じ302系requestではdatabase session時に約430ms前後のDB固定費が観測されていたため、session hot pathがMySQLから外れたことを確認できた。

既存database sessionからRedisへのstate migrationは行わないため、切替後に既存login sessionが一度失効する可能性がある。

## 2. Home Specialized Relation Gating

Homeのcommon pathから以下を外す:

- career
- memberships
- activity_logs

base Home data:

- tasks
- task_dependencies
- task_artifacts
- plan_resources
- plan_artifacts
- availability
- work_logs

その後、実際にmatching Planが存在するときだけ追加hydrateする。

### Career

PlanCategoryProfileがcareerのPlanが1件以上ある場合のみ:

- careerApplications
- careerCaptures
- selectionEvents / interviewReview

をloadする。

### Collaboration

`is_collaborative=true` Planが1件以上ある場合のみ:

- memberships
- activityLogs

をloadする。

Career / CollaborationのUI semanticsは変更しない。

## 3. Home Idle Prefetch Cost

Instant Navigationのautomatic idle prefetchではHomeを除外する。

理由:

- 通常起点がHomeの場合、current pageとして既にmemory cacheへcapture済み
- deep linkから開始した場合、Homeを開く意思がないのに高コストHome projectionをbackground実行する必要がない
- pointerover / focusin / touchstartのintent prefetchは維持する

つまり:

- speculative idle Home prefetch: 廃止
- explicit interaction intent Home prefetch: 維持
- Home click navigation: 維持

## 4. Core Bundle Boundary

V51.9.1ではCore Bundle自体の構造変更はしない。

Redis session化とHome speculative cost削減後に再計測し:

- Roadmap
- Timeline
- Core Bundle

の実server timeを比較して、bundle分割/優先prefetchが必要かをV51.9.2で判断する。

## 5. Regression Contract

Feature testsで:

- non-career / non-collaborative accountではspecialized relation SELECTを発生させない
- career / collaborative accountでは必要relationを維持する
- idle prefetchではHomeを除外する
- intent prefetchは維持する

を固定する。

## DB migration

なし。
