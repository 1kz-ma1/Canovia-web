# V58.27 Living Profile Foundation

## Goal

Initial Diagnosisを固定プロフィールにせず、
実利用からContext Update Candidateを作る最小ループを成立させる。

Core contract:

```text
Initial Diagnosis
→ User Context v1
→ Actual Behavior
→ Context Update Candidate
→ Auto Apply OR User Confirmation
→ User Context v2
```

## Core principle

> **Initial Diagnosis is a starting hypothesis, not a permanent profile.**

本人回答・Observed Fact・Inferenceを混同しない。

## Source roles

```text
self_reported_context
= 本人が明示した回答

observed_context
= Canoviaが実利用から確認した事実

inferred_context.update_candidates
= 観測事実から作った更新候補
```

更新候補が存在してもSelf-reportedを上書きしない。

## Candidate model

Concept:

```text
key
domain
kind
risk
confidence
status
confirmation_required
trigger
evidence[]
proposal{}
created_at
resolved_at
```

Status:

- pending
- auto_applied
- confirmed
- dismissed

## Risk contract

### Low risk

User confirmationなしで適用可能。

V58.27 first example:

```text
workspace_mode_preference
→ recent domain observed
→ recommended_surfaces ordering
```

Study / Developmentをユーザーが明示選択した時、
対応Surfaceをrecommended_surfaces先頭へ移す。

変更しない:

- self-reported domain
- experience
- guidance
- Plan content

### High impact

必ずpending candidateとして保存し、
ユーザー確認まで適用しない。

V58.27 first example:

```text
Observed:
GitHub integration = connected

Self-reported:
development experience = beginner / standard

Candidate:
advanced Development support may be useful
```

重要:

この候補は:

> 「あなたは上級者になった」

という推定ではない。

提案:

> 「Repository前提の高度なDevelopment支援を表示すると役立ちそう」

のみ。

確認後:

```text
feature_readiness.development.advanced_support.enabled = true
```

Self-reported experience / Guidance Levelは維持する。

## Refresh triggers

V58.27 implemented:

- workspace_change
- capability_readiness
- manual refresh

Deferred:

- new_plan
- plan_completed
- long usage window
- return after long absence
- new domain adoption without explicit workspace preference
- stronger behavior shift detection

## Growth Experience

Account:

> Canoviaが気づいた変化

からLiving Profileを確認できる。

Pending candidateがある場合は件数を表示する。

Context Update page:

- current principle
- pending candidate
- confidence
- confirm
- dismiss
- manual refresh

大量の定期質問は出さない。

## Dismiss behavior

Dismissed candidateは、
同じcandidate key / 同じ現在のObserved Factだけでは再生成しない。

将来、新しいEvidence revision / stronger signalを導入する場合は
evidence fingerprintを別途設計する。

## Telemetry

Server-side:

- context_refresh_triggered
- context_update_candidate_created
- context_update_auto_applied
- context_update_confirmed
- context_update_dismissed

Metadataは:

- candidate key
- domain
- risk
- change type
- trigger

等のenumerationのみ。

User free textは保存しない。

## Release boundary

Minimum:

```text
L1 Early Access Core
```

Required route:

- `personalization.updates.index`

Manual review:

- `living_profile_context_update`

## Security / Trust

- auth required for Living Profile page/actions
- L1+ required
- candidate key whitelist format
- unsupported / resolved candidateは変更不可
- high-impact update requires explicit POST confirmation
- Observed Fact does not imply entitlement
- confirmation does not rewrite self-reported answers

## Deferred

V58.27では実装しない:

- AI behavior inference
- experience level auto estimation
- Study stage inference
- Plan-direction automatic mutation
- Guidance Level automatic promotion
- periodic survey
- arbitrary candidate proposal execution
- evidence fingerprint / re-open rules
