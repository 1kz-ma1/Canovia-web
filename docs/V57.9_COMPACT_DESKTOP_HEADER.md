# V57.9 Compact Desktop Header

## Goal

Reduce the amount of vertical and horizontal desktop space consumed by the
global Canovia shell, especially the Workspace / specialized UI switcher.

The problem observed on desktop was not the Workspace concept itself. It was
the presentation:

```text
primary header row
+
second sticky Workspace row
+
large Workspace trigger / menu
```

This consumed too much of the viewport before page content began.

## Desktop layout

Before:

```text
Canovia   Home / 星座 / 実行 / タイムライン   utilities
────────────────────────────────────────────
WORKSPACE   [ Development ▾ ]
────────────────────────────────────────────
page content
```

V57.9:

```text
Canovia [Development ▾]   Home / 星座 / 実行 / タイムライン   utilities
────────────────────────────────────────────────────────────────
page content
```

The Workspace switch remains globally visible but no longer owns a second
desktop header row.

## Workspace dropdown

The desktop inline trigger is intentionally compact:

- no visible `WORKSPACE` kicker
- smaller icon
- no source/context subtitle in the closed trigger
- smaller trigger padding
- no large shadow
- narrower menu
- denser menu options

The underlying registry, routing, persistence and telemetry remain unchanged.

The hidden semantic kicker remains in the markup for compatibility/testing,
but the inline desktop variant does not visually render it.

## Primary navigation density

Desktop-only shell density is reduced further by:

- smaller header vertical padding
- smaller wordmark
- tighter primary nav link padding
- slightly smaller nav icons
- tighter secondary utility controls

No navigation destination is removed.

## Mobile boundary

V57.9 does not redesign mobile.

The existing mobile compact Workspace switcher and touch targets remain
authoritative.

The desktop compaction rules are scoped to:

```css
@media (min-width: 768px)
```

## Behavior compatibility

Unchanged:

- WorkspaceModeRegistry
- WorkspaceModeResolver
- persistent Workspace preference
- Instant Navigation Workspace synchronization
- behavior telemetry
- Study / Development / Career / Overview routes
- Focus Mode shell hiding
- mobile Workspace selector

No AI, database, Task, Plan or Intelligence behavior changes.

## UX principle

Workspace selection is global context, not primary content.

Therefore:

> It should remain immediately available without permanently consuming a
> second row of the working viewport.

## Validation

V57.9 adds a desktop shell regression test that verifies:

- exactly one inline Workspace switcher exists in the desktop primary row
- the old second-row desktop Workspace bar is gone
- the mobile compact switcher still exists
- compact desktop CSS remains desktop-scoped
