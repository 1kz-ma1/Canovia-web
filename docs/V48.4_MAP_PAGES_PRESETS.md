# V48.4 Map Pages / Presets

## 目的

Canovia Mapを1枚固定の画面ではなく、用途ごとに複数の「見方」を持てるNavigation Layerへ進化させる。

スマートフォンのHome Screenのように、

- 全体確認
- 実行
- 振り返り
- 共同作業
- AP学習
- Canovia開発

など、ユーザーが目的に応じてMap Pageを切り替えられる状態を作る。

## Pageはcanonical dataではない

Map PageはPlan / Task / Evidenceをコピーしない。

保存するのはpresentation/navigation stateだけ。

V48.4で保存するもの:

- Map structural route
- Page名
- Data Layer state
- Page並び順

保存しないもの:

- Plan payload
- Task payload
- Evidence payload
- selected Node / Focus hash
- Space Station Dock state
- pan / zoom
- AI reasoning

したがってMap Pageを削除してもPlan / Task等は削除されない。

## Structural route

Pageに保存できるMap queryは以下だけ。

- level
- intent
- domain
- plan
- collab_context
- reflection_context

Focus / Dockはhash stateなので保存しない。

無関係なquery parameterも保存しない。

例:

```
/map?level=l3&intent=execution&plan=12#focus=task:99
```

を保存すると:

```
/map?level=l3&intent=execution&plan=12
```

になる。

Pageを開くと局所選択ではなく、そのMap Surfaceのrootへ戻る。

## Standard presets

標準Page:

1. 全体
2. 計画
3. 実行
4. 振り返り
5. 共同

標準Pageは削除しない。

## Custom Pages

ユーザーは現在のMapを名前付きPageとして保存できる。

例:

- AP学習
- Canovia開発
- 全体確認
- 共同レビュー

V48.4では1端末につき最大8件。

カスタムPageは:

- 開く
- 前へ移動
- 後ろへ移動
- 削除

が可能。

drag & dropはNon-goal。

## Data Layer snapshot

Custom Page保存時に、その端末の現在のData Layer stateもsnapshotする。

例:

```
AP学習
route: /map?level=l3&intent=execution&plan=1
layers:
  progress
  status
  evidence
```

別Page:

```
全体確認
route: /map?level=l2&intent=plan&domain=...
layers:
  deadline
  priority
```

Page切替時は保存されたData Layer stateを先に適用する。

Data Layer設定はpresentation-onlyであり、Task/Plan状態は変更しない。

## Persistence

V48.4はlocalStorageへ保存する。

Keys:

- `canovia.map.pages.v1`
- `canovia.map.pages.active.v1`

理由:

- Map Page情報は現時点でpresentation preference
- canonical DB schemaを増やさず価値検証できる
- V48.4でAccount sync / shared Pageの複雑さを持ち込まない

将来Account syncを導入する場合も、このschemaとcanonical dataを分離したまま移行する。

## Active Page

Pageを開いた時、そのPageをactiveとして記録する。

同一routeでもData Layersが違うCustom Pageを持てる。

Semantic ZoomでPage rootから深く潜った場合は、active Page identityを保つ。

別のPageを押すと、そのPageの保存rootへ戻る。

## Global Home reset bug fix

### 症状

V48.1後も、深いMapでNodeを選択した状態から「全体へ」を押すと、

- URL / hierarchyはL0へ戻る
- しかし以前選択したIntent Nodeが中央Focusとして残る

ケースが存在した。

添付画面録画で再現確認。

### 原因境界

V48.1は遷移元で:

- clearFocus
- clearDock
- history hash removal

を行っていた。

しかしInstant Navigation / cached DOM replacementの境界をまたぐため、
「遷移先L0のmount時にもGlobal Home resetを保証する」契約が不足していた。

### V48.4修正

Global Home操作時にsessionStorageへ短命reset requestを保存する。

```
canovia.map.global-home-reset.v1
```

payload:

```json
{
  "version": 1,
  "requested_at": 1234567890
}
```

reset requestは:

- deep Map上では消費しない
- L0 mount時だけ消費する
- 10秒を超えたstale requestは破棄する

L0 mount時:

1. focus history depth = 0
2. canoviaMapFocus除去
3. canoviaMapDock除去
4. hash除去
5. Focus UI clear
6. Dock clear
7. pan / zoom reset
8. その後initial focus restoreをskip

これにより:

- Instant Navigation
- cached response
- intermediate re-render
- full page fallback

のどの経路でもL0は選択なしで開始する。

標準「全体」Pageと、routeが `/map` のCustom Pageにも同じresetを適用する。
