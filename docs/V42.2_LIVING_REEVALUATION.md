# V42.2 Living Reevaluation

## Purpose

Canovia Mapを「常に動く画面」ではなく、実際の状態変化にだけ反応するLiving Mapへ進める。

V42.2の原則:

- 時間経過だけでは動かさない
- 小さなscore変化だけでは動かさない
- Classic画面で意味のある作業をした可能性がある時だけ再評価する
- Projectionが同じなら画面を一切動かさない

## Projection key

MapProjectionServiceはNode / Edge / Primary Actionから決定論的な \`projection_key\` を生成する。

キーには現在時刻を含めない。

そのため、同じ状態を再取得しただけではキーは変化しない。

以下のような変化はキーを変える。

- Primary Task変更
- Task状態変更がMap投影へ影響
- Evidence追加
- pending Inboxの変化
- Tool / Plan / Goal Contextの投影内容変更

## Return-triggered reevaluation

MapのContextual Classic Surfaceから既存画面へ移動する時:

1. 現在のprojection_keyをsessionStorageへ保存
2. 既存Classic画面で通常どおり操作
3. Mapへ戻る
4. 戻り方に応じて最新状態を確認

### Fresh navigation

Mapがサーバーから新しく描画された場合は、その時点ですでに最新Projection。

- keyが変わっている -> 更新済み表示
- keyが同じ -> 何も表示しない

追加fetchは行わない。

### BFCache / history return

ブラウザが古いMap DOMをBFCacheから復元した場合だけ \`/map\` をno-storeで再取得する。

- keyが同じ -> DOMを変えない
- keyが異なる -> Map pageだけを最新Projectionへ置換

## Transition

再Projection時は大きな物理Animationを行わない。

- 短いfade / settle
- 「Mapを最新の状態へ更新しました」の小さなstatus
- prefers-reduced-motionではAnimationを無効化

Primary Actionが完了済みになった場合、次のTaskが新しい中央Actionになる。

## Focus continuity

再Projection後もFocus hashが存在し、同じNodeが残っていればFocusを復元する。

選択していたNodeが完了などでMapから消えた場合は、無効なFocus hashを自動で外して全体Mapへ戻す。

## Architecture boundary

V42.2でもmutation pathは変更しない。

Task / Evidence / Inboxなど既存ControllerへMap専用処理を埋め込まない。

Living Mapは:

\`Classic mutation -> canonical data -> MapProjectionService -> projection_key -> UI reevaluation\`

という一方向で追従する。

## Non-goals

- polling
- WebSocket
- 秒単位の自動更新
- Mapからの直接mutation
- AIによるnode移動
- scoreの微差による常時re-layout
