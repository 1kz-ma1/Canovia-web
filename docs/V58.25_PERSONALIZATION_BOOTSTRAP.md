# V58.25 Personalization Bootstrap Foundation

## Goal

Canoviaの新規ユーザーが、0からPlanや機能を理解して設定する負荷を減らす。

V58.25 Phase 1は:

```text
Welcome
→ Personalization Bootstrap
→ Personalization Context
→ deterministic Plan Seed
→ existing Plan create
```

を最小構成で成立させる。

WIP continuity:

- `docs/wip/PERSONALIZATION_BOOTSTRAP_IMPLEMENTATION.md`

Canonical:

- `docs/CANOVIA_PERSONALIZATION_SPEC.md`
- `docs/CANOVIA_PRODUCT_SPEC.md`
- `docs/CANOVIA_RELEASE_LEVEL_SPEC.md`

## Core principle

> **Initial Diagnosis is a starting hypothesis, not a permanent profile.**

> **初回診断はユーザーを固定的に分類するものではなく、Canoviaが伴走を始めるための初期仮説として扱う。**

Planと同様に:

```text
Initial Diagnosis = Initial Plan
Observed Behavior = Actual Result
Context Update = Replanning
```

として扱う。

## Context storage

Auth user:

```text
user_personalization_contexts
```

Source provenanceを分離:

```text
self_reported_context
observed_context
inferred_context
```

Phase 1:

- Initial Diagnosis → self_reported
- observed → empty
- inferred → empty

Derived:

- guidance_level
- recommended_surfaces
- feature_readiness

Contextには:

- schema version
- context revision
- last evaluated timestamp

を持つ。

将来inferred entryはconfidenceを保持可能なJSON構造とする。

## Living Context

将来:

```text
Initial Diagnosis
→ User Context v1
→ Actual Behavior
→ Context Update Candidate
→ optional User Confirmation
→ User Context v2
→ Plan / UI / Guidance / Feature Recommendation refresh
```

自動調整候補:

- recent domain
- recommendation order
- capability recommendation priority

確認を挟む候補:

- experience levelの大幅変更
- Plan方針への影響
- advanced capability group exposure
- inferred intent

Refresh trigger候補:

- Plan完了
- Goal / Plan新規作成
- 長期利用
- 長期離脱からの復帰
- 新カテゴリ開始
- 明確な行動変化
- advanced capability readiness

Phase 1ではInference Engineを実装しない。

## GitHub capability preview

Eligibility:

- Development selected
- GitHub use = yes
- Repository ready = yes

Then:

```text

→ Interest yes / no
→ save self-reported preference

```

GitHub接続を強制しない。
